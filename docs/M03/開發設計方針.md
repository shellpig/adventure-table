## 1. 設計目標

- **一份 codebase，兩個 entry point**：`app.main`（線上版）與 `app.standalone`（單機版）共用 `app.content` / `app.domain` / `app.persistence` / `app.api`，差別只在掛哪些 router、指向哪個資料庫、如何解析 content root。
- **匯入／匯出 server-authoritative**：build_payload 與 refs 收集邏輯只住 server，前端不重建。
- **content 與 data 位置抽象化**：`REPOSITORY_ROOT` 從硬編轉為解析器；解析結果不依賴 filesystem 呼叫者位置。
- **Alembic 一條鏈**：Postgres 與 SQLite 走同一條 migration 鏈，SQLite 由 CI gate 保證可跑。
- **Standalone 相依可裁**：`psycopg` 移到 optional extra，PyInstaller 不打包網頁 driver。
- **P2 界線機械化**：character domain 對 room / session / seat / campaign 的隔離由 static import graph test 強制。

## 3. Path 解析（M03-A 主題）

### 3.1 新增 `apps/server/app/paths.py`

```python
from pathlib import Path
import os
import sys


def _bundle_root() -> Path | None:
    """PyInstaller 凍結時的資源根路徑。"""
    if getattr(sys, "frozen", False):
        meipass = getattr(sys, "_MEIPASS", None)
        if meipass:
            return Path(meipass)
        return Path(sys.executable).resolve().parent
    return None


def resolve_content_root() -> Path:
    env = os.environ.get("ADVENTURE_TABLE_CONTENT_ROOT")
    if env:
        candidate = Path(env)
        if candidate.is_dir():
            return candidate
        raise RuntimeError(
            f"ADVENTURE_TABLE_CONTENT_ROOT 指向的路徑不存在: {candidate}"
        )

    bundle = _bundle_root()
    if bundle is not None:
        candidate = bundle / "data"
        if candidate.is_dir():
            return candidate
        raise RuntimeError(f"bundle 內找不到 data 目錄: {candidate}")

    # dev / test：repo 相對
    return Path(__file__).resolve().parents[3] / "data"


def resolve_rules_path() -> Path:
    return resolve_content_root() / "rules" / "dnd5e-2014" / "character-builder.json"


def resolve_localization_root() -> Path:
    return resolve_content_root() / "localization"
```

備註：現行 `parents[4]` 於 `app/content/registry.py` 是從 `apps/server/app/content/registry.py` 起算 4 層 → 專案根。`app/paths.py` 位於 `apps/server/app/paths.py`，起算深度為 3（app → apps/server → apps → repo root）。實作時以實際檔案位置驗證再落 constant。

### 3.2 呼叫點更新

- `app/content/registry.py`：`REPOSITORY_ROOT` / `CONTENT_PACKS_ROOT` 常數移除；改為 `from app.paths import resolve_content_root` 於載入時呼叫。
- `app/domain/character_builder/rules.py`：`RULES_PATH` 常數改為 `_rules_path()` 函式，呼叫 `resolve_rules_path()`；載入時機不變。
- 其他若後續發現有相同 pattern，同批遷移。

### 3.3 Startup failure handling

- Content root 解析失敗時，`load_default_content_registry()` 讓例外冒出，`app.main` / `app.standalone` import 時中斷。
- 例外訊息必須包含實際解析出的路徑與解析階段（`env` / `bundle` / `repo-relative`），供 launcher 顯示。

## 4. JSON schema（M03-B 主題）

### 4.1 Pydantic model

`app/interop/json_schema.py`：

```python
class Envelope(BaseModel):
    schema_version: Literal["unstable"]              # P2 lock 後改為 "1.0.0" 等
    schema_status: Literal["unstable", "locked"]
    ruleset: str                                     # e.g. "dnd5e-2014"
    content_requirements: list[PackRequirement]
    stable_key_refs_summary: int
    source_character_id: UUID
    source_export_id: UUID
    source_app: SourceApp
    exported_at: datetime


class PackRequirement(BaseModel):
    pack: str                                        # e.g. "srd5.1", "phb2014"
    version: str                                     # pack manifest version


class SourceApp(BaseModel):
    name: Literal["adventure-table"]
    channel: Literal["web", "standalone"]
    commit: str | None                               # git sha 或 build id
    build: str | None                                # release tag


class ExportedVersion(BaseModel):
    version_no: int
    version_kind: str
    base_version_no: int | None
    change_note: str | None
    build_payload: dict[str, Any]
    created_at: datetime


class ExportedCharacter(BaseModel):
    name: str
    ruleset: str


class ExportedState(BaseModel):
    state_payload: dict[str, Any]


class ExportPayload(BaseModel):
    character: ExportedCharacter
    versions: list[ExportedVersion]
    current_state: ExportedState


class CharacterExport(BaseModel):
    envelope: Envelope
    payload: ExportPayload
```

### 4.2 `content_requirements` 計算

- 由 `content_ref_walker.collect_content_refs()` 走訪 `versions` 中每個 `build_payload`。
- 每個 ref 帶 pack 名稱（來自 StableKey 前綴）；集合完成後查 registry 取得該 pack 目前 version。
- **匯出當下 registry 中該 pack 的 version**寫入 requirement，不追溯歷史。這是預期行為：`content_requirements` 只是診斷用，真實 gate 靠匯入端解析 StableKey。

### 4.3 匯出檔命名

- `{sanitized_character_name}-{version_max}-{exported_at_utc}.json`
- Sanitized: 允許 `[A-Za-z0-9_\-\.]`，其他字元換 `_`；截斷至 60 字元；empty 時 fallback `character`。

### 4.4 Endpoint

```
GET /api/characters/{character_id}/export
  → 200 OK application/json
       Content-Disposition: attachment; filename="..."
       X-Adventure-Table-Character-Archived: "true" | "false"
  → 404 character_not_found
```

## 5. Import pipeline（M03-C 主題）

### 5.1 API contract

```
POST /api/characters/import
  Content-Type: application/json | multipart/form-data
  Query:
    dry_run: bool = false

  Body (JSON):
    { envelope: {...}, payload: {...} }
  Body (multipart):
    file: <uploaded .json>
    dry_run: str = "false"

  → 200 OK ImportResult (dry_run=true)
  → 201 Created ImportResult (dry_run=false, success)
  → 400 import_rejected + reason code
  → 409 import_conflict + reason code
```

`ImportResult`：

```python
class UnresolvedRef(BaseModel):
    stable_key: str
    kind: str
    pack: str
    index: str

class ImportPreview(BaseModel):
    name: str
    ruleset: str
    highest_level: int
    class_summary: list[str]
    version_count: int

class ImportResult(BaseModel):
    landing_mode: Literal["character", "draft"]
    resolved_count: int
    unresolved_refs: list[UnresolvedRef]   # 全量；前端自行截斷顯示
    character_preview: ImportPreview
    duplicate_hint: DuplicateHint | None
    committed: bool                        # dry_run 時 false；commit 成功時 true
    landed_character_id: UUID | None       # landing_mode="character" & committed
    landed_draft_id: UUID | None           # landing_mode="draft" & committed
    source_export_id: UUID
```

### 5.2 Rejection codes

以 M02-G / M02-H 建立的 machine-readable + params 契約為模板：

- `import_rejected` 情境：
  - `invalid_envelope_shape`
  - `invalid_payload_shape`
  - `unsupported_schema_status`
  - `unsupported_ruleset`
  - `version_chain_gap`
  - `version_chain_out_of_order`
  - `current_state_version_missing`
  - `base_version_reference_invalid`
- `import_conflict`（保留給未來語意；M03 期間不觸發）

前端把 code + params 翻成 `zh-TW` / `en` presentation，比照 M02-H builder issue 契約。

### 5.3 Content ref walker

`app/interop/content_ref_walker.py`：

- 單一函式 `collect_content_refs(build_payload: dict) -> Iterable[ContentRef]`。
- `ContentRef` = `{stable_key: str, kind: str, pack: str, index: str}`。
- 走訪策略：
  - 依 build_payload 目前 schema，明列所有帶 StableKey 的路徑。**避免用 reflection / 全 dict 遞迴猜**——若某個 pack 資料形狀變動，要用 test 抓，而不是靠 walker 沉默漏收。
  - 涵蓋範圍（M01-K closeout 後預期）：race、subrace、lineage、background、class、subclass、features (choices + granted)、spells (known / prepared / spellbook / always-prepared source)、feats、infusions、maneuvers、fighting styles、starting equipment refs、tool / language / skill proficiency identity（若走 StableKey）、numeric override targets（若走 identity）。
- Walker 本身純函式，不呼叫 registry；registry 由呼叫端傳入或另做 resolver 呼叫。

### 5.5 Commit — `landing_mode == "character"`

```python
def commit_import_as_character(
    payload: CharacterExport,
    session: DBSession,
) -> UUID:
    with session.begin():
        new_character_id = uuid4()
        insert character row (name, ruleset, current_version_id=None)
        for v in payload.versions:
            insert character_version(
                id=uuid4(),
                character_id=new_character_id,
                version_no=v.version_no,
                build_payload=v.build_payload,
                version_kind=v.version_kind,
                base_version_id=<map from base_version_no>,
                change_note=v.change_note,
                created_at=v.created_at,   # 保留原時間戳
            )
        update character.current_version_id = <max version>
        insert character_states(character_id, state_payload=payload.current_state.state_payload)
        insert character_import_records(
            id=uuid4(),
            character_id=new_character_id,
            source_character_id=envelope.source_character_id,
            source_export_id=envelope.source_export_id,
            landing_mode="character",
            imported_at=now,
        )
    return new_character_id
```

### 5.6 Commit — `landing_mode == "draft"`

- 從 payload 抽 **最新 version 的 build_payload** 作為 Draft 起點。
- 呼叫既有 `builder_drafts` 模組建立 fresh draft，不綁 `base_version_id`（因為沒有既有 Character）。
- Draft 中每個未解析 ref 對應的 choice 設為未填。
- Draft 建好之後，把 `source_character_id` / `source_export_id` 記入 `character_import_records`，`landing_mode="draft"`，`draft_id=<new draft id>`。
- **Current state 不進 Draft**：Draft 沒有 live state 的概念，Confirm 產生 Version 1 時走一般 initial state 建立流程。
- 使用者於 Draft 中補完後 Confirm，走既有 P1-F create flow → 新角色的 Version 1；歷史版本鏈條無法還原（3.3 硬原則已接受）。

### 5.7 Import records table

Alembic migration `0007_character_import_records.py`：

```
character_import_records
  id                    UUID PK
  character_id          UUID NULL   FK → characters.id ON DELETE SET NULL
  draft_id              UUID NULL   FK → character_build_drafts.id ON DELETE SET NULL
  source_character_id   UUID NOT NULL
  source_export_id      UUID NOT NULL
  landing_mode          VARCHAR(16) NOT NULL   # "character" | "draft"
  imported_at           TIMESTAMPTZ NOT NULL DEFAULT now()
  INDEX (source_character_id)
  INDEX (source_export_id)
```

- `character_id` / `draft_id` 二選一 nullable：character 落地時 draft_id NULL，反之亦然。
- 記錄不刪；即使原 character 被 permanent delete，`source_character_id` 仍留作 dedupe 提示。

### 5.8 Duplicate hint

```python
def find_duplicate_hint(
    imports_repo: ImportRecordsRepo,
    source_character_id: UUID,
) -> DuplicateHint | None:
    records = imports_repo.list_by_source(source_character_id)
    if not records:
        return None
    return DuplicateHint(
        prior_import_count=len(records),
        most_recent_imported_at=max(r.imported_at for r in records),
    )
```

## 7. Alembic on SQLite（M03-D 主題）

### 7.1 現況掃描

M03-D 開工第一件事：把現有 6 個 migration（0001～0006，加上 M01-K 若引入的任何 migration）逐一在 SQLite 上跑一次 upgrade → downgrade → upgrade，抓出：

- `postgresql.JSONB` 直接引用（不透過 `with_variant`）。
- 未包成 `batch_op` 的 `alter_column` / `drop_constraint` / `add_constraint`。
- `server_default` 使用 Postgres-only function（`gen_random_uuid()` 等）。
- 使用 Postgres-only 型別（`ARRAY`、`INET`、`CIDR` 等）。

### 7.2 修法

- 有問題的 migration 就地修（M03-D 允許改 migration 檔內容），保持 Postgres 上的既有行為不變。
- 修法優先順序：
  1. `sa.JSON().with_variant(postgresql.JSONB(), "postgresql")` 已是 pattern，全面採用。
  2. `alter_column` 一律包 `batch_op`。
  3. `server_default` 用 dialect-neutral（例：`sa.text("...")` 分 dialect）。
- 若某 migration 真的無法 SQLite-friendly（例：以 Postgres partial index 表達的 unique），視情況於 SQLite dialect 分支跳過，並於 migration comment 明列。

### 7.3 CI gate

- 新增 `apps/server/tests/test_m03_migration_sqlite.py`：
  - Fixture 建立 tmp SQLite 檔。
  - 執行 `alembic upgrade head` → 驗證 tables / columns 與 `metadata.create_all` 一致。
  - 執行 `alembic downgrade base` → 應無殘留 table。
  - 執行 `alembic upgrade head` 二次 → 確認冪等。

## 8. Standalone entry / launcher（M03-E 主題）

### 8.1 `app/standalone.py`

```python
from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles

from app.api import (
    character_builder_router,
    characters_router,
    content_presentation_router,
    reference_router,
)
from app.config import settings
from app.content import load_default_content_registry
from app.paths import resolve_content_root
from app import main as web_main   # 只借用 exception handlers；不 re-mount router


def create_standalone_app() -> FastAPI:
    content_registry = load_default_content_registry()
    app = FastAPI(title=f"{settings.app_name} (standalone)")
    app.state.content_registry = content_registry

    app.include_router(reference_router)
    app.include_router(content_presentation_router)
    app.include_router(characters_router)
    app.include_router(character_builder_router)

    # 借用線上版的 exception handlers（不掛 router）
    web_main.register_exception_handlers(app)

    # SPA 靜態檔於 launcher 準備好之後 mount
    spa_root = resolve_content_root().parent / "web"
    if spa_root.is_dir():
        app.mount("/", StaticFiles(directory=spa_root, html=True), name="spa")

    return app


app = create_standalone_app()
```

- **關鍵**：`app.main` 需要重構把 `register_exception_handlers()` 抽出成可重用函式（M03-E scope 內）。
- SPA 位置：於 PyInstaller bundle 內固定為 `data/../web`；bundle 準備階段由 build 腳本放好。

### 8.2 `app/launcher.py`

```python
def main() -> int:
    setup_paths()          # 決定 content_root、data path，寫入環境變數
    port = find_free_port(range(8000, 8100))
    run_migrations(sqlite_url_from(env))
    print_banner(port=port, sqlite_path=..., content_root=...)
    server = start_uvicorn(app_module="app.standalone:app", port=port)
    wait_ready(port)
    open_browser(f"http://127.0.0.1:{port}/")
    wait_for_shutdown(server)   # Ctrl+C 或視窗關閉
    return 0
```

細節：

- `find_free_port`：`socket.socket().bind((host, 0))` + fallback 範圍。
- `run_migrations`：呼叫 alembic Python API（`command.upgrade(config, "head")`），設定 sqlite URL；失敗訊息完整印出。
- `print_banner`：資料檔絕對路徑、content root 絕對路徑、監聽 URL、結束方式提示。
- `wait_for_shutdown`：signal handler（SIGINT / CTRL_CLOSE_EVENT on Windows）。

## 9. Build 腳本

### 9.1 `scripts/build-standalone.cmd`

```
1. 建立 tmp venv on Windows。
2. venv 安裝 apps/server 主相依 + standalone extra；不裝 web extra。
3. cd apps/web && npm ci && npm run build → 產物在 apps/web/dist/。
4. Copy apps/web/dist/ 到 build 工作目錄下對應位置。
5. 於 apps/server 執行 pyinstaller pyinstaller/standalone.spec。
6. 產物根目錄放入 data/、LICENSE.txt、README-standalone.txt。
7. Zip 為 adventure-table-standalone-<version>.zip。
```

- 支援 `--version <tag>` 參數，寫入 `SourceApp.build`。
- 支援 `--skip-frontend` 用於 iterate backend 打包（開發用）。

### 9.2 `scripts/build-standalone.sh`

- 於 CI 上被呼叫的 wrapper；因為 CI 用 `windows-latest`，實際仍呼叫等效 PowerShell / cmd 指令。
- 保留 sh 版本便於未來 Linux runner。

### 10.3 Import boundary test

`apps/server/tests/test_m03_import_boundary.py`：

```python
def test_character_domain_does_not_import_multiplayer_modules():
    guarded_modules = [
        "app.content",
        "app.domain.character",
        "app.domain.character_builder",
        "app.persistence.characters",
        "app.persistence.builder_drafts",
        "app.persistence.state_mutations",
        "app.api.characters",
        "app.api.character_builder",
        "app.api.reference",
        "app.api.content_presentation",
    ]
    forbidden_regex = re.compile(r"(?:^|\.)(?:room|session|seat|campaign|party_roster)(?:\.|$)")
    for mod_name in guarded_modules:
        graph = collect_import_graph(mod_name)
        offenders = [m for m in graph if forbidden_regex.search(m)]
        assert not offenders, f"{mod_name} 透過 {offenders} 觸及多人層"
```

- `collect_import_graph` 使用 `ast.parse` 靜態抽 `import` / `from` 語句遞迴，不呼叫 `importlib.import_module`（避免載入時副作用）。

## 11. Env vars & config

新增於 `app/config.py` 的 setting：

```python
class Settings(BaseSettings):
    app_name: str = "Adventure Table"
    database_url: str = "..."
    content_root: str | None = None       # ADVENTURE_TABLE_CONTENT_ROOT
    database_path: str | None = None      # ADVENTURE_TABLE_DATABASE_PATH（standalone）
    ...

- `content_root` 為 `None` 時走 `paths.py` 解析 fallback；設值則覆寫。
- `database_path`（standalone）由 launcher 於啟動時決定：預設 `<exe_dir>/adventure-table.sqlite3`，可由環境變數覆寫。轉為 `sqlite+pysqlite:///<abs path>` 寫入 `database_url`。

## 13. 錯誤處理與觀察

### 13.1 Import endpoint

- 拒絕時回應體：`{"error": {"code": "<rejection_code>", "message": "...", "params": {...}}}`；比照 M02-H 已建立的 machine + params 結構。
- 500 保留給真正的 server bug；schema violation 一律 400。

### 13.2 Launcher

- Alembic upgrade 失敗：印錯誤 → 保留 console → 不自動關閉，讓使用者截圖回報。
- Port 全部被佔：印可讀訊息並中止。
- Content root / SPA root 找不到：印解析出的絕對路徑並中止。

### 13.3 Server startup（standalone）

- 若 content pack 少於基本集合（`srd5.1` 缺失）→ 中止並印訊息。這通常代表 `data/` 沒進 bundle。

## 14. Migration timeline

M03 期間新增／可能新增的 migration 順序：

```

- **M03-C 可 land 在 M03-D 之後**：本 phase 順序（B → C → D）刻意讓 API 端 / schema 契約定案早，SQLite gate 保留在 D。若 M03-C 撰寫過程中發現既有 migration 有 SQLite 問題，可先於 C 內修（scope 允許），或等 D 集中處理，實作者判斷。
- Alternative：若 M03-C 引入的 migration 於 SQLite 上有問題，M03-D 有義務把它一起修綠。
