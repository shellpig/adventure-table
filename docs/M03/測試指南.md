> Phase：**M03 — Standalone Character Builder Distribution**

## 1. 測試總則

- **每條 Subphase 驗收契約都要有可定位的測試證據**。每項 `X.n` 對應至少一條 pytest / Vitest / Playwright test 或人工程序，於 closeout 文件中列出檔名 + test 名稱。
- **同 turn 內把型別 / 編譯 / 該 Subphase test 修綠**。中途留錯是 M03 期間禁止的狀態。
- **零副作用的拒絕**。任何拒絕匯入 / 拒絕 startup / 拒絕 export 的 test，都要驗前後狀態不被污染（DB rows 不變、files 不變、環境變數不被污染）。
- **雙語同步驗收**。所有新加入 UI 於 `zh-TW` / `en` 兩語各跑一次同一條 flow；只驗一語不算完成。
- **不重跑 passing suite**。M03 期間**不做**「順便跑一次 M02 全套」，除非 M03 的改動確實碰到 M02 的 code path 或路徑常數。
- **CI 綠燈是必要條件，不是充分條件**。人工程序（launcher 冷啟動、Windows 上跑 build 產物、匯入缺 pack 的角色）於對應 subphase 必跑。
- **測試模擬缺 pack 一律用 `Settings.enabled_content_packs` 注入 subset**，不刪 pack 目錄。

# A. Content Root Path Abstraction & Enabled-Pack SSOT

## A.1 Path resolver unit test

`apps/server/tests/test_m03a_paths.py`：

- `test_resolve_content_root_prefers_env_var`：monkeypatch `ADVENTURE_TABLE_CONTENT_ROOT` 指向 tmp 目錄（內含 pack subset 空殼），斷言回傳該路徑。
- `test_resolve_content_root_rejects_missing_env_target`：env var 指向不存在路徑，斷言 raise 且訊息含該路徑與解析階段。
- `test_resolve_content_root_uses_exe_dir_when_frozen`：monkeypatch `sys.frozen=True` + `sys.executable=<tmp>/adventure-table.exe`，`<tmp>/data` 為目錄，斷言回傳 `<tmp>/data`。
- `test_resolve_content_root_falls_back_to_meipass_when_no_exe_data`：monkeypatch frozen 且 exe_dir/data 不存在、`sys._MEIPASS=<tmp2>` 且 `<tmp2>/data` 為目錄，斷言回傳 `<tmp2>/data`。
- `test_resolve_content_root_falls_back_to_repo_relative`：非 frozen、無 env 時斷言回傳 repo 內 `data/` 目錄。
- `test_resolve_rules_path`：回傳 `<content_root>/rules/dnd5e-2014/character-builder.json`。
- `test_resolve_spa_root_returns_none_when_not_frozen`：非 frozen 無 env 時回 `None`。

## A.4 `api.dependencies` 使用 resolver

## A.5 Repo-wide constant sweep static test

`apps/server/tests/test_m03a_no_legacy_path_constants.py`：

# B. Character JSON Schema, Export & Builder Provenance

## B.1 Migration & provenance write

`apps/server/tests/test_m03b_migration.py`：

- Alembic upgrade on Postgres 綠。Downgrade 綠。
- Upgrade 後 `character_versions` 有 `builder_provenance` 欄位，nullable。
- Existing rows 該欄位為 `NULL`。

`apps/server/tests/test_m03b_confirm_writes_provenance.py`：

- 新建 Character Draft → Confirm → 對應 `character_versions.builder_provenance` 為非 `NULL` 且與 Draft payload snapshot 對得起來。
- Level Up Draft → Confirm → Version N+1 `builder_provenance` 為非 `NULL`。
- Correction Draft → Confirm → 對應 correction version `builder_provenance` 為非 `NULL`。
- Legacy Character（migration 前落地者）的 Version 1 `builder_provenance` 保持 `NULL`。

## B.2 Pydantic model round trip

`apps/server/tests/test_m03b_json_schema.py`：

- 對每份 `apps/server/tests/data/m03/fixture_*.json`，載入 → validate → serialize → 二次 validate，斷言 idempotent。
- 斷言 `schema_status == "unstable"`。
- 斷言不允許未來 `schema_status` 值於 validation 通過（正例 / 反例對照）。
- 斷言 `ExportedVersion` 帶 `parent_version_no` / `superseded_by_version_no` / `builder_provenance` 欄位。
- 斷言 `ExportPayload` 帶 `current_version_no` 欄位。

## B.3 Content ref walker unit test（build）

`apps/server/tests/test_m03b_build_ref_walker.py`：

- 對每份 fixture 的每個 version，斷言 walker 回傳的 build refs 集合等於預期集合（預期集合手動列出）。
- 斷言 walker 對 build_payload 未覆蓋的路徑會炸掉——加一份 fixture 帶假的新路徑，斷言 walker fail 或以特定 error 提醒開發者更新。
- 斷言相同 build_payload 呼叫多次結果一致。

## B.4 Export payload builder

`apps/server/tests/test_m03b_export_payload.py`：

- 對 P1-F 已知 fixture（Fighter 5 / Wizard 5）呼叫 `build_export_payload` → 斷言：
  - envelope `content_requirements` 只列 build + state 實際引用的 pack。
  - envelope `stable_key_refs_summary` 是整數且與 walker 結果一致。
  - payload `versions` 為完整 chain，並帶 `parent_version_no` / `superseded_by_version_no`。
  - payload `current_version_no` 存在且指向 chain 內 version。
  - 每個 version 帶 `builder_provenance` 欄位（可能為 `null`）。
  - payload 不含 `archived_at` / `id` / `current_version_id`。
  - `versions` 依 `version_no` 遞增。

## B.5 Export endpoint

# C. Character JSON Import via Builder Draft

## C.1 State ref walker unit test

`apps/server/tests/test_m03c_state_ref_walker.py`：

- 對 `fixture_multiclass_mixed.json` 的 `current_state`，斷言 walker 至少回傳：
  - 每個 `conditions[].condition_ref`
  - 每個 `prepared_spells[].spell_key`
  - 每個 `inventory_state.inventory_entries[].item_ref`
  - 每個 `active_infusions[].infusion_ref`
  - `spell_storing_item.spell_ref`（若存在）
- 斷言 walker 對未覆蓋 state schema 節點會 fail-fast。
- 斷言 walker 對 minimum-shape state（空 conditions、空 inventory）回傳空集合。

## C.2 Import pipeline unit test

`apps/server/tests/test_m03c_import_pipeline.py`：

- `preview_import` 對每份 fixture：
  - `enabled_content_packs_full()` 下 `fixture_*.json` → `landing_mode="character"`，`unresolved_refs=[]`。
  - `enabled_content_packs_without("xge")` 下 `fixture_xge_dependent.json` → `landing_mode="draft"`，unresolved_refs 含所有 `xge:*` refs、`origin="build"`、標示 version_no。
  - `enabled_content_packs_without("phb2014")` 下 `fixture_multiclass_mixed.json` → landing_mode="draft"，unresolved_refs 精確列出缺項。
  - `fixture_state_only_missing.json` → build 全解、state 有未解 → `landing_mode="draft"` 且 unresolved_refs 內出現 `origin="state"`。
  - `fixture_legacy_no_provenance.json` 於 subset settings 下 → 400 `draft_reconstruction_unavailable`。
- `preview_import` 對故意破壞的 build_payload（例：class_progression_refs 帶非 class stable key）→ 400 `invalid_build_shape`（`CharacterBuild.model_validate` 失敗）。
- `preview_import` 對故意破壞的 state_payload（例：condition_ref 帶非 condition key）→ 400 `state_shape_invalid`。
- `preview_import` 對全 refs 可解析但 `validate_build_references` 會失敗的 payload（例：subclass 選擇對應等級不存在）→ 400 `build_references_invalid`。
- `preview_import` 對全 refs 可解析但 `validate_state_against_build` 會失敗的 payload（例：prepared spell 超出 build 允許）→ 400 `state_inconsistent_with_build`。

## C.3 Commit tests

`apps/server/tests/test_m03c_commit.py`：

- `commit_import_as_character`：
  - 產生新 UUID，chain 完整 append。
  - `parent_version_id` / `superseded_by_version_id` 於落地後對應到 chain 內新 UUID（不是 payload 中的 `version_no`）。
  - `builder_provenance` 逐 row 落地保留原 JSON。
  - `characters.current_version_id` 對應 `current_version_no` 的新 UUID，**不假定** = max version。
  - `character_states.state_payload == payload.current_state.state_payload`。
  - `character_import_records` 有新 row，`landing_mode="character"`。
  - `validate_build_references` / `validate_state_against_build` 於 commit 開始時再跑一次。
- `commit_import_as_draft`：
  - 建立 fresh CREATE Draft，起點為 `versions[current_version_no].builder_provenance`。
  - 未解析 ref 對應的 choice 於 draft 中呈現為未填。
  - `character_import_records.draft_id` 指向新 draft，`character_id=NULL`。
  - Current state **不**進 Draft。

## C.4 Rejection tests

`apps/server/tests/test_m03c_import_rejections.py`：

每個 rejection code 一條 test：

- `invalid_envelope_shape`：缺 `envelope.ruleset` → 400 + code。
- `invalid_payload_shape`：缺 `payload.character.name`。
- `unsupported_schema_status`：`"future_value"`。
- `unsupported_ruleset`：`"pathfinder2e"`。
- `version_chain_gap`：`versions=[1,3]`。
- `version_chain_out_of_order`：`versions=[2,1]`。
- `current_state_version_missing`：`current_version_no=99` 不在 chain。
- `version_lineage_invalid`：`parent_version_no=99`。
- `invalid_build_shape`：見 C.2。
- `state_shape_invalid`：見 C.2。
- `build_references_invalid`：見 C.2。
- `state_inconsistent_with_build`：見 C.2。
- `draft_reconstruction_unavailable`：`fixture_legacy_no_provenance.json` + subset。

每個 rejection 都斷言：

- 回應 400、含 code、含 `params`（若適用）。
- DB 狀態零副作用：`characters` / `character_versions` / `character_states` / `character_import_records` / `character_build_drafts` 無新 row。

## C.5 Duplicate hint

`apps/server/tests/test_m03c_duplicate_hint.py`：

- 相同 `source_character_id` 已有一筆 import record → dry-run 回應含 `duplicate_hint`。
- 沒有時 `duplicate_hint=None`。
- 匯入不被 duplicate_hint 阻擋；commit 後 records 累積。

## C.6 Endpoint

`apps/server/tests/test_m03c_import_api.py`：

# D. SQLite Migration Chain Gate & FK PRAGMA

## D.1 Migration up/down/idempotent

`apps/server/tests/test_m03d_migration_sqlite.py`：

- Fixture 建立 tmp SQLite 檔。
- `alembic upgrade head`：斷言無例外，結束後 tables 完整。
- `alembic downgrade base`：斷言無例外，結束後 tables 空。
- `alembic upgrade head` 二次：無例外。
- 涵蓋 M03-B 的 `builder_provenance` migration 與 M03-C 的 `character_import_records` migration。

## D.2 Schema 一致性

`apps/server/tests/test_m03d_schema_parity.py`：

- 以 `alembic upgrade head` 產生 schema A。
- 以 `metadata.create_all(engine)` 產生 schema B（另一 tmp SQLite）。
- 使用 SQLAlchemy `inspect` 對照兩者的 tables / columns / types / nullable / indexes / unique constraints。
- 差異必須為零；若某個差異已在 migration comment 中被標為 SQLite-only 讓步，於本 test 白名單明列。

## D.3 SQLite FK PRAGMA

# G. Full M03 Integration & Closeout

## G.1 End-to-end round-trip 手動 flow

於 M03 期間的最新網頁版 + 最新單機版 `.zip` 上執行以下六條流程，每條保留 evidence（截圖 / 錄影 / test log）：

### G.1.a W → S 完整

1. 網頁版建立一個 Lv5 Multiclass 角色（Fighter 3 / Cleric 2，Life Domain，含 starting equipment、prepared spells、live HP 有變動、Inventory 有加物）。
2. Character Sheet 匯出 → 檔案 `A.json`。
3. 於單機版 Workshop 匯入 `A.json`。
4. Dry-run 顯示全部 resolved（build + state）、`landing_mode="character"`。
5. 繼續匯入 → Sheet 開啟後與原網頁版 Sheet 對照：
   - HP / 資源 / conditions / prepared / inventory 一致。
   - Version History 顯示 chain 完整（含 correction lineage 若有）。

### G.1.b S → W 完整

1. 單機版建立 Lv3 Ranger with Hunter subclass。
2. 匯出 → `B.json`。
3. 網頁版匯入。
4. 對照兩邊 Sheet 一致。

### G.1.c W → S 缺 pack

1. 網頁版建立引用 `xge` 的角色（Gloom Stalker Ranger）。
2. 匯出 → `C.json`。
3. **於一個 `enabled_content_packs` 未含 `xge` 的單機版設定**匯入 `C.json`（透過設 `ADVENTURE_TABLE_ENABLED_CONTENT_PACKS` 環境變數為 subset，或啟動 launcher 時另傳）。
4. Dry-run 顯示 `landing_mode="draft"` 且 unresolved 清單含 subclass ref（origin=build）。
5. 繼續 → 導向 Draft。
6. 使用者於 Draft 中改選一個可用的 Ranger subclass。
7. Confirm → 產生 Version 1 → Sheet 開啟正常。

### G.1.d State-only 缺 ref

1. 建立一個 Artificer with active infusion，匯出為 `D.json`。
2. 於一個 subset 中刻意不含對應 infusion 的環境匯入。
3. Dry-run 顯示 build 全解、state 未解 → `landing_mode="draft"`；unresolved 內出現 `origin="state"`。
4. 走 Draft 補洞 → Confirm。

### G.1.e 重複匯入

1. 同一份 `A.json` 於單機版匯入第二次。
2. Dry-run 顯示 `duplicate_hint`。
3. 繼續 → 兩個角色並存於 Workshop。

### G.1.f Legacy 拒絕

1. 準備 `fixture_legacy_no_provenance.json`（`builder_provenance` 全為 `null`）。
2. 於缺對應 pack 的環境匯入。
3. Dialog 顯示 `draft_reconstruction_unavailable` 訊息；`character_import_records` 無新 row；`characters` 無新 row。
