# M05 — 實作規格

> Phase：**M05 — Session History Continuity & Owner End for AI DM Sessions**
> 類型：**M Phase（Modification / Maintenance Phase）**
> 插入時點：**P4 關門並合併回 `main` 之後、P6-A 開工之前。** 兩個 Subphase 都是小改動，各自關門；M05-B 關門後直接進 P6-A。
> 本文件定義 **M05-A～M05-B 每個 Subphase 完成後什麼必須為真**。具體 module、endpoint、DTO 與接線放在 `開發設計方針.md`；自動與人工驗收方式放在 `測試指南.md`。

最後更新：2026-09-20

---

## 1. M05 定位

2026-09-20 使用者在真實 Campaign 上遇到的流程：上一場由 AI 當 DM，AI 沒有按 End 就離開；Session 一直是 `active`。真人重回 Lobby 時，Resume 顯示同一場（事件串還在），但 DM Controller 依規格一場固定，無法改成由人來當 DM；真人沒有 End 權，只能 Abandon。Abandon 後可以指定真人 DM 開新場，角色 HP／狀態都延續，**但新場的聊天串從 Session Start 開始，上一場的事件串沒有任何入口可看**。

對照 `規格企劃.md`：

- 「DM 不做 Session 中途 Human ↔ AI 交接」與「DM 中途離線」讓上述每一步都是規格內行為，不是實作 bug。
- 「Session End」只允許本場 DM Controller End；Owner 只有 Abandon escape hatch（P3-D 第 23 條）。
- 事件串是 P3 durable event，資料完整保存；缺的是**跨 Session 的讀取入口**，不是記錄能力。跨 Session Timeline／Snapshot 屬 P7。

使用者目前要在 Exploration＋Quick Combat 上長期打磨，需要連續的事件串；同時 P7 的重點是 Snapshot／Restore，依賴 P6 的 Campaign Runtime world state，不宜提前。因此以一個最小的 M Phase 補兩件事：

1. **M05-A**：Owner 可以對 **AI DM** 的 active Session 執行正常 End（不只 Abandon）。
2. **M05-B**：新 Session 的聊天串可以**向上翻頁越過 Session 邊界**，連續顯示同一 Campaign 之前 Session 的可見事件，並以 Session 分隔線標示邊界。

M05 不做的事：

- 不放寬「同一 Session 的 DM Controller 固定」：Owner End 是結束那一場，不是接管。
- 不讓 Owner End **Human DM** 的 active Session；Human DM 的 Session 仍只有本場 DM 能 End、Owner 只能 Abandon（規格「Owner 不中途強制頂替 DM」）。
- 不改 P3-D 的授權模型（Seat `controller_epoch` SSOT、grant generation snapshot、pre-session TTL、Take Back 規則）。
- 不做 P7 Timeline 的 compact summary、search、`get_recent_timeline()`／`search_campaign_history()` AI tool、Snapshot／Restore；不改 MCP `get_session_context` 的 recent-event window。
- 不新增 Session 內 Combat／Stage／Roll 的跨 Session 投影；越過邊界載入的舊事件只進聊天串。
- 不動 `app.standalone`、`app.content.*`、`app.domain.character*`。

M05 順序：

```text
P4 closeout → main
→ M05-A — Owner End for AI DM Sessions
→ M05-B — Cross-Session Chat History Paging
→ P6-A
```

## 2. M05 產品行為

### 2.1 Owner 可以正常結束 AI DM 的 Session（M05-A）

- 當 active Session 的 DM Controller 是 AI，持有 `owner` authority 的真人可以按 `End Session`，效果與本場 DM 正常 End 相同：`status = ended`、記錄 Session End boundary、撤銷該場全部 session-scoped AI grant、釋放 Active Character lease、DM Seat controller 回到 `none`。
- End 後 Lobby 沒有 active Session，Owner 可依 P2-D 既有流程把 DM Seat 指派給真人並 Start 新 Session。這不是 Owner 接管同一場。
- Owner Abandon escape hatch 保留不變。對 AI DM 的 Session，End 與 Abandon 都可用；差別只在最終 status 與事件 kind（`session.ended` vs `session.abandoned`）。
- Human DM 的 active Session：Owner 仍不能 End；UI 不顯示 End，只顯示 Abandon 與既有提示。
- **End 不改 Gameplay State**（沿用規格「Session End」）。

### 2.2 聊天串跨 Session 連續（M05-B）

- 在 Session 頁的聊天串往上翻，到達本場 Session Start 後，若同一 Campaign 還有更早的 Session（`ended` 或 `abandoned`），可以繼續載入該 Session 的可見事件，接在本場之前顯示；再往上可以繼續到更早的 Session，直到 Campaign 第一場為止。
- 每次越過邊界時插入一條 Session 分隔線，至少顯示：該 Session 的最終 status（ended／abandoned）、開始與結束時間、DM Controller 種類（Human／AI）。分隔線是 UI 元素，不是事件，不寫入任何 Session。
- 舊 Session 的事件只進聊天串顯示；Stage、Combat、Roll Request、Pending Action 等本場投影不受影響，也不因舊事件被載入而改變。
- 本場沒有更早 Session、或已載到 Campaign 第一場的 Start 時，「載入更早訊息」控制項消失或標示已到最前。
- Resume Card（`/sessions/active` 的 `recent_events`）與 MCP `get_session_context` 維持只含本場事件；不因 M05-B 擴大。

### 2.3 舊 Session 的可見性以 Seat 為單位，DM 層跟著 DM Seat（M05-B）

- 讀取已結束 Session 的事件時，Server 仍做 visibility 過濾；規則沿用 P3 的四種 visibility（`public`／`dm_only`／`actor_and_dm`／`seat_private`），單位是 **Seat**，不是人。
- 讀者對已結束 Session 的 scope：讀者目前以 Human controller 控制的、未 archive 的 Campaign Seat。這些 Seat 在該場曾被 AI 代打也不影響——Seat 的 private 事件跟著 Seat，新接手該 Seat 的真人可以看。
- 若讀者目前控制的 Seat 包含**該已結束 Session 的 DM Seat**，讀者對該場擁有 DM 層可見性（含 `dm_only`、敵人精確 HP 等 DM audience projection）。因此 Owner End AI DM 的場後，被指派為 DM 的真人可以回看 AI DM 留下的 DM 層紀錄；Player 仍看不到。
- 讀者目前沒有控制任何 Campaign Seat 時，不能讀舊 Session 事件（與 active Session 的既有規則一致）。
- active Session 的可見性規則完全不變。

### 2.4 Standalone 不受影響

M05 只動 Web 多人層（Session／Table Event／Session 頁）。`app.standalone`、Character Core／Builder／Interop 零改動；`tests/test_m03_import_boundary.py` 與 `test_m03d_schema_parity.py` 持續通過。

## 3. M05 共通硬原則

### 3.1 沿用 P3-D authority，不建新授權邊界

Owner End 走既有 Owner Room authority（與 Owner Abandon 同一個分支結構）；歷史讀取走既有 `TableActorContext` resolve。不新增 AI-specific bypass，不新增「歷史讀者」專用 token 或 role。

### 3.2 秘密靠 Server 過濾

舊 Session 的 `dm_only`／`seat_private`／敵人 hidden resources 由 Server 在 event projection 層過濾，前端不做隱藏。Player 對已結束 AI DM Session 的請求，回應中不得含任何 `dm_only` 事件與 DM audience payload。

### 3.3 零副作用的拒絕

Owner End 對 Human DM Session、非 Owner 對 AI DM Session 的 End、非 Seat controller 對舊 Session 歷史的讀取，全部拒絕且不寫任何 row。

### 3.4 舊 Session 唯讀

已結束 Session 的任何寫入（append event、late join、stage、roll、combat）維持既有拒絕；M05-B 只新增讀取。

### 3.5 雙語同步交付

新 UI copy（Owner End 按鈕與提示、Session 分隔線、到達最前的提示）於 `zh-TW`／`en` 同步交付。

### 3.6 不擴散到其他投影

越過 Session 邊界載入的事件只進聊天串資料結構；不得混入本場 event stream 的 seq-based 投影（Stage revision、Combat、Roll Request、Pending Action）。

# M05-A — Owner End for AI DM Sessions

## 目標

讓 Owner 能正常結束 AI DM 遺留的 active Session，之後照 P2-D 流程指派真人 DM 開新場；不動 Human DM Session 的規則。

## 完成後必須為真

### A.1 Owner End AI DM Session 成功

- 持 `owner` authority 的呼叫者對 `dm_controller_kind == "ai"` 的 active Session 呼叫 End：回應 `status = ended`、`ended_at` 非空。
- 該 Session 所有 `active` AI grant 變 `revoked`；被這些 grant 綁定的 Seat controller 變 `none` 且 `controller_epoch + 1`；Active Character lease 釋放。與 Owner Abandon 的原子性完全相同。
- 事件串多一筆 `session.ended`，`execution_mode = system`，payload 含 `status = "ended"` 與 `owner_access_session_id`。

### A.2 Owner End Human DM Session 被拒

- 對 `dm_controller_kind == "human"` 的 active Session，Owner（非本場 DM）呼叫 End → `403 dm_controller_mismatch`；Session、Seat、grant、event row 計數不變。
- Owner 同時是本場 Human DM 時，End 走既有 DM 分支，行為不變。

### A.3 非 Owner 對 AI DM Session End 被拒

- `dm` 或 `member` authority、非本場 DM 的呼叫者對 AI DM Session 呼叫 End → `403 dm_controller_mismatch`，零副作用。
- 舊 AI DM token 在 End 後 read／wait／write 一律被拒（沿用 P3-D 第 9 條）。

### A.4 End 後 Lobby 可指派真人 DM 並 Start

- End 後 `GET /sessions/active` 的 `active_session` 為 `null`。
- Owner 將 DM Seat 指派給真人 access session 後 Start 新 Session，成功；新 Session 的 `dm_controller_kind == "human"`。
- 角色 Current State（HP、conditions、Combat 若有）不因 End 改變。

### A.5 UI

- Session 頁：Owner 對 AI DM 的 active Session 看得到 `End Session` 與 `Abandon Session`；對 Human DM 的 active Session（且自己不是本場 DM）只看得到 Abandon 與既有提示。
- End 前最多一次確認，文案說明「結束 AI DM 的這一場，不影響角色狀態」。
- `ownerAbandonHint` 更新為區分 AI DM／Human DM 兩種情況；`zh-TW`／`en` 同步。

## 本 Subphase 不要求

- 不做 AI DM 的自動 End／timeout。
- 不做 Owner 接管、DM succession。
- 不改 MCP tool catalog。

# M05-B — Cross-Session Chat History Paging

## 目標

讓真人在新 Session 的聊天串裡往上翻就能看到同一 Campaign 之前 Session 的可見事件，接著玩不需切頁；秘密過濾與 Seat 為單位的可見性維持 Server 端。

## 完成後必須為真

### B.1 前一場 Session 可定位

- 給定同一 Campaign 的任一 Session，Server 能回傳「更早一場」（依 `started_at`、`id` 排序的前一筆，任何最終 status）與該場的 `last_event_seq`；沒有更早一場時明確回傳空。
- 跨 Campaign、跨 Room 的 Session 不可被定位（404）。

### B.2 已結束 Session 的事件可讀且被過濾

- 讀者目前以 Human controller 控制至少一個未 archive 的 Campaign Seat 時，可用既有 history paging 讀該 Campaign 已結束 Session 的事件；回傳只含依 2.3 規則可見的事件。
- 讀者控制的 Seat 含該場 `dm_seat_id` → 可見 `dm_only`，Combat payload 為 DM audience；否則 `dm_only` 不出現、Combat payload 為 Player audience。
- 讀者不控制任何 Campaign Seat → `404 session_not_found`（與 active Session 現行行為一致）。
- active Session 的 actor resolve 與可見性完全不變（既有 P3-A／P3-D 測試零修改通過）。

### B.3 已結束 Session 維持唯讀

- 對已結束 Session 的 append／stage／roll／combat／late-join 仍被拒，行為與 M05 前相同。

### B.4 聊天串向上翻越過邊界

- 本場 `historyFloorSeq` 到 0 後，「載入更早訊息」繼續可用：先定位前一場，再載入其最新一頁；再往上繼續同一場的更早頁，直到該場 seq 1，再往前一場。
- 每個 Session 邊界顯示一條分隔線（status、開始／結束時間、DM Controller 種類）。
- 到達 Campaign 第一場的 Start 後，控制項消失或顯示「已到最前」。
- 已載入的訊息在 prepend 時保持讀者停在同一則（沿用 a62d3253 的 anchor 行為）。

### B.5 其他投影不受影響

- 舊 Session 事件不進本場 `eventStream.events`；Stage revision、Combat、Roll Request、Pending Action、Resume Card 在載入舊事件前後相同。
- long-poll cursor 只跟本場走。

### B.6 雙語

- 分隔線與「已到最前」copy 於 `zh-TW`／`en` 同步。

## 本 Subphase 不要求

- 不做搜尋、compact summary、依 kind 篩選。
- 不做 MCP／AI 讀取跨 Session 歷史。
- 不做 Lobby 的歷史 Session 列表頁（B2 方案已覆蓋需求；若日後需要獨立頁面另議）。
- 不做 Snapshot／Restore。

## 5. 與既有契約的關係

- **取代**：P3-D 實作規格第 23 條「Owner 仍只有既有 Abandon escape hatch」對 **AI DM Session** 的部分，由 M05-A 2.1 取代；Human DM Session 部分不變。P3 文件保留歷史全文並加註指向本檔。
- **沿用**：P3-A 事件 visibility 四態、P3-D `TableActorContext`／`require_actor_current`、P4 Combat audience projection、bc79f725／a62d3253 的 history paging 與 `historyFloorSeq`。
- **交棒 P7**：P7 Timeline／`search_campaign_history()` 在 M05-B 的「前一場定位＋per-Session history page」之上疊加，不重做讀取入口。
