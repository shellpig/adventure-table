> Phase：**M05 — Session History Continuity & Owner End for AI DM Sessions**
> 本文件定義 **M05-A～M05-B 每個 Subphase 的自動 / 人工驗收流程與測試證據要求**。驗收意圖見 `實作規格.md`；實作契約見 `開發設計方針.md`。

最後更新：2026-09-20

---

## 1. 測試總則

- **每條 Subphase 驗收契約都要有可定位的測試證據。** 每項 `X.n` 對應至少一條 pytest／Vitest／Playwright test，於 closeout 列出檔名 + test 名稱。
- **同 turn 內把型別／編譯／該 Subphase test 修綠。**
- **P3-A／P3-D／P4 測試是回歸底線且零修改。** `tests/test_p3a_*.py`、`tests/test_p3d_*.py`、`tests/test_p4*_*.py` 在每個 Subphase 關門時必須**不改任何斷言**通過；M05-B 不動 `resolve_human_actor`／`actor_binding_is_current`，若有既有測試需要改才綠，即為設計偏離，回頭修實作。
- **零副作用的拒絕。** 每個拒絕路徑前後 `sessions`、`session_participants`、`campaign_seats`、`ai_controller_grants`、`session_table_events` row 計數與 `controller_epoch` 不變。
- **秘密過濾是自動測試。** 以 fixture 在 AI DM 場寫入 `dm_only`、`seat_private`、含敵人精確 HP 的 combat 事件，用 Player 讀者實際打 history endpoint，斷言不含。
- **雙語同步驗收。** 新 copy 於 `zh-TW`／`en` 各有 Vitest 斷言；E2E 至少一個 locale 走完整 journey。
- **Standalone 邊界**：`tests/test_m03_import_boundary.py`、`tests/test_m03d_schema_parity.py` 兩個 Subphase 都必須通過。

## 2. 共通測試資料與觀察值

### 2.1 Fixture

- 沿用 `test_p3d_ai_dm_session_lifecycle.py` 的 pre-session AI DM grant → `start_session_as_ai_dm` 建 **AI DM active Session**；沿用 `test_p3d_owner_abandon.py` 的 Owner／DM／member access session 三種 authority。
- **AI DM 歷史場 fixture**（M05-B）：AI DM Session 內寫入至少：1 筆 `public` narration、1 筆 `dm_only`、1 筆 `seat_private`（recipient = Player Seat P1）、1 筆帶敵人 HP 的 combat 事件（沿用 P4 fixture）；然後 Owner End。再由真人 DM Start 第二場並寫入 1 筆 public。
- **Seat 轉手 fixture**：P1 在第一場由 AI 代打，第二場前改綁真人 access session H1。
- **未參加 fixture**：Campaign Seat P3 在第一場不是 participant；第二場前由真人 H3 控制。
- **Combat fixture**（B.3）：第二場（active）由真人 DM 開一場 Quick Combat，含至少一個 hostile Monster Instance。

### 2.2 觀察值

- Owner End 事件：`kind == "session.ended"`、`execution_mode == "system"`、`payload["owner_access_session_id"]` 等於 Owner access session。
- `SessionHistoryLink.previous_last_event_seq` 等於前一場 `session_table_runtime.last_event_seq`。
- history page `after_seq == 0` 表示該場已到 Start。

# M05-A — Owner End for AI DM Sessions

檔案：`tests/test_m05a_owner_end_ai_dm.py`；前端 `RoomSessionPage.test.ts`、`sessionCopy` 相關 test；E2E `m05-session-history.spec.ts` A 段。

## A.1 Owner End AI DM Session 成功

- `test_owner_end_ai_dm_session_finalizes_and_revokes_atomically`：Owner `POST /end` → 200、`status == "ended"`、`ended_at` 非空；所有該場 AI grant `revoked`；AI 綁定 Seat `controller_kind == "none"`、`controller_epoch` +1；lease 刪除；最後一筆事件為 `session.ended` system 事件含 `owner_access_session_id`。
- `test_owner_end_ai_dm_via_service_matches_owner_abandon_side_effects`：與 Owner Abandon 對同一 fixture 的 DB 差異只在 `sessions.status` 與事件 `kind`／`payload.status`。

## A.2 Owner End Human DM Session 被拒

- `test_owner_end_human_dm_session_rejected_without_side_effects`：Owner 非本場 DM → 403 `dm_controller_mismatch`；row 計數、epoch、status 不變。
- `test_owner_who_is_current_human_dm_ends_via_dm_branch`：Owner 同時是本場 Human DM → 200，事件 `execution_mode == "self"`、`acting_seat_id == dm_seat_id`（既有行為）。

## A.3 非 Owner End AI DM Session 被拒

- `test_dm_key_holder_cannot_end_ai_dm_session`、`test_member_cannot_end_ai_dm_session`：403，零副作用。
- `test_ai_dm_token_rejected_after_owner_end`：End 後舊 grant 的 `get_session_context`／`wait_for_event`／write tool 一律 401／403（沿用 P3-D 第 9 條的斷言方式）。

## A.4 End 後 Lobby 可指派真人 DM 並 Start

- `test_after_owner_end_lobby_can_assign_human_dm_and_start`：`GET /sessions/active` → `active_session is None`；Owner assign DM Seat 給 H0 → Start → 201、`dm_controller_kind == "human"`。
- `test_owner_end_does_not_change_character_state`：End 前後 Character Current State（HP、conditions）與 active Combat（若 fixture 有）相同。

## A.5 UI

- Vitest `RoomSessionPage.test.ts`：
  - Owner + `dm_controller_kind: 'ai'` + active → End 與 Abandon 都渲染；點 End 觸發 confirm 後呼叫 `endSession`。
  - Owner + `dm_controller_kind: 'human'` + 非本場 DM → 只有 Abandon，顯示 `ownerAbandonHint`。
  - `dm` authority + AI DM → 不渲染 End。
- Vitest copy test：`ownerEndAiDmHint`、`ownerEndAiDmConfirm`、`ownerAbandonHint` 於 `zh-TW`／`en` 皆存在且非空。
- E2E A 段：Owner 在 Lobby 發 AI DM grant → MCP `start_session` 以 AI DM 開場 → AI 送一筆 narration → Owner 瀏覽器進 Session 頁按 `End Session` 並確認 → 回 Lobby 看到無 active Session → assign 自己為 DM → Start → Active Session 頁 `dm_controller_kind` 為 human。

## A.6 回歸

- `pytest tests/test_p3d_*.py tests/test_p2e_session_*.py tests/test_p3a_*.py`。
- `npm test -- --run`、`npm run build`。
- `docker compose config`。

# M05-B — Cross-Session Chat History Paging

檔案：`tests/test_m05b_session_history_link.py`、`tests/test_m05b_history_reader_scope.py`；前端 `sessionEventStream.test.ts`、`SessionTableSurface.test.tsx`、`RoomSessionPage.test.ts`；E2E `m05-session-history.spec.ts` B 段。

## B.1 前一場 Session 可定位

- `test_previous_session_returns_latest_earlier_session_any_status`：三場（abandoned → ended → active）依序建立；對第三場 `GET /previous` → 第二場（ended）與其 `last_event_seq`；對第二場 → 第一場（abandoned）；對第一場 → `previous_session is None`、`previous_last_event_seq == 0`。
- `test_previous_session_orders_by_started_at_then_id`：同一 `started_at` 的兩場以 `id` 決定順序。
- `test_previous_session_rejects_cross_campaign_and_cross_room`：另一 Campaign／Room 的 session_id → 404 `session_not_found`。
- `test_previous_session_requires_history_scope_returns_404`：不控制任何未 archive Campaign Seat 的 member → 404 `session_not_found`（與 history endpoint 語意一致，不是 403）。
- `test_previous_session_allows_seat_holder_not_in_base_session`：H3 控制 P3、P3 未參加本場（active）→ 對本場 `GET /previous` 200，回傳第一場。

## B.2 已結束 Session 的事件可讀且被過濾

用 2.1 的 AI DM 歷史場 fixture，對第一場（已結束、AI DM）打 `GET /events/history?before=<last+1>`：

- `test_human_dm_seat_holder_reads_ended_ai_dm_session_with_dm_audience`：目前控制 `dm_seat_id` 的真人 → 含 `public`、`dm_only`、`seat_private`；combat payload 含敵人精確 HP。
- `test_player_seat_holder_reads_ended_session_seat_scoped`：H1（第二場才接手 P1）→ 含 `public` 與 recipient 為 P1 的 `seat_private`；不含 `dm_only`；combat payload 為 Player audience（無敵人精確 HP）。
- `test_other_player_cannot_see_p1_private_events_in_ended_session`：控制 P2 的真人 → 不含 P1 的 `seat_private`。
- `test_reader_without_campaign_seat_gets_404_on_ended_session`：member 不控制任何 Seat → 404。
- `test_archived_seat_does_not_grant_history_scope`：讀者只控制已 archive 的 Seat → 404。
- `test_seat_holder_who_never_joined_ended_session_reads_public_only`：H3（控制從未參加第一場的 P3）讀第一場 → 含 `public`，不含 `dm_only`、不含 P1 的 `seat_private`。
- `test_history_scope_recomputed_after_seat_reassignment`：H1 讀第一場成功後，Owner 把 P1 改綁 H9 → H1 再讀 → 404（H1 已無 Seat）；H9 讀 → 含 P1 的 `seat_private`。
- `test_active_session_history_endpoint_unchanged`：對 active Session 的 `GET /events/history` 結果與走既有 actor 路徑逐欄相同；`resolve_human_actor` 與 `actor_binding_is_current` 對 active／ended Session 的回傳值與 M05 前 byte-for-byte 相同（以 `test_p3d_table_actor_binding.py` 零修改全綠為證據）。

## B.3 已結束 Session 維持唯讀，歷史 scope 不給任何 gameplay 能力

- `test_ended_session_rejects_writes_for_history_reader`：以 B.2 的 DM Seat holder 對已結束場呼叫 exploration input、stage patch、roll request、late-join，以及 **至少一個 Combat mutation**（例如對第二場 active Combat 的 `damage`／`advance_turn` 但走第一場的 Session URL）→ 各自的既有錯誤（409 `session_not_active` 或 404），`session_table_events`、Combat row／revision、Stage revision 不變。
- `test_history_scope_does_not_grant_combat_detail_on_old_session_url`：H3（控制 P3 且 P3 未參加第一場；第一場的 `dm_seat_id` 由 H_DM 控制）與 H_DM 分別用第一場 URL 打 `GET /sessions/{第一場}/combat/detail`：結果與 M05 前完全相同——非第一場 participant → 404；是 participant 者得到與 M05 前相同的 view。特別斷言：H_DM 若不是第一場 participant（第一場 DM 是 AI），**不得**拿到 active Combat 的 DM audience（無敵人精確 HP）。
- `test_history_scope_does_not_grant_stage_roll_pending_reads_on_old_session_url`：同上對 `GET /stage`、roll request list、pending action list 逐一斷言與 M05 前相同。

## B.4 聊天串向上翻越過邊界

- Vitest `sessionEventStream.test.ts`：
  - `hasOlderHistory` 在（本場 floor>0）／（本場 floor=0、chain 空、未 exhausted）／（older 最末場 floor>0）為 true；（本場 floor=0、exhausted、older 全 floor=0）為 false。
  - `applyOlderSessionPage` 只更新對應 session、`historyFloorSeq` 取 min、不同 session_id 忽略、重複 seq 冪等。
- Vitest `RoomSessionPage.test.ts`：mock `listSessionHistory`／`getPreviousSession`，連按「載入更早訊息」依 4.6 的順序：第 1 次本場 history（floor→0）；第 2 次一次點擊發 `previous` ＋ 前一場最新 history **兩個 request**；第 3 次前一場更早頁；`previous_session === null` 時 `exhausted` 置 true 且不再呼叫。
  - 前一場 `previous_last_event_seq === 0`：仍 push 空 `OlderSessionHistory` 並渲染分隔線；再點一次繼續呼叫 `previous`。
  - 連續兩個空場：兩條分隔線、無訊息、第三次到達更早有事件的場。
  - Session route 變更或 Resume 全量重載後 `olderSessions` 為空、`exhausted` 為 false。
- Vitest `SessionTableSurface.test.tsx`：
  - 渲染順序：older[1] 分隔線 → older[1] 訊息 → older[0] 分隔線 → older[0] 訊息 → 本場訊息。
  - 分隔線含 status、DM 種類、時間；`data-session-divider` 等於該場 id。
  - 舊場訊息角色名取自該場 `participants`。
  - `historyExhausted && !hasOlderHistory` 顯示 `historyStart`，不顯示按鈕。
  - prepend 舊場訊息後 scroll anchor 維持（沿用既有 chatFollow test 的方式）。

## B.5 其他投影不受影響

- Vitest `SessionTableSurface.test.tsx`：傳入 `olderSessions` 含 combat／stage／roll-request／pending-action 事件，Stage 文字、Combat 面板、Roll Request 清單、Pending Action 面板與未傳入時相同。
- Vitest `RoomSessionPage.test.ts`：載入舊場前後 `eventStream.cursor`、`currentSeq`、`historyFloorSeq` 不變；long-poll 下一次 `waitSessionEvents` 的 `after` 參數不變。
- pytest `test_resume_recent_events_and_mcp_context_stay_single_session`：`GET /sessions/active` 的 `recent_events.session_id` 與 MCP `get_session_context` 的事件全部屬於 active Session。

## B.6 雙語

- Vitest copy test：`sessionDividerEnded`、`sessionDividerAbandoned`、`dmKindHuman`、`dmKindAi`、`historyStart` 於 `zh-TW`／`en` 皆存在；分隔線在兩 locale 各渲染一次斷言文字。

## B.7 E2E（`m05-session-history.spec.ts` B 段）

接在 A 段之後：真人 DM 在第二場送一筆 narration → 聊天串按「載入更早訊息」直到出現分隔線 → 斷言分隔線標示 AI DM／已結束 → 斷言看得到第一場 AI 的 narration → 再按一次 → 出現「已到這個 Campaign 的最前面」。Player 視角（第二個 browser context，控制 P1）重複同一流程，斷言看不到第一場的 `dm_only` 訊息（fixture 由 MCP AI DM 以 DM-only visibility 寫入一筆）。
