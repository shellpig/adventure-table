# B1 — Movement bookkeeping、path resolution、Preview／Confirm

## Scope

- **Migration `0038_p5b_movement_bookkeeping`**（parent `0037_p5a_combat_board_positions`，web track）：`combat_entries` 加 `movement_used_feet`、`movement_diagonal_steps_used`、`movement_budget_feet`（int，default 0，CHECK ≥ 0）與 `pending_movement_state`（JSON，default `{}`）。`app/persistence/combat/tables.py`、entry domain model 同步；既有 row upgrade 後值為 0／`{}`。
- **Lifecycle reset**（設計 §4.1）：四個 `movement_*` 欄位併入既有 `attacks_used`／`ready_state`／`dodging` 的同一批 `UPDATE ... values(...)`：finalize initiative 初始化所有 entry、`advance_turn` 的 incoming entry、End Combat、withdraw／remove。不得另開獨立 cleanup UPDATE。
- **Spatial（`app/domain/spatial/`，純函式）**：`GridPath`、`grid_distance()`（兩 footprint occupied cells 最小距離，5/10 alternating，從測量起點重算 parity）、`step_cost()`（orthogonal 5；diagonal 依本 Turn 已用 diagonal 數 5/10 交替；difficult ×2）、`crosses_wall_or_closed_door()`（含 diagonal 切角）、path validator：逐步驗相鄰、bounds、完整 footprint sweep、blocked terrain、wall／closed／locked door（open／broken 可過）、creature space（nonhostile 可穿＝difficult；hostile 同尺寸或差一級不可穿、差 ≥ 2 級可穿＝difficult；不可停在他人 occupied space）、剩餘 budget。一次載入 board＋positions snapshot 在記憶體驗整條 path（設計 §13）。
- **Budget**：speed 由 Character derived state／Monster `rules_snapshot` 的 walk speed 取得，套既有 condition／exhaustion speed 修正（`speed_zero` → 0）。本 Turn 首次 movement 時把 `movement_budget_feet` 設為 speed；Dash（既有 `CombatActionKind.DASH`）使 budget 再加一次 speed，不改 used 與 diagonal parity。
- **Preview**：`POST .../combat/board/movement/preview`（body `entry_id`、`path`：含起點的 anchor 序列）。不持久化、不 append event；回 planned path、used／remaining、每步 cost、difficult／blocked／collision warning、`position_revision`、`board_revision`。只依 caller 可見資料計算（Player 看不到的 hidden monster／hidden wall／未揭露 hidden door 不影響 Preview 結果、不出現在 warning）。
- **Confirm**：`POST .../combat/board/movement/confirm`（body `entry_id`、`path`、`expected_position_revision`、`expected_board_revision`、`idempotency_key`）。以 full Server truth 重驗整條 path；只能在該 entry 自己的 Turn 移動。Authority：Player（Human／AI）只能移自己控制的 Character entry；DM 可移任何 entry（DM proxy，正常 gameplay 規則，audit 保留 acting DM＋subject）。成功時同一 transaction 更新 position（`revision+1`）、`movement_used_feet`、`movement_diagonal_steps_used`，append `combat.movement_committed`（`event_repository.append(..., expected_actor_binding=actor_binding(actor), transaction_projection=...)`；payload 含 `combat_id`、`entry_id`、終點 anchor、`used_feet`；hidden monster 的移動事件 `visibility='dm_only'`）。Revision 不符 → 409 `combat_movement_stale`；path 非法 → 400 `combat_movement_invalid`，零副作用；同 key retry 回同結果、不重複移動或 append。
- **Hidden blocker 於 B1 的最低要求**：Confirm 撞到 caller 看不到的 blocker 時不得回傳 hidden identity／座標；B1 可先回 generic `combat_movement_invalid`，B2 再改為正式 `movement_interrupted`。
