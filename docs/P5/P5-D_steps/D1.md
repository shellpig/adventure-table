# D1 — AoE geometry 與 Tactical AoE 接線

## Scope

依 [實作紀錄](../P5-D實作紀錄.md) 技術決策 1～6，一次交付：

- `app/domain/spatial/aoe.py`：normalized shape、由 `area_of_effect` 建 shape、affected cells（cell-center 規則，重用 `primitives` 的 5/10 距離）、由 board positions／footprint 算 candidate entry（多格 creature 任一 occupied cell 被涵蓋即列入）。
- `apps/server/tests/fixtures/p5d_aoe_golden.json` 與讀它的 golden 測試：四種 shape 各至少一組，含恰在半徑／長度邊界、cone 楔形邊界、line 半寬邊界、奇數與偶數尺寸。
- Tactical AoE 接線：preview route（Player／DM 皆可，actor-projected）；Character AoE 提案在 Tactical 時要求 template＋`board_revision`，Server 算 candidate list 寫入既有 AoE 提案；DM confirm 沿用既有流程（可增刪 target）；Monster AoE 若既有 path 有結構化 area 資料則同樣接上，沒有則維持 DM 裁定並記錄。Quick 完全不變。
- Secrecy：Player preview／提案回應／事件不得含 hidden combatant 的 entry id、名稱、位置；DM 完整。
- Stale 與 idempotency：`board_revision` 不符 409 `combat_board_stale`、零副作用；同一 idempotency key 重送不重建 saves、不重扣 slot、不重傷害、不重套 condition。
- 新 route／error code 的 user-visible 訊息若有 locale 需求，比照既有 combat error 處理。
