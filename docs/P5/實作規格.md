# P5 — 實作規格

> Phase：**P5 — Tactical Combat**  
> 本文件只定義 **P5 各 Subphase 完成後什麼必須成立**。具體 DB schema、API、module、MCP tool、transaction 與 persistence wiring 放在同目錄的 `開發設計方針.md`；自動／人工驗收與 closeout evidence 放在 `測試指南.md`。

最後更新：2026-09-19

---

## 1. P5 定位

P4 已交付 Human / AI 共用的 canonical Combat Engine：Combat lifecycle、initiative、turn / action economy、Attack / Damage / Healing、Saving Throw、Spell、Conditions、Concentration、Reaction、Grapple / Shove、Death Save、Monster / Quick Enemy、DM adjudication 與 Quick Combat UI / MCP。

P5 不重做 Combat Engine。P5 在同一套 Combat Engine 上增加 **Tactical Combat 的 2D precise spatial state**：Battle Map、Square Grid、Token footprint / canonical position、Movement path / speed budget、Distance / Range / Reach、AoE geometry、Wall / Door / Terrain、Automatic Opportunity Attack detection，以及 Tactical Human UI / AI tool surface。

P5 關門後必須維持同一條 resolution：

```text
Quick Combat
Action → DM 提供必要的空間裁定 → P4 Combat resolution

Tactical Combat
Action → P5 Spatial system 提供可可靠計算的空間事實 → P4 Combat resolution
```

Tactical 不建立第二套 attack engine、spell engine、reaction engine、RNG、Character State 或 secret filter。

### 1.1 第一版只做 2D 地面 Tactical

P5 的 precise spatial model 固定為 **2D ground plane**。不建立 z-axis / elevation、飛行高度、vertical reach、3D distance、多樓層 geometry、climb surface graph、burrow volume 或 underwater vertical positioning。

Fly / Climb / Burrow，以及需要真正立體空間或特殊 movement mode 判定的情況，由 DM adjudication / DM reposition 處理；P5 不以假的 2D 高度替代。若某張地圖只是把水面／水底平面當作一般 2D 戰場展示，DM 可以使用同一張 Tactical map，但 P5 不因此宣稱已自動化 Swim / underwater 的完整 movement 規則。

### 1.2 P5 不偷跑 P6 / P7

P5 Battle Map 可以被 Room 重用，但一場 Combat 內的 Door state、Token position、runtime terrain / reveal 等變化是 **Combat board state**。P5 不把這些自動升格成 P6 Campaign world truth；也不把 Tactical event history 擴成 P7 Snapshot / Restore / complete Timeline subsystem。

```text
↓

```

三份 P5 文件必須使用完全一致的名稱與順序。

## 3. P4 → P5 必須承接的既有真實邊界

P5 不重造以下既有能力：Campaign-scoped durable Combat lifecycle；Combat Start 後 mode 固定且不可 Quick / Tactical 中途切換；P4 combat entries / initiative / round / current turn / action economy；Character / Monster combatant identity；Monster Template / Instance / Quick Enemy；P3 RollGroup / RollRequest / Server RNG；P4 Attack / Damage / Healing / Save / Spell / Condition / Concentration / Reaction pipeline；P4 Grapple / Shove / Death / Monster outcome；acting actor vs subject actor、DM proxy、authority、idempotency、event / waiter substrate；Server-side secrecy projection；M04 OAuth / Bearer / MCP authority；M03 Standalone Character-first boundary。

P5 新增的 spatial facts 必須作為既有 P4 action resolver 的輸入，而不是另建 Tactical-only combat business logic。

## 4. P5 全 Phase 共用產品邊界

### 4.1 Square Grid

第一版只支援 square grid，**1 格固定為 5 ft**。不做 hex、不做任意 feet-per-cell ruleset。Image map 可以調 grid pixel size 與 X/Y offset，但規則距離仍是 1 cell = 5 ft。

### 4.2 Creature footprint

第一版 footprint 固定：

```text
Tiny / Small / Medium = 1×1
Large                 = 2×2
Huge                  = 3×3
Gargantuan            = 4×4
```

Token canonical position 代表 footprint anchor；Server 必須能導出完整 occupied cells。同一 combatant 不得有兩份 authoritative position。

### 4.3 共用 5/10 alternating distance

Movement、Range、Reach 與 Tactical AoE 的 grid distance 使用同一套 5/10 alternating diagonal 定義：orthogonal step = 5 ft；diagonal steps = 5, 10, 5, 10...。

同一 Turn split movement 的 diagonal parity 不因 Attack / Bonus Action 等中途行動重置。多格 creature 的相互距離以兩邊 footprint 可合法比較的最近 occupied-cell pair 計算；不得只以 token anchor 算距離。

### 4.4 Quick Combat 不依賴 Tactical state

P5 完成後，Quick Combat 必須仍可完全沒有 Battle Map、token position、movement budget、path 或 spatial geometry。Quick 的 range / AoE / OA 既有 DM adjudication path 必須保持可用。

### 4.5 Secret 仍由 Server 隔離

Hidden Token / Hidden Door 等 secret 不能靠 CSS 或 prompt 保密。Player / AI Player 不收到 hidden entity identity / coordinates / geometry，也不可從 path preview、range preview、AoE preview、error detail 推導 hidden content。

Hidden Door reveal 前，在 Player 可見 geometry 中等同不可穿越的普通牆面。Hidden creature 造成 movement 衝突時，只能得到不洩密的 generic interruption / adjudication result，直到 DM 正式 reveal 或以遊戲行為揭露。

## 5. P5-A — Battle Map & Spatial Foundation

### 5.1 Battle Map Definition

Room 可以建立／保存可重用 Battle Map Definition，最低支援 Blank Grid、Existing Battle Map、Upload Image、Width / Height、grid size / X-Y offset、Wall、Door、Terrain、Token setup / placement affordance、Free Drawing。Blank Grid 是一等公民，不要求先有圖片。

Upload Image 必須走 P5-A 的最小 Room-scoped image asset substrate；圖片不是公開靜態資源，下載同樣經 Room authority，非該 Room 成員不得讀取圖片。

目標 UX：真人 DM 可以在約 30 秒內建立一張最小可打地圖。

### 5.2 Semantic map objects

第一版 semantic object：Wall blocks ground movement；Door = Open / Closed / Locked / Broken；Terrain = Normal / Difficult / Blocked；Token；Free Drawing 純視覺、不影響 Rules Engine。顏色與畫筆樣式不代表規則語意。

### 5.3 Map Definition 與 Combat board state 分離

Battle Map Definition 是可重用 baseline；Tactical Combat 啟用後建立／保存該場 Combat 的 board runtime state。

必須成立：某場 Combat 把 Door 改成 Broken 不直接修改 reusable Map Definition；Definition 後續被編輯不會讓 active Combat board 漂移；Tactical Combat 可跨 Session 保留同一 board state；End Combat 後可保留該 Combat 的 board history，但不自動寫成 P6 Campaign world state。

若 DM 想讓某次戰鬥的破門成為下次地圖 baseline，第一版由 Human DM 主動編輯 Map Definition，不做 Combat automatic write-back。

### 5.4 Tactical placement gate

Start Combat 時先選 `quick` 或 `tactical`；既有 Quick start 流程保持不變。選 Tactical 後固定流程：

```text
Start Combat
→ choose/create Battle Map
→ include/add combatants
→ place all current combatants
→ surprise if needed
→ initiative
```

當下所有參戰 combatants 必須先完成合法 placement 才能進正式 initiative。Mid-combat entrant 同樣先 placement，再完成既有 mid-combat initiative 流程。

### 5.5 Map editor Undo 邊界

Map Editor 的 Undo 只作用於尚未正式提交的 map editing 操作／working edit history。它不是 P7 gameplay transaction Undo，也不能回滾已 committed 的 Combat action、damage、movement 或 reaction。

## 6. P5-B — Movement & Path Resolution

### 6.1 Movement lifecycle

正式 Tactical movement 固定 `Plan → Preview → Confirm → Execute`。Plan / Preview 不改 Server canonical position；Confirm 後才 commit。

Preview 至少提供 planned path、used movement、remaining movement、difficult / blocked warning、collision warning，以及 P5-E 接線後的已知 OA warning。

### 6.2 Speed budget / split movement

Server authoritative 追蹤本 Turn ground movement budget，包括 base speed、Dash 等正式增加的 movement budget、Difficult Terrain cost、used / remaining 與 split movement。

必須支援 `Move → Attack → Move`、`Attack → Move → Attack`、`Move → Bonus Action → Move`；同一 Turn movement bookkeeping 不因中途 action 重置。

### 6.3 Creature space

採 D&D 5e 2014 基本 creature-space 規則：可穿過 nonhostile creature space；hostile creature 只有在尺寸至少相差兩級時可穿過；穿過另一 creature space 視為 difficult terrain；不可自願把 movement 結束在另一 creature occupied space。

特殊能力、形體、incorporeal 等無法由第一版可靠自動化者交 DM adjudication。

### 6.4 Terrain / obstacle

Normal 正常 cost；Difficult 加倍 movement cost；Blocked 不可穿越；Wall / Closed Door 不可穿越；Open / Broken Door 不作為 movement blocker；Locked 在仍 Closed 時照樣阻擋 movement。

### 6.5 DM proxy vs DM reposition

DM Proxy Movement 是正常 gameplay movement：遵守 speed、terrain、collision、OA、turn economy，audit 保留 acting DM + subject。

DM Reposition / Correction 用於 setup、裁定、修正、特殊立體 movement 結果等：不消耗 subject movement budget、不觸發 OA、必須留下 audit / reason，且不可偽裝成普通 Player movement。

### 6.6 非地面 movement

Fly / Climb / Burrow 及真正需要特殊 movement mode / elevation 的狀況不進 precise path resolver。DM 可用 adjudication / reposition 放置合理的 2D 投影位置；系統不得宣稱已驗證 3D legality。

## 7. P5-C — Range, Reach & Spatial Targeting

### 7.1 Spatial targeting

Tactical Attack / targeted Spell 不再要求 DM 手動提供一般 in-range / out-of-range。Server 依 source footprint、target footprint、weapon / attack / spell range、shared grid distance 與 hard blocker 產生 spatial result。

### 7.2 Melee Reach

一般 melee reach 與具明確 reach 數值的 action 由 Server 驗證。離開 reach 的 movement trigger 留 P5-E；P5-C 只提供可靠 reach query / crossing facts。

### 7.3 Ranged bands

可結構化 ranged action 至少區分 normal range、long range、out of range。long range 的 disadvantage 等後續 resolution 仍走既有 P4 modifier pipeline。

### 7.4 Wall / Door hard blocker

Wall 與 Closed Door 對第一版 ordinary direct targeting 是 hard blocker：一般 melee / ranged direct target 不可穿過；Open / Broken Door 可通過。特殊 spell / ability 若明確允許穿牆或特殊傳播，交 spell-specific rule 或 DM adjudication。

### 7.5 Cover 邊界

第一版不自動計算 Half Cover / Three-Quarters Cover / Total Cover polygon。除明確 hard blocker 外，Cover 仍由 DM 裁定並接回既有 P4 modifier / adjudication pipeline。P5 不建立完整 LOS / visibility / lighting engine。

Dodge 的「能看見攻擊者」與 Frightened 的來源可見性同樣不在 P5 建模，沿用 P4-F closeout 的已知限制，仍交 DM 裁定。

## 8. P5-D — AoE & Tactical Spell Geometry

### 8.1 支援形狀

第一版 precise AoE 至少支援 Circle / Sphere 的 2D projection、Cone、Line、Cube / Square。不支援需要 elevation / 3D volume 精確判定的版本。

### 8.2 Cell-center 規則

Affected cell 使用 **cell center 落入模板** 作 deterministic 判定。不使用覆蓋 50% 類規則；renderer 像素誤差不得改變 Server 結果；Preview 與 canonical resolution 必須使用同一 geometry。

多格 combatant 只要任一 occupied cell center 被模板涵蓋，即列為 candidate affected target。

### 8.3 Preview → Confirm → Existing resolution

Tactical AoE 流程：choose action/spell → choose origin / direction / template placement → preview affected cells + visible candidate targets → confirm → P4 RollGroup / Saving Throw / Damage / Effect pipeline。

geometry 只決定 affected candidate list，不另建 spell resolution。

### 8.4 Obstruction 邊界

P5 第一版不做完整 AoE 繞牆／門縫傳播 generic simulator。若 spell / effect 對 obstruction 有明確且可靠的 structured rule，可由 specific resolver 處理；其餘由 DM confirm / adjudication 調整 affected list。Hidden entity 不得因 AoE preview 被提前揭露。

## 9. P5-E — Opportunity Attack & Spatial Reactions

### 9.1 Automatic OA detection

Tactical committed voluntary movement 若從某敵對 combatant 的合法 reach 內移到 reach 外，Server 自動建立既有 P4 ReactionRequest。Quick Combat 仍維持 DM trigger OA。

### 9.2 不觸發 OA 的 movement

Forced movement、Teleport、DM Reposition / Correction 不因離開 reach 自動觸發 OA。特殊 feature 若改變此規則，只有在已有可靠 structured rule 時才自動化，否則交 DM。

### 9.3 Movement pause / resume

OA trigger 後固定為：movement 執行到 trigger boundary → pause → create / resolve eligible ReactionRequest(s) → recompute mover state → continue legal remaining path or stop。

若 reaction 後 mover 0 HP、不能繼續、speed = 0、被 Grappled / Restrained 而使路徑非法，或 position 因其他效果改變，剩餘 path 必須重新驗證或取消，不得盲目 replay。

### 9.4 Multiple reactors

同一 movement boundary 若有多個合法 reactors，Server 必須 deterministic 地建立／排序 reaction windows，不能因 retry / reconnect 漏掉或重複。每個 combatant 仍依既有 P4 reaction economy 消耗合法 Reaction。

### 9.5 Grapple / Shove spatial integration

P4 Grapple / Shove 在 P5 接入 spatial system：Grapple dragging 套用對應 movement cost / reduced movement；Shove push 5 ft 真正修改 canonical token position；若目的位置 blocked / occupied / wall 阻擋則拒絕。Cliff、hazard、掉落等後果交 DM，不建立完整物理引擎。

## 10. P5-F — Tactical Combat UI & AI Tool Surface

### 10.1 Tactical Main Stage

Human UI 至少提供 Combat Header / Round / Current Turn、Battle Map、Initiative / combatant context、Token selection、movement plan / preview、range / target feedback、AoE template preview、compact combat log 與 DM map / adjudication affordance。不要求做成 Foundry 式大型 VTT editor。

### 10.2 Camera state

支援 bounded zoom、pan、wheel / pinch、drag empty space、middle mouse、Fit Map、optional Center Party。Camera / zoom / pan 是 per-client UI preference，不進 Campaign canonical gameplay state。

### 10.3 Player drag semantics

Active Tactical Combat 中，Player 拖自己可控 Token = 建立／修改 movement plan；拖曳本身不得直接寫 canonical position；Confirm 才走 Server movement command。Player 不得任意拖其他 Token；DM setup / reposition 使用獨立 authority / command。

### 10.4 Hidden rendering

Human Player / AI Player 只取得 projected board。Hidden token / hidden door / secret geometry 不可存在於 Player payload 後再靠前端 hide。

### 10.5 AI Tactical context

AI DM / AI Player 透過 MCP 取得 role-scoped structured spatial context，包括 own / visible combatant positions、visible map bounds、visible walls / doors / terrain、current movement used / remaining、target range result、preview / pending reaction / movement state。AI Player 不得取得 hidden board truth。

### 10.6 Human / AI service parity

Human movement、AI movement、Human Tactical attack、AI Tactical attack 必須共用相同 application / spatial services。MCP tool 只表達 intent，不得直接寫 raw coordinates、bypass path validation 或修改 repository row。

## 11. P5-G — Full P5 Integration & Closeout

P5-G 關門前必須證明：

- Quick Combat 無 map / coordinates 時仍完整運作，以 DM adjudication 提供 geometry facts。
- Tactical Combat 以 P5 Spatial system 提供 geometry facts，最後進相同 P4 action / roll / state mutation pipeline。
- app restart / Session boundary 後恢復 active board、positions、round / turn、movement bookkeeping、pending ReactionRequest、pending roll / action、hidden projection、Door / Terrain runtime state。
- 真人 browser journey涵蓋 map、placement、initiative、movement、Difficult Terrain、split movement、range、AoE、automatic OA、reaction resume / stop、Grapple或Shove、hidden secrecy、Session resume、End Combat。
- 至少一條真實 ChatGPT Web journey 使用既有 M04 connector / OAuth / AI Join Kit，實際改變 Adventure Table spatial / combat state，而不是只在 host chat 回答文字。
- P5 multiplayer schema 不得進 Standalone，Character Core 不得反向 import Tactical multiplayer module。

## 12. P5 明確不做

P5 第一版不做 Hex grid、Variable feet-per-cell、Elevation / z-axis、3D、Vision cone、Dynamic Lighting、Darkvision rendering、Fog of War、Automatic LOS polygon、Automatic Half / Three-Quarters Cover geometry、Physics engine / falling simulator、Full destructible environment、Generic spell propagation simulator、Exploration grid movement、Quick ↔ Tactical mid-combat conversion、Automatic Campaign world-state write-back、P7 Undo Transaction / Snapshot Restore、Foundry 級 asset / scene / map management平台。

---

## 13. P5 Closeout 原則

每個 Subphase 各自完成對應實作、focused tests、static review、必要 regression 與 closeout evidence；P5-G 完成 full integration 後 P5 才能關門。

以下任一仍存在時不得關 P5：Tactical 另建第二套 Combat resolution；Quick 被迫依賴 Map / position；client 可直接寫 canonical Token coordinates；hidden spatial data 透過 payload / preview / errors 外洩；restart 後位置或 pending reaction 消失；preview 與 Server commit 使用不同 geometry；OA retry 重複觸發／漏失；AI tool 能繞過 Human 共用 spatial rules；P5 schema 污染 Standalone。
