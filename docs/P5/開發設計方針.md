# P5 — 開發設計方針

> Phase：**P5 — Tactical Combat**  
> 本文件是 P5 的具體實作契約。產品完成條件以 `實作規格.md` 與根目錄 `規格企劃.md` 為準；測試與 closeout evidence 以 `測試指南.md` 為準。

最後更新：2026-09-19

---

## 1. P5 Subphase 順序

三份 P5 文件固定使用：

```text
P5-A — Battle Map & Spatial Foundation
P5-B — Movement & Path Resolution
P5-C — Range, Reach & Spatial Targeting
P5-D — AoE & Tactical Spell Geometry
P5-E — Opportunity Attack & Spatial Reactions
P5-F — Tactical Combat UI & AI Tool Surface
P5-G — Full P5 Integration & Closeout
```

每個 Subphase 只建立自己需要的 substrate；不得因後段一定會用，就把後段完整能力偷塞進前段。

---

## 2. Architecture：P5 是 Spatial provider，不是第二套 Combat Engine

固定依賴方向：

```text
Human Web UI ─┐
              ├─> Tactical application services ─> Spatial domain
MCP Adapter ──┘                │                    ├─ Map / Board
                               │                    ├─ Path / Distance
                               │                    ├─ Targeting
                               │                    └─ AoE / OA facts
                               │
                               └─> existing P4 Combat application services
                                      ├─ RollGroup / RollRequest
                                      ├─ Attack / Save / Damage
                                      ├─ Spell / Condition
                                      ├─ Reaction
                                      └─ Character / Monster state
```

禁止 Tactical UI 或 MCP tool 直接更新 position row；禁止 Spatial domain 自建第二套 attack / spell / reaction / damage resolver。

Spatial layer 只回答：哪些 cells 可走、path cost、source/target distance、target legality、AoE affected cells / candidate targets，以及 committed movement 何時離開 reach。P4 仍負責命中、save、damage、effect、reaction economy 與 Current State mutation。

## 3. Canonical model / persistence boundary

### 3.1 Battle Map Definition

建議在 Web multiplayer track 新增 Room-scoped 可重用 map 定義，最小概念模型：

```text
battle_maps
  id
  room_id
  name
  source_kind = blank | image
  image_asset_ref nullable
  width_cells
  height_cells
  grid_pixel_size nullable
  grid_offset_x nullable
  grid_offset_y nullable
  revision

battle_map_walls
  battle_map_id
  start_vertex / end_vertex
  visibility = public | hidden

battle_map_doors
  battle_map_id
  edge / segment anchor
  default_state = open | closed | locked | broken
  visibility = public | hidden

battle_map_terrain
  battle_map_id
  cell
  terrain_kind = normal | difficult | blocked

battle_map_drawings
  # visual only
```

實際 table / JSON 正規化可依 codebase 調整；契約是 Definition 可重用、semantic 與 visual 分離、Room-scoped，而且不是 Combat live state。

Image map 優先引用既有 Room-scoped upload / asset substrate；不得另造繞過 Room authority 的 public asset storage。

### 3.2 Combat board runtime

建議 Combat-scoped board runtime 至少能表達：

```text
combat_boards
  combat_id PK/FK
  source_battle_map_id nullable
  source_battle_map_revision nullable
  width_cells
  height_cells
  runtime_revision

combat_board_doors
  combat_id
  board_object_id
  state = open | closed | locked | broken
  reveal / visibility runtime state

combat_positions
  combat_entry_id unique
  anchor_x
  anchor_y
  footprint_w
  footprint_h
  revision
```

可用 snapshot JSON 或正規化 table；但必須滿足：一個 active combat entry 最多一個 canonical position；Tactical combat 有且只有一個 canonical board；Quick combat 沒有 board 也合法；board 與 Combat 同 lifecycle 可跨 Session；Definition 更新不改 active board；Combat runtime mutation 不回寫 Definition。

### 3.3 Combat mode

沿用 P4 `Combat.mode` truth，P5 開始正式接受 `quick | tactical`。mode 在 Combat Start 後 immutable。所有 tactical-only command 先驗 `combat.mode == tactical`；Quick action 不要求 board。

## 4. Shared spatial primitives

Movement、Range、Reach、AoE、OA 必須共用單一 spatial domain package，至少抽象：`GridCell`、`Footprint`、`GridPath`、`DistanceResult`、`SpatialBlocker`、actor-specific `VisibilityProjection`。

至少有共用 utility：`occupied_cells()`、`grid_distance()`、`step_cost()`、`is_inside_bounds()`、`intersects_blocked_cell()`、`crosses_wall_or_closed_door()`、`can_occupy()`。不得 movement 一套 diagonal、range 又一套。

### 4.1 Diagonal bookkeeping

5/10 alternating 的 parity 在正式 movement 時屬於本 Turn movement bookkeeping。建議 entry turn state 至少有 `movement_used_feet`、`movement_diagonal_steps_used`、`movement_budget_feet` 或等價 truth；每個新 Turn reset，同 Turn split movement 保留。

一般 distance query，例如 source-target range，從該次測量起點重新計算自身 diagonal sequence，不污染 Turn movement parity。

### 4.2 Multi-cell distance

多格 creature 使用兩 footprint occupied cells 的最小合法 grid distance；禁止 anchor-to-anchor 當唯一距離。

## 5. P5-A — Battle Map & Spatial Foundation

### 5.1 Map service

建議 application service 能力：create blank map、create image map、update grid alignment、edit semantic objects、read actor-projected map。Map Definition mutation 使用 Room authority，不冒充 Combat Seat action。

### 5.2 Combat board initialization

```text
start tactical combat
→ select map / blank board
→ freeze or snapshot map revision into board baseline
→ create combat entries
→ placement phase
→ validate every current entry
→ initiative
```

若 Combat 已建立但 placement 未完成，要有 explicit setup / pre-initiative state；不得靠 nullable initiative 讓 client 猜。

### 5.3 Placement validator

placement 至少驗 footprint in bounds、blocked terrain、非法 overlap、Wall / Door 基本限制與 actor authority。DM setup placement 不消耗 movement。

### 5.4 Hidden projection

DM projector 可拿 full semantic objects / hidden token positions。Player projector 必須省略 hidden token；Hidden Door 必須投影成不洩密的 opaque blocker / wall-equivalent，而不是把 `hidden=true` 物件整筆傳給 Player。

## 6. P5-B — Movement & Path Resolution

### 6.1 Command boundary

建議 intent：preview/plan movement、confirm movement、cancel draft、DM reposition。Preview 可不持久化，但 Confirm 必須以 Server current revision 重新驗證，不能信 client cached legality。

### 6.2 Path representation

authoritative movement command 傳完整相鄰 cell / anchor path，不只傳終點讓 Server 猜路。因為 5/10 parity、Difficult Terrain、creature space、OA、hidden blocker 都依賴實際 path。

前端可做 local pathfinding 作 UX，但 Confirm 時 Server 逐步驗完整 proposed path。

### 6.3 Step validation

每一步至少驗 adjacent legal step、board bounds、完整 footprint sweep、Wall / Closed Door、Blocked terrain、creature-space rule、terrain cost、remaining budget、hidden conflict；P5-E 再加入 reach-exit reaction trigger。

一般 invalid path 應零副作用，不可先移半條再因後段 invalid 留下半 commit；只有產品明確的 reaction interruption 才允許 durable partial progress。

### 6.4 Hidden blocker

Preview 只根據 caller 可見資料。Confirm 用 full Server truth；若 hidden creature / object 阻止路徑，不回傳 hidden identity / coordinate detail，改成 generic `movement_interrupted` / adjudication state 或等價安全結果。

### 6.5 Atomicity / stale protection

Movement commit 至少需要 command idempotency + combat/board/entry revision 或等價 compare-and-set。Human、AI、另一 browser tab 不能同時用舊 preview 把同一 token 移到兩個位置。

### 6.6 DM reposition

DM correction command 獨立於 gameplay movement，不消耗 budget、不改 diagonal parity、不觸發 OA，並保留 acting DM / subject / reason audit。

## 7. P5-C — Range, Reach & Spatial Targeting

### 7.1 Spatial targeting result

建議 normalized result 至少含 `legal`、`distance_feet`、`range_band`、`blocked`、public-safe blocker kind、`requires_dm_adjudication` 與 modifier facts；不在此 service 擲骰或扣 HP。

### 7.2 接回 P4

Quick：P4 pending adjudication → DM in/out range / cover → P4 resolve。

Tactical：P5 spatial targeting → exact range band / hard blocker → optional DM cover adjudication → 同一 P4 resolve。

若 P4 action 已有 adjudication/result fields，優先 additive 演進，避免新增 `TacticalAction` 第二套 action model。

### 7.3 Reach

Reach query 由同一 grid-distance / footprint primitive 提供。P5-C 只提供 reach facts；何時離開 reach 並觸發 reaction 由 P5-E 負責。

### 7.4 Cover

generic spatial engine 不從 wall polygon 自動推 Half / 3/4 Cover。完整 hard wall / closed door 可判 direct target invalid；其他 cover 走既有 DM adjudication。

---

## 8. P5-D — AoE & Tactical Spell Geometry

### 8.1 Canonical geometry 在 Server

前端 renderer 可即時 preview，但 Confirm 時 Server 使用同一 domain math 重算。Server result 是 canonical；像素 overlay 不是 truth。

### 8.2 Normalized shape

建議 AoE shape 能表達 `circle | cone | line | square`、size / radius / length / width、origin、direction / target anchor。Sphere 在 2D normalize 成 circle projection；Cube normalize 成 square footprint。

Spell content 若已有 AoE metadata，從 stable content data 讀，不在 P5 以 spell name hardcode。

### 8.3 Candidate resolution

```text
shape
→ affected cells by center-point rule
→ actual occupied footprints
→ candidate affected combatants
→ obstruction / special-rule adjudication if needed
→ final affected target ids
→ existing P4 spell/save/damage service
```

Player preview 只能列 visible candidates。Hidden combatant 不可因 preview 被 reveal；正式 resolve 時 Server 可依規則處理，但 Player payload 僅回傳角色合理可知的結果。

### 8.4 Idempotency

同一 AoE confirm retry 不得建立第二組 saves、重扣 slot、重傷害、重複套 condition。沿用 P4 command / PendingAction idempotency。

## 9. P5-E — Opportunity Attack & Spatial Reactions

### 9.1 Reach crossing detector

movement step execution 提供 previous footprint、next footprint、hostile positions、reach definitions 與 movement cause。對可能 reactor 判斷：previous 在 reach、next 離開 reach、cause = voluntary、reaction available，才建立既有 P4 ReactionRequest。

### 9.2 Durable paused movement

OA 不可讓整條 path 一次 commit 到底。建議 durable pending movement 至少保留 command id、mover entry、original path、current path index、movement cost committed、diagonal parity、pending reaction ids、revision。

Reaction resolve 後重新進 MovementService 續走；不能靠 client 自己從下一格拼接。

### 9.3 Multiple reactors

同一 crossing 可有多個 eligible reactors；順序使用 deterministic rule，例如 canonical initiative order，再以 stable entry order tie-break。Reconnect 後順序不變。

### 9.4 Reaction後 revalidation

每次 reaction 後重新讀 mover canonical HP/status、conditions、speed、grapple link、position、remaining path legality。不得沿用 reaction 前快照。

### 9.5 Grapple / Shove

Shove displacement 使用同一 occupancy validator，但 movement cause 不是 voluntary，因此不觸發 generic OA。Grapple drag 建立明確 movement cause / cost；拖曳目的地非法就拒絕該 step。

## 10. P5-F — Tactical Combat UI & AI Tool Surface

### 10.1 Frontend local vs canonical

Frontend 可持有 camera、hover、selected token、draft path、draft AoE template、local map-edit working state；不得把 committed position、remaining movement、hidden map truth、range legality 或 OA eligibility 當 client truth。

### 10.2 Tactical Stage

沿用既有 Session Main Stage composition，在 `mode=tactical` 時切 Tactical Stage，不建立另一個獨立 app。DM map toolbar 至少可承載 Select、Wall、Door、Terrain、Token、Draw、Erase、Undo、Fit Map。

setup/editor manipulation 與正式 gameplay movement 在 command 與視覺上必須可區分。

### 10.3 MCP surface

確切 tool 名實作時依現有 catalog naming 核對，但能力至少需要 actor-scoped tactical context、movement preview / confirm、target validation、AoE preview / confirm；DM-only 另有 map setup/edit、placement、reveal/hide、reposition/correction、spatial adjudication。

MCP schema 使用 structured coordinates / cell lists；自然語言可描述意圖，但不能以一句「往北走一點」直接當 canonical movement。

### 10.4 AI briefing

`get_session_context` / combat briefing 在 Tactical mode 至少提供 current board摘要、visible positions、current turn、own movement remaining、pending movement / reaction、next required action、tool usage order。不要把整張 map 轉巨大 ASCII。

### 10.5 Locale

新增 map editor copy、movement validation、range / blocker result、OA / reaction copy、MCP descriptions 必須同 Subphase 交付 zh-TW + en。

## 11. Event / waiter / audit integration

每個 committed Tactical gameplay mutation 沿用 P3/P4 durable event + notifier。可新增 `combat.board_initialized`、`combat.position_placed`、`combat.movement_committed`、`combat.movement_interrupted`、`combat.door_state_changed`、`combat.spatial_adjudication_requested/resolved`、`combat.token_revealed` 等 event family，命名依現有 convention 調整。

要求：event payload actor-projected；Human UI / MCP wait 從同一 truth 醒來；position mutation與event同 transaction或等價 atomic boundary；retry不重複append實質event；DM correction保留acting DM / subject / reason。

---

## 12. Migration / PostgreSQL / Standalone

P5 multiplayer資料走 Web migration track。必測 upgrade from current web head、fresh DB migration、真 PostgreSQL constraint/concurrency、existing P4 combat data backward compatibility。

Standalone 不建立 Battle Map / Combat Board / Position tables；`app.standalone` 不 import P5 multiplayer modules。若 footprint 需要 Character size，只能透過既有 Character/Content primitive或上層注入，不得讓 Character Core import Combat/Tactical。

---

## 13. Performance baseline

朋友桌規模下不需要大型 MMO path engine，但不能每次 pointer move 都開昂貴 transaction。Frontend draft preview 可 local；Server preview 可節流；Confirm 必須重驗。

常見 20–60 cells path 應一次載入必要 board / combatant spatial snapshot，在 domain memory 中驗證整條 path，再一次 commit；避免每格各自打一輪 DB query。

不得為效能把 hidden full map 送到 Player client。

---

## 14. Subphase implementation boundary

**P5-A**：Map / board / placement / projection substrate；不做正式 movement budget。

**P5-B**：完成 path / movement；尚未要求 Attack range 或 OA。

**P5-C**：distance / range / reach / hard blocker 接回 P4 targeting；不做 AoE。

**P5-D**：AoE shapes + spell affected list；不做 OA。

**P5-E**：movement ↔ reach ↔ Reaction 接線，並把 Grapple / Shove 空間化。

**P5-F**：Human Tactical UI、必要 Map editor surface、MCP tools、briefing、雙語。

**P5-G**：integration、repair、real gates、closeout；不得把尚未做的 P5 核心功能拖到 G 才第一次實作。
