# C1 — Reach／range 欄位、spatial targeting、Tactical 攻擊與法術接線

## Scope

- **`ResolvedAttack` additive 擴充**（設計 §7.2）：新增 `reach_feet`、`range_normal_feet`、`range_long_feet`。`AttackDefinitionResolver` 是唯一來源：Monster 從 normalized `MonsterAction.reach／range_normal／range_long` 帶入；Character weapon 由 ContentRegistry equipment 的 range／reach properties 推導（Reach property＝10 呎；thrown 武器近戰時用 reach、投擲時用 range）；普通 melee 未標 reach 時 `reach_feet=5`。Spatial targeting 只消費 `ResolvedAttack`，不得自行解析 Monster 描述或 Character 武器資料。既有 Quick 測試行為不變。
- **Spatial targeting（`app/domain/spatial/targeting.py`，純函式）**：輸入 source／target footprint cells、`ResolvedAttack`（或 spell range）、board barriers；輸出 `legal`、`distance_feet`（沿用 P5-B `grid_distance`，不另寫一份）、`range_band`（`reach`／`normal`／`long`／`out_of_range`）、`blocked`、public-safe `blocker_kind`、`requires_dm_adjudication`、modifier facts（`long_range`、`target_within_5ft`）。Hard blocker 判定照實作紀錄技術決策 2。
- **Tactical attack 接線**：Tactical Combat 的 attack request 以 caller 可見 board 投影判定；不合法 → `combat_target_out_of_range`（409）或 `combat_target_blocked`（409），零副作用；合法 → 不建立 DM range adjudication，直接進既有 P4 formal roll／damage／mutation 流程。Player 投影看不到的 hidden wall／未揭露 hidden door（對 Player 是牆）／hidden monster 不得因錯誤訊息或回應欄位洩漏；目標是 hidden monster 時 Player 本來就無法指定。Quick Combat 同一 attack 仍走 DM adjudication，不要求 position。
- **P4 modifier pipeline**：long range → disadvantage source（`attack:long_range`）；Tactical 以實際 `target_within_5ft` 取代 Quick 的「melee＝5 呎內／ranged＝5 呎外」假設，套到既有 `attacks_against_advantage_within_5ft`、`attacks_against_disadvantage_beyond_5ft`、`adjacent_hit_is_critical` 等 condition 語意（例：prone 目標被 5 呎內的 ranged 攻擊時不應有 disadvantage）。Quick 的判斷不變。Cover 不自動加 AC。
- **Targeted spell**：Tactical 的 spell attack 與單一／多目標指定型 save spell（非 AoE）依 spell `range` 驗證每個 target：`Self` 只能自己、`Touch`＝5 呎 reach、`N feet` 為上限；hard blocker 同攻擊；解析不了的 range → `requires_dm_adjudication`，走既有 DM 裁定。AoE 屬 P5-D，不動。
- **Reach query**：提供「entry A 是否在 entry B 某攻擊的 reach 內」的共用函式（P5-E 會用），P5-C 不觸發任何 reaction。
