# A1 — Schema、battle_map_image、Battle Map Definition

## Scope

- **Migration `0035_p5a_combat_mode_tactical`**（parent `0034_m06b_event_actor_stamp`，web track）：`ck_combats_mode_quick` 換成 `ck_combats_mode`：`mode IN ('quick', 'tactical')`；`app/persistence/combat/tables.py` 同步。downgrade 若存在 `mode='tactical'` row 直接 raise，不改寫資料；否則還原舊 constraint。Domain 行為不變（`start_quick_combat` 仍只建 quick；tactical start 是 A2）。
- **Migration `0036_p5a_battle_maps`**（parent `0035`）：
  - `ck_room_assets_kind` 加 `battle_map_image`；`RoomAssetKind` Literal、`RoomAssetService.create` kind 分支（沿用 image 的 `IMAGE_MIME_TYPES` 與 20 MiB 上限）。
  - `battle_maps`：`id`、`room_id`（FK rooms CASCADE）、`name`、`source_kind`（`blank | image`）、`image_asset_id`（FK `room_assets.id` RESTRICT，image 時必填、blank 時必 null）、`width_cells`／`height_cells`（1～200）、`grid_pixel_size`／`grid_offset_x`／`grid_offset_y`（image 時使用、blank 時 null）、`revision`（>0）、`created_at`／`updated_at`。
  - `battle_map_walls`：`id`、`battle_map_id`（CASCADE）、`x1,y1,x2,y2`（grid vertex 整數座標，水平或垂直、長度 ≥1、在 `0..width`／`0..height` 內）、`visibility`（`public | hidden`）。
  - `battle_map_doors`：同 wall 但長度必須 = 1；`default_state`（`open | closed | locked | broken`）、`visibility`。
  - `battle_map_terrain`：`battle_map_id`、`x`、`y`、`terrain_kind`（`difficult | blocked`），PK／unique `(battle_map_id, x, y)`；normal = 無 row。
  - `battle_map_drawings`：`id`、`battle_map_id`、`payload` JSON（純視覺；Server 只驗大小上限與基本形狀，不賦予規則語意）。
- **Room asset 參照與 hard delete**：`RoomAssetRepository.is_referenced` 納入 `battle_maps.image_asset_id`（被地圖引用的 asset 刪除回既有 in-use 409）；`app/persistence/rooms/workspace.py` `hard_delete_room` 在刪 `room_assets` 前先刪 `battle_maps`（cascade 子表），filesystem cleanup 沿用既有可重試流程。
- **Domain／service**（`app/domain/battle_maps/`）：create blank、create image（asset 須同 Room、`kind=battle_map_image`）、get、list、patch（name／尺寸／grid alignment，`expected_revision`；縮小尺寸導致既有 object 出界 → 409）、PUT semantic objects（walls／doors／terrain／drawings 整批原子替換，`expected_revision`，client 可帶既有 object id 保留 identity，新物件由 Server 配 id）、delete。Authority：Room Owner／DM（`RoomAccessContext`，比照 `require_adventure_author` 的 RoomAccessContext 分支）；MEMBER 與跨 Room 一律 404。Revision 衝突 409。
- **Audience projector**：`project_battle_map(definition, audience="dm" | "player")`。DM：完整。Player：hidden wall 省略；hidden door 變成普通 wall segment（無 id、無 state、無 visibility 欄位）；Player 端所有 wall 都不帶 id；public door 保留 id 與 state；terrain／drawings 照送。A1 只做函式與單元測試，接到 Combat board 是 A2。
- **Routes**（`app/api/rooms/battle_maps.py`，prefix `/api/rooms/{room_id}/battle-maps`，比照 `app/api/rooms/adventures.py` 的 error mapping 形狀）：`POST ""`、`GET ""`、`GET /{map_id}`、`PATCH /{map_id}`、`PUT /{map_id}/objects`、`DELETE /{map_id}`。Error code：`battle_map_not_found`（404）、`battle_map_revision_conflict`（409）、`battle_map_invalid`（400）、`battle_map_asset_invalid`（400）。
- **M03 boundary**：`FORBIDDEN_MODULE_RE` 加 `battle_maps?|combat_boards?|spatial|tactical` 段與正／反斷言；`test_m03d_schema_parity.py` `FORBIDDEN_MULTIPLAYER_TABLES` 加五張新表。
- **Tests**：`tests/test_p5a_battle_maps.py`（A.1 全部項目；Room A／B 隔離；Member 404；revision conflict；出界 object 拒絕；Door 四狀態 roundtrip；projector DM／Player 斷言 hidden 物件不出現在 Player JSON 任何位置）、`tests/test_p5a_room_asset_battle_map.py`（`battle_map_image` 上傳、非 png／jpeg／webp 與 >20 MiB 拒絕且無 orphan、被地圖引用時 asset delete 409、跨 Room 引用拒絕、hard delete Room 後 metadata＋檔案消失）、`tests/test_p5a_postgres_migration.py`（A.7：從 `0034` 升級時既有 quick combat row 與 P6 Adventure／Runtime 資料不變、升級後 tactical row 可寫入、有 tactical row 時 downgrade 被拒、無 tactical row 時 downgrade 到 `0034` 成功且新表消失）。已寫死 web head 的既有測試（`test_migration_heads.py` 等）同步更新。
