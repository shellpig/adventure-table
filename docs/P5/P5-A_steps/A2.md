# A2 — Spatial primitives、Combat board runtime、Tactical start／placement gate、secrecy projection

## Scope

- **Spatial primitives**（`app/domain/spatial/`，純函式、不碰 DB）：`GridCell`、`Footprint`、`SIZE_FOOTPRINT`（Tiny／Small／Medium 1×1、Large 2×2、Huge 3×3、Gargantuan 4×4）、`occupied_cells()`、`is_inside_bounds()`、`intersects_blocked_cell()`、`footprint_straddles_barrier()`（footprint 內部 edge 與 wall／非 open door 重合）、`can_occupy()`。P5-B 以後的 distance／path 由後續步驟加，不在本步。
- **Size 解析共用**：把 `app/domain/combat/special_attacks.py` 的 `_parse_size`／`_size` 抽成 combat 共用 helper（Character 走 race `size`、Monster 走 `rules_snapshot["size"]`），Grapple／Shove 與 placement 共用同一份；行為不變。
- **Migration `0037_p5a_combat_board_positions`**（parent `0036`）：
  - `combat_boards`：`combat_id` PK／FK（combats CASCADE）、`source_battle_map_id`（FK battle_maps SET NULL，nullable）、`source_battle_map_revision`、`width_cells`、`height_cells`、`image_asset_id`（nullable，FK room_assets RESTRICT；`is_referenced` 與 `hard_delete_room` 同步納入）、`grid_pixel_size`／`grid_offset_x`／`grid_offset_y`、`baseline` JSON（開戰時凍結的 walls／doors／terrain／drawings snapshot，含 visibility）、`runtime_revision`。
  - `combat_board_doors`：`combat_id`、`door_id`（baseline 內 door 的 id）、`state`（`open | closed | locked | broken`）、`revealed`（bool，hidden door 是否已對 Player 揭露；P5-A 只保存，揭露操作可做 DM route）；PK `(combat_id, door_id)`。
  - `combat_positions`：`combat_entry_id` PK／FK（combat_entries CASCADE）、`combat_id`、`anchor_x`、`anchor_y`、`footprint_w`、`footprint_h`、`revision`。
  - Web track only；`test_m03d_schema_parity.py` 加三張表。
- **Tactical start**：新 input `StartTacticalCombatInput`（`battle_map_id: UUID | None`；為 None 時必填 `blank_width_cells`／`blank_height_cells`；`include_active_party`、`idempotency_key` 同 quick）與新 route `POST .../combat/tactical/start`（DM only）。同一 transaction：建 `mode='tactical'` combat（`status='initiative_pending'`）＋entries＋board（從 map 凍結 baseline 與 doors 初始 state）＋`combat.started` event（payload 含 `mode: "tactical"`）。既有 `POST .../combat/start`、`StartCombatInput`、MCP `combat_start` **完全不變**（仍只建 quick）。
- **Placement**：`PUT .../combat/board/positions/{entry_id}`（body `anchor_x`、`anchor_y`、`idempotency_key`）。Authority：DM 可放任何 entry；Player（Human／AI）只可放自己控制 Character 的 entry。時機：combat `initiative_pending` 時可放／改放；`running` 時只可放**尚未有 position** 的 mid-combat entrant；已放好的 entry 在 `running` 移動屬 P5-B，回 409。驗證：footprint（由 size 導出）in bounds、不含 blocked terrain、不與其他 active entry 的 occupied cells 重疊、不跨 wall／非 open door（含 hidden）。拒絕錯誤不得透露 hidden 物件（hidden token／hidden wall 造成的衝突與其他衝突回同一個 generic code `combat_placement_invalid`）。Retry 同 idempotency key 不產生重複 position 或重複 event。
- **Initiative gate**（只對 `mode='tactical'`）：`resolve_initiative_order`／initiative finalize／reorder，以及對 mid-combat entrant 的 initiative request，若目標 active entry 尚無 position → 409 `combat_placement_incomplete`；Quick combat 完全不受影響。Withdraw／remove entry 刪除其 position。End Combat 保留 board 與 positions 作歷史，不寫回 Map Definition、不寫 P6 world。
- **Runtime door**：`PATCH .../combat/board/doors/{door_id}`（DM only，body `state`、可選 `revealed`、`idempotency_key`）只改 `combat_board_doors`，`runtime_revision+1`，不動 Map Definition。
- **Board read**：`GET .../combat/board`（任何在場 actor）回 actor-projected board：尺寸、grid alignment、`has_image`、walls／doors／terrain／drawings（沿用 A1 `project_battle_map` 規則套到 baseline＋runtime door state；hidden door `revealed=true` 後對 Player 以 door 呈現）、positions。Player 版省略 hidden monster（`monster_instances.visibility='hidden'`）的 position。`GET .../combat/board/image` 串流 board 的 image asset（任何在場 actor；無 image 404），不要求 Player 對 `room_assets` 有讀權。
- **Secrecy（A.5，含既有洩漏修正）**：目前 Player 呼叫 `GET .../combat` 與 `/combat/detail` 時 `entries` 會帶 hidden monster 的 entry（含 `display_name`）——P4 既有洩漏，本步一併修：Player audience 的 `CombatView.entries` 省略 hidden monster entry（`current_turn_entry_id` 指向 hidden entry 時對 Player 回 `null`）。MCP `combat_get_active`／`combat_get_context` 走同一 projection。新事件：`combat.position_placed`（payload 只有 `combat_id`、`entry_id`）、`combat.door_state_changed`（`combat_id`、`door_id`、`state`）；hidden monster 的 placement event 與 hidden 且未 revealed door 的事件用 `visibility='dm_only'`。所有事件以 `event_repository.append(..., expected_actor_binding=actor_binding(actor), transaction_projection=...)` 寫入（M06 寫入者欄位），position／door 寫入與 event 同 transaction；新 kind 不加入 `OWN_ECHO_EVENT_KINDS`（P5-F 決定）。
- **M03 boundary**：新 module 名稱若未被 A1 加的 regex 涵蓋，同 commit 擴充。
