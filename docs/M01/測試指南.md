# M01 — 測試指南

> Phase：**M01 — D&D 5e 2014 Private Content Expansion**  
> 本文件定義 M01-A～M01-J 的自動測試、API integration、real-backend E2E、migration / restart persistence、人工 smoke 與 closeout 證據。  
> Subphase 名稱與順序必須與 `實作規格.md`、`開發設計方針.md` 完全一致。

最後更新：2026-08-30

---

## 1. M01 共通測試原則

M01 建立在已 closeout 的 P0 / P1 上，因此每個 Subphase 都要同時證明兩件事：

```text
新內容 / 新規則真的可用
AND
既有 SRD / Character Builder 沒被破壞
```

每個 Subphase closeout 最低要求：

1. Backend pytest green。
2. Frontend unit/build/typecheck依 repository 當時正式 command green。
3. 若有 DB migration：fresh DB + P1 → head upgrade皆通過。
4. 既有 SRD Character load / Sheet regression green。
5. P1 Create / High-level / Multiclass / Spell / Equipment / Review / Confirm / Level Up / Version History主要 flow green。
6. 新 stable refs / source identity reload後不改變。
7. malformed content必須 fail-fast，不能 silent ignore。
8. UI新增 structural choice時要有 real-backend browser coverage。
9. 重要規則用 focused assertion驗數值／來源／選擇，不只 snapshot大 JSON。
10. 每個 Subphase的 closeout回報要列已知 manual boundary，不可用「TODO」混過去。

# M01-A — Multi-Source Content Pack Foundation

## A.1 Tiny fixture packs

不要只拿正式 PHB當 foundation test。

建立最小 fixture：

```text
pack-a
  race:test-race
  feature:test-a

pack-b
  feature:test-b
  background:test-background
  ref → pack-a:feature:test-a
```

再加入 same-index fixture：

```text
pack-a:race:goblin
pack-b:race:goblin
```

## A.2 Positive registry tests

必測：

- SRD單獨載入。
- SRD + pack-a。
- SRD + pack-a + pack-b。
- `get(full_key)`。
- `list_kind("race")`聚合多來源。
- source+kind query（若有）。
- explicit cross-pack ref。
- legacy SRD URL ref仍解析為原 stable key。
- same index different source同時存在。
- manifest source metadata可讀。

## A.3 Negative registry tests

必須 fail-fast：

- pack id有 `:`。
- StableKey少段／多段／空段。
- key prefix與 entry.source不同。
- manifest id與directory/entry source矛盾（若 contract要求一致）。
- duplicate full key。
- category file不存在。
- category count mismatch。
- manifest total mismatch。
- explicit dangling ref。
- ref expected race卻指 spell。
- legacy URL/index mismatch。
- unknown legacy API route被誤判為 valid ref。

## A.4 Character schema tests

- `phb2014:background:x`可通過 generic stable key lexical validator。
- kind validator仍能拒 `spell`填到 `race_ref`。
- malformed source prefix被拒。
- existing `srd5.1:*` fixture完全不需改 key。

## A.5 Build provenance tests

Candidate包含：

```text
srd5.1 race
phb2014 background
```

預期：

```text
content_sources = deterministic(srd5.1, phb2014)
```

再驗：

- duplicate source dedupe。
- order不受 selection insertion order影響。
- frontend傳假 source list不影響結果。

## A.6 Builder regression

至少跑 existing：

- Lv1 SRD create。
- Fighter 5 / Wizard 5 high-level create。
- multiclass slot calculation。
- Starting Equipment。
- Level Up。

Purpose：抓到 `_stable_key()` / class-level lookup / `resolve()`泛化造成的回歸。

## A.7 UI sanity

若 selector已加 source badge：

- source名稱顯示正確。
- SRD選項仍可搜尋。
- 同名不同 source都看得到。
- keyboard navigation不因 secondary label壞掉。

## A Closeout Evidence

回報：

```text
Loaded pack count
Loaded entry count per pack
Legacy SRD entry count
Fixture cross-pack tests
P0/P1 regression result
```

```json
{"entry_id":"x","item_ref":"...","quantity":1,"equipped":false,"carried":true}
```

新 schema載入後：

```text
attuned == false
```

不能 migration crash。

## I.4 Attune action positive tests

- add item。
- carried item可 attune。
- within capacity成功。
- state persisted。
- unattune成功。
- no Build Version created。

## I.5 Attune action negative tests

- nonexistent inventory entry。
- item不需 attunement但 call attune的 policy明確（拒絕或 no-op，建議拒絕）。
- class restriction不符。
- over capacity。
- item未 carried（若 policy要求 carried）。
- duplicate attune same entry。

拒絕零副作用。

- class restriction ignored。
- race restriction ignored。
- spell/level restriction按 supplied rule ignored。
- capacity = 5。
