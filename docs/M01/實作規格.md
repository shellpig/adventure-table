# M01 — 實作規格

> Phase：**M01 — Multi-Source Character Content Expansion**  
> 類型：**M Phase（Modification / Maintenance Phase）**  
> 本文件定義 **M01-A～M01-J 每個 Subphase 完成後什麼必須為真**。具體資料格式、schema、模組、API、migration 與接線放在 `開發設計方針.md`；自動與人工驗收方式放在 `測試指南.md`。

最後更新：2026-08-30

---

## 1. M01 定位

P0 / P1 已完成 Character Core、SRD 5.1 Content Foundation、Character Builder、Level Up、immutable Build Versions 與 Current State。M01 不重做這些地基；M01 要解決的是：

1. **SRD 5.1 角色內容量不足。**
2. **Content Registry / StableKey / Builder 仍有 `srd5.1` 單一來源假設。**
3. 使用者已提供一批 PHB / SCAG / GoS / VGM / VRGR / TCE 私人規則資料，需要正式轉成 runtime content。
4. Variant / Lineage / Artificer / Magic Item 會帶來幾種現有 P1 尚未正式表示的規則形狀，需要補最小通用能力。

M01 的目標不是「一次做完整 D&D」，而是把已提供的內容做成可靠的 Multi-Source Character Content，並確保既有 Character Builder 真正可用。

M01 完成後：

```text
回到 P2 — Room / Campaign / Session / Seat
```

M01 不改寫 P2～P8 的產品 Roadmap。

M Phase 不得拿來偷跑未來產品系統。例如 M01 遇到 Combat feature 時，可以保存 metadata，但不得因此提前建立 P4 Combat Engine。

- parse Markdown。
- 依 Markdown 標題判規則。
- 從 Markdown 即時生成 Builder choices。

### 3.4 Private project boundary

Repository 為 private，專案為朋友間私人使用。M01 不建立：

- Marketplace。
- Publisher backend。
- 公開 Content Pack distribution。
- 商業 license workflow。

但來源／provenance仍要明確，因為它直接影響資料 identity 與未來維護。

## 4. M01 共通硬原則

### 4.1 StableKey

正式格式：

```text
<pack-id>:<kind>:<index>
```

例如：

```text
srd5.1:race:elf
phb2014:subrace:wood-elf
phb2014:race:variant-human
scag:race-variant:half-elf-wood-descent
vgm:race:goblin
vgm:race:aasimar
vgm:subrace:protector-aasimar
vrgr:lineage:dhampir
tce:class:artificer
tce:item:all-purpose-tool-plus-1
```

同 `kind:index` 不同 pack 可共存。Display Name 永遠不是 foreign key。

### 4.2 `content_sources`

`CharacterBuild.content_sources` 的 canonical semantics：

> **該 Build 實際引用到的 Content Pack 集合。**

由 server compiler 依 candidate Build refs derive；不信任 client 手填。

如果 Builder 需要控制「目前允許選哪些 pack」，使用 Draft / server policy 的 `enabled_content_sources` 或等價概念，與 Build 最終 provenance 分離。

**`CharacterBuild.content_sources` 絕不可被拿來當 Builder allowlist / permission gate。** 它是 compile 後的 provenance summary；允許哪些來源必須在選項產生／validation 前由獨立 policy 決定。

### 4.3 Server authoritative

M01 所有新規則仍走：

```text
Builder Draft
→ server choices / compile / validation
→ Review
→ Confirm
→ immutable CharacterBuild
```

Frontend 不 hardcode D&D legality。

### 4.4 Build vs Current State

延續 P0/P1：

**Build：**永久角色選擇與來源，例如 race / subrace / M01-E 起的 race variant / lineage / class / known infusions。  
**Current State：**目前 HP、resources、prepared、Inventory、attuned、目前 active infusion、目前 Armor Model等 live state。

不得因 M01 新功能把這條邊界打亂。

### 4.5 不做 Universal Rules DSL

M01 可以增加目前資料真正需要的 primitive：

- choice
- grant
- replacement
- level-gated grant
- lineage replacement
- resource capacity metadata
- attunement restriction metadata

但不做：

- arbitrary expression language
- user-authored scripts
- combat trigger DSL
- generic effect interpreter

### 4.6 Automation 等級

優先：

1. identity / source 正確。
2. Builder legality正確。
3. Build / State persistence正確。
4. Character Sheet / Review顯示正確。
5. 已有 Rules / State substrate能安全支援的效果才自動化。
6. 需要未來 Combat / Rest / Roll / day-clock的效果可先 structured + manual。

UI 不得把 manual effect誤表示為已自動套用。

# M01-A — Multi-Source Content Pack Foundation

## 目標

把 P0/P1 的「單一 `srd5.1` registry」泛化成真正 Multi-Source Content Pack foundation，同時保持所有舊 SRD Character / Builder compatibility。

## A1. Generic Content Pack

Registry 可以同時載入多個 pack。每個 pack至少有：

- stable pack id。
- display metadata。
- ruleset identity。
- provenance。
- category declarations。
- entry counts。
- optional usage / license metadata。

SRD-specific extraction / CC BY / P4-A scope guard不能被硬塞成所有 pack的必填欄位。

M01-A 必須把目前 `ContentManifest` 的 SRD-only 限制明確拆開：

- `id`：從 `Literal["srd5.1"]` 改為 generic pack id。
- `license`：generic manifest 可省略；存在時不得鎖死 CC-BY-4.0。
- `extraction`：改為 optional；只在有實際 upstream extraction provenance 的 pack 使用，手動整理的 private pack 不需偽造 repository / 40-hex commit / MIT license。
- `scope_guard`：改為 optional 或 SRD-specific metadata；不得要求所有 pack 排除 monsters / beasts，也不得要求所有 pack `deferred_to=P4-A`。
- `categories[].upstream_file`：改為 optional；手工整理 pack 不需偽造 upstream filename。
- `categories[].count` 與 manifest `total_entries`：仍需可驗證，並維持 count consistency fail-fast。

既有 SRD manifest 必須仍可原樣載入；這是 schema generalization，不是要求先重寫 `data/srd5.1/manifest.json`。

## A2. Generic StableKey

`require_stable_key()`、ContentEntry envelope、Builder DTO、CharacterBuild validators不再限制第一段只能 `srd5.1`。

Schema-level驗 syntax；Registry/service-level驗存在與 kind。

## A3. Legacy SRD compatibility

現有：

```text
srd5.1:<kind>:<index>
```

全部維持不變。

現有 SRD 仍可能透過：

```text
index + /api/2014/... URL
```

表示 reference。M01-A保留 compatibility adapter，不要求一次 rewrite全部 SRD data。

## A4. Explicit new-pack references

新的 non-SRD normalized data直接用 StableKey reference。

不得為了讓舊 parser接受而偽造 `/api/2014/...` URL。

## A5. Cross-pack refs

必須合法支援：

```text
phb2014:subrace:wood-elf
→ srd5.1:race:elf
```

以及其他 pack → SRD / pack → pack references。

## A6. Multi-pack lookup / search

Registry至少能：

- full StableKey lookup。
- list/search by kind across packs。
- optional source filtering。
- source metadata lookup。

同名／同 index不同 source不得互相覆蓋。

Production/dev 啟用哪些 pack 必須是 **explicit enabled pack list**；不得因 `data/` 下多一個資料夾就自動成為正式可用 pack。Registry 必須允許測試注入替代 content root / enabled pack list，使 `testpack`、`pack-a`、`pack-b`、`future` 等 fixture 不污染 production registry。

## A7. Builder source policy

Builder options可以來自多 pack。

Draft / server policy如果需要限制 allowed packs，必須與 Build final `content_sources`分離。

Build final `content_sources`由實際 refs derive、deterministic sort、dedupe。

## A8. Source-aware UI

Reference DTO至少能給 UI：

- stable key。
- display name。
- source id。
- source display label。

UI value用 StableKey，不用 display name / bare index。

## A9. Fail-fast

Server startup仍要阻擋：

- malformed manifest。
- malformed StableKey。
- key/source mismatch。
- duplicate full key。
- category count mismatch。
- dangling reference。
- wrong-kind reference。

## A10. 明確不做

- 不新增 PHB正式資料。
- 不做 Half-Elf replacement。
- 不做 Dhampir lineage。
- 不做 Artificer rounding。
- 不做 Infusion / Attunement。
- 不做 Content Pack marketplace / downloader / dependency manager。

## M01-A Closeout

至少用：

```text
srd5.1 + tiny test pack A + tiny test pack B
```

證明 multi-pack / cross-pack / same-index different-source / invalid-pack behavior，並維持完整 P0/P1 regression green。

# M01-B — PHB Character Origins & Background Expansion

## 目標

補足第一輪真人創角最直接缺少的 PHB 內容：

- PHB 13 個核心 Background。
- PHB 文件中 supplied 的 5 個官方變體 Background。
- PHB 非 SRD subraces。
- Variant Human。

M01-B 完成後立即進行第一輪真人創角 Gate。

## B1. PHB Background completeness

每個 Background至少完整承載：

- skill proficiencies。
- tool proficiencies / choices。
- language grants / choices。
- starting equipment / quantity / nested choice。
- Background Feature。
- optional Personality Traits。
- optional Ideals。
- optional Bonds。
- optional Flaws。
- variant identity / relation（如來源有）。

不能只做到「下拉看得到 Background 名稱」。

## B2. Roleplay tables

Personality / Ideal / Bond / Flaw：

- 可提供建議選項。
- 可手動填。
- 可完全不填。
- 不屬 Structural Validation。
- 不得阻止 Confirm。

## B3. PHB missing subraces

至少導入 supplied source列出的：

- Wood Elf。
- Drow。
- Mountain Dwarf。
- Stout Halfling。
- Forest Gnome。

其母種族沿用既有 SRD identity；subrace只存自己的差異 grants。

必須正確反映：

- ability bonus。
- speed adjustment。
- proficiency。
- racial feature。
- racial spell。
- level gate。

## B4. Variant Human

Variant Human **必須在 B 完成**，而且不得假裝成 subrace，也不得提前使用 M01-E 才引入的 `race-variant` 機制。

正式 Character identity：

```text
race_ref = phb2014:race:variant-human
subrace_ref = None
```

Content data 可以保存：

```text
variant_of = srd5.1:race:human
```

但 `variant_of` **只代表 provenance / 關聯 metadata，不具有任何 mechanical inheritance 語意**。Compiler 不得因 `variant_of` 自動載入普通 Human 的 mechanical grants，也不得先套標準 Human ability package再做替換。

因此 Variant Human 必須是一個 mechanically complete Race package：它自己的 entry / explicit refs 必須足以決定所有實際 grants 與 choices。若要重用共同 trait，可以使用明確的 reusable feature/trait references；不能靠 `variant_of` 偷做繼承。

M01-B **不新增**：

```text
race-variant StableKind
CharacterBuild.race_variant_ref
BuilderDraft.race_variant_selection
```

這三者全部留到 M01-E，因為 SCAG Half-Elf descent 才是真正「保留 base race、針對部分 grant 做 replacement」的規則形狀。

Builder必須支援：

- 兩個不同 Ability，各 +1。
- 一個 Skill proficiency。
- 一個合法 Feat。
- Feat prerequisite走 P1 existing structural validation。
- Numeric Override與 prerequisite互動沿 P1規則。

這裡刻意接受兩種相近名稱使用不同機制：

- **Variant Human**：完整 Race package，整包取代普通 Human racial package。
- **SCAG Half-Elf descent**：M01-E 的 `race-variant`，保留 Half-Elf base package，只替換指定 grant。

不要為了名稱都叫 Variant 而強行統一成同一資料模型。

## B5. Racial spells

Drow / Forest Gnome等 racial spells必須保留 source identity。

不得：

- 混成 class spellbook。
- 混成 daily prepared list。
- 把一次／長休 racial spell錯當 normal spell slot。

## B6. Background Equipment

沿用 P1 `starting_equipment_choices` / equipment compiler。

Create Confirm只初始化 initial Inventory一次；Level Up不得再次從 Background重建 Inventory。

## B7. Builder UX

Origin step至少做到：

- Race / Subrace / Background searchable 或以等價 server-driven flow 正確選擇；Variant Human直接作為 `Race` option出現。
- source label可辨識。
- options由 server回傳。
- Draft reload不遺失。
- 回上一步改 Race/Subrace/Background後 stale choices不污染 Build。
- Review能看到 final grants與source。

M01-B 不顯示獨立 Race Variant selector；該 UI / Draft identity直到 M01-E才存在。

## B8. Mandatory First Real Character-Creation Gate

至少真人完整建立：

1. 純 SRD角色。
2. PHB新增 subrace角色。
3. Variant Human。
4. 有 tool/language choice的 PHB Background。
5. martial角色。
6. caster角色。

每隻走：

```text
Draft
→ Origin
→ Abilities
→ Class Progression
→ Spells（如有）
→ Equipment
→ Review
→ Confirm
→ Character Sheet
→ browser reload
```

M01-A/B引入或揭露的 Blocker / Major UX confusion必須在 B closeout前修完。

## B9. 不做

- SCAG Half-Elf replacement：E。
- Dhampir lineage：F。
- Artificer：G/H。
- 正式 Roll System。
- Background自動生成器。

## M01-B Closeout

成功標準：**真人已能用 PHB 級別的 Origin / Background內容量完成合法創角**，而不只是資料檔已存在。

# M01-C — SCAG / GoS Background Expansion

## 目標

在 B 已驗證 Background pipeline後，完整導入：

- SCAG supplied 13 個 Background。
- GoS supplied 4 個 Background。

並驗證不同 source、roleplay table reuse、variant/branch、航海／派系等 flavor不會逼系統建立不必要 subsystem。

## C1. Packs

正式建立／啟用：

```text
data/scag/
data/gos/
```

Background StableKey保留來源。

## C2. Mechanical completeness

每筆至少逐項資料化：

- skill grants。
- tool grants / choices。
- language grants / choices。
- starting equipment。
- quantities / currency metadata（依現有 State能力）。
- Background Feature。
- mechanical branch / choice。

Pure flavor tables不得誤成 blocking choice。

## C3. Roleplay table inheritance

SCAG部分 Background會指向 PHB Soldier / Guild Artisan / Sage等建議表格。

系統必須能表達：

```text

```

```text
roleplay inheritance != mechanical inheritance
```

## C4. GoS flavor tables

Fisher Tale、Marine hardship等可作 optional roleplay suggestion / custom field。

- 不填可 Confirm。
- 不需建立 Fishing / Ship / Hardship subsystem。

## C5. Background variant identity

若 supplied content有 variant：

- identity可追溯。
- active branch可見。
- inactive branch不進 Build。
- source collision不靠 display name去重。

如果只是 Background所需最小 replacement，可在 C補；不得提前為 E做大型 universal replacement graph。

## C6. Source-aware UI

Background selector：

- 同時搜尋 SRD / PHB / SCAG / GoS。
- 同名／相近名可看來源。
- 不要求先選 source book。
- persisted value永遠是 StableKey。

## C7. Build / Inventory

Background grants正確進 Build；Starting Equipment只初始化一次 Current State。

Roleplay suggestion只進 roleplay profile，不影響 Build mechanical validity。

## C8. 不做

- 不建立 Faction system。
- 不建立 Ship system。
- 不建立 setting lore graph。
- 不把 Background Feature做 Adventure automation。

## M01-C Closeout

至少：

- SCAG Background完整 Create / Confirm / reload。
- GoS Background完整 Create / Confirm / reload。
- roleplay table reuse不污染 mechanical grants。
- same-name/source collision不選錯。

# M01-E — SCAG Half-Elf Variant & Grant Replacement

## 目標

支援 SCAG Half-Elf ancestry variants，並建立第一個真正需要的 **最小通用 Grant Replacement primitive**。

Supplied descents：

- Moon Elf or Sun Elf Descent。
- Wood Elf Descent。
- Aquatic Elf Descent。
- Drow Descent。

## E1. Base Race

Base Half-Elf繼續使用：

```text
srd5.1:race:half-elf
```

Variant有獨立 stable identity，不複製整份 Half-Elf。

## E2. Variant identity

M01-E **首次正式引入**：

```text
race-variant StableKind
CharacterBuild.race_variant_ref
BuilderDraft.race_variant_selection
```

例如：

```text
scag:race-variant:half-elf-moon-sun-descent
scag:race-variant:half-elf-wood-descent
scag:race-variant:half-elf-aquatic-descent
scag:race-variant:half-elf-drow-descent
```

`CharacterBuild.race_variant_ref` 為 backward-safe optional field，kind限定 `race-variant`；舊 P0/P1/M01-B Build缺欄位時以 `None`載入，不 bulk rewrite舊 immutable Build JSON。
