## 1. 設計目標

1. **只改 MCP 回傳端。** 過濾與精簡都在 `AIToolApplicationService.wait_for_event` 呼叫的路徑上生效；`TableEventService.list_after`、Human REST `/events`、`/events/wait`、Resume、`get_pending_events` 行為不變。
2. **身分資料跟著事件寫入，一次蓋章。** 寫入者的 AI grant 與 generation 在 `TableEventRepository.append_in_transaction` 由 `expected_actor_binding` 取得並存進事件列；約 70 個 append call site 不需逐一改參數。
3. **不確定就照送。** 沒有蓋章（真人寫入、系統事件、未帶 binding 的 call site、M06 前的舊事件）一律視為「非自己」，只會多一次喚醒，不會漏資訊。
4. **公開 DTO 不外洩 controller 身分。** 新欄位只存在 `StoredTableEvent`；`TableEvent`（REST／MCP 回傳）不新增 grant id 或 generation。
5. **Standalone 邊界不動。** 改動在 `app.domain.rooms.*`、`app.persistence.rooms.*`、`app.mcp.*` 與 web track migration；`session_events` 本來就不在 Standalone schema。

## 4. M06-B — Own-Write Echo Suppression in wait_for_event

### 4.1 Persistence（`app/persistence/rooms/table_runtime.py` 與 migration）

- `session_events` 新增兩個可為空欄位：`acting_ai_controller_grant_id`（UUID，不加 FK，避免 grant 生命週期影響事件保存）與 `acting_grant_generation`（integer）。不回填既有列。
- `append_in_transaction`：當 `expected_actor_binding` 不為 None 且 `actor_kind == "ai"` 時，寫入 `binding.ai_controller_grant_id` 與 `binding.grant_generation`；其餘情況寫 NULL。`append()` 經由它，不需另改。
- `StoredTableEvent` 新增 `acting_ai_controller_grant_id: UUID | None`、`acting_grant_generation: int | None`，`_event(row)` 帶出。
- `TableEvent`（公開 DTO）**不**新增欄位。

### 4.2 白名單（`app/domain/rooms/table_events.py`）

```python
OWN_ECHO_EVENT_KINDS = frozenset({
    "stage.updated",
    "exploration.narration", "exploration.dialogue", "exploration.action",
    "exploration.ooc", "exploration.whisper_dm",
    "roll.quick",
    "character.state.updated",
    "world.entry.created", "world.entry.updated", "world.entry.archived",
    "world.override.created", "world.override.updated", "world.override.cleared",
    "world.action.resolved", "world.context_changed",
})
```

- `roll.requested` 只在 payload 沒有 `combat_id` 時視為 echo（非戰鬥正式檢定）；戰鬥中的 `roll.requested` 照送。
- 不列入：`combat.*`、`roll.resolved`、`pending_action.*`、`controller.changed`、`session.*`。
- 加入新種類的前提：寫入該事件的 MCP tool 回傳已包含事件的全部資訊，且有對應測試（見測試指南 B.7）。

### 4.3 判斷函式

```python
def _is_own_echo(actor: TableActorContext, stored: StoredTableEvent) -> bool:
    if actor.actor_kind is not TableActorKind.AI:
        return False
    if stored.acting_ai_controller_grant_id is None:
        return False
    if (stored.acting_ai_controller_grant_id, stored.acting_grant_generation) != (
        actor.ai_controller_grant_id, actor.grant_generation
    ):
        return False
    if stored.kind == "roll.requested":
        return "combat_id" not in stored.payload
    return stored.kind in OWN_ECHO_EVENT_KINDS
```

判斷在可見性過濾之後、`_present` 之前套用；需要 `StoredTableEvent`，因此實作為 `TableEventService` 內部方法，由 `list_after` 的新參數驅動。

### 4.4 `list_after` / `wait_after`

- `list_after(..., suppress_own: bool = False)`：掃描既有範圍、做可見性過濾後，`suppress_own` 為真時再移除 own echo。回傳的 `cursor` 以**掃描到的最後 seq** 計，不因移除而倒退；`has_more` 語意不變。
- `wait_after(..., suppress_own: bool = False, max_timeout=...)`：以 deadline（`loop.time() + bounded_timeout`）取代單次等待。每輪：
  1. `page = list_after(after_seq=cursor, suppress_own=...)`；
  2. `page.events` 非空 → 回傳；
  3. `page.cursor > cursor`（只有 own echo）→ `cursor = page.cursor`，不回傳，繼續；
  4. 否則在剩餘時間內 `notifier.wait`；逾時回傳空 `events` 與目前 `cursor`。
- 無 notifier 時沿用 sleep 至 deadline 後再掃一次。
- Human route 不傳 `suppress_own`，行為不變。

### 4.5 MCP 輸入與接線（`app/domain/rooms/ai_tools.py`）

- `WaitEventsInput` 新增 `include_own: bool = False`。
- `wait_for_event` 呼叫 `wait_after(..., suppress_own=not input.include_own, max_timeout=WAIT_EVENT_MAX_TIMEOUT_SECONDS)`。
- `get_pending_events` 不變（`suppress_own=False`）。

### 4.6 AI 文字（`app/mcp/tools.py`、`app/mcp/guide.py`）

- `wait_for_event` description（en／zh-TW）補一句：預設略過你自己寫入的純 echo，cursor 仍前進；需要時用 `include_own=true` 或 `get_pending_events`。
- guide「進場與事件迴圈」段補：重連或新對話先用 `get_session_context`／`get_pending_events` 補帳。
- briefing 不改（DM combat briefing 已 2983／3000 字）。

## 5. M06-C — Compact Roll Result Projection for MCP wait

### 5.1 `compact_roll_resolved()`（`app/domain/rooms/ai_event_projection.py`）

輸入：已經過可見性與 `project_combat_event_payload` 的 payload、對應 roll request 的 `(dc, auto_fail)`（可能為 None）、`is_current_dm`。輸出：

```python
{
    "roll_request_id": ..., "total": ..., "formula": ..., "visibility": ...,
    "natural": kept_dice[0] if formula in {"1d20...", "2d20kh1...", "2d20kl1..."} and len(kept_dice) == 1 else None,
    # 僅 DM：
    "dc": dc, "outcome": "failure" if auto_fail else ("success" if total >= dc else "failure") if dc is not None else None,
}
```

- `formula` 前綴判斷依 `app/domain/rooms/rolls.py` 現行格式（`1d20`、`2d20kh1`、`2d20kl1`，後接修正值）。
- 投影前的 payload 若缺 `kept_dice`（例如敵方投影已隱藏），`natural` 為 None，不從其他欄位推測。

### 5.2 接線（`AIToolApplicationService.wait_for_event`）

- 取得 `TableEventPage` 後，對 `kind == "roll.resolved"` 的事件批次查詢 roll request 的 `dc`、`auto_fail`（沿用 `RollService`／roll repository 既有讀取；一頁一次查詢，不逐筆），再以 `compact_roll_resolved` 取代 payload。
- 其他事件 payload 不變；`get_pending_events` 不經此投影。
