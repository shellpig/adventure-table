> Phase：**M04 — AI Join Kit & Web AI Connector Compatibility**

最後更新：2026-09-11

## 1. 測試總則

- **每條 Subphase 驗收契約都要有可定位的測試證據。** 每項 `X.n` 對應至少一條 pytest／Vitest／Playwright test 或人工程序，於 closeout 文件列出檔名 + test 名稱。
- **同 turn 內把型別／編譯／該 Subphase test 修綠。**
- **P3-E 測試是回歸底線。** `tests/test_p3e_*.py` 全部在 M04 每個 Subphase 關門時必須通過；M04 只能加斷言、改 subset 比對，不得刪 P3 斷言或改其語意。
- **指引不含秘密是自動測試，不是人工檢查。** A.1／A.2 的測試用 fixture token 與 fixture DC 實際打 `/mcp/guide` 與 `briefing`，斷言回應不含那些字串。
- **雙語同步驗收。** 新 UI 與 `GET /mcp/guide` 於 `zh-TW`／`en` 各跑一次。
- **真實 AI 人工 gate 不可用 mock 代替。** A.8 與 B.4 必須用真的外部 AI session；證據要含 client／平台名稱、版本、日期與該 AI 實際呼叫的 tool 序列（從 server event stream 或 log 取）。

### 1.1 M04 的 E2E 範圍對照

| Subphase | diff 性質 | Subphase 關門要跑的 E2E |
|---|---|---|
| **M04-A** | backend 加 GET route 與文字；`apps/web` 兩個面板加 kit 區塊與新 copy | `p3e-mcp-browser-integration.spec.ts`（既有 AI DM grant 面板路徑）擴充 kit 斷言，或新增 `m04a-ai-join-kit.spec.ts`；`m02h-bilingual-site-smoke.spec.ts` 若已納入 Lobby 路由則一併跑 |
| **M04-B** | 主要為 backend；kit 模板若因形態 A 加一行則碰 `apps/web` | 形態 A 或模板變更時跑 `m04a-ai-join-kit.spec.ts`；純 backend 時無 E2E，以 protocol pytest 與 B.4 人工 gate 為證據 |

合併回 `main` 前比照 AGENTS.md「Phase 關門」跑全套 Playwright（`npm run test:e2e:docker`）。

## 2. 共通測試資料與觀察值

### 2.1 Fixture

- 沿用 `test_p3e_*.py` 的 `_RecordingController`／`AIControllerAuthView` 建 DM、Player、pre-session DM 三種 auth。
- 秘密 fixture：`SECRET_TOKEN = "at_ai_fixture_secret_9f3e..."`、`SECRET_DC = 27`（在一個 `dm_only` request 上）。A.1／A.4 斷言指引與 briefing 不含這兩個值。

### 2.2 觀察值

- `GET /mcp/guide` 的 `Content-Type` 必須是 `text/plain; charset=utf-8`。
- `tools/list` 的 description 長度：每個工具 ≥ 80 字元（en 段），作為「加厚」的機械下限；上限不設。
- `briefing` 長度 ≤ 1,200 字元。

# M04-A — AI Join Kit & Server-hosted Guide

## A.1 `GET /mcp/guide` endpoint

`tests/test_m04a_mcp_guide.py`

- `test_guide_returns_plain_text_without_auth`：無 `Authorization` header，200，`Content-Type` 正確，body 非空。
- `test_guide_supports_both_locales`：`?locale=zh-TW` 與 `?locale=en` 都 200；兩者 body 不同；zh-TW 版含至少一個中文字元。
- `test_guide_rejects_unknown_locale`：`?locale=fr` 回 400 且 stable code `mcp_guide_locale_unsupported`，`messages` 含 en 與 zh-TW。
- `test_guide_contains_contract_sections`：body 含 `MCP-Protocol-Version: 2026-07-28`、`Mcp-Method`、`Mcp-Name`、`io.modelcontextprotocol/protocolVersion`、`get_session_context`、`wait_for_event`、`ai_token_unauthorized`。
- `test_guide_contains_no_secret`：以 2.1 的 fixture 建立含 secret 的 Session 後再打 guide，body 不含 `SECRET_TOKEN`、`SECRET_DC`、任何 Room／Seat UUID。
- `test_guide_does_not_touch_db`：以 `Session` spy 或 engine event 斷言 guide route 零 DB query。

## A.2 指引與 tool catalog 同源（漂移 gate）

`tests/test_m04a_guide_tool_parity.py`

- `test_guide_lists_every_tool_definition`：對 `_TOOL_DEFINITIONS` 每個 name，兩個 locale 的 guide body 都含它。
- `test_guide_has_no_unknown_tool_names`：以 regex 抽出 guide 內所有 `[a-z_]+` 且出現在「工具表」段的識別字，每個都必須在 `_TOOL_DEFINITIONS`。
- `test_guide_module_has_no_hardcoded_tool_names`：static 掃描 `app/mcp/guide.py` 原始碼，不得出現任何 `_TOOL_DEFINITIONS` 的 name 字面值（工具名只能透過迭代取得）。
- `test_guide_required_params_match_schema`：對每個工具，guide 列出的必要參數集合 == `input_model.model_json_schema()["required"]`。

## A.3 tool description 加厚

`tests/test_m04a_tool_descriptions.py`

- `test_every_description_has_en_and_zh`：description 含 ` / ` 分隔且兩段非空。
- `test_description_minimum_length`：每個 en 段 ≥ 80 字元。
- `test_role_scoped_catalog_unchanged`：DM／Player／pre-session 三種 `tool_catalog(auth)` 回的 name 集合與 P3-E 關門時相同（把 P3-E 的集合寫成常數斷言，防止加厚時誤改 scope）。

## A.4 `get_session_context.briefing`

`tests/test_m04a_briefing.py`

- `test_pre_session_dm_briefing_mentions_start`：pre-session DM auth 的 context 有 `briefing`，含 `start_session` 與 `/mcp/guide`。
- `test_active_dm_briefing`：含 DM 守則關鍵字（`idempotency_key`、`dm_only` 或 `secret`）；不含 Player-only 工具名（`quick_roll`、`whisper_dm`）。
- `test_active_player_briefing`：含 Player 守則；不含 `post_narration`、`set_stage_text`、`request_check`。
- `test_briefing_keeps_temporary_instruction_separate`：設定 `temporary_instruction` 後，`briefing` 不含該字串，`temporary_instruction` 欄位原樣存在。
- `test_briefing_length_cap`：≤ 1,200 字元。
- `test_briefing_contains_no_secret`：同 A.1 的 secret fixture。
- 既有 `test_p3e_mcp_tools.py`／`test_p3e_pre_session_ai_dm.py`／`test_p3e_temporary_instruction_context.py` 若有精確 dict 比對，改 subset 並在 PR 註明；斷言數不得減少。

## A.5 `server/discover.instructions`

`tests/test_m04a_discover_instructions.py`

- `test_discover_points_to_guide`：`server/discover` 回應 `instructions` 含 `/mcp/guide` 與 `get_session_context`。
- `test_discover_still_cacheable`：`ttlMs`／`cacheScope` 仍存在（P3-E 契約不變）。

## A.6 Standalone 不掛 guide

擴充 `tests/test_p3e_standalone_mcp.py`

- `test_standalone_has_no_mcp_guide_route`：standalone app 對 `GET /mcp/guide` 回 404。

## A.7 前端 kit builder

`apps/web/src/features/rooms/aiJoinKit.test.ts`

- `builds kit with url token role and guide pointer`：含 `{origin}/mcp`、token、role 文字、`/mcp/guide?locale=`。
- `adds loopback warning only for localhost origins`：`http://localhost:5173`、`http://127.0.0.1:8000` 有提醒；`https://at.example.ts.net` 沒有。
- `renders both locales with parity keys`：兩 locale 的 `kitCopy` key 集合相同；兩份輸出都含 token。
- `filename contains role and date but never token`。
- `hardcodedUiCopy.test.ts` 掃描範圍涵蓋 `aiJoinKit.ts`。

## A.8 面板接線

擴充 `LobbyAIDMGrantPanel.test.ts` 與 `PlayerAIControlPanel.test.ts`

- issued 後 `[data-ai-join-kit]` 出現，textarea 值含 token 與 `/mcp`。
- 「複製 kit」寫入 clipboard 的內容 == textarea 值。
- 「下載」呼叫 `downloadAiJoinKit`（spy）且 filename 符合 A.7。
- 既有 token-once 測試不動。

## A.9 E2E

`apps/web/e2e/m04a-ai-join-kit.spec.ts`（或擴充 `p3e-mcp-browser-integration.spec.ts`）

- Owner 在 Lobby 為 DM Seat 產生 AI credential → kit 區塊可見 → 讀 textarea 內容 → 以該內容的 URL 與 token 用 Playwright `request` 打 `GET /mcp/guide` 得 200、打 `POST /mcp` `get_session_context` 得 `mode: pre_session`。
- 兩 locale 各跑一次（切換 `LocaleSwitcher` 後 kit 文字語言跟著變）。
- Player 端：Session 中 `Let AI Control` 後 kit 區塊可見，role 顯示 Player。

## A.10 真實 AI 人工 gate（實作規格 A.8）

兩條路徑各至少一次，證據寫入 `M04-A_CLOSEOUT.md`：

| 路徑 | 程序 | 必須觀察到 |
|---|---|---|
| **MCP client** | 新開一個 Claude Code session（或其他已驗證支援 `2026-07-28` + static header 的 client），工作目錄**不在本 repo**，只給它 kit 檔案，提示語僅「依這份檔案進桌當 DM」 | AI 自行完成 `claude mcp add`（或等價）→ `get_session_context` → `start_session` → `post_narration` → `wait_for_event`；Human 在 Session 頁回一句 → AI 收到並再回一段 |
| **純 HTTP** | 新開一個有 code execution 但**沒有** MCP client 的 AI session（例如 claude.ai 開 code execution，或 Claude Code 明確不設定 MCP），只給 kit | AI 自行 `GET /mcp/guide` → 依範例寫 client → 同上迴圈 |

記錄：client／平台、版本、日期、AI 從拿到 kit 到第一次成功 `get_session_context` 之間的 tool call 次數（作為指引好不好懂的量化觀察）、以及 AI 有沒有問使用者任何指引已寫的事（有就是指引缺口，回填後再跑一次）。

## A.11 雙語與回歸

- `npm test -- --run` 與 `npm run build` 綠。
- `cd apps/server` 後 `pytest tests/test_m04a_*.py tests/test_p3e_*.py` 綠。
- Subphase 關門：全套 backend pytest、全套前端單元測試與 build、`docker compose config`，加 1.1 對應 E2E。

# M04-B — Web AI Connector Compatibility

## B.0 Preflight 證據

不是自動測試。`M04-B_CLOSEOUT.md`「Preflight」段必須有下表，每個平台一列：

| 欄位 | 內容 |
|---|---|
| 平台與可辨識版本 | claude.ai / ChatGPT；UI 上可見的版本或日期 |
| 入口 | HTTPS host 形態（Tailscale 等），不含憑證 |
| 探測請求 | 有無 `GET /mcp`、`/.well-known/*`；method 與 path |
| 第一個 POST | `MCP-Protocol-Version` 值、JSON-RPC method、是否 `Mcp-Session-Id`、`Accept` 是否要求 SSE |
| 認證選項 | connector 設定頁提供的每一種；能否 static header |
| 結論 | 對照開發設計方針 5.2 決策表的哪一列；in scope / out of scope 與原因 |

Preflight 期間的 request logger 不得記 `Authorization` 值；closeout 附 logger 設定方式的描述。

## B.1 認證適配

依 preflight 選定形態後，對應測試：

**形態 A（token 進 path）** — `tests/test_m04b_path_token.py`

- `test_path_token_reaches_same_handler`：同一 token 走 `POST /mcp`（Bearer）與 `POST /mcp/t/{token}`，對 `get_session_context` 回同一份 `structuredContent`。
- `test_path_token_malformed_rejected`：`/mcp/t/not-a-token` 回 400 `mcp_path_token_malformed`，零 DB 寫入。
- `test_path_token_revoked_401`：revoke 後 path 形態同樣 401 `ai_token_unauthorized`。
- `test_path_token_epoch_check_enforced`：Seat epoch 前進後，舊 token 走 path 形態被拒；證明沒有繞過 P3-D。
- `test_access_log_redacts_path_token`：捕捉 log handler 輸出，不含 token 明文，含 `[redacted]`。
- `test_path_guide_alias`：`GET /mcp/t/{token}/guide` 與 `GET /mcp/guide` body 相同，且不驗 token（guide 本來就無認證）。

**形態 B（最小 OAuth）** — 設計拍板後補測試清單；至少涵蓋：access token 對應到既有 grant、revoke 同步失效、epoch 檢查仍生效、DB 只留 hash。

## B.2 Protocol 相容層（僅在必要時）

`tests/test_m04b_legacy_protocol.py`

- `test_modern_path_unchanged`：`test_p3e_mcp_protocol.py` 全部原樣通過（在 CI 同 job 內）。
- `test_legacy_initialize_static`：legacy 版本 `initialize` 回 capabilities 與 serverInfo；連續兩次回應相同；不寫 DB。
- `test_legacy_session_id_is_opaque_and_stateless`：帶任意 `Mcp-Session-Id` 或不帶，`tools/call` 結果相同；server 重啟後同 id 仍可用（因為根本沒存）。
- `test_legacy_and_modern_share_catalog`：同 auth 下兩版本 `tools/list` 的 name 集合與 description 相同。
- `test_legacy_and_modern_share_auth`：revoke 後兩版本都 401。
- `test_legacy_wait_does_not_hold_db`：沿用 P3-A waiter starvation 測試替身，對 legacy 路徑再跑一次。

## B.3 對外入口文件

- README 新段落存在，`docs/M04/M04-B_CLOSEOUT.md` 記錄實際使用的入口形態。

## B.4 真實網頁版 AI 人工 gate

對每個 in-scope 平台：

1. 使用者在 Lobby 產生 kit，貼給該平台的網頁版 AI，只說「依這份檔案進桌當 DM」。
2. AI 以 connector 連上（過程截圖或 server log）。
3. 完成 `get_session_context` → `start_session` → `post_narration` → `wait_for_event` → Human 回應 → AI 再回應。
4. Owner 在 UI revoke；AI 下一次呼叫收到 401 並停止。

證據：平台、日期、認證形態、protocol version、tool call 序列、revoke 後的 401。Player 路徑至少一個平台再跑一次（`Let AI Control` → AI 以 Player 進桌 → `post_dialogue` → Human DM `request_check` → AI `roll_pending`）。

## B.5 回歸

- `pytest tests/test_m04b_*.py tests/test_p3e_*.py tests/test_p3d_*.py` 綠。
- 若碰 `apps/web`：`npm test -- --run`、`npm run build`、`m04a-ai-join-kit.spec.ts`。
- Subphase 關門依 AGENTS.md 分層 gate；合併回 `main` 前全套 E2E。
