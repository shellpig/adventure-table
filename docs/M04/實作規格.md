# M04 — 實作規格

> Phase：**M04 — AI Join Kit & Web AI Connector Compatibility**
> 類型：**M Phase（Modification / Maintenance Phase）**
> 插入時點：**P3 關門之後。** M04-A 先於 P4 開工；M04-B 依 preflight 結果決定是否與 P4 並行或延後，不阻塞 P4。
> 本文件定義 **M04-A～M04-B 每個 Subphase 完成後什麼必須為真**。具體 module、endpoint、文字內容格式與接線放在 `開發設計方針.md`；自動與人工驗收方式放在 `測試指南.md`。

最後更新：2026-09-11

---

## 1. M04 定位

P3 已交付 `POST /mcp` 這條真實可用的 AI 入口：AI 以 P3-D 的 scoped AI Join Token 進場，tool catalog 依 Player／DM／pre-session DM 產生，Human UI 與 MCP 共用同一組 application service。P3-F 也用真實 external client（Claude Code 2.1.260 經 HTTPS）跑完整條 DM journey。

但 2026-09-11 P3 關門當天的第一次真實使用暴露了兩個缺口：

1. **AI 拿到 token 之後不知道該怎麼開始。** 目前 token 只在 Lobby 顯示一次，沒有任何隨附說明。要讓 AI 進桌，使用者得自己解釋 `/mcp` 的 header 契約、哪個工具先呼叫、cursor 怎麼推進、DM 該守什麼。這些知識今天全在 P3 文件與 `app/mcp/` 原始碼裡，AI 看不到。實際情況是：client 連不上時，使用者的 AI session 花了十幾次 tool call 讀 repo 才拼出一個 40 行的 HTTP client；能讀 repo 的 AI 才做得到，一般使用者的 AI 做不到。
2. **只有裝了「會講 MCP `2026-07-28` 且能帶 static Bearer header」的 client 才連得上。** Claude Code CLI 可以；當天 Claude Desktop 內建的 MCP client 送舊版 protocol version，被 server 以 400 擋下。使用者的最終目標是讓朋友用 claude.ai／ChatGPT **網頁版** 直接當 DM 或 Player，那條路目前完全不通：網頁版 connector 不能填自訂 header、需要公開 HTTPS 入口、而且 client 送的 protocol version 未知。

M04 的目標是把「發一個 token 給 AI」變成「發一份 **AI Join Kit** 給 AI」，並讓這份 kit 對 **有 MCP client 的 AI** 與 **只有 HTTP 能力的 AI** 都通用；再以實測為前提，處理網頁版 connector 的相容問題。

M04 不做的事：

- 不改 P3-D 的授權模型（Seat `controller_epoch` SSOT、grant generation snapshot、pre-session TTL、Take Back 規則）。
- 不讓網站接 LLM API；kit 與指引只是文字，智能仍來自外部 AI Session。
- 不提前做 P6 的 Adventure／Campaign context。指引告訴 AI「怎麼用桌」，不提供「這一團的劇本」。
- 不做 `prompts/*`、`resources/*` MCP method；沒有已知 client 依賴它們之前不加 surface。

M04 不改寫 P Roadmap：

```text
P3 closeout
→ M04-A — AI Join Kit & Server-hosted Guide
→ P4 開工前置（可與 M04-B 並行）
→ M04-B — Web AI Connector Compatibility（以 B.0 preflight 結果定範圍）
```

## 2. M04 產品行為

### 2.1 AI Join Kit 是唯一的 AI 交付物

使用者在 Lobby（AI DM）或 Session 頁（AI Player handoff）取得 AI credential 時，畫面上拿到的不再只是 token，而是一份可複製、可下載的純文字 **AI Join Kit**。kit 只含三樣東西：

1. **URL**：這個部署的 `/mcp` 入口。
2. **Token**：P3-D 既有的一次性 AI Join Token，語意與生命週期完全不變。
3. **指引在哪**：一句話說明「有 MCP client 怎麼接、沒有 MCP client 去哪拿 HTTP 契約、連上後第一步呼叫什麼」。

kit 本身不塞完整操作說明。指引住 server，理由見 3.1。

### 2.2 Role 由 token 決定，kit 不分版本

DM 與 Player 用同一份 kit 模板。token 已綁死 Seat／Role，AI 呼叫 `get_session_context` 後 server 回的 briefing 自然是該 role 的內容。kit 只把 role 印出來給人看，不讓 AI 或人在 kit 裡「選」角色。

### 2.3 指引對 MCP AI 與非 MCP AI 都可達

同一份指引內容透過三個通道交付，AI 用哪條路進來都拿得到：

| 通道 | 誰用 | 內容 |
|---|---|---|
| `GET /mcp/guide` | 沒有 MCP client、只能發 HTTP 的 AI；人也可讀 | 完整純文字：header 契約、JSON-RPC 範例、工具表、進場流程、DM／Player 守則 |
| `tools/list` 的 tool description | 有 MCP client 的 AI | 每個工具的用途、何時用、參數要點；比 P3 的一句話說明厚 |
| `get_session_context` 回傳的 `briefing` | 兩者；進場必經 | 依 caller role 的守則與本場注意事項；既有 `temporary_instruction` 仍獨立保留 |

`server/discover` 的 `instructions` 指向 `GET /mcp/guide`，讓走 discover 的 client 也能找到完整指引。

### 2.4 網頁版 AI connector 是 M04-B 的目標，範圍由 preflight 決定

M04-B 的產品目標是：使用者把 kit 交給 claude.ai 或 ChatGPT 網頁版的 AI，AI 能以 connector 方式進桌。要達成它至少要跨過三件事——公開 HTTPS 入口、connector 能接受的認證方式、client 實際送出的 protocol version——其中後兩項在文件撰寫時**沒有可信的實測資料**。因此 M04-B 的第一個驗收項是 preflight（B.0），其結果決定 B.1 之後的實作範圍；本文件只鎖定不論結果都必須成立的約束（見 M04-B 段）。

### 2.5 Standalone 不受影響

單機版不掛 `/mcp`，也不掛 `/mcp/guide`；Lobby／Session 頁本來就不存在於 standalone。M04 不得讓 `app.standalone` 或 `app.content.*`／`app.domain.character*` 反向依賴 `app.mcp`。

## 3. M04 共通硬原則

### 3.1 指引與 tool 契約同源

`GET /mcp/guide` 的工具表與 `tools/list` 的 catalog 必須由同一份定義產生。指引不得手抄工具名稱或參數；一旦工具增減，指引自動跟上，且有自動測試擋住漂移。

### 3.2 kit 與指引不含任何秘密

除了 token 本身，kit 與指引不得含 Room password、Owner Key、DM Key、其他 Seat 的 token、secret DC、DM Notes 或任何 Server 會對該 role 過濾的內容。`GET /mcp/guide` 不需要認證，因此它的內容必須是「任何人都可以知道」的：只描述契約與流程，不含部署細節以外的任何資料。

### 3.3 Token 語意不變

kit 不改變 P3-D 的任何 token 行為：仍只在建立／rotate 時顯示一次、DB 只留 hash、TTL／epoch／revoke 規則不變。kit 只是把既有的一次性顯示畫面多包一層文字。

### 3.4 指引是使用者可見內容，雙語同步交付

`GET /mcp/guide`、tool description、`briefing`、kit 模板與 Lobby／Session 頁新增的 UI copy 都是 user-visible system content，依 AGENTS.md 工程實作守則第 7 條在同一 Subphase 交付 `zh-TW`／`en`。

### 3.5 指引告訴 AI 怎麼用桌，不替 AI 決定怎麼跑團

指引可以給守則（敘事長度、秘密不進 Stage、狀態一律用工具寫回、401 就停），不得給劇本、世界觀或 NPC 設定。那些是 P6 的範圍；在 P6 之前由使用者另外提供給 AI。

### 3.6 不改 P3 授權模型

M04-B 不論選哪種認證適配，每個 request 仍必須經過 P3-D 的 grant／Seat current binding／epoch 驗證；不得新增任何繞過它的入口。M04-B 若引入第二種 protocol version 的相容層，該相容層只做 wire 轉換，不得在 process 內保存 gameplay scope。

## 4. M04 Subphase 順序

```text
M04-A — AI Join Kit & Server-hosted Guide
→ M04-B — Web AI Connector Compatibility
```

每個 Subphase 必須能獨立實作、驗證並 commit；完成時應處於可執行、可測試、沒有已知編譯／型別／該 Subphase 測試錯誤的狀態。

M04-A 完成後，任何有 HTTP 能力或 MCP client 的 AI 只憑 kit 就能進桌，這是可獨立驗證的產品增量，不依賴 M04-B。M04-B 的 B.0 preflight 可以在 M04-A 之前或同時執行，因為它只是量測，不改 code。

# M04-A — AI Join Kit & Server-hosted Guide

## 目標

把「發 token」升級成「發 kit」，並讓指引住在 server，透過 `GET /mcp/guide`、tool description 與 `get_session_context.briefing` 三個通道交付。完成後，一個從未見過本專案的 AI 只憑 kit 就能完成 context → Start／續場 → 敘事 → 等待事件的完整迴圈。

## 完成後必須為真

### A.1 `GET /mcp/guide` 存在且無需認證

- Web channel 提供 `GET /mcp/guide`，回 `text/plain; charset=utf-8`，HTTP 200。
- 不需要 Bearer；沒有任何 Room／Seat 資訊可洩漏。
- 內容以純文字呈現，AI 直接 fetch 就能讀；不是 HTML、不是 SPA shell。
- 支援 `zh-TW` 與 `en`；選取方式在開發設計方針定義。
- Standalone channel 不掛此 route。

### A.2 指引內容涵蓋「從零到迴圈」

指引至少包含：

1. `POST /mcp` 的 header 契約（`Authorization`、`MCP-Protocol-Version`、`Mcp-Method`、`Mcp-Name`）、body `_meta` 要求、不需 `initialize`、不得帶 `Mcp-Session-Id`。
2. 一個完整的 JSON-RPC `tools/call` 範例與成功／業務錯誤／協定錯誤三種回應長什麼樣。
3. 工具表：名稱、用途、必要參數、適用 role（由 3.1 的同一份定義產生）。
4. 進場流程：`get_session_context` → `pre_session` 就 `start_session`、`active_session` 就續場 → cursor 取法 → `wait_for_event` 迴圈 → 自己送出的 event seq 如何推進 cursor。
5. DM 守則與 Player 守則各一節。
6. 401 `ai_token_unauthorized` 的處置：停止並告知使用者，不重試。
7. 一段可直接使用的最小 HTTP client 範例，使用該語言的標準函式庫、不依賴第三方套件；語言選擇在開發設計方針定義。

指引不得含 3.2 列出的任何秘密，也不得含 3.5 禁止的劇本內容。

### A.3 tool description 加厚

`tools/list` 每個工具的 description 從 P3 的一句話擴充為：用途、何時該用、關鍵參數的意義與合法值。DM-only 與 Player-only 工具仍依 scope 過濾，description 不洩漏對方 scope 的工具存在。

### A.4 `get_session_context` 回傳 `briefing`

- `pre_session` 與 `active_session` 兩種 mode 都回傳 `briefing`。
- `briefing` 依 caller role 產生：DM 拿 DM 守則與本場注意事項，Player 拿 Player 守則。
- 既有 `temporary_instruction` 欄位保持獨立，不併入 `briefing`；handoff 指令的語意與 P3-D 相同。
- `briefing` 含「指引全文在 `GET /mcp/guide`」的指向，但不重抄整份指引。

### A.5 `server/discover.instructions` 指向指引

`server/discover` 回傳的 `instructions` 明確告訴 client 完整指引在 `GET /mcp/guide`，並提示第一步呼叫 `get_session_context`。

### A.6 Lobby 與 Session 頁提供 kit

- Lobby 的 AI DM credential 面板與 Session 頁的 Player `Let AI Control` 面板，在 token 一次性顯示的同一個畫面同時提供 kit：可見的純文字區塊、「複製 kit」、「下載 .txt」。
- kit 內容依開發設計方針的模板產生，含 URL、token、role、指引指向。
- URL 取自使用者目前瀏覽器所在的 origin；若 origin 是 loopback（`localhost`／`127.0.0.1`），kit 內附一行提醒「遠端 AI 需要改成對外入口」。
- 既有「只顯示一次」與「複製 token」行為不變；kit 是加法。
- 下載的檔案是純文字，副檔名 `.txt`，檔名含 role 與日期，不含 token。

### A.7 雙語

A.1～A.6 所有 user-visible 文字同時交付 `zh-TW`／`en`；tool description 維持 P3 既有的 `en / zh-TW` 併列格式。

### A.8 真實 AI 只憑 kit 能進桌

以一個**沒有讀過本 repo、沒有額外口頭說明**的 AI session，只給它 kit 檔案，它必須能完成：讀指引 → `get_session_context` → Start 或續場 → 至少一次 `post_narration`（DM）或 `post_dialogue`（Player）→ `wait_for_event` 收到 Human 回應。MCP client 路徑與純 HTTP 路徑各至少一次。證據要求見測試指南。

## 本 Subphase 不要求

- 不做網頁版 connector 相容（M04-B）。
- 不做 `prompts/*`、`resources/*`。
- 不做 kit 的伺服器端保存或重新下載；token 仍只出現一次，kit 跟著只出現一次。
- 不做「AI 進場後自動讀劇本」；P6 才有 Adventure context。

# M04-B — Web AI Connector Compatibility

## 目標

讓 claude.ai 與 ChatGPT **網頁版**的 AI 能以其原生 custom connector 機制連進 `/mcp` 當 DM 或 Player。因為兩個平台 connector 的認證選項與 protocol version 在撰寫時沒有可信的實測資料，本 Subphase 以 preflight 開頭，用實測結果鎖定範圍。

## 完成後必須為真

### B.0 Preflight 先於任何 code 改動

- 對 claude.ai 與 ChatGPT 各做一次 connector 連線嘗試，指向一個對外 HTTPS 的 `/mcp`（Tailscale 或等價入口，沿用 P3-F E1 的形態）。
- 記錄每個平台 client 實際送出的：HTTP method、`MCP-Protocol-Version` header 值（或缺席）、第一個 JSON-RPC method、是否帶 `Mcp-Session-Id`、connector 設定頁提供的認證選項（OAuth／無認證／其他）、以及是否有任何方式帶入 static header。
- Preflight 記錄寫入 M04-B closeout；記錄日期、平台、client 版本或可辨識的 UI 版本。
- Preflight 結果決定 B.1～B.3 哪些要做。若某平台在 preflight 就證明「無論如何不可能」（例如只接受某種本專案不打算實作的認證且無替代），該平台在本 Subphase 標記為 out of scope，寫明原因，不視為 M04-B 失敗。

### B.1 認證適配（依 preflight 決定形態）

不論最後選哪一種，以下必須成立：

- 每個 request 仍走 P3-D 的 grant → Seat current binding → epoch 驗證；不存在任何跳過它的入口。
- 若採「token 進 URL path」形態：token 不得出現在 server access log 與 error log 的明文中；該 path 與既有 `POST /mcp` 共用同一段 auth／protocol／tool 邏輯，不得複製第二份。
- 若採 OAuth 形態：authorization server 只發放對應到既有 AI Join Token grant 的 access token；scope 仍是 Seat 級；revoke／TTL／epoch 語意與 P3-D 一致。
- kit（M04-A）依最後形態更新 URL 與指引，仍是唯一交付物。

### B.2 Protocol version 相容（僅在 preflight 證明必要時）

- 若某平台 client 送的不是 `2026-07-28`，且該版本是 MCP 官方已發布的 wire contract，server 可加相容層接受它。
- 相容層只做 wire 轉換：`initialize` 若必須回應，只回靜態能力，不建立 transport session state；若對方要求 `Mcp-Session-Id`，可以回一個無狀態的 opaque 值，server 端不得以它保存任何 gameplay scope。
- `2026-07-28` 路徑行為完全不變；P3-E 全部 protocol 測試繼續通過。
- 相容層有自己的 protocol 測試，且有測試證明兩種版本共用同一份 tool catalog 與 auth 邏輯。

### B.3 對外入口與傳輸

- Connector 只接受 HTTPS；沿用 P3-E 9.2「bearer endpoint 不得暴露到非 loopback plain HTTP」。
- 文件記錄推薦的入口形態（例如 Tailscale Funnel）與操作步驟，放 README 的部署段落；不進 repo 的東西（tunnel 設定）只寫步驟不寫憑證。

### B.4 真實網頁版 AI 進桌

對每個 in-scope 平台，以只拿到 kit 的網頁版 AI 完成 A.8 相同的迴圈至少一次，並記錄平台、日期、認證形態與 protocol version。

## 本 Subphase 不要求

- 不做完整 MCP Authorization spec 的 Protected Resource Metadata 與 dynamic client registration，除非 preflight 證明某 in-scope 平台非它不可，且使用者拍板。
- 不做 Claude Desktop 桌面版 MCP client 相容；它與網頁版 connector 是不同 client，若 preflight 順便量到就記錄，不列驗收。
- 不做多 Room／多 token 的 connector 管理 UI。
