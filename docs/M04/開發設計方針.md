## 1. 設計目標

1. **指引與 tool catalog 同源。** `GET /mcp/guide` 的工具表、`tools/list` 的 description、`get_session_context.briefing` 三者都從 `app/mcp/tools.py` 的 `_TOOL_DEFINITIONS` 與一份新的指引文字模組產生；沒有第二份手抄清單。
2. **kit 是前端純文字組合，backend 零新 endpoint。** kit 需要的資料（token、role、expires_at）P3-D 的 `AIControllerGrantView` 已經全有；URL 取 `window.location.origin`。與 M01-N HTML export 同模式：client-side、不新增 API、不保存。
3. **不碰 P3-D 授權邏輯。** M04-A 在 `app/mcp/` 只加文字與一個無認證的 GET route；M04-B 的認證適配只能是 `authenticate_request` 之前的 token 擷取層，之後的流程共用。
4. **Standalone 邊界不動。** 新 route 掛在既有 `app.mcp.router`，standalone 本來就不 include 它；`test_p3e_standalone_mcp.py` 與 `test_m03_import_boundary.py` 只需擴充斷言，不需新機制。

## 3. 指引產生器（M04-A 主題）

### 3.1 `app/mcp/guide.py`

```python
GUIDE_LOCALES = ("zh-TW", "en")

def render_guide(locale: str) -> str: ...
def render_briefing(role: str, mode: str, locale_pair: bool = True) -> str: ...
def tool_reference_rows(role: str | None) -> list[ToolReferenceRow]: ...
```

- `render_guide` 回整份純文字指引。內容分節固定為：

  ```text
  1. 你是誰（token 決定 role；第一步呼叫 get_session_context）
  2. HTTP 契約（header、body _meta、不 initialize、不 Mcp-Session-Id）
  3. 回應格式（result.structuredContent.data / isError / error 三種）
  4. 工具表（由 tool_reference_rows 產生：name、role、用途、必要參數、合法值）
  5. 進場流程（pre_session → start_session；active_session → 續場；cursor 規則）
  6. DM 守則
  7. Player 守則
  8. 401 處置
  9. 最小 client 範例
  ```

- 工具表由 `_TOOL_DEFINITIONS` 迭代產生：`name`、`roles`、`pre_session`、description，以及從 `input_model.model_json_schema()` 抽出的 `required` 欄位與 enum 值。**不得在 guide.py 內手寫工具名稱字串**；測試指南 A.2 用 static 掃描擋。
- `render_guide(role=None)` 列全部工具並標 role；`briefing` 內的工具提示只列該 role 可用的。
- 最小 client 範例使用 **Python 3 標準函式庫**（`urllib.request`、`json`），約 40 行，提供 `call(name, args)` 與 `wait(after_seq)` 兩個函式；選 Python 是因為 2026-09-11 實測時它是唯一不需要安裝東西就能跑的路徑，且多數 AI 執行環境都有。範例內 URL 與 token 用 `<SERVER_URL>`／`<AI_JOIN_TOKEN>` 佔位，**指引本身永遠不含真 token**。
- 第 9 節第一段固定為適用性聲明（en / zh-TW）：「本節只給有 shell 或可對外連網 code execution 的 AI。網頁版 chat（claude.ai、ChatGPT）的 sandbox 沒有對外網路，請不要執行此範例；請使用者以 connector 方式接入。」kit 模板（4.2）的「沒有 MCP client」段也加同一句提醒。
- 指引內的 URL 一律相對描述（「本指引所在 origin 的 `/mcp`」），不寫死 host。

### 3.2 `render_briefing`

- 輸入 `role in {"dm","player"}`、`mode in {"pre_session","active_session"}`。
- 輸出一段 `en / zh-TW` 併列的短文（≤ 1,200 字元），內容：
  - 這一步該做什麼（pre_session：呼叫 `start_session`；active_session：讀 `stage`／`recent_events`／`pending_actions`，先處理 pending）。
  - 該 role 的守則精簡版（DM：敘事精簡、秘密不進 Stage、狀態用工具寫回、每次寫入帶 `idempotency_key`；Player：只控制自己的 Seat、check 用 `/check` 語意即 `request_check` 不可自訂 DC、等 DM 裁決）。
  - 一句「完整指引：`GET /mcp/guide`」。
- 不含任何 Session 資料；Session 資料仍在既有欄位。`temporary_instruction` 保持獨立欄位，briefing 只提醒「若 `temporary_instruction` 非空，優先遵守」。

### 3.3 Tool description 加厚

`tools.py` 的 `_desc(en, zh)` 保留格式，每個 description 改為兩到三句：用途、何時用、關鍵參數。範例：

```text
request_check:
  en: Create one formal Check request group for one or more Player Seats. Use it when
      the narrative calls for an ability check, skill check or saving throw. ability /
      saving_throw require ability_ref (str|dex|con|int|wis|cha); skill requires
      skill_ref (lowercase SRD skill id). dc is optional and hidden from Players when
      visibility is roller_and_dm or dm_only.
  zh: 為一個或多個 Player Seat 建立一組正式 Check 請求。……
```

description 是 `tools/list` 回應的一部分，仍依 role scope 過濾；Player 看不到 `post_narration` 的存在。

### 3.4 `get_session_context` 加 `briefing`

`AIToolApplicationService.get_session_context` 兩個 return dict 各加：

```python
"briefing": render_briefing(role=auth.role, mode="pre_session" | "active_session")
```

放在 dict 最後一個 key，與 `temporary_instruction` 相鄰。P3-E 既有測試對 context 的斷言若是精確 dict 比對，改成 `subset` 比對或補上 `briefing` key；不得刪 P3 斷言。

### 3.5 `GET /mcp/guide`

```python
@router.get("/mcp/guide", response_class=PlainTextResponse)
def mcp_guide(locale: str = "en") -> PlainTextResponse
```

- `locale` 以 query 傳入，沿用 `app.content.localization.require_content_locale` 的驗證；非法值回 400 與既有 stable error 格式。預設 `en`，與 `DEFAULT_SERVER_PRESENTATION_LOCALE` 一致。
- 回應 header：`Content-Type: text/plain; charset=utf-8`、`Cache-Control: public, max-age=300`。
- 無 `Depends(get_ai_controller_service)`；此 route 不碰 DB。
- 不走 `validate_request`；它不是 JSON-RPC。

### 3.6 `server/discover.instructions`

改為（en / zh-TW 併列）：

```text
Adventure Table external AI transport. Read the full guide at GET {origin}/mcp/guide
before acting. Your first call must be get_session_context; it returns a briefing
for your Seat role. Use only the scoped Seat capabilities exposed by this server.
```

`{origin}` 由 `request.url` 組成（scheme + host）；反向代理情境下沿用既有 `X-Forwarded-*` 處理，若目前 app 沒有處理則只用 `request.base_url`，並在 closeout 記錄限制。

## 4. AI Join Kit（M04-A 主題）

### 4.1 `apps/web/src/features/rooms/aiJoinKit.ts`

```ts
export type AiJoinKitInput = {
  origin: string            // window.location.origin
  grant: AIControllerGrantView
  locale: Locale
  issuedAt: Date
}
export function buildAiJoinKit(input: AiJoinKitInput): string
export function aiJoinKitFilename(role: 'dm' | 'player', issuedAt: Date): string
export function downloadAiJoinKit(text: string, filename: string): void
```

- `buildAiJoinKit` 純函式，無副作用，可單元測試。
- `downloadAiJoinKit` 沿用 `CharacterSheetHtmlExport.downloadCharacterSheetHtml` 的 Blob + `URL.createObjectURL` 模式，MIME `text/plain;charset=utf-8`。
- `aiJoinKitFilename`：`adventure-table-ai-<role>-<YYYYMMDD>.txt`。不含 token、不含 Room 名稱。

### 4.2 Kit 模板

兩個 locale 各一份，內容結構固定：

```text
Adventure Table — AI Join Kit
==============================
URL:    {origin}/mcp
Token:  {token}
Role:   {DM | Player}（由 token 決定，不可更改）
Expires:{expires_at | 直到 Session 結束或被撤銷}

有 MCP client（例如 Claude Code）：
  以 HTTP transport 加入上面的 URL，header Authorization: Bearer {token}。
沒有 MCP client、但有 shell 或可連網的 code execution：
  先 GET {origin}/mcp/guide?locale={locale} 讀取 HTTP 契約與流程，再依說明呼叫工具。
網頁版 chat（claude.ai／ChatGPT）：
  sandbox 無法對外連線，請以 connector 接入（見指引）；不要嘗試自己寫 client。
連上後第一步一律呼叫 get_session_context，回傳的 briefing 會告訴你這一場該做什麼。

安全：此 token 只顯示這一次；勿轉傳；用完請 Owner／DM 在網站撤銷。
{loopback 提醒（僅當 origin 為 localhost / 127.0.0.1）：
  這個 URL 只有本機能連。要給遠端 AI 使用，請把 URL 換成對外 HTTPS 入口。}
```

- `{origin}` 判斷 loopback：hostname 為 `localhost`、`127.0.0.1`、`[::1]`。
- 模板文字放 `aiJoinKit.ts` 內的 `kitCopy` 物件，key 對稱兩 locale；`hardcodedUiCopy.test.ts` 的掃描範圍要涵蓋此檔。

### 4.3 面板接線

`LobbyAIDMGrantPanel` 與 `PlayerAIControlPanel` 在 `issued !== null` 的一次性區塊內，token `<textarea>` 下方新增：

```tsx
<section data-ai-join-kit="true">
  <h4>{copy.aiJoinKitTitle}</h4>
  <p>{copy.aiJoinKitHint}</p>
  <textarea readOnly value={kitText} aria-label={copy.aiJoinKitTitle} />
  <button onClick={copyKit}>{copy.aiJoinKitCopy}</button>
  <button onClick={downloadKit}>{copy.aiJoinKitDownload}</button>
</section>
```

- `kitText` 以 `useMemo` 從 `issued`、`locale`、`window.location.origin` 計算；`issuedAt` 取 `issued` 設定當下的 `new Date()`，存 state 一次。
- 既有 `copyToken` 與 `data-ai-dm-token-once`／`data-ai-token-once` 不動；E2E 既有 selector 不變。
- 面板本身已有 `locale`（透過 `copy` 傳入）；若 `copy` 型別沒帶 locale，從 `LocaleProvider` 的 hook 取。

### 4.4 UI copy 新增 key

`lobbyCopy.ts` 與 `sessionCopy.ts` 各加：`aiJoinKitTitle`、`aiJoinKitHint`、`aiJoinKitCopy`、`aiJoinKitCopied`、`aiJoinKitDownload`。兩 locale 同步；既有 locale parity 單元測試自動涵蓋。

## 5. M04-B — Web AI Connector Compatibility

### 5.1 B.0 Preflight 程序

1. 用 P3-F E1 的 Tailscale HTTPS 入口（或等價）把現行 `/mcp` 露出。
2. 在 server 端開一個臨時 request logger（只記 method、path、header 名稱與 `MCP-Protocol-Version` 值、JSON-RPC method；**不記 Authorization 值**），可用 middleware 或 reverse proxy log，不進 repo。
3. claude.ai：Settings → Connectors → Add custom connector，URL 填 `https://<host>/mcp`；分別嘗試「無認證」與 connector 提供的每一種認證選項；記錄設定頁的欄位。
4. ChatGPT：對應的 connector／developer mode 入口，同樣步驟。
5. 每個平台記錄：
   - 是否有 `GET /mcp` 或 `/.well-known/*` 探測；
   - 第一個 POST 的 `MCP-Protocol-Version` 與 JSON-RPC method；
   - 是否帶 `Mcp-Session-Id`、是否期待 SSE；
   - 認證選項清單；能否設定 static header。
6. 結果表寫入 `docs/M04/M04-B_CLOSEOUT.md`「Preflight」段，並依 5.2 決策表決定範圍。

### 5.2 決策表

| Preflight 觀察 | 對應設計 |
|---|---|
| Client 送 `2026-07-28` 且可帶 static header | 只需 B.3 入口文件；B.1／B.2 免做 |
| Client 送 `2026-07-28`，不可帶 header，但支援「無認證」 | B.1 形態 A：token 進 path（5.3） |
| Client 送 `2026-07-28`，只支援 OAuth | B.1 形態 B：最小 OAuth（5.4）；先回使用者拍板工作量 |
| Client 送 `2025-06-18` 或其他官方版本 | 疊加 B.2 相容層（5.5）；認證形態依上三列 |
| Client 送非官方或無法辨識的協定 | 該平台 out of scope，記錄原因 |

### 5.3 B.1 形態 A — token 進 path

```text
POST /mcp/t/{token}
GET  /mcp/t/{token}/guide   （等同 /mcp/guide，方便 connector 探測）
```

- `server.py` 新增 route，內部把 `{token}` 放進一個 `Authorization`-equivalent 的內部 header 後**直接呼叫既有 `mcp_endpoint` 的核心函式**；auth／protocol／tool 三段不複製。實作方式：把現有 `mcp_endpoint` 拆成 `_handle_mcp(request, token, service)`，兩個 route 都呼叫它。
- Log 遮罩：在 app 的 access log formatter 與 exception handler 加 path 遮罩，`/mcp/t/<...>` 一律輸出 `/mcp/t/[redacted]`；uvicorn access log 若無法客製，closeout 記錄並在 README 標明「反向代理層需遮罩」。
- Token 在 URL 的取捨（會進 client 端歷史與 proxy log）寫進 kit 的安全段與 README；朋友間私用可接受，這是與 P2-A「token 明文存 localStorage」同等級的既知取捨。
- kit 模板依形態 A 增加一行「網頁版 connector 請填 `{origin}/mcp/t/{token}`，認證選無」。

### 5.4 B.1 形態 B — 最小 OAuth

只在 5.2 第三列成立且使用者拍板後設計；本文件只鎖約束：

- Authorization endpoint 的「登入」動作就是貼上 AI Join Token；成功後發放的 access token 只是對同一張 grant 的第二個 secret，DB 只留 hash，與 grant 同生共死（revoke／TTL／epoch 全沿用）。
- 不引入使用者帳號、不引入 refresh token 以外的新 persistence。
- Protected Resource Metadata（`/.well-known/oauth-protected-resource`）與 dynamic client registration 只在 preflight 證明該平台必需時才做。

### 5.5 B.2 Protocol 相容層

- `protocol.py` 新增 `LEGACY_PROTOCOL_VERSIONS`（只放官方已發布版本），`validate_request` 依 header 分流：`2026-07-28` 走現有路徑不變；legacy 版本走 `validate_legacy_request`。
- Legacy 路徑允許 `initialize`（回靜態 capabilities 與 `serverInfo`）、`notifications/initialized`（回 202 空 body）、`tools/list`、`tools/call`；`Mcp-Session-Id` 若 client 要求則回一個隨機 opaque 值，server 不保存。
- 兩條路徑呼叫同一個 `tool_catalog` 與 `call_tool`；測試證明對同一 token、同一 tool，兩版本回傳的 `structuredContent` 相同。
- 若 client 期待 SSE stream（`Accept: text/event-stream`），先回 JSON；只有 preflight 證明非 SSE 不可時才加，且仍不得持有 DB connection（沿用 P3-A async wait 原則）。

### 5.6 B.3 對外入口

README 部署段新增「讓網頁版 AI 連進來」：Tailscale Funnel（或等價）開 443 → `server:8000`；只轉發 `/mcp*`，不把 Room UI 露出（Room UI 的 access token 在 localStorage，不適合公網）；所有步驟不含憑證。
