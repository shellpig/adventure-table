# F1 — Review state：entry review status、warning 三級與 resolve、question answer

## Scope

- `app/domain/adventure_imports/schemas.py`（維持 `schema_version=1`，新欄位一律 optional 帶預設）：
  - `DraftEntry` 加 `review_status: Literal["pending","accepted","ignored","uncertain"] = "pending"`、`asset_ids: list[UUID] = []`（F2 用，F1 只定義與驗證格式）。
  - `DraftWarning` 加 `resolved: bool = False`、`resolution: str | None = None`；`level` 三值語意固定為 Info／Warning／Blocking，**只有真的無法建立必要資料才 Blocking**（例如 entry 缺必要 payload 欄位、parent 指向不存在 entry）。
  - `DraftQuestion.answer` 已存在，補 `answered_at` 不需要——不加欄位，以 `answer is not None` 判定已回答。
- `AdventureImportService` 新增三個 intent（皆走既有 `update_draft` 的 revision guard 與 `_writable_import`，不新增 repository 方法）：
  - `set_entry_review(context, room_id, import_id, *, entry_id, review_status, expected_revision)`；
  - `resolve_import_warning(context, room_id, import_id, *, warning_id, resolution, expected_revision)`（把 warning 標 resolved；已 resolved 再解視為 validation error）；
  - `answer_import_question(context, room_id, import_id, *, question_id, answer, expected_revision)`。
  - 三者都對不存在的 id 回 `AdventureImportNotFoundError`，stale revision 回 `AdventureImportRevisionConflictError`，皆零副作用。
- 新增 `unresolved_blocking_warnings(draft_view) -> list[DraftWarning]` 純函式（F2 的 finalize gate 與 F3／F5 共用），住 schemas 或新 `review.py`，擇一即可，不要兩處各寫一份。
- provenance 規則不變：service 不因 review 動作改寫 `provenance`；Human 改值時由呼叫端給定 `user_explicit`／`user_approximation`，AI 給定 `ai_generated`，**任何程式路徑都不得把非原文內容標成 `source_document`**。
- 不做 finalize（F2）、不做 route（F3）、不做 MCP（F4）、不做 UI（F5）。
