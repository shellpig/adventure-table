## 2. P6 核心風險

P6 最危險的 regression：

- Campaign 被迫 attach Adventure才能 Start / Explore；
- Adventure Definition被 gameplay直接修改；
- multiple Adventures被誤做成唯一 active Adventure；
- Current Scene / Situation變 mandatory；
- AI Player拿到 Secret / DM Note / character knowledge of others；
- AI DM只 narrate、不更新重要世界 state；
- write-back失敗卻留下「已發生」的 definitive narration；
- retry建立 duplicate NPC / Fact / Adventure；
- Runtime truth與 Adventure baseline衝突時 AI仍把 baseline當現況；
- `get_session_context`塞整本 Adventure造成 briefing爆量；
- importer沒有外部 AI就完全不能操作；
- PDF/DOCX extraction失敗被 AI fabricated成原文；
- URL importer變成 unrestricted backend crawler；
- P6 map/image被做成假 Tactical geometry；
- P6重造 P3 Roll / P4 Combat；
- Session boundary後 Current Scene / world changes消失；
- P6 multiplayer schema污染 Standalone。

P6 minimum gate：

```text
manual Adventure + multi-attach
+ empty Campaign works
+ immutable Adventure / mutable Runtime separation
+ public / character / DM-only projection
+ optional Current Scene / Situation
+ bounded AI context
+ Human / AI service parity
+ atomic/idempotent P6 write-back
+ Exploration + formal Check + Quick Combat integration
+ importer Source / Draft / Review / Finalize
+ provenance / warning truthfulness
+ restart / reconnect / next Session continuity
+ PostgreSQL migration/concurrency
+ standalone boundary
+ browser full journey
+ real ChatGPT Web world-state journey
```

## P6-A — Adventure Definition & Campaign Attachment

### A.1 Manual Adventure

至少測：

- 只 Name 的 Adventure 可建立；
- 建 section / scene / npc / lore / secret / dm_note / suggested_check / map entry；
- known kind invalid payload被拒；
- freeform entry合法；
- finalize / archive lifecycle；
- attached finalized Adventure不能被 destructive delete；
- Room A不能讀／改 Room B Adventure。

### A.2 Multiple attach

```text
Campaign
→ attach Adventure A
→ attach Adventure B
→ list returns both
→ no single-active constraint
→ detach A
→ B remains
```

另測 cross-Room attach拒絕；duplicate attach idempotent / conflict contract明確。

### A.3 Empty Campaign regression

Campaign完全沒有 Adventure時仍可 Start Session、post narration、送 Exploration action、Request Check、Start Quick Combat。這條從 P6-A起就是常駐 regression。

### A.4 Assets

image upload / read authority、dm_only projection、cross-Room asset reference拒絕、invalid MIME / oversize零 orphan。Room hard delete後 asset metadata / bytes依 storage contract清理。

### A.5 Standalone

第一個 P6 module commit即擴充 M03 import boundary；驗證 Standalone schema沒有 Adventure / Room Asset table。

## P6-B — Campaign Runtime World State

### B.1 CRUD / template separation

Adventure NPC baseline = neutral；Campaign建立 override hostile；assert Adventure仍 neutral，Campaign view = hostile。刪／改 Runtime不回寫 Adventure。

### B.2 Runtime without Adventure

空 Campaign直接建立 Runtime NPC / Scene / Fact / Quest，跨 reload仍存在。

### B.3 Current context optional

- null scene + null situation合法；
- situation only合法；
- Adventure scene ref合法；
- Runtime scene ref合法；
- 同時兩個 scene ref拒絕；
- clear後 Session仍可繼續。

### B.4 Knowledge / secrecy

Matrix：

| Actor | public | own character | other character | dm_only / dm_notes |
|---|---:|---:|---:|---:|
| Current DM | ✓ | ✓ | ✓ | ✓ |
| Human Player | ✓ | ✓ | ✗ | ✗ |
| AI Player | ✓ | ✓ | ✗ | ✗ |

直接檢查 REST / MCP / serialized DTO，禁止只做 UI hide。

### B.5 Concurrency

兩個 expected revision同時更新同一 Runtime entry / Current Situation，只能一個成功；失敗方拿 stable conflict，資料/event無半筆。

### B.6 Detach with overrides

attached Adventure entry被 Runtime override/reference時 detach依設計拒絕且零副作用；清除／materialize後才可 detach。

## P6-C — AI Context & Retrieval

### C.1 Compact session context

`get_session_context` 有 current scene/situation摘要與 context hints，但不含整本 Adventure body。既有 M04 briefing cap gate全綠。

### C.2 Relevant detail

`get_scene_context` / search / get entry可取到需要的 Adventure + Runtime資訊；Runtime override存在時 current truth明確優先於 baseline。

### C.3 Bounded query

建立大量 Adventure entries，search limit / pagination / max payload仍受控；不得因 query空字串回傳整本 Adventure。

### C.4 Projection

Current DM能讀 secrets；Player / AI Player同 query拿不到 secret entry id、title、body、source ref、存在提示或結果 count side channel。

### C.5 Authority lifecycle

AI grant revoke / controller epoch改變後 context tool立刻失效；pre-session DM grant不新增完整 P6 context，Start後才取得。

---

## P6-D — AI DM Write-back & Exploration Integration

### D.1 Human / AI parity

同 fixture，Human DM與AI DM建立同樣 Fact / Runtime NPC時進同一 service、相同 validation / event shape；AI adapter不直接 repo write。

### D.2 Atomic world + narration

刻意讓 world mutation validation失敗：

```text
resolve_world_action("door destroyed", invalid override)
→ reject
→ no world change
→ no definitive narration event
```

成功時 world event + narration一起存在；DB commit失敗不得只留其中一邊。

### D.3 Idempotency

同 idempotency key retry create Fact / NPC / set situation / resolve world action，只成功一次、回同一 result，不重複 event。

### D.4 Ephemeral vs persistent

- 純 atmosphere narration 不強迫建 Fact；
- persistent request建立 Runtime / Override；
- `needs_review=true`不阻塞後續 Exploration / Combat。

### D.5 Stage bridge

DM從 Adventure / Runtime image set Stage；Player只讀合法 stage image；dm_only asset不可因 Stage helper / raw URL外洩。

### D.6 Existing mechanics reuse

P6 flow中的 Check仍產生 P3 RollRequest；Quick Combat仍走 P4 attack/save/damage；P6 world action不產自造 RollResult / Combat state。

### D.7 Waiter

成功 world mutation後既有 `wait_for_event` 被 notifier喚醒；timeout / reconnect cursor語意不變。

## P6-E — Adventure Source & Import Draft

### E.1 Pasted / TXT / Markdown

normalize後文字可 chunk讀取，保留 source metadata / hash；重傳相同 source的 idempotency依 contract成立。

### E.2 PDF / DOCX

使用可抽文字 fixture驗 deterministic extraction與 page/section/source locator；沒有文字的 PDF不做 OCR假裝成功，產 warning / empty extraction state供 Human補內容。

### E.3 URL boundary

Backend不對 arbitrary URL做 unrestricted fetch。MCP提交 URL metadata + normalized content可成功；只 URL 無內容時依 UI contract要求 Human / external AI補 source，不暗中 crawl。

### E.4 Draft revision

AI / Human update draft需 expected revision；stale edit拒絕；restart後 draft / warning ids不變。

### E.5 No LLM backend

Static review / tests確認 importer module沒有 model API client、API key setting、外部 LLM HTTP call。

## P6-F — Import Review, Finalization & Importer MCP

### F.1 Warning levels

Info / Warning可 finalize；Blocking未解不可 finalize。解掉 blocking後可 finalize。

### F.2 No fabricated rule values

Fixture原文只有「門很難撬」無 DC；Draft若有 suggested DC必須標 approximation / ai_generated，不能標 `source_document`。Human可改成 `DM decides`。

### F.3 Review actions

Accept / Edit / Ignore / Mark uncertain / source view不要求逐條 Accept；只處理 warnings也可完成。

### F.4 Finalize idempotency

double submit / retry / reconnect只產一個 finalized Adventure；import row指向同一 target id。

### F.5 MCP parity

tool catalog / descriptions / guide parity涵蓋：

`import_adventure_source`、`get_import_draft`、`resolve_import_warning`、`answer_import_question`、`update_import_draft`、`finalize_adventure`。

Current AI DM合法時可操作允許的 importer scope；AI Player拒絕；stale/revoked grant拒絕。P6不改 pre-session grant可用工具集合。

### F.6 Locale

Importer UI、warnings、validation與 MCP descriptions全部 zh-TW / en parity。

## P6-G — Full P6 Integration & Closeout

### G.1 Empty Campaign browser journey

Playwright：

```text
create/select Campaign with no Adventure
→ Start Session
→ narration
→ Quick Add NPC + Fact
→ Player exploration action
→ DM Request Check
→ Player roll
→ Start Quick Combat
→ resolve attack/damage
→ End Combat
→ update Current Situation
→ End Session
→ next Session
→ prior Runtime + Character/Combat outcome still reflected
```

### G.2 Adventure-driven browser journey

manual/import Adventure → attach → select Scene → set Stage image → Exploration → Check → Quick Combat → override / Fact write-back → next Session看到改變後 world。

### G.3 Real PostgreSQL restart

active Session中建立 Runtime、current context、import draft後 restart server；reconnect後資料 / revision / visibility一致。

### G.4 Real ChatGPT Web gate

沿既有 M04正式 connector：

```text
AI get_session_context
→ get relevant P6 context
→ narrate / request existing check
→ observe result
→ start or participate in existing Quick Combat flow
→ write persistent Campaign Fact / Runtime change
→ wait_for_event
→ reconnect / next Session
→ verify changed world is returned
```

AT UI / database evidence必須能看到實際 world state改變。不能只用 AI文字自述。

### G.5 Secrecy matrix

跨 REST / Resume / Event / MCP / UI network檢查 Adventure secret、DM Notes、Runtime secret、character knowledge、source excerpt。任何 Player-visible leak是 blocker。

### G.6 Quick / P5 independence

P6 full journey不建立 tactical map / coordinates仍全綠。不得 import P5 module。未來 P5可在 P6後開工而不需要改 P6核心玩法。

### G.7 Standalone

M03 import boundary + schema parity全綠；若 dependency / packaging有受影響，依 AGENTS提升到 standalone build / frozen smoke gate。

### G.8 Closeout evidence

至少記錄 backend focused + relevant full regression、frontend unit + build、PostgreSQL migration / concurrency、browser journeys、real ChatGPT Web journey、secrecy matrix、standalone boundary、static review、known limitations。

## 4. 人工驗收重點

人眼確認：

- 沒 Adventure也不會被 UI卡住；
- Adventure editor不像大型 campaign CMS；
- Attached Adventures只是參考來源，不像「選一個 Active Module」；
- Current Scene / Situation不更新也能跑；
- Campaign Changes足夠看重要變化，但不是 Wiki；
- AI DM取得的是當下相關資料，不是整本設定 dump；
- AI DM重要改變真的寫進 AT；
- `needs_review`是提醒不是每步 approval；
- Import Review能快速處理不確定項，不需要逐行審稿；
- Quick Combat / Exploration維持原本速度。

---

## 5. P6 closeout blocker

以下任一成立不得關 P6：

- Campaign沒有 Adventure不能正常玩；
- Adventure template被 Runtime mutation直接修改；
- 只能 attach一個 Adventure；
- Current Scene / Situation成為 mandatory；
- Player / AI Player可讀 secret / dm_notes / other-character knowledge；
- P6 context無上限塞整本 Adventure；
- AI DM不能可靠寫入 persistent world state；
- failed write-back仍發布 definitive narration；
- retry重複建立 world entity / Adventure；
- importer必須有 server LLM才能完成；
- source provenance可把 AI猜測標成原文；
- P6依賴 Tactical geometry；
- 跨 Session world truth遺失；
- P6 schema污染 Standalone；
- 真實 ChatGPT Web P6 journey未通過。
