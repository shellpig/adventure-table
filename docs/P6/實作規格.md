# P6 — 實作規格

> Phase：**P6 — Adventure & Campaign Runtime**  
> 本文件只定義 **P6 各 Subphase 完成後什麼必須成立**。具體 DB schema、API、module、MCP tool、transaction 與 persistence wiring 放在同目錄的 `開發設計方針.md`；自動／人工驗收與 closeout evidence 放在 `測試指南.md`。

最後更新：2026-09-19

---

## 1. P6 定位

P6 讓 Adventure Table 從「已有角色、探索工具與 Quick Combat」進一步成為可持續跑 Campaign 的桌面：可以保存世界／冒險資料，將一個或多個 Adventure 掛到 Campaign，讓 Human / AI DM 取得當下相關 context，並把真正重要的世界變化寫回 Campaign Runtime。

P6 **提前於 P5 執行**。這是執行順序調整，不重編 Phase 編號，也不廢止既有 P5 契約。P6 必須完全能在沒有 Tactical Map / coordinates / spatial geometry 的情況下完成；戰鬥使用既有 P4 Quick Combat，探索使用既有 P3 Exploration / Roll / Event substrate。P5 完成後再把 Tactical spatial facts 接進同一 Campaign，而不是反過來讓 P6 依賴 P5。

P6 關門後至少能跑通：

```text
建立／匯入世界或冒險資料
→ Attach 到 Campaign（也可完全不 Attach）
→ Human / AI DM 取得當下 relevant context
→ Exploration
→ Check / Roll
→ Quick Combat
→ 戰鬥結果保留
→ 重要世界變化寫回 Campaign Runtime
→ Session End
→ 下一個 Session 從改變後的世界繼續
```

---

## 2. P6 固定 Subphase

P6 固定拆成七個可獨立實作、驗證與 commit 的 Subphases：

```text
P6-A — Adventure Definition & Campaign Attachment
↓
P6-B — Campaign Runtime World State
↓
P6-C — AI Context & Retrieval
↓
P6-D — AI DM Write-back & Exploration Integration
↓
P6-E — Adventure Source & Import Draft
↓
P6-F — Import Review, Finalization & Importer MCP
↓
P6-G — Full P6 Integration & Closeout
```

三份 P6 文件必須使用完全一致的名稱與順序。

此順序刻意先完成可手動建立／即興成長的 Campaign，再做大型 source importer：**沒有 Importer 也先能玩；Importer 是加速器，不是 P6 前半段的阻塞條件。**

## 3. P6 共用產品邊界

### 3.1 Adventure 是可附加的世界／冒險資料包

第一版不另建立 World Setting / Lorebook 類型。**Adventure Definition 同時可以是完整冒險模組、世界設定包、城市資料、幾個 NPC / 地點，或其混合。**

Adventure 是 read-only template / reference；Campaign Runtime 才是這一團實際玩出的世界真值。

Adventure 內的 Section、Scene、NPC、Item、Monster ref、Secret、DM Note、Suggested Check、Map / image 都是 optional；不要求形成線性劇本，不要求有 Quest，也不要求所有 entry 都結構化到能自動 resolve。

### 3.2 Campaign 不需要 Adventure

空 Campaign 必須能直接開始 Session：

```text
Campaign
→ DM narration
→ Exploration
→ Quick Add / Runtime additions（可有可無）
→ Check / Quick Combat
→ continue
```

Adventure 永遠不是 Campaign Start、Session Start、Exploration 或 Quick Combat 的前置條件。

### 3.3 一個 Campaign 可 Attach 多個 Adventure

同一 Campaign 可同時附加零到多個 Adventure，沒有唯一 Active Adventure。Attach 只增加可查閱的 template / lore，不自動覆蓋 Runtime，也不自動 entity matching / merge。

若兩個 Adventure 都有同名 NPC / Scene，第一版視為不同資料；由 DM 自己決定是否建立 Runtime link / override 或忽略其中一份。

### 3.4 Current Scene / Current Situation optional

Campaign Runtime 可保存：

- optional Current Scene reference；
- optional Current Situation 摘要。

兩者用於跨 Session 接續與 AI context，但**都不是必填**。真人 DM 不更新 Scene 也能繼續跑；Party 分頭行動仍不建立 per-character scene position。

### 3.5 P6 Map 只是世界／舞台素材

P6 可保存及呈現地圖／場景圖片，可將其顯示在 Main Stage；但在 P5 完成前，它們只是 image / Adventure asset：

- 沒有 token coordinates；
- 沒有 Wall / Door geometry；
- 沒有 movement path / speed budget；
- 沒有 range / AoE / LOS；
- 不用 map 才能進 Exploration / Quick Combat。

所有 precise Tactical geometry 仍屬 P5。

### 3.6 AI DM 可以直接維護 Runtime

Current AI DM 與 Human DM 依同一 backend world services 建立／修改 Runtime Scene、NPC、Item、Quest、Fact、Secret、Adventure State Override 等。一般有效寫入不逐筆等待 Human approval。

`needs_review=true` 只給高影響、歧義或來源衝突的變化；它是提醒，不阻塞跑團。

### 3.7 世界改變不能只存在敘事

AI DM 的 write-back 依既有三層政策：

- **Ephemeral Narration**：只影響氣氛，不建立 world state。
- **Session-Relevant State**：本場需要，寫 Current State / Current Situation。
- **Campaign-Persistent State**：之後合理需要記住，寫 Runtime entity / Fact / Override / Item ownership 等。

若一個 P6 world action 同時宣告 canonical world state 改變與 definitive narration，P6 的高階 world action 必須讓 world mutation 成功後才發布「已經發生」的敘事；P6 自己管理的 world mutation + narration 需具原子／idempotent contract。既有 P3/P4 gameplay mutation 仍由原服務先成功 resolve，AI 再依 Server 結果敘事；P6 不提前重造 P7 的通用 GameTransaction / Undo / Snapshot。

### 3.8 Secret 仍由 Server projection

**Adventure Definition 是 DM authoring / reference material。Human Player / AI Player 第一版一律不可直接讀 Adventure entry，不論該 entry 的 Adventure visibility。** Adventure entry 的非 secret 標記只代表 Human / AI DM 可直接 narrate、放進 DM context 或放上 Stage，不是 Player read permission；Secret / DM Note 則維持更嚴格的 DM-only 語意。

Player 可見世界只來自 Campaign Runtime 的 public / own-character knowledge、Main Stage，以及既有公開 Session / Combat projection。Runtime secret、Character-only knowledge 不得先送到 Human Player / AI Player 再靠 UI 或 prompt 隱藏。

AI context 只是 projection；Server state 才是真值。

## P6-A — Adventure Definition & Campaign Attachment

P6-A 完成後：

- Room owner / dm 可建立／編輯／finalize／archive Adventure Definition；
- Adventure entry 至少可表達 Section、Scene、NPC、Item、Monster Reference、Secret、DM Note、Suggested Check、Map / image reference、Freeform lore；
- Adventure 可只有極少資料，手動建立不需 AI，也可不經 Importer 直接 finalize；
- finalized Adventure 仍可由 Room owner / dm 做 authoring 修正（例如 name / summary / typo / entry 內容）；「immutable-ish baseline」只代表 gameplay / Runtime / AI world write 不得直接改 Adventure；
- Adventure Definition 對 Human Player / AI Player 第一版完全不可直接讀；
- Room 可保存 P6 reusable assets，至少支援 scene / map image 與 importer source 後續重用；source document 固定 DM-only，asset download 必須走 Room authority / projection，不公開裸檔；
- Campaign 可 attach / detach 多個 **finalized** Adventure；draft 不可 attach；
- Attach 不改 Adventure、不複製一整份 Runtime、不自動 merge 同名 entities；
- 已被 Campaign 使用的 finalized Adventure 依資料生命週期 archive 優先，不因一般 delete 破壞引用；
- Human UI 有最小 Adventures workspace，可建立、瀏覽、編輯及 Attach。

P6-A 不要求 importer、AI parsing、runtime override 或 AI context。

## P6-B — Campaign Runtime World State

P6-B 建立 Campaign mutable world layer。完成後至少支援：

- Runtime Scene；
- Runtime NPC；NPC typed payload 可 optional reference 既有 Monster Instance / Monster Template，僅建立敘事↔戰鬥對應，不自動建立 Monster Instance，也不自動同步 HP / state；
- Runtime Item / important object；Item typed payload 可表達 scene / npc / character / party / unknown 等 holder reference，但 **P6 world service 不寫 Character `inventory_state`**；
- Runtime Quest；
- World Fact；
- Runtime Secret / DM Note；
- Adventure State Override；
- Character-specific / Public / DM-only knowledge；
- optional Current Scene；
- optional Current Situation；
- `needs_review` 標記與來源／provenance。

Campaign Runtime 可完全從空 Campaign 長出來，也可 reference attached Adventure entry。Runtime 改變不得回寫 Adventure Definition。

Human DM 必須能 Quick Add 最小資料：NPC 只需 Name；Fact 只需文字；Scene 可只需 Name / Description；需要戰鬥的 Enemy 繼續沿用 P4 Quick Enemy / Monster Instance，不要求先建立完整 Runtime NPC。

跨 Session restart / reconnect 後 Runtime world、Current Scene / Situation、visibility / knowledge projection 都必須保留。

---

## P6-C — AI Context & Retrieval

P6-C 讓 AI 不再只看到 table mechanics，而能取得 bounded、role-scoped 的 Campaign context。

AI DM context 至少可取得：

- Campaign identity / basic summary；
- Current Scene / Current Situation（存在時）；
- current Party / visible Character context；
- Active Combat 摘要（有時）；
- attached Adventure relevant entries；
- Runtime entities / overrides / facts；
- DM-only secret / notes（僅 current DM）；
- recent relevant Session events 的 bounded 摘要／引用。

AI Player 只取得自己合法可見的 Runtime public / own-character knowledge、Stage 與既有公開 table state；**不得直接取得任何 Adventure Definition entry**，也不得拿到 DM-only Runtime truth。

Context retrieval 必須支援「先小 context、按需查詢」；不得把所有 attached Adventure 或整個 Campaign history 一次塞進 `get_session_context`。至少要有可按 scene / query / entity ref 取詳細資料的路徑。

P6-C 不改 P3-D pre-session AI DM grant 邊界：pre-session grant 仍只給既有最小 context + Start；完整 P6 gameplay context 在 Session Start 後依 current authority 取得。

---

## P6-D — AI DM Write-back & Exploration Integration

P6-D 讓 Human / AI DM 使用同一套 World Action service：

- Quick Add Runtime Scene / NPC / Item / Quest / Fact / Secret；
- update Runtime entity state；
- create / update Adventure State Override；
- set / clear Current Scene；
- set / clear Current Situation；
- reveal / grant knowledge；
- mark / clear `needs_review`；
- 將可呈現的 Adventure / Runtime image 放到 Main Stage；
- 以高階 world resolve 操作在成功 mutation 後 append narration / event。

寫入必須 authority-aware、idempotent、留下 acting actor / subject / source audit。active Session 內的正式 world mutation 才寫 durable table event 並喚醒既有 event waiter；Session 外的 Human owner / dm authoring write 不假造 Session event。

P6 Runtime Item 的 character holder 只代表 world truth；真正進出角色背包仍必須呼叫既有 Character Current State / `update_character_state` 寫入 `inventory_state`。P6 不建立第二套 inventory writer，也不因 holder reference 自動同步角色 Inventory。

P6-D 必須與 P3 Exploration / Roll、P4 Quick Combat 共存：世界 context 不取代 RollRequest、不自己捏正式骰、不另建 Combat engine。

AI DM 說出永久性世界變化時，不可只 post narration；相反地，純氣氛敘事也不得被強迫建立 Fact。

---

## P6-E — Adventure Source & Import Draft

P6-E 建立 importer 的 Source → Draft substrate。來源至少支援：

- pasted text；
- TXT / Markdown；
- PDF；
- DOCX；
- URL reference（可由外部 AI 讀取後連同來源 URL / excerpt 寫回；P6 不因 URL 輸入而建立任意 server-side web crawler）。

Source 必須保留可回查的原文／normalized text、filename / URL / media metadata 與 source reference。大型來源提供 bounded chunk / section 讀取，不要求一次把全文塞給 AI。

Import Draft 是 mutable review state，不是 Adventure truth；AI parse 結果可帶 provenance：

- `source_document`
- `user_explicit`
- `user_approximation`
- `ai_generated`

沒有 AI 也能停在 Source 階段或由 Human 直接編 Draft。

---

## P6-F — Import Review, Finalization & Importer MCP

P6-F 完成完整 Review / Finalize：

- Draft entry 可 Accept / Edit / Ignore / Mark uncertain / View source；
- Warning 分 Info / Warning / Blocking；
- 只有真的無法建立必要資料時才 Blocking；
- 原文未給 DC / 規則值時不可 AI 自行冒充原文，可保留 `DM decides` / approximation provenance；
- 不要求逐項 Accept 才能 finalize；
- Finalize 建立新的 immutable-ish Adventure Definition baseline；gameplay / Runtime / AI world write 只能用 Runtime / Override 改變世界，但 Room owner / dm 仍可做明確 authoring 修正；
- retry / reconnect 不重複 finalize。

Importer MCP 至少覆蓋既有產品契約的 intent：

`import_adventure_source`、`get_import_draft`、`resolve_import_warning`、`answer_import_question`、`update_import_draft`、`finalize_adventure`。

P6 不為 Importer 放寬 P3-D pre-session Seat grant。Human importer 可在 Session 外使用；Seat-based MCP importer 在第一版只在 existing authority 合法的範圍內 expose，不建立可繞過 Room / Seat / grant 的 AI-specific bypass。

## P6-G — Full P6 Integration & Closeout

P6-G 關門前必須證明至少兩條完整玩法都成立：

### G.1 無 Adventure 即興團

```text
empty Campaign
→ Start Session
→ DM narration
→ Quick Add NPC / Fact
→ Request Check
→ Quick Combat
→ Runtime world change
→ End Session
→ next Session resumes with prior world truth
```

### G.2 Adventure 驅動團

```text
Source / manual Adventure
→ Review / Finalize
→ attach to Campaign
→ AI DM starts Session
→ get bounded relevant context
→ Exploration
→ formal Check
→ Quick Combat
→ persistent world write-back
→ Session End
→ reconnect / next Session
→ AI DM sees changed world, not original template as current truth
```

至少一條真實 ChatGPT Web journey 使用既有 M04 connector，在 AT 內實際讀取 P6 context 並寫入 Campaign Runtime；不能只由 host chat 自述。

P6 multiplayer schema 不得進 Standalone SQLite；Character Core / Builder / Interop 不得反向 import Adventure / Campaign Runtime module。

---

## P6 明確不做

P6 第一版不做：

- Tactical grid / token coordinates / pathfinding / range / AoE geometry；
- Fog of War / dynamic lighting；
- World Setting 第二套 entity 類型；
- Campaign Wiki / auto knowledge graph / NPC relationship graph；
- Adventure automatic entity matching / merge wizard；
- linear quest script / CRPG trigger graph；
- point-and-click exploration verb system；
- mandatory Scene / Quest / Fact workflow；
- full economy / shop simulation；
- P7 Timeline search / Snapshot / Restore / Undo Transaction；
- arbitrary server-side URL crawler；
- server-built-in LLM / external model API key；
- 自動把每句 narration 變 Fact；
- 自動把每場 Combat board state 升格成 Campaign world truth。

---

## P6 Closeout 原則

每個 Subphase 各自完成 focused tests、static review、必要 regression 與 closeout evidence；P6-G 完成 full integration 後 P6 才能關門。

以下任一存在不得關 P6：Campaign 沒 Adventure 就不能跑；Adventure mutation 直接改 template；AI Player 可取得 secret / DM Note；AI DM 只能 narrate 不能寫重要 state；write-back retry 會重複建 entity / Fact；Current Scene / Situation 變成 mandatory；Importer 沒 AI 就不能用；P6 map 變成假 Tactical geometry；P6 context 一次灌整本 Adventure；跨 Session 後世界變化遺失；Standalone 出現 P6 multiplayer schema；真實 ChatGPT Web world-state journey 未通過。
