# D1 — `CampaignWorldService` 八個 intent

## Scope

新增 `app/domain/campaign_runtime/world.py` `CampaignWorldService`，以契約 D.1 的 intent 名稱統一 Human UI 與 MCP：`create_world_entry`、`update_world_entry`、`archive_world_entry`、`set_adventure_override`、`clear_adventure_override`、`set_current_context`、`grant_character_knowledge`、`set_needs_review`。

- 兩條路徑都委派既有 `CampaignRuntimeService`：management（`RoomAccessContext`，Session 外 Human owner／dm；無 TableEvent、無 notifier）與 active（`TableActorContext`，active Session Human／AI current DM；`world.*` event＋notifier）。AI actor 一律 active。
- `grant_character_knowledge`＝entry patch 到 `visibility="character"`＋recipient character ids（沿用 `validate_runtime_visibility_recipients`）；`set_needs_review`＝entry／override 的 `needs_review` patch。不新增 persistence、不新增 event kind。
- 不做 `resolve_world_action`（D2）、不碰 Character `inventory_state`。
- **派工決策**：既有 P6-B REST route 不改接本 service（見接手摘要）。

## 契約與輸入

- 規格 P6-D 全段；設計 D.1；測試 D.1、D.3、D.4。前置：D0b。

## 驗收

- `tests/test_p6d_world_service.py`（parametrize）：同 fixture 的 Human current DM 與 AI DM 走同一 intent 得同 validation／event shape（D.1）；Session 外 Human management 有 mutation record／revision audit、無 `session_events`、無 notifier，AI 同情境被拒零副作用（D.1）；同 idempotency key retry 只成功一次、回同 result、不重複 `world.*` event（D.3）；`needs_review=true` 不影響後續讀取（D.4）；Player／AI Player／revoked grant／stale epoch 全拒零副作用。
