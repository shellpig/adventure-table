
## Architecture

固定依賴方向：

```text
Human Web UI ─┐
              ├─> Adventure / Campaign World application services
MCP Adapter ──┘                    │
                                   ├─ Adventure Definition repositories
                                   ├─ Campaign Runtime repositories
                                   ├─ Room Asset repository
                                   ├─ TableEventService / notifier
                                   ├─ P3 Exploration / Roll services
                                   └─ P4 Quick Combat services
```

P6 不建立第二套 Room / Campaign / Session / Seat / Event / Combat authority。

Human 與 AI 對同一 Adventure / Runtime mutation 共用 application service；MCP 只轉 intent，不可直接改 row / JSON raw field。

## P6-A — Adventure Definition & Campaign Attachment

### A.1 Room asset substrate

P6-A 建立 Room-scoped reusable asset substrate，供 Adventure image、Importer source attachment，並讓未來 P5 Battle Map image 重用。**第一版 storage 固定採「PostgreSQL metadata + Server-managed filesystem」**，不把通用 asset bytes 存入 PostgreSQL bytea。

最低資料：

```text
room_assets
- id
- room_id
- kind                 # image | source_document；P5 後續再加 battle_map_image
- storage_key
- original_filename
- mime_type
- size_bytes
- sha256
- visibility           # room | dm_only
- created_at
```

bytes 存在 Server 管理的 filesystem root `ADVENTURE_TABLE_ASSET_ROOT`；Web / Docker 預設以 named volume 掛載到 `/data/adventure-table/assets`。asset root 不作 public static mount，client payload 不得暴露 `storage_key`、filesystem root 或實體路徑；所有 download/read 都先驗 Room authority，再驗 entity / asset visibility。

Room Hard Delete 必須 cascade `room_assets` metadata 並連帶刪除 filesystem bytes；檔案 cleanup 失敗要保留可重試定位資訊，不得因 DB row 先消失而留下永遠無法定位的 orphan。

`kind=source_document` **固定 `visibility=dm_only`**，不可建立或 patch 成 room-visible；原始 TXT / Markdown / PDF / DOCX 可能包含尚未揭露的秘密。一般 `kind=image` 才可依用途使用 room / dm_only projection。

P6 image 支援 image/png、image/jpeg、image/webp；Importer 文件支援 text/plain、text/markdown、application/pdf、DOCX media type。大小上限由 Settings / validation 固定並測試，不接受無上限 upload；P5 日後的 battle-map image 沿用既有 20 MiB image 上限與同一 storage / cleanup contract。

### A.2 Adventure Definition

```text
adventure_definitions
- id
- room_id
- name
- summary
- ruleset
- status               # draft | finalized | archived
- created_at / updated_at

adventure_entries
- id
- adventure_id
- parent_entry_id?     # section tree / grouping only
- kind                 # section | scene | npc | item | monster_ref |
                       # quest | secret | dm_note | suggested_check |
                       # map | lore | other
- title?
- body?
- data_json            # kind-specific validated payload, not arbitrary gameplay writes
- visibility           # public | dm_only
- sort_order
- provenance_json?
- source_ref_json?
- created_at / updated_at

adventure_entry_assets
- adventure_entry_id
- asset_id
- role                 # image | map | source | attachment
- sort_order

campaign_adventure_links
- campaign_id
- adventure_id
- sort_order
- attached_at
```

Adventure entry `data_json` 允許 authoring flexibility，但每個 known kind 必須由 Pydantic typed payload 驗證；不得在 service 裡到處 `dict.get` 猜欄位。Freeform / other 才使用受限 arbitrary metadata。

Adventure entry 的 `visibility = public | dm_only` **都只屬 DM authoring semantics，不是 Player read permission**：`public` 表示 Human / AI DM 可直接 narrate、放 Stage 或放進 DM context；`dm_only` 用於 secret / DM Note。Human Player / AI Player 的 Adventure read service對兩者都拒絕，Player可見內容要先成為 Runtime public / own-character knowledge或被 DM放上 Stage。

Campaign 可有多筆 link；不得 unique 限制成單一 active Adventure。

### A.3 Lifecycle

- draft可由 Room owner / dm編輯與直接 finalize；**只有 finalized Adventure可 attach**；
- finalized仍可由 Room owner / dm做 authoring修正（name / summary / entries）；immutable-ish只限制 gameplay / Runtime / AI world write不得直接修改 Definition；
- attached finalized Adventure hard delete需拒絕，改 archive；
- detach只移除 Campaign link，不刪 Definition；detach blocker另見 P6-B；
- Room hard delete仍依既有 cascade / filesystem cleanup契約；
- cross-Room attach / asset reference一律拒絕。

## P6-B — Campaign Runtime World State

### B.1 Generic runtime entity with typed payloads

```text
campaign_world_entries
- id
- campaign_id
- kind                 # scene | npc | item | quest | fact | secret | hazard | other
- title?
- body?
- state_json
- dm_notes?
- visibility           # public | dm_only | character
- needs_review
- source_adventure_entry_id?
- provenance_json?
- revision
- created_by_actor_kind
- created_by_actor_id?
- created_at / updated_at / archived_at?

campaign_world_entry_characters
- world_entry_id
- character_id
```

Known `kind` 的 `state_json` 一樣走 typed model；Player-facing projection不回傳 `dm_notes`、dm_only entry、或 character visibility 不屬於其 active Character 的 entry。

第一版 typed boundary另外固定：

- `item` 可有 structured `holder_ref`，target kind至少支援 `scene | npc | character | party | unknown`。這只表達 Campaign world truth；若 holder是 Character，P6 service **不得**直接寫 Character `inventory_state`，真正背包異動仍走既有 `TableCharacterStateService` / `update_character_state`。
- `npc` 可有 optional `monster_instance_id` / `monster_template_ref`，用來把長期 NPC與既有戰鬥資料對上。它是純 reference：不自動建立 Monster Instance、不雙向同步 HP / conditions / combat outcome；戰鬥真值仍在 P4 Monster Instance / Combat。

### B.2 Adventure overrides

```text
campaign_adventure_overrides
- id
- campaign_id
- adventure_entry_id
- state_json
- note?
- needs_review
- revision
- updated_at
```

Override 表示「這團對原 Adventure entry 的狀態差異」，不修改原 entry。Campaign 必須已 attach 該 Adventure 才可建立 active override。

Detach只刪 `campaign_adventure_links`，Adventure / entry row本身仍存在，因此 `campaign_world_entries.source_adventure_entry_id` 這種 provenance reference **不會 dangling，也不阻擋 detach**。第一版 detach只有兩種 blocker：

1. 該 Adventure仍有 active `campaign_adventure_overrides`；
2. `campaign_runtime_context.current_adventure_scene_entry_id` 指向該 Adventure entry。

DM清除 blocker後即可 detach；既有 Runtime entry的 provenance ref保留。

### B.3 Current context

```text
campaign_runtime_context
- campaign_id PK
- current_adventure_scene_entry_id?
- current_runtime_scene_entry_id?
- current_situation?
- revision
- updated_at
```

兩個 scene ref 最多一個非 null；也允許兩者都 null。Current Situation 可單獨存在。

不建立 `character.current_scene_id`。

### B.4 Knowledge

Character-only knowledge 使用 `campaign_world_entries.visibility=character` + recipient table。Recipient 綁 Character identity，不綁 Seat，確保跨 Session / controller handoff 後知識仍屬同一角色。

## Shared authority / projection

### Human

- Room owner / dm 可管理 Adventure / source / import；
- **沒有 active Session 時**，Human Room owner / dm可透過 HTTP修改 Campaign Runtime / override / Current Scene / Current Situation，用於開場前準備與跨 Session整理。這類 write不建立假的 `TableActorContext`、不產 `session_events` / notifier；audit留在 Runtime / override / context本身的 actor + revision欄位，idempotency走 P6 campaign-scoped mutation record。
- **有 active Session 時**，Human current DM的 gameplay world write解析成既有 `TableActorContext`，與 AI DM走同一 World service；成功後寫 `world.*` TableEvent並 notifier。
- Player不可建立 dm-only world truth；
- Player可讀 Runtime public + own-character knowledge，但 **Human Player不直接讀任何 Adventure Definition entry**；要給玩家看的 Adventure內容必須先由 DM narrate、放 Stage或 materialize / reveal成 Runtime knowledge。
- 第一版不新增 Adventure公開分享 URL。

### AI

Gameplay AI 沿用 P3-D `TableActorContext` / current grant / `controller_epoch` / M04 OAuth revalidation。

- current AI DM = current **active Session** DM 的 world write authority；AI 不提供 Session 外的 management write；
- AI Player = 只讀合法 Runtime / own-character projection，不能 world-author write，也不能直接讀 Adventure Definition；
- revoked / stale grant 每次 call 都失效；
- pre-session AI DM grant仍維持 P3-D 的最小 context + Start，不因 P6 自動擴權。

Importer MCP 不得用「只要知道 Room id 就可寫」之類旁路。P6-F 第一版的 Seat-based importer tools 只在 current DM actor 已合法成立時 expose；Human pre-session importer則走既有 Room owner/dm HTTP authority。若未來要做獨立 management connector，另開後續契約，不在 P6 偷改 M04 authority model。

## P6-C — AI Context & Retrieval

### C.1 Context service

新增單一 `CampaignContextService`（名稱可依現有 module convention微調，但責任固定），輸入 canonical actor / campaign scope，輸出 role-projected structured DTO。

最低 service intents：

```text
get_campaign_context(actor)
get_scene_context(actor, scene_ref?)
search_campaign_context(actor, query, kinds?, limit?)
get_world_entry(actor, world_entry_id)
get_adventure_entry(actor, adventure_entry_id)
```

`get_session_context` 只加入 compact P6 summary / references，例如：

- current scene label；
- current situation；
- attached adventure count / relevant refs；
- world entry refs；
- next recommended context tool hints。

不得把整份 Adventure entry bodies塞進 briefing。M04 `BRIEFING_MAX_CHARS` 仍是 hard gate。

AI DM 必須能在不被告知任何 entry id／關鍵字的情況下自行發現 Adventure 內容（P6-G G4 補缺）：

- DM 的 `get_campaign_context` 對每個 attached Adventure 回傳 `summary` 與 **outline**（Adventure 目錄）：每筆只含 entry `id`、`parent_entry_id`、`kind`、`title`、`visibility`、`has_override`，**不含 body / data / source**；上限 `ADVENTURE_OUTLINE_MAX_ENTRIES`（100），超過時 `outline_truncated=true`，其餘靠 `search_campaign_context`。Player / AI Player view 不含 outline、名稱或數量。
- AI context 投影對沒有寫入上限的欄位自行設界（P6-G G5a 補缺）：Adventure `summary` 與 `current_situation` 截到 `CONTEXT_TEXT_MAX_CHARS`（1000）並帶 `summary_truncated`／`current_situation_truncated`；`get_campaign_context` 的 `world_entries` 取前 `CAMPAIGN_CONTEXT_MAX_WORLD_REFS`（100）筆並帶 `world_entries_truncated`，其餘靠 `search_campaign_context`。只影響 AI context 回傳，不改寫入 DTO 與資料。
- `get_session_context` 的 DM compact summary 帶 `attached_adventures`（id、name、`outline_entry_count`）；有 attached Adventure 時 `next_context_tools` 以 `get_campaign_context` 開頭，current scene 為 none 時加入 `world_set_current_context`。
- DM briefing（pre-session 與 active loop）與 `/mcp/guide` 的「Adventure 與世界狀態」段必須教會 AI DM：讀 outline → `get_adventure_entry` → `world_set_current_context` 設開場 scene → 世界改變時 `world_set_override`／`world_create_entry` 寫回。zh-TW / en 同步。
- 同一處必須明示 **Adventure 是底稿不是劇本**（`規格企劃.md` 〇 第 7 條 DM 保留即興裁定）：Adventure 沒提供可行路徑時（例如寫了開啟條件卻沒有對應遭遇），AI DM 要即興補上（新 NPC 用 `world_create_entry`、敵人用 Quick Combat），重要即興內容同樣寫回，不得讓桌面卡住；並以**玩家使用的語言**敘事、寫 Stage 與寫回，Adventure 原文為其他語言時轉述而非照抄。

Search 第一版可用 PostgreSQL normalized text / simple indexed matching，不要求 vector DB / embeddings / LLM reranker。結果必須 deterministic、bounded，且先做 authority projection再回傳。

Context source優先級：

```text
Campaign Runtime truth / Override
> attached Adventure baseline
> source excerpt
```

相同 subject 有 Runtime override時，AI DM context 必須清楚標出 baseline + current state，不能把原 Adventure 值當成仍然有效的現況。

Player role的 context / search只能從 Runtime public、own-character knowledge、Stage與既有公開 table state取資料；不得因 search命中 attached Adventure而回傳 Adventure entry id / title / body / source ref或命中數 side channel。

### C.2 MCP tool contract

P6-C tool name / role set固定如下，全部需要 active Session；不得由 worker自行改名：

| Tool | Roles | Service intent |
|---|---|---|
| `get_campaign_context` | player, dm | `get_campaign_context` |
| `get_scene_context` | player, dm | `get_scene_context` |
| `search_campaign_context` | player, dm | `search_campaign_context` |
| `get_world_entry` | player, dm | `get_world_entry` |
| `get_adventure_entry` | dm | `get_adventure_entry` |

所有 tool都進既有 M04 catalog / description parity；新增名稱同步加入 `app/mcp/guide_tool_names.py` 的固定 `_EXPECTED`，guide需要引用時再加對應 `GuideToolNames` 欄位。description維持 English + zh-TW contract。

## P6-D — AI DM Write-back & Exploration Integration

### D.1 World service

新增 `CampaignWorldService` / `WorldActionService` 層，統一 Human UI 與 MCP：

```text
create_world_entry
update_world_entry
archive_world_entry
set_adventure_override
clear_adventure_override
set_current_context
grant_character_knowledge
set_needs_review
resolve_world_action
```

所有 mutation都要 validate same Campaign / Room、expected revision / optimistic concurrency、idempotency key、actor audit，拒絕時零副作用。事件邊界依執行情境分開：

- Session 外 Human owner / dm management write：HTTP authority；寫 Runtime / override / context + P6 campaign-scoped idempotency record與 actor/revision audit；**不產 TableEvent、不 notifier**。
- active Session Human / AI current DM write：`TableActorContext` + 同一 World service；成功 transaction內寫 `world.*` TableEvent，commit後 notifier。
- AI write一律要求 active Session。
- `resolve_world_action`（含 narration）只在 active Session內合法。

P6 world service不直接寫 Character `inventory_state`。Runtime Item若改成 Character holder，而角色背包也要改，Human / AI DM需另外呼叫既有 Character Current State action；兩邊不得暗中互相同步。

### D.2 resolve_world_action atomic boundary

P6 自己管理的 world writes + definitive narration 使用同一 DB transaction：

```text
validate
→ apply Runtime / Override / Current Context changes
→ append canonical world.* event
→ append既有 P3 `exploration.narration` + `session_messages(kind=narration)` projection（若 supplied）
→ commit
→ notifier
```

任何 world validation / persistence 失敗，不可只留下「門已壞」等 definitive narration。Narration **不得**另造 `world.narration`；必須沿用 P3既有 narration event kind、DTO、visibility與 `session_messages` projection。實作若需要同 transaction寫入，應抽取／重用 transaction-bound persistence helper，而不是建立第二種 narration資料。

Existing P3/P4 mutations不被 P6 包裝成第二套 transaction engine。需要 Attack / damage / formal Check 時先呼叫原 canonical service；AI 依回傳結果再決定是否做 P6 world write-back / narration。完整跨所有 subsystem 的通用 GameTransaction留 P7。

### D.3 Stage integration

P6 不遷移、不改寫 P3既有 `room_stage_images` bytea storage，也不改變 `ExplorationStageService` 的 canonical Stage contract。DM從 P6 `room_assets` 設定 Stage image時，application boundary先經 Room / asset authority讀 filesystem bytes，再**複製一份**成既有 stage image，之後沿用 `ExplorationStageService` 的 revision / event語意。不得讓 `session_stages.image_id` 直接指向 `room_assets`，也不得公開原始 asset URL / storage key。

### D.4 MCP tool contract

P6-D write tool全部 DM-only且需要 active Session，名稱固定：

| Tool | Service intent |
|---|---|
| `world_create_entry` | `create_world_entry` |
| `world_update_entry` | `update_world_entry` |
| `world_archive_entry` | `archive_world_entry` |
| `world_set_override` | `set_adventure_override` |
| `world_clear_override` | `clear_adventure_override` |
| `world_set_current_context` | `set_current_context` |
| `world_grant_knowledge` | `grant_character_knowledge` |
| `world_set_needs_review` | `set_needs_review` |
| `world_resolve_action` | `resolve_world_action` |
| `set_stage_image` | asset / entry image → P3 Stage bridge |

同 P6-C，所有新增名稱必須同步 `guide_tool_names.py` / M04 catalog parity與 English + zh-TW descriptions；MCP adapter只轉 intent，不直接 repository write。

`state` 是依 kind 辨識、在 domain 層驗證的 payload，JSON Schema 只能是 open object；因此 `world_create_entry`／`world_update_entry` description 必須寫明各 kind 的 state 形狀（含 item `holder_ref` 的 kind／`target_id`，character 的 `target_id` 來自 `get_campaign_context` 的 `party[].active_character_id`），並註明 `patch.state` 整個取代 state。Runtime payload／business validation 失敗回 `invalid_arguments` 時，DM caller 的錯誤必須帶 `detail`（pydantic 錯誤壓成 `loc: msg`，上限 600 字），讓 AI DM 能自行修正重試；Player caller 不帶 detail（P6-G G4c 補缺）。

## P6-E — Adventure Source & Import Draft

### E.1 Source

```text
adventure_imports
- id
- room_id
- name
- status               # source | drafting | review | finalized | cancelled
- target_adventure_id?
- revision
- created_at / updated_at

adventure_import_sources
- id
- import_id
- asset_id?
- source_kind          # paste | txt | markdown | pdf | docx | url
- source_url?
- normalized_text
- metadata_json
- sha256
- created_at

adventure_import_drafts
- import_id PK
- draft_json
- warnings_json
- revision
- updated_at
```

Draft JSON 必須有 versioned internal schema；parsed entries的 shape對應 P6-A typed Adventure entry payload。Warnings / questions帶 stable id，讓 retry / reconnect可定位。

### E.2 Extraction

TXT / Markdown：decode + normalize。

PDF / DOCX：只做 deterministic text extraction與 source location mapping，不用 OCR 當預設，不自行做 AI parsing。無法可靠抽文字時標 source warning，Human / external AI仍可補 pasted text。

PDF / DOCX extraction 若需要新增 Python 套件，套件只加入 `apps/server/pyproject.toml` 的 `[project.optional-dependencies].web`，**不加入 base `dependencies`，也不加入 Standalone runtime dependencies**；importer module需 lazy import extractor，或由 M03 import-boundary gate明確禁止 Standalone / Character core反向依賴 Importer。即使新套件只屬 web extra，仍屬 AGENTS 工程守則 8 的「新增 Python 套件」：同一實作改動必須重新產生 `constraints-standalone-win.txt`、執行 standalone build與 frozen smoke，並證明重產後的 Standalone constraints / frozen app沒有拉入該 extraction套件。

URL：第一版不讓 backend 任意 fetch Internet。External AI 可以讀取可存取 URL，再以 `import_adventure_source` 提交 normalized text + URL / excerpt metadata；Human 也可貼內容。這避免 SSRF / crawler scope膨脹。

## P6-F — Import Review, Finalization & Importer MCP

Review service intents：

```text
get_import_draft
update_import_draft
resolve_import_warning
answer_import_question
finalize_adventure
```

Finalize transaction：

```text
lock import revision
→ validate no unresolved blocking warnings
→ create finalized Adventure Definition + entries + links to assets/source refs
→ mark import finalized + target_adventure_id
→ commit
```

同一 idempotency key retry回傳同一 Adventure，不建立 duplicate。Finalize建立的是 gameplay / Runtime 不可直接改寫的 authoring baseline；finalized後仍可由 Room owner / dm進行明確 authoring修正。

Importer MCP tool names以產品契約為基準：

- `import_adventure_source`
- `get_import_draft`
- `resolve_import_warning`
- `answer_import_question`
- `update_import_draft`
- `finalize_adventure`

Tool descriptions必須 zh-TW / en 並進既有 M04 catalog / guide parity。MCP adapter不自行 parse；智能內容由外部 AI產生。

P6-F 的 current AI DM importer 由 `AdventureImportService` 在同一 transaction 內重驗 active `TableActorContext`；不把 table actor 偽裝成 `RoomAccessContext`。`AdventureService` 的共用 authoring 入口可接受該 DM actor，但 table actor 只能建立／修改 draft Adventure entry、連結 draft asset 並將 draft finalize；finalized Adventure 的後續明確 authoring 修正仍限 Human Room owner／dm。其他 Adventure management 入口不因 Importer 開放給 table actor。這項 P6-F 接線是 P6-A「僅 RoomAccessContext」實作邊界的後續收斂，不改 Player read 權限或 gameplay／Runtime 不可直接改寫 Adventure baseline 的產品規則。

## P6-G — Full P6 Integration & Closeout

P6-G 不建立新的核心資料模型；它只做跨 Subphase integration、修正、browser / real web chat AI agent gates 與 closeout。G 必須以 P6-A～F 已存在的 production services 跑通 empty Campaign 與 Adventure-driven 兩條 journey，確認 restart / next Session continuity、secrecy、idempotency、Quick Combat regression、Standalone boundary。若 G 才發現某個 A～F 必要核心能力從未實作，先回到對應 Subphase補齊並取得該 Subphase evidence，不把功能偷塞成 closeout-only hack。

## REST / UI surface

路徑遵循既有 Room-first pattern，具體 route命名可按現有 `/api/rooms/{room}/...` convention。

最低 Human UI：

- Room workspace：Adventures；
- Adventure editor：entries / assets / archive；
- Campaign：Attached Adventures；
- Campaign Changes：Runtime NPC / Scene / Quest / Fact / Overrides / needs_review；
- Session DM：Current Scene / Situation、Quick Add world entry、可從 Adventure / Runtime image set Stage；
- Player：唯讀 Journal，只顯示 public Runtime Quest / Fact 與自己角色的 knowledge；直接重用既有 Player projection，不另建 service；
- Importer：Source、Draft Review、Warnings、Finalize。

所有首次 expose copy同 Subphase交付 `zh-TW` / `en`。

## Events

active Session內新增 event kind採 `world.*` namespace，至少涵蓋正式 Runtime mutation與context change；world action附帶的 narration仍使用既有 `exploration.narration`，不建立 `world.narration`。

Adventure authoring / attach-detach / import finalize若發生在 Session 外，不為了 audit假造 `session_events`；其 durable truth與 audit落在自己的 Room / Campaign tables。若這些操作在 active Session內需要通知桌上 actor，可另外 append安全的 `adventure.*` / `import.*` TableEvent projection，但 event不是資料真值。

P6 active-session event仍使用 P3 durable event / cursor / waiter substrate；它不是 P7 跨 Session Timeline 完整模型。需要跨 Session查 world truth直接讀 Campaign Runtime repository，不靠 replay所有 Session events重建。

Secret world event依 actor projection過濾，不能把完整 payload append成 public再靠 UI藏。

## Migration / PostgreSQL / Standalone

P6 multiplayer資料走 Web migration track。契約建立當下 current web head為 `0030_p4f_entry_dodging`；P6 從下一個可用 web revision開始，預期：

```text
0031_p6a_room_assets_adventures
0032_p6b_campaign_world_runtime
0033_p6e_adventure_imports
```

若實作前 web head已前進，使用當時 next available revision；**不可為了符合本文數字重寫已存在 migration**。P5 因改為 P6 後執行，也必須從 P6 完成後的 web head往後接，不再保留 0031～0034。

P6 table / migration不得出現在 Standalone SQLite。第一個新增 Adventure / Runtime multiplayer module的同一 commit就要擴充 `tests/test_m03_import_boundary.py` forbidden regex / protected modules，並驗 `test_m03d_schema_parity.py`。

Room asset / Adventure code不得被 `app.content.*`、`app.domain.character*`、`app.interop` 或 `app.standalone` import。

## Concurrency / idempotency

所有 mutable Draft / Runtime / Current Context需 revision。典型競爭：

- Human DM 與 AI DM同時改 Current Situation；
- AI retry重建同一 Fact；
- Import draft舊 revision覆蓋新 edit；
- finalize double-submit；
- detach Adventure與建立 override競爭。

使用 expected revision + DB transaction / unique idempotency records解決；禁止 last-write-wins 靜默蓋掉。

P6 world mutation使用 campaign-scoped idempotency substrate（例如 `campaign_world_mutations(campaign_id, idempotency_key)` unique）保存 command/result identity，不能依賴 `session_events(session_id, idempotency_key)` 作為唯一去重來源，因為 Human owner / dm允許 Session 外寫入。active Session內同一 transaction再把對應 `world.*` event寫進 `session_events`；Session 外則只有 mutation record + target row revision / actor audit，不建立 fake Session event。

## Subphase implementation boundary

**P6-A**：Room Asset、Adventure Definition、manual authoring、Campaign attachment；不做 Runtime。

**P6-B**：Campaign Runtime / overrides / knowledge / current context；不做 AI retrieval。

**P6-C**：role-scoped bounded context / search / MCP read surface；不做 write-back。

**P6-D**：world write services、atomic P6 world+narration、Stage bridge、MCP write surface；跑通 manual Adventure / empty Campaign 的可玩 loop。

**P6-E**：Source / extraction / Draft substrate；不 finalize。

**P6-F**：Review / warning / finalize / importer MCP；不做 P7 package import/export。

**P6-G**：integration、browser、real web chat AI agent、repair、closeout；不得把前面未做的核心能力拖到 G 才第一次實作。
