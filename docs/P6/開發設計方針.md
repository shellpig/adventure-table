# P6 — 開發設計方針

> Phase：**P6 — Adventure & Campaign Runtime**  
> 本文件是 P6 的具體實作契約。產品完成條件以 `實作規格.md` 與根目錄 `規格企劃.md` 為準；測試與 closeout evidence 以 `測試指南.md` 為準。

最後更新：2026-09-19

---

## 1. P6 Subphase 順序

三份 P6 文件固定使用：

```text
P6-A — Adventure Definition & Campaign Attachment
P6-B — Campaign Runtime World State
P6-C — AI Context & Retrieval
P6-D — AI DM Write-back & Exploration Integration
P6-E — Adventure Source & Import Draft
P6-F — Import Review, Finalization & Importer MCP
P6-G — Full P6 Integration & Closeout
```

P6 先於 P5 實作；不得 import / call 尚未存在的 P5 spatial module。P5 之後承接 P6 的 asset / Campaign world substrate時只能擴充，不得要求 P6 回頭依賴 Tactical。

---

## 2. Architecture

固定依賴方向：

```text
Human Web UI ─┐
              ├─> Adventure / Campaign World application services
MCP Adapter ──┘                    │
                                   ├─ Adventure Definition repositories
                                   ├─ Campaign Runtime repositories
                                   ├─ Room Asset repository
                                   ├─ TableEventService / notifier
                                   ├─ P3 Exploration / Roll services
                                   └─ P4 Quick Combat services
```

P6 不建立第二套 Room / Campaign / Session / Seat / Event / Combat authority。

Human 與 AI 對同一 Adventure / Runtime mutation 共用 application service；MCP 只轉 intent，不可直接改 row / JSON raw field。

## P6-A — Adventure Definition & Campaign Attachment

### 3.1 Room asset substrate

P6-A 建立 Room-scoped reusable asset substrate，供 Adventure image、Importer source attachment，並讓未來 P5 Battle Map image 可重用／引用。

最低資料：

```text
room_assets
- id
- room_id
- kind                 # image | source_document
- media_type
- filename
- byte_size
- sha256
- visibility           # room | dm_only
- data / storage locator
- created_at
```

第一版可使用 DB bytea 或既有部署可可靠備份的單一 storage abstraction；不把 asset 放成可猜 URL 的 public static file。所有 download/read 必須先經 Room authority，再依關聯 entity projection 驗 visibility。

支援 image/png、image/jpeg、image/webp；Importer 文件支援 text/plain、text/markdown、application/pdf、DOCX media type。大小上限由 Settings / validation 固定並測試，不接受無上限 upload。

### 3.2 Adventure Definition

```text
adventure_definitions
- id
- room_id
- name
- summary
- ruleset
- status               # draft | finalized | archived
- created_at / updated_at

adventure_entries
- id
- adventure_id
- parent_entry_id?     # section tree / grouping only
- kind                 # section | scene | npc | item | monster_ref |
                       # quest | secret | dm_note | suggested_check |
                       # map | lore | other
- title?
- body?
- data_json            # kind-specific validated payload, not arbitrary gameplay writes
- visibility           # public | dm_only
- sort_order
- provenance_json?
- source_ref_json?
- created_at / updated_at

adventure_entry_assets
- adventure_entry_id
- asset_id
- role                 # image | map | source | attachment
- sort_order

campaign_adventure_links
- campaign_id
- adventure_id
- sort_order
- attached_at
```

Adventure entry `data_json` 允許 authoring flexibility，但每個 known kind 必須由 Pydantic typed payload 驗證；不得在 service 裡到處 `dict.get` 猜欄位。Freeform / other 才使用受限 arbitrary metadata。

Campaign 可有多筆 link；不得 unique 限制成單一 active Adventure。

### 3.3 Lifecycle

- finalized Adventure 不因 Campaign Runtime 改變而更新；
- attached finalized Adventure hard delete 需拒絕，改 archive；
- detach 只移除 Campaign link，不刪 Definition；
- Room hard delete 仍依既有 cascade / cleanup 契約；
- cross-Room attach / asset reference 一律拒絕。

## P6-B — Campaign Runtime World State

### 4.1 Generic runtime entity with typed payloads

```text
campaign_world_entries
- id
- campaign_id
- kind                 # scene | npc | item | quest | fact | secret | hazard | other
- title?
- body?
- state_json
- dm_notes?
- visibility           # public | dm_only | character
- needs_review
- source_adventure_entry_id?
- provenance_json?
- revision
- created_by_actor_kind
- created_by_actor_id?
- created_at / updated_at / archived_at?

campaign_world_entry_characters
- world_entry_id
- character_id
```

Known `kind` 的 `state_json` 一樣走 typed model；Player-facing projection不回傳 `dm_notes`、dm_only entry、或 character visibility 不屬於其 active Character 的 entry。

### 4.2 Adventure overrides

```text
campaign_adventure_overrides
- id
- campaign_id
- adventure_entry_id
- state_json
- note?
- needs_review
- revision
- updated_at
```

Override 表示「這團對原 Adventure entry 的狀態差異」，不修改原 entry。Campaign 必須已 attach 該 Adventure 才可建立 active override；detach 時保留既有 Runtime truth，但不得留下 dangling FK。具體可選 RESTRICT detach 或先 materialize/review，第一版採 **detach 被 reference/override 時拒絕**，由 DM 先清理／轉成 Runtime entry。

### 4.3 Current context

```text
campaign_runtime_context
- campaign_id PK
- current_adventure_scene_entry_id?
- current_runtime_scene_entry_id?
- current_situation?
- revision
- updated_at
```

兩個 scene ref 最多一個非 null；也允許兩者都 null。Current Situation 可單獨存在。

不建立 `character.current_scene_id`。

### 4.4 Knowledge

Character-only knowledge 使用 `campaign_world_entries.visibility=character` + recipient table。Recipient 綁 Character identity，不綁 Seat，確保跨 Session / controller handoff 後知識仍屬同一角色。

## 5. P6 authority / projection

### 5.1 Human

- Room owner / dm 可管理 Adventure / source / import；
- current Session DM 可修改 Campaign Runtime / current context；
- Player 不可建立 dm-only world truth；
- Player 可讀 public + own-character knowledge；
- Room member是否可在 Session 外瀏覽 public Adventure，由既有 Room authority + Adventure visibility 決定，第一版不新增公開分享 URL。

### 5.2 AI

Gameplay AI 沿用 P3-D `TableActorContext` / current grant / `controller_epoch` / M04 OAuth revalidation。

- current AI DM = current Session DM 的 world write authority；
- AI Player = 只讀合法 projection，不能 world-author write；
- revoked / stale grant 每次 call 都失效；
- pre-session AI DM grant仍維持 P3-D 的最小 context + Start，不因 P6 自動擴權。

Importer MCP 不得用「只要知道 Room id 就可寫」之類旁路。P6-F 第一版的 Seat-based importer tools 只在 current DM actor 已合法成立時 expose；Human pre-session importer則走既有 Room owner/dm HTTP authority。若未來要做獨立 management connector，另開後續契約，不在 P6 偷改 M04 authority model。

## P6-C — AI Context & Retrieval

新增單一 `CampaignContextService`（名稱可依現有 module convention微調，但責任固定），輸入 canonical actor / campaign scope，輸出 role-projected structured DTO。

最低 service intents：

```text
get_campaign_context(actor)
get_scene_context(actor, scene_ref?)
search_campaign_context(actor, query, kinds?, limit?)
get_world_entry(actor, world_entry_id)
get_adventure_entry(actor, adventure_entry_id)
```

`get_session_context` 只加入 compact P6 summary / references，例如：

- current scene label；
- current situation；
- attached adventure count / relevant refs；
- world entry refs；
- next recommended context tool hints。

不得把整份 Adventure entry bodies塞進 briefing。M04 `BRIEFING_MAX_CHARS` 仍是 hard gate。

Search 第一版可用 PostgreSQL normalized text / simple indexed matching，不要求 vector DB / embeddings / LLM reranker。結果必須 deterministic、bounded，且先做 authority projection再回傳。

Context source優先級：

```text
Campaign Runtime truth / Override
> attached Adventure baseline
> source excerpt
```

相同 subject 有 Runtime override時，AI DM context 必須清楚標出 baseline + current state，不能把原 Adventure 值當成仍然有效的現況。

## P6-D — AI DM Write-back & Exploration Integration

新增 `CampaignWorldService` / `WorldActionService` 層，統一 Human UI 與 MCP：

```text
create_world_entry
update_world_entry
archive_world_entry
set_adventure_override
clear_adventure_override
set_current_context
grant_character_knowledge
set_needs_review
resolve_world_action
```

所有 mutation：

- validate current actor；
- validate same Campaign / Room；
- expected revision / optimistic concurrency；
- idempotency key；
- actor audit；
- durable TableEvent；
- commit 後 notifier wake；
- reject 時零副作用。

### 7.1 resolve_world_action atomic boundary

P6 自己管理的 world writes + definitive narration 使用同一 DB transaction：

```text
validate
→ apply Runtime / Override / Current Context changes
→ append canonical world.* event
→ append narration event（若 supplied）
→ commit
→ notifier
```

任何 world validation / persistence 失敗，不可只留下「門已壞」等 definitive narration。

Existing P3/P4 mutations不被 P6 包裝成第二套 transaction engine。需要 Attack / damage / formal Check 時先呼叫原 canonical service；AI 依回傳結果再決定是否做 P6 world write-back / narration。完整跨所有 subsystem 的通用 GameTransaction留 P7。

### 7.2 Stage integration

P6 不重造 P3 Stage。Adventure / Runtime image顯示到 Main Stage時，使用既有 `ExplorationStageService` 的 revision / authority / event語意；可以用 P6 Room Asset 作來源並在 stage persistence記 authorized reference，或在 application boundary copy 成 stage image，但不得公開原始 asset URL、不得繞過 Room scope。

## P6-E — Adventure Source & Import Draft

### 8.1 Source

```text
adventure_imports
- id
- room_id
- name
- status               # source | drafting | review | finalized | cancelled
- target_adventure_id?
- revision
- created_at / updated_at

adventure_import_sources
- id
- import_id
- asset_id?
- source_kind          # paste | txt | markdown | pdf | docx | url
- source_url?
- normalized_text
- metadata_json
- sha256
- created_at

adventure_import_drafts
- import_id PK
- draft_json
- warnings_json
- revision
- updated_at
```

Draft JSON 必須有 versioned internal schema；parsed entries的 shape對應 P6-A typed Adventure entry payload。Warnings / questions帶 stable id，讓 retry / reconnect可定位。

### 8.2 Extraction

TXT / Markdown：decode + normalize。

PDF / DOCX：只做 deterministic text extraction與 source location mapping，不用 OCR 當預設，不自行做 AI parsing。無法可靠抽文字時標 source warning，Human / external AI仍可補 pasted text。

URL：第一版不讓 backend 任意 fetch Internet。External AI 可以讀取可存取 URL，再以 `import_adventure_source` 提交 normalized text + URL / excerpt metadata；Human 也可貼內容。這避免 SSRF / crawler scope膨脹。

## P6-F — Import Review, Finalization & Importer MCP

Review service intents：

```text
get_import_draft
update_import_draft
resolve_import_warning
answer_import_question
finalize_adventure
```

Finalize transaction：

```text
lock import revision
→ validate no unresolved blocking warnings
→ create finalized Adventure Definition + entries + links to assets/source refs
→ mark import finalized + target_adventure_id
→ commit
```

同一 idempotency key retry回傳同一 Adventure，不建立 duplicate。

Importer MCP tool names以產品契約為基準：

- `import_adventure_source`
- `get_import_draft`
- `resolve_import_warning`
- `answer_import_question`
- `update_import_draft`
- `finalize_adventure`

Tool descriptions必須 zh-TW / en 並進既有 M04 catalog / guide parity。MCP adapter不自行 parse；智能內容由外部 AI產生。

## P6-G — Full P6 Integration & Closeout

P6-G 不建立新的核心資料模型；它只做跨 Subphase integration、修正、browser / real ChatGPT Web gates 與 closeout。G 必須以 P6-A～F 已存在的 production services 跑通 empty Campaign 與 Adventure-driven 兩條 journey，確認 restart / next Session continuity、secrecy、idempotency、Quick Combat regression、Standalone boundary。若 G 才發現某個 A～F 必要核心能力從未實作，先回到對應 Subphase補齊並取得該 Subphase evidence，不把功能偷塞成 closeout-only hack。

## 10. REST / UI surface

路徑遵循既有 Room-first pattern，具體 route命名可按現有 `/api/rooms/{room}/...` convention。

最低 Human UI：

- Room workspace：Adventures；
- Adventure editor：entries / assets / archive；
- Campaign：Attached Adventures；
- Campaign Changes：Runtime NPC / Scene / Quest / Fact / Overrides / needs_review；
- Session DM：Current Scene / Situation、Quick Add world entry、可從 Adventure / Runtime image set Stage；
- Importer：Source、Draft Review、Warnings、Finalize。

所有首次 expose copy同 Subphase交付 `zh-TW` / `en`。

---

## 11. Events

新增 event kind採 `world.*` / `adventure.*` / `import.*` namespace，至少涵蓋正式 Runtime mutation、context change、Adventure attach/detach、import finalize。

P6 event仍使用 P3 durable event / cursor / waiter substrate；它不是 P7 跨 Session Timeline 完整模型。需要跨 Session查 world truth直接讀 Campaign Runtime repository，不靠 replay所有 Session events重建。

Secret world event依 actor projection過濾，不能把完整 payload append成 public再靠 UI藏。

---

## 12. Migration / PostgreSQL / Standalone

P6 multiplayer資料走 Web migration track。契約建立當下 current web head為 `0030_p4f_entry_dodging`；P6 從下一個可用 web revision開始，預期：

```text
0031_p6a_room_assets_adventures
0032_p6b_campaign_world_runtime
0033_p6e_adventure_imports
```

若實作前 web head已前進，使用當時 next available revision；**不可為了符合本文數字重寫已存在 migration**。P5 因改為 P6 後執行，也必須從 P6 完成後的 web head往後接，不再保留 0031～0034。

P6 table / migration不得出現在 Standalone SQLite。第一個新增 Adventure / Runtime multiplayer module的同一 commit就要擴充 `tests/test_m03_import_boundary.py` forbidden regex / protected modules，並驗 `test_m03d_schema_parity.py`。

Room asset / Adventure code不得被 `app.content.*`、`app.domain.character*`、`app.interop` 或 `app.standalone` import。

---

## 13. Concurrency / idempotency

所有 mutable Draft / Runtime / Current Context需 revision。典型競爭：

- Human DM 與 AI DM同時改 Current Situation；
- AI retry重建同一 Fact；
- Import draft舊 revision覆蓋新 edit；
- finalize double-submit；
- detach Adventure與建立 override競爭。

使用 expected revision + DB transaction / unique idempotency records解決；禁止 last-write-wins 靜默蓋掉。

---

## 14. Subphase implementation boundary

**P6-A**：Room Asset、Adventure Definition、manual authoring、Campaign attachment；不做 Runtime。

**P6-B**：Campaign Runtime / overrides / knowledge / current context；不做 AI retrieval。

**P6-C**：role-scoped bounded context / search / MCP read surface；不做 write-back。

**P6-D**：world write services、atomic P6 world+narration、Stage bridge、MCP write surface；跑通 manual Adventure / empty Campaign 的可玩 loop。

**P6-E**：Source / extraction / Draft substrate；不 finalize。

**P6-F**：Review / warning / finalize / importer MCP；不做 P7 package import/export。

**P6-G**：integration、browser、real ChatGPT Web、repair、closeout；不得把前面未做的核心能力拖到 G 才第一次實作。
