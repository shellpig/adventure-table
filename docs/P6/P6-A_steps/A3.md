# A3 — Campaign attachment

## Scope

- `app/persistence/adventures/repository.py` 追加 `CampaignAdventureLinkRepository`：`attach`、`detach`、`list_for_campaign`（依 `sort_order, attached_at`）、`is_attached`、`campaign_ids_for_adventure`（供 A2b delete 規則共用）。
- `app/domain/adventures/attachments.py`：`CampaignAdventureService.attach(room_id, campaign_id, adventure_id, context)`：owner／dm；Campaign 與 Adventure 同 Room 否則 404；Adventure 必須 `finalized`（draft／archived → 409 `adventure_not_finalized`）；已 attach → 409 `adventure_already_attached` 零副作用；`detach`：不存在 link → 404；**不**檢查 P6-B blocker（尚不存在），但 detach 只有這一個 service 入口供 P6-B 加 blocker。`list` 回 `AttachedAdventure`（link 欄位＋Adventure name／summary／status）。
- `app/api/rooms/campaign_adventures.py`：`/api/rooms/{room_id}/campaigns/{campaign_id}/adventures` GET／POST（body `{adventure_id}`）；`DELETE /{adventure_id}`。
- `tests/test_p6a_campaign_adventures.py`：attach A、attach B → list 兩筆、順序穩定；detach A → B 仍在；duplicate 409 且 link 數不變；draft attach 409；archived attach 409；cross-Room Adventure 404；member 404；detach 不存在 404。**空 Campaign regression（A.3）**：Campaign 零 Adventure 時 start Session、post narration、Exploration action、request check、start Quick Combat 全部照常（沿用既有 P3／P4 測試 helper 各呼叫一次）。**無 gameplay 寫入路徑**：斷言 `app.domain.adventures` 下沒有任何 public 方法的參數型別為 `TableActorContext`，且 MCP tool registry 不含名稱含 `adventure` 的 tool。
