## 3. 權限、引用與 transaction 共通契約

庫 authoring 接 `RoomAccessContext`，驗 context Room、有效 access session、authority=`owner|dm`；不是看 Session Seat role。AI read 接 current `TableActorContext`，驗 role=dm、有效 active Session／grant／generation；不透過目前 `_room_access_context(actor)` 偽造 Human DM 寫入權。

讀 raw map objects／custom stats、archived lookup／copy、references、asset 與管理錯誤都先驗 scope。一般 Player 即使知道 UUID 也不可讀庫；戰鬥 board 與既有合法 public rule reference／Stage asset 仍走各自 projection，不能把庫權限擴成封鎖所有 reference routes。

編輯、封存、刪除與複製來源使用 `expected_revision`；新庫 mutation 使用 `idempotency_key`。新增 `room_library_mutations`（id、Room FK、actor access session id、operation kind、key、intent digest、result refs JSON、created_at；unique Room＋actor＋kind＋key），保存 authoring result。不存 token。相同 key／intent 回原結果，不同 intent 409。Room Hard Delete 清此表；只為新庫 authoring 用，不取代 P3/P4 runtime ledger。

庫 row revision 單調增；patch／archive／delete、建立引用與開戰讀最新版在 transaction 內取同目標 row lock。次序：既有 Session runtime lock（若戰鬥操作需要）→ map ids 排序 → template ids 排序；場外 authoring 從 map／template 開始，不引入 Campaign 全域新鎖。需要同時操作兩者時遵守此序。

P6 場內 writer 先進既有 runtime transaction，再取模板引用鎖；不得在外層先鎖模板、內層另開 connection 才 append。引用校驗、domain 寫入與 event 共用同一 Connection。場外 authoring 可直接從模板 row 開始；檢查引用與刪除均在取得同一鎖後執行。

不用泛用外部引用 DSL。A 的自訂模板 resolver／引用檢查針對已存在的 typed 欄位；B 的 map 檢查針對 source board 與已存在的資料來源；C 加明確 map placement FK。建立／移除字串參照的所有 P6 writers（Human／AI、authoring、Importer finalize、override、world change）在同 transaction 取 template lock，delete 取同鎖再重查。FK 已覆蓋的引用另用 DB `RESTRICT`。由 PG race 測完整性，不能只掃 JSON 然後另開 transaction 刪除。

# M07-A — Room Monster Library

## A.1 模型與 migration

`monster_templates` 保留 table 名稱及 id，新增 `room_id` FK rooms（CASCADE）、`revision`、`archived_at?`、`presentation_json`；移除 campaign_id／舊 index，以 room_id＋archive／name 建 index。保留 source_key、name、rules、timestamps；source_key 是 provenance，不是共用 live state。

Migration 用原 Campaign 的 room_id backfill，一筆模板保持一個 id，不依名稱去重。缺 parent／非法跨 Room 引用中止並報可定位錯誤，不猜 Room、不更新已存在 `monster_instances.rules_snapshot`。`monster_instances.custom_template_id` 改 `RESTRICT`，保留 Campaign identity；Session／combat history 不重寫。Room Hard Delete 在單一 graph cleanup 中先清 dependent Campaign／Instances／references 再清 templates，不能因 RESTRICT 破壞 workspace hard delete。

既有 repository dataclass `StoredMonsterTemplate.campaign_id` 改 room_id；`create_template` 收 room_id，`create_instance_from_template` 需明確 target campaign_id，驗 Campaign Room＝template Room；`save_instance_as_template` 從 Instance 的 Campaign 推導 Room。既有 `create_instance` 也必須驗 custom source 的 Room，不能只檢查 id 存在。

規則仍用 `rules` normalized shape，基礎驗證沿 `app.content.p4a_combat_templates.monster_to_reusable_rules`／`normalize_monster_action`。新 editor 收 typed 核心欄位與攻擊更新，merge 未編輯欄位；不把自由 JSON raw patch 給 client。從內建複製／再複製保留完整 Traits／Multiattack／Spellcasting 等，description 與 automation_level 不因單一欄位 patch 被丟掉。

`presentation_json` 保存複製時 supported locale 的名稱／能力呈現與來源；canonical rules 及 structured dice 不因 locale 改動。自訂名稱／內文覆寫是使用者資料，顯示原文；沒有要求使用者填雙語。若 UI 呈現內建 desc，對應 `data/srd5.1/locales/zh-TW/monster.json` 與正式 completeness gate 同步交付，不以英文 fallback 替代。編輯 description 不得暗自聲稱自動化其效果。

## A.2 參照與封存

參照定案：內建沿 content stable key；自訂為 `custom:<uuid>`。只有 reserved `custom:` 參照須 strict UUID、同 Room、存在及使用情境驗證。P6 舊任意字串不因 M07 自動變非法；migration 只轉換能確定對應的 legacy custom identity，未識別值維持原文／警告，不猜測名字。

引用檢查至少涵蓋 Instance custom_template_id、Adventure NPC／monster_ref、Runtime NPC／override、已保存 importer draft、durable mutation／event 的 typed provenance，以及 C 的 placement。archived Adventure／Runtime／draft 仍保存有效引用時也算被引用。reference reader 是 typed walker，只讀該欄位，文字中 UUID 不算機器引用；authoring/finalization 驗出 custom ref 時即登記／檢查，不等開戰。

建立新引用不得用 archived template。既有引用可解析：caller 提交 typed origin（map placement／Adventure entry／Runtime entry id），Server 驗 origin 屬該 Room、確實已引用該模板；不接受 `allow_archived=true`。Human 複製既有地圖時可沿有效配置複製引用，不把 archived 模板放回新增選單。

刪除 template 先 lock＋收集引用；有引用回 409 `monster_template_referenced`，提供 Human 管理 scope 的摘要；無引用才能刪。封存只設定 archived_at 並增 revision。封存管理詳情可看、可複製成新未封存模板，existing refs 仍讀原 identity；不在本階段另做回收桶。

## A.3 REST／MCP／UI

Human 庫 root：`/api/rooms/{room_id}/monster-library`。

| 介面（新增設計） | 契約 |
|---|---|
| GET root／GET `/{ref}` | bounded builtin＋custom 列表／搜尋、詳情；Human Owner／DM，archive 管理 filter；ref 作 URL segment 需正常編碼 |
| POST `/custom` | 從零建立，typed 核心／攻擊／description；Room authority |
| POST `/custom/from-content` | content_key＋新名稱可選，完整複製內建資料 |
| POST `/custom/{id}/copy` | 新 identity，從自訂複製 |
| PATCH `/custom/{id}` | typed update＋expected_revision＋idempotency_key |
| POST `/custom/{id}/archive`、DELETE `/custom/{id}` | revision／引用檢查，atomic |
| POST `/custom/from-instance` | instance_id＋名稱可選，驗 Instance Campaign 同 Room，只存規則 |

UI 新頁面建議 `apps/web/src/features/rooms/RoomMonsterLibraryPage.tsx`，從 `RoomWorkspacePage.tsx` 與 `App.tsx` 接入。UI 分內建唯讀與自訂可編輯，非管理者不顯示入口且 Server 拒絕 direct request；操作失敗不清掉未保存表單。

新增 DM-only MCP `monster_library_list`／`monster_library_get`，bounded paging／query；Room 由 actor 推導，不接受 caller 改 Room。`combat_create_monster_from_template` 使用 ref 及可選 existing origin，調同一 Instance 服務；不順便改庫。Human session REST 在既有 `monster_instances.py` 加 `/from-template`，authoring Save as Template 走庫 Room access endpoint。沒有 AI 庫 create／save 工具。

錯誤：越界依既有 404 policy；`monster_template_read_only`／library auth 403；`monster_template_revision_conflict`、`monster_template_referenced`、`monster_template_archived` 409；invalid ref／rules 422。所有機器碼映射雙語，MCP 錯誤不得冒成功 result。

# M07-B — Map Library Lifecycle & AI DM Boundary

## B.1 庫 lifecycle／引用

沿既有 `battle_maps`，新增 `archived_at`，保留 Room identity、revision／objects／asset。既有 `combat_boards.source_battle_map_id` 改刪除行為為 `RESTRICT`；保留 source revision 與 frozen baseline。歷史 board 引用也阻擋刪除。若其他 typed 資料已引用 map，同樣保護；不能因目前沒有 active Combat 就認定未引用。

Human 新增 `POST /api/rooms/{room_id}/battle-maps/{map_id}/copy`、`.../archive`；copy 深複製 geometry 並產生新物件 id，可共用同 Room 的 image_asset_id。C 完成後 copy 也複製 placements（新 placement id）。list 預設排除 archived、管理 filter 可看封存詳情；新 Combat 不能選封存 map。existing board 持自己的 snapshot 繼續，不再依庫圖是否顯示。

delete 驗引用與 revision，reference 與 delete 競爭同 map 鎖＋FK 保護；Room Hard Delete 先清 dependent board 等 graph 再清 map、資產，沿既有可重試 filesystem cleanup。複製只在 DB 新增 map／objects，不複製 filesystem bytes 造成無必要副作用。

UI 新增場外 `RoomBattleMapLibraryPage.tsx`，重用 `BattleMapEditor.tsx` 與既有 `apps/web/src/api/battleMaps.ts`；editor copy／locale 不得綁 active Session。保留 Tactical Setup Panel 的選圖／編輯入口，但由 Room authoring 權限控制編輯；Human 僅有 current DM Seat 而沒有 Room DM authority 也不能 author 庫。

## B.2 AI boundary 與臨時棋盤

移除 `app.mcp.tools` 中 `battle_map_create`／`battle_map_patch`／`battle_map_replace_objects` definitions、description intent、dispatch 與對應 AI application 方法；移除 `guide_tool_names` 與 Join Kit／guide 引用。呼叫移除工具用協定 unknown-tool 錯誤；即使舊 adapter 被直接調用，也無可把 Seat 映成 Room DM 寫庫的入口。

`battle_map_list`／`battle_map_get` 仍驗 active DM grant，以 actor Room 只讀服務，不偽造 Human access。這包含已存在 map get raw geometry 投影與後續 C 預配置，不對 Player 開放。

BattleMapService 新增 `get_for_actor`／`list_for_actor` 只讀入口，從 TableActorContext 重驗授權後調共用內部讀取／projection；Human 原 get／list 仍用 RoomAccessContext。兩者讀相同 repository，不能用 AI-specific raw DB bypass 或偽造 owner／dm context。

擴充既有 `StartTacticalCombatInput`：新增 optional `temporary_map`，typed `TemporaryBattleMapInput(width_cells,height_cells,walls,doors,terrain,drawings)`，不含 library map id／expected revision。既有 `battle_map_id`、blank dimensions 與 temporary_map 三者嚴格互斥；庫圖與空白舊合法 payload 繼續接受。

Wall／Door／Terrain／Drawing 沿 `BattleMapObjectsReplace` 的 element schemas，抽共用 object／bounds validator，不能把含 expected_revision 的整個 replace DTO 強塞進 temporary_map。臨時 object id 由 Server 分配，client 不可引用另一庫 map 的 object；door 預設 state／visibility 與 drawing limits 沿既有規則。

`_freeze_board` 接臨時來源，產生 board baseline 及 runtime doors，`source_battle_map_id=null`、`source_battle_map_revision=null`。`create_tactical_combat` 只寫 Combat board／entries／events，絕不 insert battle_maps／Room assets。擴充已存在 `combat_start_tactical` MCP 與 Human Tactical REST 使用相同 schema；對 Player／pre-session grant 拒絕。

## B.3 錯誤與 revision

封存選圖 409 `battle_map_archived`；引用中刪除回 409 `battle_map_referenced`；stale copy／patch／archive 沿 map revision conflict；source conflict／臨時物件非法回 422。臨時圖失敗不建 board／Combat／事件，retry 重用原 combat 而非生成新物件；formal transaction 與 notifier 沿既有 P4/P5，notify 只在 commit 後。

# M07-C — Map Monster Placement & Combat Load

## C.1 模型與編輯

新增 `battle_map_monster_placements`：id、battle_map_id FK（CASCADE）、template_key?、custom_template_id? FK（RESTRICT）、anchor_x、anchor_y、visibility、sort_order；兩種 source 恰一，visibility 僅 public／hidden。數量由 rows 計算，沒有 count。Room 從 map 推導，custom 須同 Room；不保存 HP／initiative／資源或 Monster Instance id。

預配置是 map revision 的一部分。Human 新增 `PUT .../battle-maps/{map_id}/monster-placements`（expected_revision、整組 typed placements、idempotency_key），同 transaction 替換與增 map revision；給 get map 的管理 DTO 加入 placements。既有 objects PUT 只改 geometry，不因省略 placements 而清掉它們。保存 map 縮小／改 terrain 時驗現有 placement，衝突列明且拒絕；模板外部變更仍在開戰重新驗。

Editor 接內建／custom 模板列表與 footprint，以 `resolve_entry_size`／`footprint_for_size` 共用來源 preview，放置的物件是模板引用。支援 drag／remove／hidden；不呼叫 live `place_position` API，不創建 Instance 或改 Character 位置。

## C.2 Atomic Tactical load

`StartTacticalCombatInput` 新增 `load_map_monsters=false`；僅 battle_map_id 來源可為 true。UI 顯式提供只載入地圖／連怪物選項；blank／temporary_map／Quick 帶此 flag 拒絕。保持舊客戶端預設只載入地圖。

開戰 atomic 步驟：

```text
驗 current authority／DM scope → 查 idempotent 已完成結果
→ 新建立操作驗 active Session binding
→ 取得既有 Session runtime 互斥、map lock、來源 templates 排序 lock
→ 讀 map revision 與全配置、解析當前完整 rules＋template revisions
→ 用同份 board geometry 與最新 Size 做全批 placement validation
→ 同 Connection 建立各 Instance／Combat／entries／board／doors／positions／events
→ 保存 idempotent result → commit → notifier
```

不能迴圈呼叫獨立 commit 的 create_instance／add_monster／place_position。給 repositories 增加 internal connection-aware 方法，共用既有純 rules／spatial validator 與 event allocator；戰鬥權限、turn economy／RNG 不另造。

保存 Monster `rules_snapshot`、source ref/revision 與 Combat board map revision；copy-derived presentation 同時快照，避免 live 模板 rename 影響舊戰鬥。新 Instance 滿 HP、無 conditions／concentration、initial resources 沿既有初始化；AI 角色行為不能為 library 權限繞過 Character writer。

批次驗 bounds／footprint／blocked terrain／wall/door interior／全 batch overlap，不僅逐隻對尚未創建的位置驗。Party entries 仍由 existing auto-include 建，初始未定位角色不虛構位置；其後依既有 placement gate 才可 initiative。DM problem DTO 列 placement id 及錯誤 code，只給 DM。

`map_monster_placement_invalid`409 帶整批問題；missing／wrong Room template 回 404、invalid source 回 422、stale intent 回 409。失敗 rollback 所有 Instance／Combat／event／board，map 與 template 未變。已成功 retry 先讀 result，不因庫模板後來改變重新 validation 而 spawn 另一批。copy map 保留已有 archived template 引用，新增 placement 不能引用 archived 模板。

成功操作的 Human idempotent replay 沿既有 End／Abandon 後的合法 current binding 契約，不把讀取舊結果當新建戰鬥；新操作才要求 active Session。AI 仍須有效 active grant，已撤銷 grant 不能藉知道舊 key 取得結果。stored start intent 必須包含 map source、load_map_monsters 及 temporary geometry digest，避免同 key 不同來源誤回成功。

## C.3 Secrecy 與歷史接線

Current combat view／detail、board、initiative request／suggested order／ties／turn summary、roll／mutation responses、Resume、MCP 都以同一 Server audience projection 排除 hidden identity／位置／數量。公開 ordinal／group count 不可讓 Player 逆推出隱藏參與者；placement 載入內部 audit 可 DM-only，對 Player 事件只含其可見資料。

修正 `get_table_event_service` 現 `hidden_combat_entry_ids(campaign_id)` 的 get_active 接線。按每事件來源 combat_id／durable entry 或 roll request 關聯解析 hidden ids，同頁按 Combat cache；ended Combat 與別場 active Combat 名單不能混用。需持久化 event-time visibility facts 於多人層 sidecar（event id、Combat、hidden entry／instance ids），不送公開 DTO；legacy events 以已保存來源驗證，無法確定則對 Monster identity 保守遮蔽，不改原 event payload 或泛用玩家 Narration 文字。

新增 `combat_event_visibility`：event_id FK `session_events.id`（CASCADE、PK）、combat_id FK combats（RESTRICT）、hidden_entry_ids／hidden_instance_ids JSON。與 source event 同 transaction 寫入，adapter 不回傳此表；event-time facts 不隨後來 Reveal／模板更新覆寫。解析表中來源須驗 Room／Campaign 與該 event 一致；舊資料 backfill 不可猜測缺失來源或把未知視為公開。

將來源解析及 redaction 接入 `TableEventService._present`／`_hidden_ids_for` 與所有 page／wait／Resume consumer，不只新 load 的 HTTP response。M05 history／Player replay 與 MCP pending events 實測修 KI-P5A-001；M06 own-echo 維持 seq，不使用 sidecar 做 authority。正式修復後證據留 M07-C closeout，D 更新已知問題條目；這次文件準備不改已知問題檔。

# M07-D — Full M07 Integration & Closeout

## D.1 回歸與實際 AI

全 stack 真 PG journey 驗兩 Room、同 Room 兩 Campaign 共庫而 runtime 分離、舊模板 migration、雙語、封存引用／Room Hard Delete、template update 與 batch load 競爭、restart／跨 Session board 不變。AI 正式 M04 connector 跑查庫、庫圖預配置 load、臨時 map、庫 mutation 拒絕／舊 tool 錯誤、Reveal、revoke 與 history；不能用 HTTP stub 替代正式 AI client 證據。
