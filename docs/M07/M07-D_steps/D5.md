# M07-D D5 — 真人使用驗收

## 決定與範圍

使用者於2026-10-05決定：M07-D剩餘的正式AI connector gate改為真人實際使用驗收。既有AI權限／MCP自動化驗證仍保留；真人通過不代表已驗證真實AI client的OAuth／Join Kit、工具理解、wait／reconnect或主持能力。此決定只適用M07-D，不改P5延期記錄或未開工P7的正式AI要求。

本步狀態只住M07-D步驟板；下面目前是操作計畫，尚無真人通過結果。完成本步後仍需D.3工程gate、限制處置與closeout，不能直接宣稱M07關門。

## 準備方式

1. 使用包含 `f79d3d10`（D3程式基準，亦含D1／D2修補）的Web build。文件commit不更新已啟動的Docker映像；若介面仍缺相關功能，先依README部署目前分支的版本再驗，不把舊build結果混入。網址沿实际部署，本機預設 `http://localhost:5173/`。
2. 建立新Room「M07真人驗收」，全部用專用測試角色與素材；不在既有朋友Campaign上試刪除、封存、傷害。驗收不需要執行會重置DB的E2E script。
3. 真人DM與Player各操作自己的獨立browser身份。可同一人切換驗，但更建議兩人實際協作；準備A＝建立Room的Owner、B＝只用Room code／password進入的一般Player、C＝另一個只用code／password進入的Member。不同瀏覽器或Chrome不同個人資料可隔離；多個無痕視窗常共用同一身份，不能當B／C隔離。
4. A建Campaign A、準備一位可正常攻擊／移動的測試PC並放Roster，指定A為Human DM、B為PC的Player controller。C先不授予DM Key／Owner Key，留作後面的Member DM測試。Adventure／Scene可完全不建立。
5. 場外準備：從Goblin內建複製一個自訂「驗收_斥候」、從Ogre複製「驗收_大守衛」，保留不同Size與攻擊能力。HP等數值可刻意改為驗證用值（下文20→30只是自訂測試資料，不是SRD規則）；另準備一張底圖與一張空白地圖。

Server process restart、真PG migration／race、Standalone／Web exchange與AI MCP拒絕等已有自動化範圍；本真人gate不要求使用者操作終端或反覆重建daily服務。重新整理／重連不是server restart，兩者證據分開。P7 Snapshot／Restore／portable UI尚未實作，本次不找這些功能。

## 記錄方式與判定

每項填 `PASS / FAIL / BLOCKED / 未做`，加角色A/B/C、locale、實際build／日期及一兩句結果。保存關鍵畫面（配置與載入、DM／Player Reveal前後、Member DM無authoring、跨Session同一Combat、封存／刪除提示）。若不方便錄影，文字＋截圖即可；不保存Room password／Owner或DM Key／AI token。

FAIL記「第幾步、預期、實際、是否每次發生」，不要直接重試到綠後刪掉失敗記錄。D3曾觀察P5G列表一直Loading／movement confirm後不移動；真人若再遇到，要保留畫面與操作順序。條目有partial pass要分開記，不把未做視為通過。

回報可用此格式：

```text
日期／build：
實際操作者與browser身份：
H01：PASS／FAIL／BLOCKED／未做；觀察：
... H13：
問題：步驟／角色／locale／預期／實際／重現頻率／截圖
操作手感：哪些地方卡、看不懂、容易誤按
```

H01～H13必要路徑由真人完成並有可定位結果後，才能整理本步驗收結論；已知限制與任何blocked／未做仍需明列。正式AI client使用未驗，不在此表填PASS，不改成「AI已驗收」。
