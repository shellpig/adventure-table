> Phase：**M07 — Room Map & Monster Libraries**
> 本文件定義完成條件與驗收意圖；具體資料模型與介面見 [開發設計方針](開發設計方針.md)，驗收見 [測試指南](測試指南.md)。產品行為以根目錄 `規格企劃.md` 為準。

## 1. M07 定位

P5 已關門。M07 插在 **P5 → M07 → P7**，補齊 Room 工作區的場外地圖庫、怪物庫與可選怪物預配置；不需啟動 Session 即可備團，同 Room 的 Campaign 可重用。

承接產品規格第二章「Room 地圖庫／怪物庫權限」、第四章「Room Workspace」、第六章「地圖庫與怪物預配置」、第八章「怪物庫」及第十一章「資料生命週期」。內建資料保持唯讀，庫內原始資料、Campaign Monster Instance 與 Combat board 是三個不同生命週期。

本階段不建立必要的 Encounter Template、不重造 Combat／施法／擲骰／空間引擎，不做跨 Room 共用 identity、Fog／Lighting／3D 或自動把戰鬥變化寫回庫。現在只設計 M07；P7 相容文件修訂列為 M07-D 交付，不在準備 M07 時提前改 P7。

## 2. 共通硬原則

- Human Owner／DM 以 **Room authority** 管理庫，不因今日坐 Player Seat 就失去 Room 管理權；一般 Human／AI Player 的 Seat role 不授予查庫權。
- 僅具 Member Room authority 的 Human current DM 可在有效 active Session 唯讀列出／讀取同 Room 兩庫並用於戰鬥；不授予任何庫 authoring。Owner 在開場前指定 DM Seat、Session中途不換DM的規則沿P2。
- AI DM 只在有效 active Session 內查庫、使用模板／地圖與戰鬥配置；不得建立、修改、複製、封存或刪除庫內資料。pre-session grant 不能查庫。
- Human 與 AI 的戰鬥使用共用後端規則；禁止 MCP 偽造 Human Room authority 作庫操作。
- 秘密在 Server projection 過濾，庫資料及 hidden 配置不以 UI 隱藏取代權限。
- 角色核心、共用 content 與 Standalone 不反向依賴 Room 庫。Room 自訂模板屬多人層，內建 Monster content 仍可供 Standalone 共用。
- 新 UI、錯誤、MCP 說明及首次呈現的內建規則內容同時交付 `zh-TW`／`en`；唯一例外是內建 Monster 能力 `desc`（見 A.1）。自訂文字是使用者資料，不強制翻譯；從內建複製保留原有雙語名稱與呈現資料。
- 庫編輯以 revision 防衝突，建立／複製由 UI 防連點，不承諾庫操作可冪等重送。開戰與既有戰鬥 retry 維持原保證；拒絕操作對正式資料、事件與 runtime 零副作用。

# M07-A — Room Monster Library

## 目標

Human 在 Room 工作區備好可重用怪物；AI DM 可在 Session 中查閱及使用，Instance 永遠保留建立時的規則快照。

## 完成後必須為真

### A.1 場外怪物庫與內建唯讀

Room 有怪物庫入口、列表／搜尋、詳細資料、建立、複製、編輯、封存及未引用刪除。內建 Monster／Beast 來自 pinned content manifest，不修改規則來源；可選「以此建立自訂怪物」產生新 Room 模板。

可從零建立或由 Quick Enemy「Save as Monster Template」保存規則。編輯核心數值與攻擊，其他能力保留 description 與原有資料，由既有 automation／DM adjudication 處理；不要求所有能力變成自動腳本。複製後只改 AC 等單一欄位，不得清掉未編輯的 Traits／Spellcasting／Multiattack／其他能力。

所有流程不要求 Session／Combat。內建怪物詳情顯示能力 `desc`：依 AGENTS 工程守則 7 的唯一例外，`zh-TW` 介面以英文原文顯示並明確標示，不納入搜尋；怪物名稱、能力名稱及其他 UI 仍須雙語。複製成自訂怪物後，帶過來的說明文字成為使用者資料，可照原文顯示與編輯。

### A.2 Room identity、migration 與引用

模板改為 Room 所屬。Migration 支援空表；若有 rows，按原 Campaign 回填 Room，保持 identity、來源、規則與 Instance 快照，不依名稱合併。只允許同 Room 引用，其他 Room 不可查、改或建立 Instance。

被 map 預配置、Adventure／Runtime、Monster Instance 或歷史引用的模板不能永久刪除。封存保留 identity，不出現在新增怪物選單；只有載入地圖已保存的預配置可用原封存模板建立 Instance，其他建怪入口拒絕。Human 管理頁仍可讀詳情及複製成新模板；既有 Adventure／Runtime 參照保留供歷史辨識。

新增自訂模板引用與刪除競爭時，合法結果不能留下失效參照；Instance、配置與歷史引用仍受保護。不另造通用引用追蹤系統，也不轉換假想的舊自訂參照格式。

### A.3 使用模板與控制權

Human／AI current DM 可從庫建立 Campaign Monster Instance，沿既有戰鬥加入流程。模板更新只影響新 Instance；舊 Instance 的 HP、資源、能力與 rules snapshot 不同步。

Save as Template 限 Human Room Owner／DM，只保存規則與可用來源資料，不帶 current HP、initiative、conditions、reaction 已用等 live state。AI DM 可建 Quick Enemy Instance，但不能藉此存入庫。

AI 的查庫工具每次重驗 current Seat grant／Session／epoch；Player、pre-session grant、revoke／Take Back 後皆不能查庫。庫管理 API 不接受 AI token 取代 Room access。

# M07-B — Map Library Lifecycle & AI DM Boundary

## 目標

在 Room 場外管理可重用地圖，並讓 AI DM 透過正確戰鬥入口建立臨時棋盤，收回既有 AI 寫庫能力。

## 完成後必須為真

### B.1 地圖庫 UI 與生命週期

Room 有地圖庫入口，重用現有 editor：空白格線／上傳底圖、牆、門、地形與繪圖、保存、再次編輯、複製、封存、未引用刪除。上傳沿既有 Room asset 與 grid alignment，不新增另一套 storage。

複製建立新 map identity，幾何物件 identity 亦獨立，可共用同 Room immutable 底圖。已被 Combat board／歷史或其他有效資料引用的地圖只能封存；封存圖不出現在新開戰選單，既有戰鬥仍可繼續。Room Hard Delete 仍是整包刪除例外。

### B.2 AI 唯讀庫與臨時地圖

正式工具清單及 guide 不再提供 AI 寫庫的 create／patch／replace_objects；直接呼叫舊工具亦被拒絕，不能只藏掉工具介紹。AI DM 保留 active Session 內的 list／get／選用庫圖能力。

AI／Human current DM 可在開 Tactical Combat 時提交臨時地圖的 Wall／Door／Terrain／Drawing，直接建立該場 Combat board，不產生庫內地圖。臨時資料使用既有物件與空間驗證，不放寬 bounds／visibility／payload 限制。

庫圖、空白棋盤、臨時幾何三種方式皆可開戰；來源互斥，非法組合零副作用。戰鬥中的變化不回寫原始地圖。

### B.3 既有流程與接入相容

Human 場外操作不要求 fake Session actor；active Combat runtime 的 DM 權限與操作保持。AI Join Kit、tool schema、dispatch、guide 同步交付雙語，舊 AI conversation 使用已移除工具能收到可理解的錯誤並改用臨時地圖入口。

Quick Combat 不需 map／board，既有公開戰場圖片與合法 asset 讀取不被誤封鎖。Player 不得透過 raw 庫 API／UUID／錯誤資料讀到庫圖秘密。

# M07-C — Map Monster Placement & Combat Load

## 目標

Human 可在庫圖預放怪物，Human／AI DM 開 Tactical 時整批載入；保持秘密、原子性與 existing combat lifecycle。

## 完成後必須為真

### C.1 可選預配置

每隻配置保存內建／自訂模板參照、站位與 public／hidden；數量由配置數決定，不另存 count，不綁 Character／Seat 或既有 Monster Instance。Editor 可放置、移動、移除、改可見性，使用模板 Size 顯示 footprint。

庫圖可只載入地圖，或連同配置載入；Quick 不使用預配置，仍可加入未封存模板建立的怪物。封存模板只供地圖已保存配置載入，不能從一般建怪入口使用或新增到配置。複製地圖可保留原配置的有效引用，配置 identity 則是新的。

### C.2 最新模板、整批拒絕與獨立 runtime

開戰時按一致資料點解析模板最新版，產生各自獨立 Instance／Combat Entry／position，保留來源模板及 map revision。模板變大導致重疊、越界、壓到阻擋等時，整批拒絕並向 DM 列出問題；不挪位置、不略過壞怪物、不留下半場戰鬥或一部分 Instance。

Party 仍沿既有 auto-include 與 placement／initiative gate，不預放玩家角色、不自動開始先攻或擲骰。已開戰後改模板／map／配置不影響該場；同 Room 其他 Campaign 可使用同庫而獲得自己的 Instance。

同 request retry 只得到原來那場戰鬥與怪物，不能因模板更新又 spawn 一批；相同 idempotency key 配不同意圖須拒絕。

### C.3 Server secrecy

Hidden 預配置不向 Human／AI Player 暴露存在、數量、identity、名稱、位置或 initiative，直到正常 DM Reveal。Server 管理者驗 placement 時可讀 full truth，但錯誤不可傳給無權 Player。

本條只涵蓋進行中的戰鬥。已結束戰鬥的隱藏 Monster 在歷史中洩漏是既有缺陷 `KI-P5A-001`，依使用者 2026-10-03 決定仍由 P7-A 修正，M07 不處理也不新增歷史 projection 接線。

# M07-D — Full M07 Integration & Closeout

## 目標與完成條件

### D.1 完整旅程與 migration

場外建立自訂模板／地圖 → 預放不同 Size、public／hidden 怪物 → 改模板 → 開新場載入最新版 → placement／initiative → 攻擊／移動／Reveal → End／跨 Session 接續 → 改庫但已上場資料不變。另一 Room 及同 Room 第二個 Campaign 都須驗 scope。

真 PostgreSQL migration 驗空模板表及少量 seeded rows，並驗既有 map／board；restart 後庫、配置與戰鬥一致。P4／P5／P6 consumer、Standalone boundary、雙語與E2E取得證據。依使用者2026-10-05決定，M07-D剩餘使用gate改為真人DM／Player實際操作驗收，流程與證據見測試指南D.2；不把真人結果宣稱為真實AI connector已驗證，既有AI／MCP自動化要求不取消。

### D.2 P7 契約交接

M07-D 才修訂 P7 正式文件：Room 怪物庫、地圖預配置、封存狀態、來源／typed 引用與 revision 納入 portable export／import／reference registry；Room 備份保留共用 identity，Campaign 匯出包含自己的完整引用閉包，Import 仍 new copy。

同時修正 P7 Snapshot 範圍：Room 怪物模板是共用 authoring，不隨 Campaign Restore 回捲；Instance rules snapshot 與庫分離。這是文件與相容交接，不在 M07 實作 P7 serialization／Snapshot／API。

### D.3 關門證據

每條 A.1～C.3／D.1～D.3 對應實際測試節點、commit、環境與結果。完整工程gate、真人使用gate、產品符合性與文件一致性均完成後才關門；真實AI client未驗範圍依使用者決定明列，不冒充已通過。依AGENTS完成closeout與簡報／歷史搬移。
