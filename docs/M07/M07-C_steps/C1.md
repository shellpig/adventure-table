# C1 — Backend：配置模型、配置 PUT、map lifecycle 接線、整批 placement validator（Muse）

## Scope

- web track migration `0043`：`battle_map_monster_placements`（id、battle_map_id FK CASCADE、template_key?、custom_template_id? FK RESTRICT、anchor_x、anchor_y、visibility public|hidden、sort_order；兩種 source 恰一）。不存 count、HP、initiative、資源或 Instance id。revision id ≤ 32 字元。
- Persistence：讀取／整組替換配置；map copy 複製配置並給新 id。
- `BattleMapService`：`replace_monster_placements(context, room_id, map_id, input)`，收 `expected_revision` 與整組 typed placements，同 transaction 替換並增 map revision；鎖序依設計 §3（map → templates 依 id 排序）。來源規則：內建 `template_key` 須存在於 content；custom 須同 Room；新增或改成封存模板拒絕，已保存且未改變的封存引用可保留。
- 整批 placement validator（純函式，C2 開戰重用）：以模板 Size 算 footprint，驗越界、Blocked terrain、牆／非 open 門切過 footprint 內部、全 batch 互相重疊；回傳每筆問題（placement id＋code），不在第一筆就停。
- 管理 map DTO（Human `get`／`list` 詳情、AI DM `get_for_actor`）帶配置；既有 objects PUT 與 patch 只改幾何，不清空配置；改尺寸或幾何後若現有配置衝突，整筆拒絕並列問題。
- 自訂模板刪除：`is_monster_template_referenced` 納入配置，回既有 referenced 409，不靠 FK IntegrityError。
- Human REST：`PUT /api/rooms/{room_id}/battle-maps/{map_id}/monster-placements`，權限沿 RoomAccessContext owner|dm；錯誤碼對應設計 C.2（配置問題 409 `map_monster_placement_invalid` 帶 DM-only 問題清單、缺引用／跨 Room 404、非法來源 422、revision 衝突沿用 `battle_map_revision_conflict`）。
- `test_m03_import_boundary.py`、`test_m03d_schema_parity.py` 納入新 table。
- 不做：開戰載入、名稱呈現、Player／AI secrecy projection、MCP 新工具、前端（C2／C3）。
