# C3 — Frontend：配置 editor、開戰載入選項、名稱呈現、雙語 copy（Muse 1.3 via OpenCode CLI）

## Scope

- API client（`apps/web/src/api/battleMaps.ts`、`tacticalCombat.ts`、相關型別）：`BattleMap.monster_placements`、`PUT .../monster-placements`（`expected_revision` + 整組 placements）、`TacticalStartInput.load_map_monsters`、錯誤碼 `map_monster_placement_invalid`（`params.problems[]` 的 `placement_id`／`code`）、`monster_placement_reference_not_found`、`monster_placement_invalid_source`、`combat_idempotency_conflict`；combatant 的 `name_presentation`。欄位一律對照 server model，不自造 optional 欄位。
- 庫圖 editor（`BattleMapEditor.tsx`／`mapEditorState.ts`／`BattleMapCanvas.tsx`，Room 地圖庫頁進入）：怪物配置模式，從內建／自訂模板（`monsterLibrary` API，`ref` 為 content key 或 `custom:<uuid>`）選擇後放到格子；依模板 `size` 畫 footprint；可拖曳移動、移除、切換 public／hidden；儲存走配置 PUT。封存模板不出現在新增清單，但地圖已保存的封存配置照常顯示並可移動／移除。409 problems 在對應配置上標出錯誤並列出原因；revision 衝突沿用既有地圖 editor 的處理。編輯配置不呼叫任何 live combat API。
- Tactical 開戰（`TacticalSetupPanel.tsx`）：以庫圖開戰時提供「只載入地圖」與「連同怪物載入」，預設只載入地圖；空白／臨時地圖不顯示此選項。載入失敗時顯示 DM-only 問題清單，修正後可重試。
- 名稱呈現：怪物名稱顯示處使用 `name_presentation`：`name_is_custom` 為 true 用原名；否則用目前 locale 的 `names[locale]`，再 fallback `names.en`，再 fallback 原本的名稱欄位。沒有 `name_presentation` 的舊資料維持現狀。
- 所有新 UI copy 同步 `zh-TW`／`en`（含錯誤碼與 problem code 的說明），parity test 要過。
- unit test：editor 放置／移動／移除／hidden 切換送出的 PUT payload、problems 顯示、開戰選項送出的 `load_map_monsters`、名稱選擇規則、封存模板不可新增。
- 不做：後端、Playwright E2E（C4 由指揮者寫並以 Docker 跑）。

## 對應契約

規格 C.1～C.3 的 UI 部分；設計 §1（`BattleMapEditor.tsx`／`TacticalSetupPanel.tsx` 列）、C.1、C.2 的 UI 段落；測試 C.1～C.3 與 Browser 段。後端欄位見 [C1](C1.md)、[C2](C2.md)「交付」。

指揮者本機：`npm test -- --run`、`npm run build`（cwd `apps/web`）、diff 審核（每個新欄位對照 server model、每個新 handler 有呼叫者）；C4 再以 Docker 跑 `e2e/m07c-map-monsters.spec.ts`。
