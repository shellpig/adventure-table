# C2 — Backend：原子 Tactical 載入、名稱呈現快照、idempotency intent、secrecy（Muse）

## Scope

- `StartTacticalCombatInput.load_map_monsters: bool = False`：只有 `battle_map_id` 來源可為 true；blank／temporary_map 帶 true 拒絕（422）。舊客戶端不帶時行為不變（只載入地圖）。Human REST 與 MCP `combat_start_tactical` 同一 schema，MCP 說明雙語更新。
- 開戰原子流程依設計 C.2：驗 current authority → 查 idempotent 已完成結果 → 新操作驗 active Session → Session runtime 互斥、map lock、templates 依 id 排序 lock → 讀 map revision 與全配置、解析最新模板 → 以凍結 board geometry 與最新 Size 跑 C1 的 `validate_monster_placements` 全批驗證 → 同一 Connection 建 Instance／Combat／entries／board／doors／positions／events → 保存結果 → commit → notifier。不得迴圈呼叫獨立 commit 的 create_instance／add_monster／place_position；需要時給 repository 加 connection-aware 內部方法。
- 開戰時封存模板只要是地圖已保存配置就可載入；缺模板／跨 Room 404；配置問題 409 `map_monster_placement_invalid`（problems 只給 DM）；任一失敗整批回滾，庫不變、無半場戰鬥、無多餘事件、不提前 notifier。
- 每隻怪物獨立 Instance／Combat Entry／position；visibility 依配置（hidden → Instance hidden）。Party 沿既有 auto-include，未定位角色不虛構位置，initiative gate 不變；不自動擲先攻。
- 快照：`rules_snapshot.provenance` 記來源（template_key 或 custom_template_id）與自訂模板 `template_revision`（內建不虛構 revision）；Combat board 記 map revision。`rules_snapshot.presentation.names`（可用的 en／zh-TW）與 `name_is_custom`，不新增 Instance SQL 欄位。DM／Player projection 只送可見怪物的 `name_presentation`（names、name_is_custom）與 name，不送整份 rules snapshot；缺 presentation 的既有 Instance 以 name 兜底。之後改模板不影響已建 Instance。
- Idempotency：stored start intent 含 map source、`load_map_monsters`、temporary geometry digest；同 key 不同意圖 409，且不建立任何 Instance。成功後 retry 回原結果（模板之後改了也不重 spawn）。Human 在 End／Abandon 後以合法 current binding retry 仍取原結果；新 key 不得在已結束 Session 建戰鬥；AI grant 已失效即使知道舊 key 也拒絕。
- Secrecy（只限進行中戰鬥）：hidden 預配置怪物對 Human／AI Player 在 combat view／detail、board、initiative request／suggested order／ties、turn summary、group count／ordinal、events、roll／mutation responses、Resume、MCP 都不洩存在、數量、id、名稱、位置。DM 全看得到，Reveal 照常。事件沿既有 `hidden_combat_entry_ids` → `TableEventService._hidden_ids_for`，不新增 sidecar table、不動歷史 reader（`KI-P5A-001` 屬 P7-A）。
- 不做：前端、新 MCP 寫庫工具、配置編輯（C1 已完成）。
