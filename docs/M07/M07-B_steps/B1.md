# B1 — Backend：migration、庫 lifecycle、AI boundary、臨時地圖開戰（agy）

## Scope

- web track migration `0042`：`battle_maps.archived_at`；`combat_boards.source_battle_map_id` 由 `SET NULL` 改 `RESTRICT`。Room Hard Delete 順序確認先清 board graph 再清 map／資產。
- `BattleMapService` 庫 lifecycle：`copy`（深複製 geometry、新物件 id、共用同 Room `image_asset_id`，不複製 bytes）、`archive`、list 預設排除封存＋管理 filter、delete 驗 revision 與引用（board／歷史 board 皆阻擋，409 `battle_map_referenced`）；copy／archive／delete 帶 `expected_revision`，鎖序依設計 §3。
- Human REST：`POST .../battle-maps/{map_id}/copy`、`.../archive`；既有 route 權限仍為 RoomAccessContext owner|dm。
- AI boundary：移除 `battle_map_create`／`battle_map_patch`／`battle_map_replace_objects` 的 tool definition、dispatch、AI application 方法、guide 名單與 Join Kit／guide 引用；`battle_map_list`／`battle_map_get` 改走新 `BattleMapService.list_for_actor`／`get_for_actor`（TableActorContext 重驗 active DM grant），不再用 `_room_access_context(actor)`。
- 臨時地圖：`StartTacticalCombatInput.temporary_map: TemporaryBattleMapInput`，與 `battle_map_id`／blank dimensions 三者互斥；共用抽出的 object／bounds validator；`_freeze_board` 產生 `source_battle_map_id=null` 的 board；封存 map 開戰 409 `battle_map_archived`；Human REST 與 `combat_start_tactical` MCP 同 schema。
- M03 import boundary／schema parity 視新增欄位更新。
