> Phase：**P3 — Exploration + Roll + AI**  
> 本文件定義 P3-A～P3-F 的自動／人工驗收與 closeout evidence。產品完成條件以 `實作規格.md` 為準；具體架構、schema、API、MCP與transaction contract以 `開發設計方針.md` 為準。

## 1. P3 Subphase 順序

三份 P3 文件固定使用：

```text
P3-A — Session Table Runtime & Event Stream
P3-B — Exploration, Chat & Actions
P3-C — Roll, Check & PendingAction
P3-D — AI Controller, Scoped Token & Handoff
P3-E — AI Tool Surface & Event Delivery
P3-F — Full P3 Integration & Closeout
```

每個 Subphase 的 code與對應tests同一小階段完成；先做focused local驗證與static review，review完成後才依 `AGENTS.md` gate使用GitHub Actions。不要把permission / secret filtering / restart / concurrency全部留到P3-F第一次驗。

## 2. P3 測試核心風險

P3開始處理真正的多人桌上即時事件與外部AI credential，最危險的regression不只是UI壞掉，而是：

- Player / AI Player收到DM-only或secret DC。
- Whisper DM被其他Seat讀到。
- 猜event sequence / UUID繞過audience filter。
- reconnect後pending roll消失或被重roll。
- retry造成同一formal RollRequest出現兩個結果。
- Character State已改，但對應table event沒commit；或反過來。
- Player Human → AI → Human後舊token還能操作。
- AI DM拿到Owner destructive authority。
- AI DM disconnect後Session被錯誤接管／自動結束。
- event同步靠process-local queue，server restart就斷歷史。
- Session頁為了即時更新高頻重抓P2 Resume，放大N+1。
- MCP adapter直接繞過Human UI共用service。
- standalone因P3新module/table/MCP route被多人層污染。
- P3 event log被誤當成P7完整Timeline，形成難以演進的contract。

P3 minimum gate因此是：

```text
scope isolation
+ audience secrecy
+ durable ordered events
+ atomic gameplay writes
+ roll idempotency
+ controller generation / token revocation
+ real PostgreSQL concurrency
+ real browser UX
+ real external MCP client
+ restart recovery
+ standalone independence
```

## 3. 執行環境與指令原則

### Backend

Windows / PowerShell 5.1 不使用 `&&`。需要 `alembic.ini` / relative path的Backend Python指令，cwd在 `apps/server`，interpreter使用repo root `.venv`。

```powershell
Set-Location .\apps\server
..\..\.venv\Scripts\python.exe -m pytest
```

Focused：

```powershell
Set-Location .\apps\server
..\..\.venv\Scripts\python.exe -m pytest tests\test_p3a_table_events.py -q
```

### PostgreSQL focused tests

P3建立自己的環境變數：

```text
P3_POSTGRES_URL
```

CI service同時：

```text
P3_POSTGRES_URL=<dedicated test db>
DATABASE_URL=$P3_POSTGRES_URL
```

本機示例：

```powershell
docker compose up -d db
docker compose exec -T db psql -U adventure -d postgres -c "DROP DATABASE IF EXISTS adventure_table_p3_test;"
docker compose exec -T db psql -U adventure -d postgres -c "CREATE DATABASE adventure_table_p3_test;"
Set-Location .\apps\server
$env:P3_POSTGRES_URL = "postgresql+psycopg://adventure:adventure@localhost:5432/adventure_table_p3_test"
$env:DATABASE_URL = $env:P3_POSTGRES_URL
..\..\.venv\Scripts\python.exe -m pytest <P3 PostgreSQL focused tests> -q
```

不要drop開發中的真實資料庫。

### Frontend unit / build

```powershell
Set-Location .\apps\web
npm test -- --run
npm run build
```

### E2E

依既有 `KI-ENV-001`，完整Playwright走Docker/Linux web service。

P2-F已知限制：`test:e2e:docker`只rebuild web。P3在第一次新增backend-dependent E2E時必須把這個operational trap收斂掉：

- 優先修改script讓它一起build server；或
- 建立P3 wrapper command，明確build server + web後再跑。

不得讓P3 closeout evidence可能靜默測到舊backend image。

### MCP client smoke

P3-E起需有官方／真實MCP client path。測試分兩層：

1. protocol-level automated client：對真HTTP `/mcp` 做discover/list/call與auth。
2. closeout human / external-client smoke：至少一個實際可用外部AI host連線Adventure Table。

只call Python handler function不算P3-E正式MCP evidence。

## 5. Test layers

### Layer A — Domain / pure policy

驗：

- event audience projection。
- TableActorContext / role permission。
- PendingAction transition。
- RollRequest status / visibility。
- advantage / disadvantage / flat adjustment計算。
- controller type / generation validation。
- token scope policy。

### Layer B — Persistence / migration

驗：

- P3 web-branch Alembic revisions。
- fresh PostgreSQL `upgrade heads`。
- P2 final DB → P3 heads upgrade。
- standalone `character@head`完全無P3 tables。
- event seq unique / monotonic。
- message+event / roll+event atomicity。
- restart persistence。
- Room Hard Delete清P3 Room-scoped rows/assets。

### Layer C — API integration

驗：

- Session / Seat / Room path scope。
- audience filtering。
- Stage upload/read auth。
- Chat / Action / Whisper。
- Request Check / Group Check / Secret Check。
- formal / physical / quick roll。
- handoff / token revoke。
- AI DM Start policy。
- stable error code。

### Layer D — Concurrency

真 PostgreSQL至少驗：

- concurrent event append不重seq。
- duplicate formal roll completion。
- roll resolve vs cancel。
- PendingAction resolve vs cancel。
- Human→AI與Take Back同時競態。
- two token rotations / two Let AI Control。
- old AI token request racing with revocation。
- Session End vs event / roll commit。

SQLite sequential test不能取代這些證據。

### Layer E — Frontend unit / projection

驗：

- capability route split。
- Session initial Resume + incremental cursor reducer。
- stale event / duplicate event reducer idempotency。
- Stage modes。
- Seat / Character input selector。
- secret field永遠不出現在Player DTO type / rendered DOM。
- token只顯示一次與copy UX。
- bilingual copy parity / raw key guard。

### Layer F — Real-backend Playwright

驗真正browser：

- multi-browser Human DM + Players。
- Stage / Chat / Action。
- roll request與result。
- secret roll network/DOM不洩漏。
- reload / reconnect。
- handoff UI。
- late join。

### Layer G — MCP protocol / external AI

驗：

- `/mcp`只在web channel存在。
- invalid / revoked / wrong-seat token被拒絕。
- tool schema與structured error。
- get context audience。
- wait cursor。
- action / roll共用canonical state。
- real external client能完成journey。

### Layer H — Standalone regression

驗：

- frozen build成功。
- SQLite無P3 tables。
- import graph無P3 modules。
- `/mcp` / P3 routes不存在或capability disabled。
- Character Create / Import / Sheet / Level Up / Export仍正常。

## P3-A — Session Table Runtime & Event Stream

### Automated gate

最低案例：

1. event seq由1起單調增加，同Session無duplicate。
2. 兩個transaction並發append，真PostgreSQL得到不同且連續／可排序seq。
3. public event所有合法participant可見。
4. DM_ONLY只current DM可見；Owner但不是current DM不可見。
5. ACTOR_AND_DM只有actor controller + DM。
6. SEAT_PRIVATE只recipient Seat + DM（依contract）。
7. Room A caller拿Room B Session id → not found/scope reject，不洩漏existence。
8. `after_seq`只回後續；limit/cursor正確。
9. duplicate idempotency key不產生第二event。
10. wait timeout正常回empty，不報500。
11. process restart後last seq / runtime revision保持。
12. Ended Session不接受新gameplay event write，但既有event可依history policy讀取。
13. initial Resume後增量event不用再call完整Resume；前端mock/spy或API contract證明。
14. P3-A修正／避開P2 Resume N+1後有query-count或repository batch test，避免heartbeat級別放大。
15. standalone schema / import boundary新增P3命名後仍綠。

### Static review checklist

- 是否有任何audience filter只在frontend。
- 是否用 `max(seq)+1` 無鎖配置seq。
- 是否process-local queue成為唯一truth。
- 是否P3 event payload複製整份Character snapshot。
- 是否event endpoint可以傳flag要求DM資料。

### Subphase closeout evidence

- focused backend。
- PostgreSQL concurrent event test。
- frontend cursor reducer tests。
- `P3 Non-E2E` exact SHA綠。
- standalone boundary綠。

## P3-B — Exploration, Chat & Actions

### Automated gate

1. current DM設定Text only Stage。
2. Image only / Image+Text / Clear round-trip。
3. Player不能改Stage。
4. DM Key holder但不是current DM不能改active Stage。
5. PNG/JPEG/WebP allowlist成功；SVG/HTML/超size/偽MIME被拒。
6. Room A asset URL不能由Room B access讀取。
7. Character Dialogue綁正確Seat/Character。
8. 一個Human控制兩Seat時可選不同角色，各自actor identity正確。
9. Action / OOC / Narration kind正確。
10. Whisper DM sender與DM看得到，其他Human/AI Player API response裡完全沒有。
11. browser reload後Stage/message仍在。
12. server restart後Stage/message仍在。
13. Session End保留已commit message，不改Character State。
14. `zh-TW` / `en` parity。
15. P3 Session page進hardcoded copy scan。

### Real-backend journey B1

```text
DM browser + Player browser
→ Start Session
→ DM set image + text Stage
→ Player Character Dialogue
→ Player Action
→ Player Whisper DM
→ DM receives whisper
→ second Player never receives whisper
→ reload both browsers
→ Stage / public stream / own private stream still correct
```

### Static review checklist

- Stage是否被做成Scene/Adventure entity偷跑P6。
- asset是否public static path繞過Room auth。
- Whisper是否先回全量再frontend filter。
- slash command是否另外打另一套business endpoint。

## P3-C — Roll, Check & PendingAction

### Domain / backend cases

#### Normal formal roll

- DM request Investigation。
- target controller roll。
- Server保存raw d20、modifier、total。
- request `pending -> resolved`。

#### Advantage / Disadvantage

- raw two d20皆保存。
- kept die由Server計。
- modifier來自canonical Character rules。

#### Group Check

- 一個RollGroup多requests。
- 每個Seat各自完成。
- group projection顯示Waiting/Rolled。
- 不自動宣稱fiction success/failure。

#### Secret Check

- Player能看到「需要擲」所需資訊。
- secret DC不在Player JSON。
- dm-only result不在Player JSON / event stream。
- DM projection完整。

#### Physical formal dice

- submit raw die成功。
- Server重算total。
- 只傳total被schema拒絕。

#### Quick Dice

- 可roll / log。
- pending formal request狀態完全不變。

#### Duplicate completion

同一RollRequest兩個並發completion：

- 一個結果commit。
- DB只有一個formal result。
- retry取得same result或stable conflict。
- 不得重新RNG。

### PendingAction cases

- legal transition全覆蓋。
- illegal reverse transition拒絕。
- waiting_for_roll綁request。
- roll resolve後action可繼續resolve。
- cancel與resolve concurrency有真PostgreSQL證據。

### Character state atomicity

至少一條journey：

```text
formal action
→ legal Character Current State change
→ table event
```

故障注入／transaction rollback證明不能只成功一半。

### Real-backend journey C1

```text
Player Action: check the door
→ DM Request Check
→ Player sees pending request
→ Player roll
→ DM sees raw/result/DC
→ Player sees allowed result only
→ reload
→ request remains resolved, no second roll
```

### Static review checklist

- client能不能自填proficiency / total。
- AI/tool能不能直接提交「natural 20」當Server roll。
- formal roll有沒有unique result constraint。
- secret DC是否只是TypeScript optional但backend其實全回。

## P3-D — AI Controller, Scoped Token & Handoff

### Token security cases

1. plaintext token只create/rotate response出現一次。
2. DB row / log不含plaintext。
3. random wrong secret拒絕。
4. Room/Campaign/Seat mismatch拒絕。
5. revoked generation拒絕。
6. token不能取得Owner endpoint。
7. AI Player token不能取得DM tool/action。

### Player handoff journey D1

```text
Human controls Mira
→ Let AI Control
→ token generated once
→ AI-auth request can act as Mira
→ Human gameplay write is rejected while AI controls
→ Take Back Control
→ Human can act again
→ old AI token rejected everywhere
→ Mira id / state / active character unchanged
```

### Handoff concurrency

真PostgreSQL：

- two Let AI Control同時。
- Let AI Control vs Take Back。
- old token write transaction vs revoke。
- repeated Take Back idempotency / stable conflict。

結果不得留下兩個active generation。

### AI DM Start journey D2

```text
Owner creates active Campaign / DM Seat
→ Owner sets DM Seat AI
→ mint AI DM token
→ AI auth/join
→ AI calls Session Start
→ fixed DM controller = that AI grant generation
→ AI disconnect/offline
→ Session stays active
→ Owner cannot End as DM / cannot reassign controller
→ Owner may Abandon by existing escape hatch
```

另驗：active Session時rotate DM grant被拒絕，避免暗中handoff。

### Static review checklist

- 是否token plaintext入DB。
- 是否只驗token hash、不驗current generation。
- 是否AI DM因role=dm順便拿Room Owner service。
- 是否Human/AI controller id混用同一無type欄位。

## P3-E — AI Tool Surface & Event Delivery

### Protocol automated tests

以真HTTP MCP endpoint：

1. supported MCP protocol negotiation / discovery成功。
2. tools list穩定且只含P3正式工具。
3. no token / invalid token拒絕。
4. Player token呼DM-only tool得到structured permission error。
5. structured result schema可被client SDK解析。
6. `get_session_context` Player projection無secret。
7. `post_action`後Human browser/event API看到同一canonical action。
8. Human DM Request Check後AI Player `get_pending_events`看到pending。
9. AI `roll_pending`完成後Human UI看到同一result。
10. `wait_for_event` timeout成功empty。
11. wait中server無process-local history依賴；disconnect後cursor補回。
12. revoked token對所有tool由共同auth resolver拒絕。
13. standalone endpoint不可用。

### Shared-service proof

至少用spy / dependency injection / architecture test證明：

- Web action route與MCP action tool呼同一application service。
- Web roll route與MCP roll tool呼同一Roll service。
- MCP module不得import persistence repository作direct mutation（static import boundary）。

### External MCP human gate E1

P3-E closeout必做一次真實external client：

```text
1. 建Player AI Seat/token。
2. 外部MCP client連Adventure Table。
3. get_session_context。
4. Human DM在browser送Narration或Request Check。
5. AI wait/get pending event收到。
6. AI post_action。
7. AI完成formal roll。
8. Human browser看到同一action/result。
9. revoke token。
10. 外部client下一個call被拒絕。
```

可用ChatGPT / Claude / Codex或其他支援該正式MCP protocol的真實host；closeout記錄client名稱與測試日期。不要求特定廠牌。

### AI DM gate E2

至少一次AI DM tool：

- DM context可見DM資料。
- Player secret不外洩反方向也要驗。
- AI DM可Request Check / Narration。
- AI DM不能Room Hard Delete / rotate Owner credentials。
- AI DM不能修改Player Character Build。

## P3-F — Full P3 Integration & Closeout

### Journey 1 — Human Exploration

```text
Create/Enter Room
→ Campaign/Roster/Lobby
→ Human DM Start
→ Stage text/image
→ Dialogue / Action / OOC
→ Whisper DM
→ Request Check
→ Roll
→ Character state change
→ reload
→ continue
→ End
```

驗所有資料持久、End不reset Character State。

### Journey 2 — Secret / Group Roll

```text
DM group check for 3 Player Seats
→ one Human controls 2 Seats
→ third Player separate browser
→ secret DC
→ each rolls
→ DM sees all + DC
→ each Player only sees allowed results
→ reload
```

### Journey 3 — Late Join

```text
Session already has Exploration events
→ Late Join Player
→ gets current Stage + allowed current context
→ does not receive old DM-only/private events
→ can receive new public / own events
→ can complete new Request Check
```

### Journey 4 — Human → AI → Human

用真MCP client完成handoff、action、wait、roll、take back、old token rejection。

### Journey 5 — AI DM

```text
Owner assigns AI DM before Start
→ AI MCP Start Session
→ Human Players enter Exploration
→ AI DM Narration / Request Check
→ Human roll
→ AI receives result
→ AI disconnect/reconnect
→ fixed DM identity unchanged
→ End by same AI DM or Owner Abandon escape path
```

### Journey 6 — Restart recovery

完整dataset至少：

- active Session。
- Stage image+text。
- public / whisper / dm-only events。
- one resolved + one pending RollRequest。
- one PendingAction waiting_for_roll。
- Human controller Seat。
- AI controller Seat with active token generation。
- ended historical Session有messages/rolls。

重建server process / engine後：

- cursor接續不重置。
- Stage存在。
- visibility仍正確。
- pending仍pending。
- resolved不會重roll。
- AI token verifier / generation仍有效；plaintext本來就不需保存。

真PostgreSQL migration/restart至少有一條整合證據；若另有SQLite fast integration，只能補充，不能取代Web DB證據。

### Journey 7 — Cross-scope attack matrix

至少：

| Attack | Expected |
|---|---|
| Room A token + Room B Session UUID | reject |
| Player A event cursor猜Player B private event | absent/reject |
| Player token Request Check as DM | reject |
| Owner不是current DM改Stage | reject |
| revoked AI token post action | reject |
| stale AI generation roll pending | reject |
| ended Session新gameplay write | reject |
| quick roll id冒充formal result | impossible/reject |

### Journey 8 — Standalone

Frozen standalone：

- launch。
- Create/Import/Sheet/Level Up/Export。
- no Room/Session/Stage/Roll/MCP UI。
- no P3 DB tables。
- direct P3 path capability-disabled / not mounted。

## 6. Static review gate before final Actions

P3-F跑最終Actions前，static review至少逐項回答：

1. Human / MCP是否存在兩套permission/rules。
2. DM-only / private資料是否任何endpoint先全量回傳。
3. token secret是否可能進log、DB、exception。
4. current controller generation是否每個AI request都重驗。
5. formal roll能否duplicate commit。
6. Character State + event是否atomic。
7. event seq是否DB-safe。
8. Session Resume是否被高頻poll。
9. P3 modules/tables是否被standalone forbidden gate涵蓋。
10. capability backend/frontend是否同步。
11. UI copy是否雙語與hardcoded scan完整。
12. 是否偷做P4/P6/P7而形成不必要schema contract。

發現blocker先修code + test並commit，再重新review；review完成後才跑final non-E2E Actions。

## 8. P3 closeout後不得誤宣稱

P3關門只代表 **Exploration + Roll + AI** 可用。Closeout明確不得宣稱：

- Combat完成。
- Adventure / world runtime完成。
- full AI DM campaign memory完成。
- Timeline / Snapshot / Restore完成。
- Site Tools所有transport都完成。

下一個正常產品Phase仍是 **P4 — Quick Combat**。
