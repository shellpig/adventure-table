# P0 — 測試指南

> Phase：**P0 — Character Core + SRD / Rules Foundation**  
> 本文件定義 P0 如何驗收。測試要證明 `實作規格.md` 的 AC-P0-01 ～ AC-P0-10，而不是只證明「頁面打得開」。

最後更新：2026-08-29

---

## 1. 測試原則

P0 測試分五層：

1. **SRD Content Validation** — reference data 是否完整、合法、可引用。
2. **Rules Unit Tests** — D&D 角色衍生計算是否正確。
3. **Persistence / API Tests** — Character Build / State 是否正確保存與讀回。
4. **Frontend Tests** — 三頁 Character Sheet 是否正確呈現 Server DTO。
5. **Playwright E2E** — 真實瀏覽器操作、保存、重載是否成立。

測試 fixture 必須固定、可重現，不依賴人工先去 DB 改資料。

---

## 2. P0 標準驗證角色

P0 使用固定 fixture：

> **Human Fighter 5 / Wizard 5，Character Level 10**  
> Class order：Fighter 1→5，再 Wizard 1→5。

建議固定 Ability Scores：

| Ability | Score | Modifier |
|---|---:|---:|
| STR | 16 | +3 |
| DEX | 14 | +2 |
| CON | 14 | +2 |
| INT | 16 | +3 |
| WIS | 10 | +0 |
| CHA | 8 | -1 |

Starting Class：Fighter。

至少包含：

- Saving Throw proficiency：STR、CON。
- Skill proficiency：Athletics、Arcana、Perception。
- Armor：Chain Mail + Shield。
- Weapon：Longsword。
- Wizard spell data：至少包含 1st / 2nd / 3rd-level spell references。
- Inventory：至少一個可堆疊 consumable，例如 Healing Potion ×2。
- Current HP 初始設為 Max HP。
- Temporary HP 初始 0。
- 初始無 Condition。

### 2.1 固定 Derived Expectations

依上面 fixture，至少驗證：

| 項目 | 預期 |
|---|---:|
| Total Character Level | 10 |
| Fighter Level | 5 |
| Wizard Level | 5 |
| Proficiency Bonus | +4 |
| STR Save | +7 |
| CON Save | +6 |
| Athletics | +7 |
| Arcana | +7 |
| Perception | +4 |
| Passive Perception | 14 |
| AC（Chain Mail + Shield） | 18 |
| Wizard Spell Save DC | 15 |
| Wizard Spell Attack | +7 |

若 P0 Max HP 使用 5e fixed average 且 Fighter 為 starting class：

```text
Fighter Lv1: 10 + CON 2 = 12
Fighter Lv2-5: 4 × (6 + 2) = 32
Wizard Lv1-5: 5 × (4 + 2) = 30
Total = 74
```

因此標準 fixture 的 Max HP 預期為 **74**。

若未來 fixture 改成 rolled HP，必須同步改 fixture 與 expectation，不可在 test 裡模糊接受兩種答案。

## 3. SRD Content Validation

對應：AC-P0-01、AC-P0-02。

### 3.1 Manifest / Required Categories

測試必須確認 P0 規格要求的主要 category 都存在並可載入：

- races
- classes
- subclasses
- backgrounds
- feats（若 SRD source 有）
- skills / abilities / saves reference
- equipment / weapons / armor / adventuring gear
- spells
- conditions
- monsters
- damage types
- languages

不要只測「檔案存在」；至少要 parse 成對應 Pydantic model。

### 3.2 Stable Key Uniqueness

每個 reference category：

- key 不可重複。
- key 不可空白。
- Character fixture 使用的 key 必須存在。

### 3.3 Cross-reference Validation

至少驗證：

- Class / Subclass reference 可解析。
- Spell source / class reference 可解析。
- Equipment property / damage type 等必要 reference 可解析。
- Monster 使用的 damage type / condition 等 reference 不出現 dangling key（若 schema 有此引用）。

### 3.4 Negative Cases

測試故意注入：

- duplicate key
- missing required field
- dangling content reference
- invalid enum / malformed value

預期：ContentRegistry validation fail，不能靜默略過。

## 4. Rules Unit Tests — pytest

對應：AC-P0-05、AC-P0-08。

### 4.1 Ability Modifier

至少測：

```text
8  -> -1
10 -> 0
14 -> +2
16 -> +3
```

### 4.2 Proficiency Bonus

至少覆蓋 level boundary：

```text
Lv1  -> +2
Lv5  -> +3
Lv9  -> +4
Lv13 -> +5
Lv17 -> +6
```

標準 fixture Lv10 必須是 +4。

### 4.3 Skill / Save

標準 fixture：

- Athletics = STR + PB = +7。
- Arcana = INT + PB = +7。
- Perception = WIS + PB = +4。
- STR Save = +7。
- CON Save = +6。
- 未 proficiency 的 DEX Save = +2。

### 4.4 Passive Perception

標準 fixture：

```text
10 + Perception modifier 4 = 14
```

### 4.5 Armor Class

標準 fixture：

```text
Chain Mail 16 + Shield 2 = 18
```

確認 Heavy Armor 不錯誤加入 DEX modifier。

### 4.6 Spellcasting

標準 fixture Wizard INT 16、PB +4：

```text
Spell Save DC = 8 + 4 + 3 = 15
Spell Attack = 4 + 3 = +7
```

### 4.7 Max HP

標準 fixture固定 expected = 74。

### 4.8 Numeric Override

至少測：

- 無 override → 使用正常 derived value。
- 指定 AC override → Sheet 顯示 override AC。
- 指定 Max HP override → current HP validation 使用 override 後 Max HP 規則。
- override 不應改動 Race / Class / Feature reference。

對應：AC-P0-03、AC-P0-08。

### 5.1 Class Order

標準 fixture 必須保存：

```text
Fighter

Fighter
Fighter

Wizard
Wizard
```

測試 derive：

- starting class = Fighter
- Fighter level = 5
- Wizard level = 5

### 5.2 Spell Source

同一角色 spell entries 必須能辨識：

- spell key
- source class / feature
- access type

至少有：

- spellbook
- prepared

不要求 P0 驗證完整 Wizard progression legality，但 schema 不能丟掉來源資訊。

### 5.3 Optional Roleplay

Roleplay profile 全空時：

- schema 合法。
- Character Sheet 可正常 render。

有資料時可正確 round-trip。

## 6. Persistence Tests — pytest

對應：AC-P0-03、AC-P0-04、AC-P0-07。

### 6.1 Save / Reload

流程：

```text
Seed fixture
↓
Read character
↓
Serialize Build + State
↓
Close transaction/session
↓
Read again
↓
Compare
```

結果：

- Build 完整相同。
- State 完整相同。
- Derived result 相同。

### 6.2 Build / State Isolation

先記錄 current build version payload。

依序修改：

- current HP
- temporary HP
- Condition
- spell resource usage
- potion quantity

再讀回 build payload。

預期：build payload byte-for-byte / canonical-object equivalent 不變。

### 6.3 Server Restart Persistence

Integration test 至少模擬新的 application / DB session，不能只測同一 ORM object 還在 memory。

## 7. API Tests — pytest / FastAPI Test Client

### 7.1 Reference Content

測：

```text
GET /api/rules/content/spells
GET /api/rules/content/spells/{fireball-key}
GET /api/rules/content/classes/{fighter-key}
```

預期：

- known key → 200 + valid DTO
- unknown key → 404 + machine-readable error code

### 7.2 Character Sheet

```text
GET /api/characters/{fixture-id}/sheet
```

驗證 Header 與三頁所需欄位完整。

### 7.3 State Patch

至少測：

```text
PATCH HP
PATCH temporary HP
PATCH condition list
PATCH resource usage
PATCH inventory quantity
```

每次 patch：

- request validation 正常。
- DB state 改變。
- build version 不變。
- 後續 GET sheet 反映新值。

### 7.4 Invalid State

至少測：

- negative inventory quantity
- malformed condition key
- wrong data type

預期 4xx，且資料庫不得留下半套更新。

## 9. Playwright E2E

對應：AC-P0-06、AC-P0-07、AC-P0-09、AC-P0-10。

### E2E-P0-01 — Character Sheet 基本流程

```text
啟動 app
↓
開啟 Fighter 5 / Wizard 5 fixture
↓
看到 Header
↓
切換 Attributes / Skills
↓
切換 Spells
↓
切換 Inventory
```

驗證預期主要數值。

### E2E-P0-02 — Current HP Persistence

```text
HP 74 → 50
↓
保存成功
↓
reload browser
↓
仍為 50
```

### E2E-P0-03 — Temporary HP / Condition

```text
Temp HP 0 → 8
加入 Poisoned
↓
reload
↓
Header / Page 1 仍正確顯示
```

### E2E-P0-04 — Spell Resource

改變 spell slot 使用狀態，reload 後保持。

### E2E-P0-05 — Inventory Quantity

Healing Potion ×2 → ×1，reload 後保持；Character Build 不因 inventory current quantity 改變而產生新 build choice。

### E2E-P0-06 — Optional Roleplay

使用一名 Roleplay profile 全空的 fixture 或變體；Page 1 不報錯、不顯示強制填寫訊息。

### E2E-P0-07 — P0 Independence

P0 UI 在沒有 Room / Campaign / Session / Combat / AI 連線的情況下可完整操作 Character Sheet。

## 11. 人工驗收

自動測試全綠後，人工快速檢查：

1. Character Sheet 三頁閱讀性。
2. 繁體中文 UI 文案正常；Action / Spell Slot 等規則關鍵字保留英文。
3. Fighter / Wizard features 與 spells 沒有明顯被混在錯誤頁面。
4. HP / Conditions 在 Header 一眼可見。
5. Roleplay 空白不造成大片空洞或必填提示。
6. 重新整理後沒有短暫顯示錯誤 authoritative state 再跳回正確值的明顯 UX 問題。

P0 不需要人工驗收 Room、AI、Combat、Map。
