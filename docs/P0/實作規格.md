# P0 — 實作規格

> Phase：**P0 — Character Core + SRD / Rules Foundation**  
> 本文件只定義 **P0 完成後什麼必須成立**。具體 DB schema、API、檔案結構與程式接線放在同目錄的 `開發設計方針.md`。

最後更新：2026-08-29

---

## 1. P0 目標

P0 要建立 Adventure Table 後續所有角色與規則功能共用的第一層地基：

1. **SRD 5.1 reference content 在系統內可正式使用。**
2. **Character 核心資料可以被建立、保存、讀回。**
3. **Digital Character Sheet 可以正確顯示角色。**
4. **常用角色衍生數值由 Server 規則層計算。**
5. **角色 Build 與 Current State 明確分離。**
6. **P0 的資料表示能力不能阻止下一個 Phase 的完整 Character Builder / Multiclass。**

P0 不是完整創角器，也不是多人跑團功能。

---

## 2. P0 完成定義

P0 完成時，應能做到以下完整流程：

```text
啟動專案
↓
載入並驗證 SRD 5.1 reference data
↓
載入一名已存在的 Character
↓
Server 計算 Character Sheet 所需衍生數值
↓
Web UI 以三頁 Character Sheet 顯示
↓
修改 Current State（例如 HP / Spell Slot 使用狀態 / Condition / Inventory 數量）
↓
保存
↓
重新啟動／重新載入
↓
Character Build 不變，Current State 保持最後保存結果
```

同時，P0 必須能**承載**一名合法的高等 Multiclass 角色資料，例如：

> Human Fighter 5 / Wizard 5，Character Level 10。

這不代表 P0 要從 UI 一級一級建立這名角色；完整 Builder 與 progression validation 屬 P1。

## 3. P0 範圍

### 3.1 SRD 5.1 Reference Content

P0 應建立正式可用的 SRD 5.1 structured reference content，至少涵蓋後續角色與遊戲功能會引用的主要類別：

- Race / racial traits
- Class
- SRD Subclass
- Background
- Features / Traits
- Feats（SRD 5.1 有提供者）
- Ability / Skill / Saving Throw reference
- Equipment
- Weapons
- Armor
- Adventuring Gear / Items
- Spells
- Conditions
- Monster stat blocks / actions / traits
- Damage Types
- Languages
- 其他 SRD 5.1 中可重複引用的 structured rules content

要求：

- Reference entry 必須有穩定識別方式，角色不能靠顯示名稱硬連結資料。
- Reference data 要能通過 schema validation。
- Reference 之間的必要引用要能被驗證。
- 保留資料來源／ruleset / licensing 所需資訊。
- SRD 資料完整存在，不代表所有玩法 mechanics 都要在 P0 自動化。

例如：

- Fireball 的 spell definition 可在 P0 存在；Tactical AoE 是 P5。
- Goblin 的 monster definition 可在 P0 存在；正式 Combat 是 P4。

### 3.2 Character Core

Character 至少要能表示：

- Identity：名稱與基本角色識別資訊。
- Ruleset / content references。
- Race。
- Character Level。
- 一個或多個 Class 與各自 Class Level。
- Class level acquisition order。
- Subclass（存在時）。
- Ability Scores。
- Proficiencies。
- Saving Throw proficiencies。
- Skills。
- Features / Traits。
- Feats。
- Spell-related build data。
- Equipment / Inventory references。
- Optional Roleplay / Biography data。
- Numeric Override 所需資料表示能力。

P0 不要求完整檢查「玩家是否依合法創角流程選到這些資料」，但資料本身必須可被 schema / reference validation 正確讀取。

### 3.3 Build 與 Current State 分離

P0 必須把「角色是什麼」和「角色現在剩多少資源」分開。

**Build** 類型包含：

- Race / Class / Subclass
- Level progression
- Ability Scores
- Proficiencies
- Features / Feats
- Spell access / spellbook / prepared / known choices
- 長期角色設定與 Numeric Override

**Current State** 類型包含：

- Current HP
- Temporary HP
- 當前 Conditions / temporary effects
- 已使用／剩餘的 Spell Slot 等消耗型資源
- Hit Dice 等會隨遊戲變動的資源
- Inventory quantity / consumable usage
- 其他 session 間必須延續的角色目前狀態

Current State 改變不得偷偷改掉 Build。

Session 結束也不會自動重置這些狀態；真正的 Session lifecycle 到 P2 再實作。

### 3.4 Character Derived Calculations

P0 Server 規則層至少提供 Character Sheet 需要的常用衍生值：

- Ability Modifier
- Total Character Level
- Proficiency Bonus
- Skill Modifier
- Saving Throw Modifier
- Passive Perception
- Armor Class
- Initiative Modifier
- Spell Save DC
- Spell Attack Modifier
- Max HP 所需的角色基礎計算

若某數值受到 Numeric Override，顯示與後續引用應使用 override 後的結果；Numeric Override 只改數值，不代表合法性／結構規則被繞過。

P0 不必實作所有 D&D 5e gameplay mechanics。

### 3.5 Digital Character Sheet

Character Sheet 第一版固定三頁。

#### Header — 三頁都顯示

- Name
- Level
- HP
- AC
- Conditions

#### Page 1 — Attributes / Skills

至少顯示：

- Ability Scores / Modifiers
- Skills
- Saving Throws
- Passive Perception
- Features / Traits
- Conditions / temporary effects
- Optional Roleplay / Biography 區域（可收合）

Roleplay / Biography 可包含：

- Alignment
- Personality
- Ideal
- Bond
- Flaw
- Biography
- Goals
- Relationships
- Roleplay Guidance

這些全部是 optional，不得因空白阻止角色存在或顯示。

#### Page 2 — Spells

至少能顯示角色目前擁有／可使用的 spell-related 資料：

- Spell references
- Source class / source feature（適用時）
- Known / Prepared / Spellbook / Always-prepared 等必要區別
- Spellcasting ability
- Spell Save DC / Spell Attack
- Spell Slot / resource current state

P0 的重點是**正確表示與顯示**；完整合法選法與升級流程屬 P1。

#### Page 3 — Inventory

至少顯示：

- Item / Equipment reference
- Quantity
- Equipped / carried 等 P0 需要的基本狀態
- Weapon / Armor 的主要可讀規則資訊
- Consumable 當前數量

P0 不需要 Shop / Loot / Container 系統。

### 3.6 Character Persistence

P0 必須支援：

- Character 保存。
- Character 重新讀取。
- Build 與 Current State 分別保存。
- Server restart 後資料仍存在。
- 同一角色 Save → Reload 後，沒有未預期資料遺失或重算漂移。

## 4. P1 相容要求

P1 緊接 P0，因此 P0 不可以採用會立即阻止以下能力的表示方式：

- Multiclass。
- Character Level 與 Class Level 分離。
- Class acquisition order。
- Starting class 與後續 multiclass 的差異。
- Subclass progression。
- ASI / Feat progression。
- Spell 來源追蹤。
- Spell Access 與 Spell Resource 分離。
- Wizard Spellbook / Prepared Spell。
- Character Build versioning / Level Up。

P0 的驗證 fixture 應至少包含一名 Fighter 5 / Wizard 5，證明資料表示能力已足夠。

這一節只要求**相容**，不要求 P0 提前做完整 P1 Builder。

## 5. 明確不屬於 P0

以下不在 P0 實作：

- 完整 Character Builder wizard。
- 從 Level 1 逐級合法選擇到高等角色。
- Level Up workflow。
- 完整 Multiclass prerequisite validation UI。
- P1 的 Character Version History UI。
- Room / Campaign / Session / Seat。
- Human / AI controller handoff。
- MCP Join / AI gameplay tools。
- Roll system。
- Exploration。
- Quick Combat。
- Tactical Combat / Map。
- Adventure Importer / AI DM Runtime。
- Snapshot / Restore / Export。
- Shop / Loot / Quest / Rest workflow。

若 P0 實作為了這些後續功能加入大量提前設計，視為 scope creep。

## 6. P0 驗收契約

P0 至少要通過以下驗收：

### AC-P0-01 — SRD 資料可完整載入

啟動時所有 P0 定義的 SRD 5.1 類別可被載入；schema / required reference 錯誤必須明確失敗，不得靜默略過。

### AC-P0-02 — Reference 查詢

後端可依穩定 key 取得指定 Race / Class / Spell / Equipment / Condition 等 reference entry。

### AC-P0-03 — Character Save / Reload

建立／載入一名 P0 fixture Character，保存後重新讀取，Build 與 Current State 資料一致。

### AC-P0-04 — Build / State 隔離

修改 Current HP、Temporary HP、Condition、Spell Slot 使用狀態或 Inventory quantity 時，不會改變 Race / Class / Ability / Feature / Spell access 等 Build 資料。

### AC-P0-05 — Derived Calculation

固定 fixture 的 Ability Modifier、Proficiency Bonus、Skill、Save、Passive Perception、AC、Spell Save DC / Spell Attack 等結果符合 D&D 5e 2014 規則與 fixture 的 Numeric Override。

### AC-P0-06 — 三頁 Character Sheet

Web UI 能顯示固定 Header 與三頁：Attributes / Skills、Spells、Inventory；optional Roleplay 空白時仍可正常使用。

### AC-P0-07 — Current State Persistence

修改 HP / resource / condition / inventory 後重新載入頁面與重啟 server，狀態保持一致。

### AC-P0-08 — Multiclass 承載能力

系統可載入並正確顯示一名 Human Fighter 5 / Wizard 5（Character Level 10）fixture；能分辨 total level、各 class level、class order、不同來源的 features / spells。

### AC-P0-09 — 前端不自行產生 authoritative derived state

Character Sheet 使用 Server 回傳的 authoritative Character Sheet / derived data；重新整理後結果一致，不依賴只存在 browser memory 的正式角色狀態。

### AC-P0-10 — P0 Scope Guard

P0 可以在沒有 Room、Campaign、Session、AI、Combat、Adventure 的情況下獨立啟動與驗收。

## 7. P0 收尾條件

只有以下全部成立才可進 P1：

- P0 SRD content validation 全綠。
- P0 backend rules / persistence tests 全綠。
- P0 frontend tests 全綠。
- P0 Playwright 核心流程全綠。
- Fighter 5 / Wizard 5 fixture 可穩定 Save / Reload / display。
- 沒有為 P1 以後功能提前建立未使用的大型 subsystem。

P0 收尾後，再以實際完成的 codebase 為基礎規劃 P1。
