# M02 — 測試指南

> Phase：**M02 — Traditional Chinese / English Localization**  
> 類型：**M Phase（Modification / Maintenance Phase）**  
> 插入時點：**M01-C — SCAG / GoS Background Expansion closeout 後，暫停 M01；M02 closeout 後回到 M01-D。**  
> 本文件定義 M02-A～M02-H 的自動化與人工驗收流程。完成條件以 `實作規格.md` 為準，具體接線、localizable field policy 與 translation authoring pipeline 以 `開發設計方針.md` 為準。

最後更新：2026-08-30

---

## 1. 測試總則

M02 的測試不能只驗「畫面上有中文」；必須同時驗：

1. 語言切換 runtime 行為正確。
2. locale 不污染 Draft / Character / Current State。
3. UI copy 與**目前 user-visible** rules content 都能完整切換。
4. StableKey / persisted identity 不因語言改變。
5. user-authored text 不被翻譯。
6. search / sort / error presentation 使用目前 locale。
7. localizable field policy 能明確決定 required translation scope。
8. 缺 required translation 會被自動化 gate 擋住。
9. M02 closeout 時 `srd5.1 / phb2014 / scag / gos` 的 policy-required fields 具有完整雙語 coverage。
10. 尚未 user-visible 的 field 不會因 category 存在被誤列為 M02 blocker；未來首次 expose 時有 regression guard 承接。

所有 Subphase 完成時都必須保持既有 backend pytest、frontend build / Vitest、Playwright 與 relevant regression 綠燈。

---

## 2. 共通測試資料與觀察值

### 2.1 Locale

正式測試 locale：

```text
zh-TW
en
```

### 2.2 必須觀察的不變 identity

切換 locale 前後至少比較：

- current URL
- Builder Draft id
- Draft revision
- selected StableKeys
- Character id
- current version id / version number
- CharacterBuild refs
- CharacterState values

### 2.3 必須觀察的 presentation

至少涵蓋目前可達 surface 的：

- UI heading / button / label
- SearchableSelect options
- Builder grants / choices
- class / race / background / spell / equipment / inventory names
- policy-required rule description
- validation / error message
- roleplay system suggestion
- source label（若有）

### 2.4 Policy-driven fixture

測試 fixture 必須能同時包含：

- `required` field。
- 同一 entry 上 `not user-visible yet` field。

用來證明 completeness checker 是按 field policy，而不是「entry/category 有字串就全部要求翻譯」。

# M02-A — Locale Foundation & Runtime Switch

## A.1 Unit / component tests

驗證：

- default locale 為 `zh-TW`。
- browser storage 有 `en` 時初始化為 `en`。
- invalid stored locale 不被接受，回到合法 default。
- 切換 locale 更新 runtime state。
- 切換後 browser storage 正確保存。
- `html lang` 同步。

## A.2 No mutation test

在有既存 Builder Draft 的頁面：

1. 讀取 Draft revision。
2. 切換 `zh-TW → en → zh-TW`。
3. 再次讀取 Draft。

必須：

- revision 完全相同。
- draft payload 完全相同。
- 不發生 PATCH / Confirm / Cancel mutation。

可用 frontend request spy 或 real backend request log 驗證。

## A.3 Browser persistence E2E

1. 開啟網站，切 English。
2. reload。
3. 仍為 English。
4. 離開頁面再重新開啟。
5. 仍為 English。
6. 切回繁中，reload。
7. 仍為繁中。

## A.4 No reload E2E

在 Character Builder 中保留可觀察 local UI state，切換 locale。

必須：

- page 不 reload。
- current step 不變。
- current URL 不變。
- relevant transient state 不因 navigation 消失。

# M02-B — Full UI Copy Localization

## B.1 Static UI coverage

建立可維護的 UI copy inventory 或等價檢查，至少涵蓋：

- Landing
- Character Workshop
- Builder：Basic
- Builder：Origin
- Builder：Abilities
- Builder：Class
- Builder：Spellcasting
- Builder：Equipment
- Builder：Review
- Character Sheet
- Version History
- shared components

不要再寫「steps 01～06 / 01～07」作驗收依據；step 名稱才是較穩定的 surface identity。

每個 surface 在 `zh-TW` / `en` 都有對應 copy。

## B.2 Hardcoded visible text regression

對 frontend source 做 targeted lint / test / review，避免新增明顯 user-visible hardcoded English / Chinese literal。

不是要求禁止任何 string literal；測試只針對 presentation surface，避免誤傷 enum、code、StableKey、test fixture。

## B.3 Accessibility

兩種 locale 都驗：

- aria-label
- accessible button name
- form label
- placeholder / hint（若可見或 accessibility-relevant）

語言切換後 accessible name 同步更新。

## B.4 Mixed-language smoke

在純繁中與純英文模式巡覽主要頁面，記錄任何可避免的 system UI 混語；Blocker / Major 必須在 B closeout 前清掉。

# M02-C — Localized Content Model & Terminology Contract

## C.1 StableKey invariant

使用同一 content entry，例如：

```text
srd5.1:spell:fireball
```

分別 resolve `zh-TW` / `en`。

驗證：

- identity 相同。
- canonical mechanics data 相同。
- 只有 presentation fields 不同。

## C.2 Resolver fixture

至少用數種不同 kind 測試：

- race / background
- proficiency / skill
- equipment
- magic item name
- spell
- feature
- long description

每種 required field 都能正確取得兩語 presentation。

## C.3 Field policy tests

建立 machine-verifiable localizable field policy tests，至少驗證：

- policy 可以指到 pack / kind / field path。
- required field 缺 locale → fail。
- 同 entry 的 not-yet-user-visible field 缺 translation → 不應造成 M02 completeness failure。
- product surface 將 field 改為 required 後，缺 translation 立即 fail。

至少加入現況型案例：

```text
magic item name = required（目前 Inventory selector 可見）
magic item long description = 若目前無 surface，not required yet
```

實際斷言仍以 M02-C 定稿 policy 為準，不把測試範例硬編成永久 category 規則。

## C.4 Missing translation behavior

故意建立缺一個 required locale / field 的 fixture：

- development resolver 可明確指出 missing translation。
- completeness test 必須 fail。
- 不得 silent fallback 後仍通過 completeness。

另建立缺少 not-required field 的 fixture，確認不會誤判為 blocker。

## C.5 DTO identity test

Builder / Character rules presentation path 中，驗證 rules item 有足夠 StableKey / structured identity 支援 locale switch。

禁止只有 raw English `label` 而無法追溯 identity 的 user-visible rules entity 成為新 contract。

## C.6 Roleplay suggestion identity

測試 system-provided suggestion：

1. 同一 suggestion 在 English 顯示英文。
2. 切繁中後顯示繁中。
3. persisted selection / identity 不因 locale 改變。

另測 user manually typed roleplay text：切 locale 後原文不變。

## C.7 Glossary review gate

建立 glossary consistency fixture / review checklist：

- 新增／修改 glossary term 100% review。
- 比對 `docs/暫用規則資訊/` 本次用到的既有繁中名稱。
- 若 chosen zh-TW 與 reference 不同，要有 legacy/reference value + decision note。
- runtime 不 parse reference Markdown。

# M02-D — SRD 5.1 Names & Structured Text

## D.1 Policy-driven dataset coverage

對 `srd5.1` 執行：

```text
all entries
× M02-C required name / label / structured fields
× zh-TW / en
```

任何 required field 缺 locale 即 fail。

不得另外維護「所有 categories 都必翻全部欄位」的手工清單。

## D.2 Current-surface representative coverage

至少抽查目前實際可見的：

- Race / Subrace
- Background
- Alignment
- Class
- proficiency / language choices
- equipment choices
- spell names
- conditions
- inventory equipment / magic item names

切 locale 後 option display 全部更新，selected persisted value 仍是同一 StableKey。

## D.3 Character Sheet presentation

建立含多種 SRD refs 的 Character，驗目前 Sheet 可見的：

- class / race / background
- proficiencies
- features
- equipment / inventory names
- spells
- conditions

兩語 render 正確；只有 policy-required field 才納入完整性 blocker。

## D.4 No identity drift

比較兩語下 Review / Confirm candidate：

- Build refs 相同。
- content_sources 相同。
- mechanics result 相同。

## D.5 Batch evidence

每個翻譯 batch 保存：

- category / entry count
- required field count
- translation source/method
- review count
- glossary lint result
- schema/completeness result

允許 category 分批 commit，但 D 所有 required scope 未完成前不得 closeout。

# M02-E — SRD 5.1 User-Visible Descriptions

## E.1 Long-text completeness

只對 M02-C policy 標為 currently user-visible / required 的 SRD long-form fields 執行 coverage scan。

缺任一 supported locale 即 fail。

canonical dataset 中目前無 product surface 的 long text 不納入 M02-E completeness。

## E.2 Rules fidelity automated checks

能可靠抽取時，比較 canonical English 與 zh-TW translation 中的：

- dice expression
- numeric values
- level
- DC
- range / duration
- named StableKey / structured reference

不得因翻譯遺失或改變 mechanics-sensitive token。

自動檢查不能取代人工語意 review。

## E.3 Human spot review

每個 long-form category / batch 至少人工抽審：

```text
max(10 entries, 10% of batch)
```

batch <= 10 時全審。

抽審優先涵蓋實際在 policy 中 required 且 rules-sensitive 的：

- spells
- class / subclass features
- conditions
- race / background features
- 其他含限制、資源、例外或數值的長文

若 policy 當下沒有 magic item long description surface，就**不因 items category 存在而硬抽 magic item description**。

發現系統性錯譯時要擴大 review，同類 batch 不可只修抽中的幾筆。

## E.4 Structured rendering

若 required description 有 list / paragraph 結構，兩種 locale 都需：

- 不破版。
- 不把 list 黏成難讀單行。
- 不因 locale 切換遺失內容。

## E.5 Batch evidence

同 D.5；E 所有 required scope 未完成前不得 closeout。

# M02-F — PHB / SCAG / GoS Localization

## F.1 Pack + policy completeness

對：

```text
phb2014
scag
gos
```

執行 localizable field policy × supported locales completeness。

不是要求每個 canonical string 都翻，而是所有目前 user-visible required field 全綠。

## F.2 Existing reference comparison

針對本次會出現在 runtime 的 PHB / SCAG / GoS zh-TW names / terminology：

- 比對對應 `docs/暫用規則資訊/`。
- 相同譯名可直接進 glossary / translation draft review。
- 不同譯名須有 glossary decision note。
- reference 文件若有 extraction artifact / typo，不得原樣機械複製進 runtime。

## F.3 PHB flow

至少一條完整 E2E：

```text
PHB race/subrace or Variant Human
+ PHB background
+ SRD class
```

在 Builder 中：

- 繁中顯示完整 current-surface rules presentation。
- 切 English 後完整英文。
- selection / Draft 不變。
- Confirm 後 Character Sheet 兩語都正確。

## F.4 SCAG background flow

至少一個 reuse PHB roleplay suggestion table 的 SCAG Background：

- roleplay suggestions 兩語正確。
- mechanical grants 仍來自 SCAG background 自己的 grants。
- locale 不影響 roleplay inheritance isolation。

## F.5 GoS flavor flow

至少一個帶 optional flavor table / suggestion 的 GoS Background：

- 兩語可見。
- 留白不阻擋 Confirm。
- 選用 system suggestion 後 identity 可跨 locale render。

## F.6 Variant / source collision

同名或近似名稱跨來源同時存在時：

- 兩語 source-aware display 都能辨識。
- persisted key 永遠是正確完整 StableKey。
- locale switch 不發生誤選或 dedupe。

## F.7 Batch evidence

每批保存 translation / review / lint evidence；F 完整 policy scope 未完成前不得 closeout。

# M02-G — Localized Search, Errors & Completeness Gates

## G.1 Localized search

繁中模式：

- 中文名稱可搜尋。
- English alias 也可命中。
- 結果只顯示繁中 presentation。

English mode 反向驗證。

## G.2 Locale-aware sort

準備名稱排序會與 StableKey/index 順序不同的 fixture，驗證：

- `zh-TW` 依繁中 display presentation 排序。
- `en` 依英文 display presentation 排序。

## G.3 Validation errors

觸發至少：

- missing required choice
- illegal choice
- stale / invalid state
- generic request error

驗證：

- machine code / path 不變。
- UI message 隨 locale 切換。
- 動態 rules name 也隨 locale。

## G.4 Completeness CI

CI 自動掃描：

```text
supported locales
× enabled packs
× M02-C required localizable fields
```

M02 closeout packs：

```text
srd5.1
phb2014
scag
gos
```

任何 required field 缺：

```text
pack
StableKey
field
locale
```

即失敗並輸出可定位資訊。

## G.5 Orphan / duplicate checks

至少測：

- overlay StableKey 不存在。
- overlay field path 已不存在。
- duplicate locale / StableKey / field definition。
- unsupported locale。

## G.6 Future visibility guard

建立 fixture：

1. 某 canonical field 初始 policy = not user-visible，只有 English，不阻擋。
2. 模擬新 product surface 將該 field 改成 required。
3. 只有 English 時 completeness 必須 fail。
4. 補 `zh-TW` 後才通過。

這證明 M02 closeout 後「首次 expose 舊 content」也不會無聲加入單語 UI。

# M02-H — Full M02 Integration & Closeout

## H.1 Full regression

至少包含：

- backend pytest
- localization dataset / policy validation
- fresh migration / existing schema compatibility（若 M02 有 migration）
- frontend TypeScript build
- Vitest
- real-backend Playwright
- restart / reload relevant persistence

## H.2 Full bilingual Create Character E2E

至少完成兩條：

### Flow 1 — 繁中開始

```text
zh-TW
→ Create Draft
→ Origin
→ Abilities
→ Class
→ Spellcasting（若 caster）
→ Equipment
→ Review
→ Confirm
→ Character Sheet
→ switch en
→ verify same Character / Build / State, English presentation
→ reload
```

### Flow 2 — English 開始

反向完成一條 create flow，再切 `zh-TW` 驗證。

## H.3 Draft safety stress

建立有多個 selection 的 Draft：

- race / subrace / background
- class progression
- spell choices
- equipment choices
- roleplay user text

連續切：

```text
zh-TW → en → zh-TW → en
```

驗證：

- Draft revision 不因純切語言增加。
- payload 不變。
- selected StableKeys 不變。
- user text 不變。

## H.4 Character State safety

在 Character Sheet 先建立可觀察 live state：

- HP damage
- Temp HP
- condition
- resource used
- prepared spell
- inventory state

切換 locale 多次並 reload，所有 live state 不變。

## H.5 Pure-language human browser gate

人工逐頁巡覽：

- Landing
- Workshop
- Builder：Basic / Origin / Abilities / Class / Spellcasting / Equipment / Review
- Character Sheet every relevant tab/section
- Version History

分別以 `zh-TW` / `en` 進行。

Blocker：

- policy-required rules name / description 顯示錯語言。
- 切語言造成 Draft / Character state mutation。
- reload 才能完成切換。
- locale persistence 失效。

Major：

- 可達頁面出現明顯 system/rules 混語。
- error / empty / loading / accessibility copy 漏翻。
- search result / source label 錯語言。

Blocker / Major 必須在 M02 closeout 前清零。

## H.6 Completeness final gate

最終 gate 必須證明：

```text
M02-C localizable field policy valid ✓
srd5.1  required fields zh-TW ✓ en ✓
phb2014 required fields zh-TW ✓ en ✓
scag    required fields zh-TW ✓ en ✓
gos     required fields zh-TW ✓ en ✓
UI copy zh-TW ✓ en ✓
errors  zh-TW ✓ en ✓
```

並證明 not-yet-user-visible fields 不會被錯誤納入當期 blocker。

## H.7 Resume gate

M02 closeout 後，才可 resume：

```text
M01-D — VGM Race Expansion
```

從 M01-D 起，每個新增／修改／首次 expose user-visible system / rules content 的測試都必須同時驗 `zh-TW` / `en` coverage；缺任一 locale 視為該 Subphase regression failure。

## H.8 Documentation closeout

M02 closeout 測試／人工 checklist 必須確認：

- `AGENTS.md`：目前階段已切回 M01-D，且永久 supported-locale engineering rule 已加入。
- `PROJECT_BRIEF.md`：M02-A～H 全部 ✅，下一個 coding step = M01-D。
- `規格企劃.md`：產品層語言行為與實際 M02 一致；若原本無對應產品規格則補入，不寫 implementation detail。
- `data/srd5.1/NOTICE.md`：已標示本專案提供 SRD 5.1 實際翻譯之 user-visible presentation text 的繁中 translation / adaptation，並明確說明已修改；不得誇大成整份 SRD 全譯。
- 三份 M02 文件 status / closeout evidence 一致。

## H.9 Translation evidence closeout

彙整 M02-D / E / F batch evidence，至少能回答：

- 各 pack / category 翻譯 entry / field 數。
- translation method。
- 人工抽審數。
- glossary lint 結果。
- completeness 結果。
- 是否有已知非-required untranslated field，以及它為何尚非 user-visible。

Required missing translation 不得列成 accepted exception。
