# M02 — 實作規格

> Phase：**M02 — Traditional Chinese / English Localization**  
> 類型：**M Phase（Modification / Maintenance Phase）**  
> 插入時點：**M01-C — SCAG / GoS Background Expansion closeout 後，暫停 M01；M02 closeout 後回到 M01-D。**  
> 本文件定義 **M02-A～M02-H 每個 Subphase 完成後什麼必須為真**。具體資料格式、module、API、locale resource layout、migration 與接線放在 `開發設計方針.md`；自動與人工驗收方式放在 `測試指南.md`。

最後更新：2026-08-30

## 1. M02 定位

P0 / P1 已完成 Character Core、Character Builder、Character Sheet、Version History 與 SRD 5.1 Character Content；M01-A～M01-C 進一步建立 Multi-Source Content Pack，並加入 PHB / SCAG / GoS Character Origins / Background content。

在繼續 M01-D～M01-I 大量加入 VGM / VRGR / TCE 內容前，M02 先建立永久的雙語基礎，避免之後每新增一批規則資料都累積 English-only presentation debt。

M02 要解決的是：

1. 網站目前 UI 文案同時存在英文、繁中與混合顯示。
2. Content Registry、Builder DTO、Character Sheet / Review 等既有流程會直接傳遞 `name` / `label` / `desc` 等 presentation text，尚未有正式 locale contract。
3. 第一版語言功能必須支援兩個純語言模式：**繁體中文（`zh-TW`）**與 **English（`en`）**。
4. 語言切換必須即時完成，不重新載入頁面，不改變 Builder Draft / Character / Current State。
5. 語言選擇只屬於瀏覽器 presentation preference，必須在下次開啟網站時沿用。
6. M02 closeout 當下所有正式 runtime content（SRD 5.1、PHB 2014 additions、SCAG、GoS）必須具有完整的 `zh-TW` / `en` presentation coverage。
7. M02 完成後，後續 M01-D～M01-I 新增的任何 user-visible rules content 必須在該 Subphase 內同步提供兩種語言，不得再另外累積「之後補翻譯」的工作。

M02 不改寫正常 P0 → P1 → P2 Roadmap，也不取消 M01-D～M01-J：

```text
M01-A
→ M01-B
→ M01-C
→ 暫停 M01
→ M02-A～M02-H
→ M02 closeout
→ 回到 M01-D
→ M01-E～M01-J
→ P2
```

## 2. M02 第一版產品行為

### 2.1 只支援兩個 locale

M02 第一版正式 locale：

```text
zh-TW — 繁體中文
en    — English
```

第一版不做：

- 簡體中文。
- 日文或其他語言。
- 使用者自訂語言包。
- 每個 Character / Campaign / Room 各自保存 locale。
- 帳號層語言同步。
- 自動機器翻譯服務。

### 2.2 純語言模式

**繁中模式：**所有可翻譯的系統 UI、規則名稱、規則說明、系統提示與系統提供文字使用繁體中文。  
**English mode：**所有可翻譯的系統 UI、規則名稱、規則說明、系統提示與系統提供文字使用英文。

「純語言」要求禁止正常使用流程出現可避免的中英混合 presentation，例如：

```text
種族：Wood Elf
背景：Guild Artisan
法術：Fireball
```

或：

```text
Race：木精靈
Background：公會工匠
```

下列內容不視為語言混用缺陷：

- 使用者自行輸入的 Character name / Appearance / Biography / Roleplay notes / notes 等自由文字。
- `D&D`、`SRD`、`PHB`、`SCAG`、`GoS`、`VGM`、`VRGR`、`TCE` 等產品／來源縮寫或正式標記。
- 骰子記法、數值、單位、StableKey、URL、程式／debug identity 等非自然語言 token。
- 專案刻意保留的規則縮寫；但其周邊說明仍須符合目前 locale。

### 2.3 切換行為

語言切換必須：

- 在目前頁面立即生效。
- 不做 full page reload。
- 不透過 URL navigation 假裝切換。
- 不離開目前 Builder step / Character Sheet page / Version page。
- 不改變目前 selection、輸入值、展開狀態等與語言無關的使用者工作內容。
- 不建立、修改或取消 Builder Draft。
- 不增加 Draft revision。
- 不修改 Character Build Version。
- 不修改 Current State。
- 不因切換語言而送出 rules / character mutation。

切換完成後，使用者不應觀察到持續性的「一部分已切換、一部分仍是上一語言」狀態。

### 2.4 瀏覽器記憶

locale preference 保存於目前瀏覽器。

要求：

- 關閉分頁後再次開啟仍沿用。
- page reload 後仍沿用。
- 不寫進 Builder Draft / Character / Campaign domain data。
- 第一版在沒有既存 preference 時預設 `zh-TW`。
- 第一版不要求 browser-language auto detection。

## 3. Localization 共通硬原則

### 3.1 Rules identity 與 display language 完全分離

Canonical identity 永遠使用既有 StableKey，例如：

```text
srd5.1:spell:fireball
phb2014:subrace:wood-elf
scag:background:city-watch
gos:background:marine
```

切換 locale 不得改變：

- StableKey。
- Content Pack identity。
- Draft selection identity。
- CharacterBuild refs。
- Current State refs。
- choice id / option id。
- version identity / provenance。

Display Name 永遠不是 foreign key，也不得因翻譯不同建立第二個 rules entity。

### 3.2 Localization 是 presentation，不是第二套規則資料

M02 必須維持：

```text
同一份 mechanics / identity
→ en presentation
→ zh-TW presentation
```

不得建立兩份會各自演化的 mechanics content，例如：

```text
srd5.1-en
srd5.1-zhTW
```

不得讓英文版與中文版具有不同 eligibility、choice、數值、grant、reference graph 或 Build 結果。

### 3.3 Server authoritative rules 不變

M02 只改 presentation 能力，不把 rules legality 搬進 frontend。

既有流程仍為：

```text
Builder Draft
→ server choices / compile / validation
→ Review
→ Confirm
→ immutable CharacterBuild / Current State
```

同一 Draft 在 `zh-TW` 與 `en` 下，除 presentation text 外，所有 machine-readable result 必須相同。

### 3.4 Locale 不屬於 Draft / Build / State

第一版 locale 是 browser preference，不是遊戲狀態。

禁止把 locale 寫入：

- `BuilderDraftPayload`。
- `CharacterBuild`。
- `CharacterState`。
- Character Version metadata。

因此切換語言不能造成 autosave、revision bump、new version 或 state write。

### 3.5 系統文字與使用者文字分離

M02 必須區分：

**System-authored / rules-authored text：**要依 locale 切換。  
**User-authored free text：**保持使用者原文，不自動翻譯、不在切換時重寫。

例如：

- Background 系統提供的 Personality Trait suggestion：必須能依 locale 顯示。
- 使用者自己輸入的 Personality Trait：保持原文。
- 系統提供的 Background Feature description：依 locale 顯示。
- 使用者自己寫的 Biography：保持原文。

若系統提供的 suggestion 需要在選取後仍保有「可隨 locale 切換」的語意，必須保存可辨識的 system identity，而不是只把某一語言的 display string 當唯一身份。

既有已保存且沒有 system identity 的自由文字不得用字串比對、猜測或機器翻譯方式偷偷改寫。

### 3.6 Translation fallback 不可掩蓋缺漏

M02 closeout 後，正式支援的 `zh-TW` / `en` 不得以「缺繁中就顯示英文」作為正常 production 行為。

缺 translation 必須：

- 在開發／測試中可被清楚偵測。
- 在完整性驗證中造成 failure。
- 不得 silent fallback 後仍宣稱該 content 已完成 localization。

### 3.7 Glossary 是翻譯標準，不是 runtime replace engine

M02 必須建立一致的 D&D 5e 2014 翻譯術語規則，用來約束：

- Ability / Ability Score。
- Saving Throw。
- Skill。
- Armor Class / AC。
- Difficulty Class / DC。
- Proficiency Bonus。
- Advantage / Disadvantage。
- Short Rest / Long Rest。
- Spell Slot / Cantrip / Concentration。
- Race / Subrace / Background / Class / Subclass / Feat / Trait / Feature。
- Equipment / Weapon / Armor / Tool / Language。
- 其他在 M02 內容中反覆出現的核心術語。

Glossary 不得靠 regex / global string replacement 直接把長篇規則文字機械替換成翻譯。

## 4. M02 closeout 內容邊界

M02 插入時點固定在 **M01-C closeout 後**。

因此 M02 closeout 必須涵蓋當時正式存在的 content packs：

```text
srd5.1
phb2014
scag
gos
```

### 4.1 SRD 5.1

M02 第一版不是只翻目前某一頁恰好出現的 SRD 名稱。

SRD 5.1 Character Content 中所有正式 translatable presentation fields 均納入完整性要求，包括但不限於：

- abilities
- alignments
- backgrounds
- classes
- conditions
- damage types
- equipment categories
- equipment
- feats
- features
- languages
- levels 中的 user-visible names / presentation text
- items
- magic schools
- proficiencies
- races
- skills
- spells
- subclasses
- subraces
- traits
- weapon properties

Monster / Beast 仍依既有 P0 scope guard 延後，不因 M02 提前導入 P4 content。

### 4.2 PHB / SCAG / GoS

M01-B / M01-C 正式導入的所有 runtime presentation content 都必須納入，包括：

- race / subrace / Variant Human names。
- Background / Background Variant names。
- feature names / descriptions。
- skill / tool / language / equipment choice text。
- Background Feature presentation。
- roleplay suggestions。
- roleplay suggestion reuse / inheritance 後真正呈現在畫面上的文字。
- GoS optional flavor tables / suggestions，只要正式 runtime UI 可顯示就必須雙語。
- source labels 與其他會出現在 selector / Review / Sheet 的 presentation text。

### 4.3 M01-D 之後的永久承接規則

M02 closeout 後恢復 M01-D 時：

> **任何 Subphase 新增或修改 user-visible system / rules content，必須同步維護所有正式支援 locale；缺少 `zh-TW` 或 `en` 視為該 Subphase 未完成。**

因此未來 VGM / VRGR / TCE content 的翻譯不再另開「補翻譯 Phase」，而是內容本身 Definition of Done 的一部分。

## 5. M02 Subphase 順序

三份 M02 文件固定使用以下名稱與順序：

```text
M02-A — Locale Foundation & Runtime Switch
M02-B — Full UI Copy Localization
M02-C — Localized Content Model & Terminology Contract
M02-D — SRD 5.1 Names & Structured Text
M02-E — SRD 5.1 Full Descriptions
M02-F — PHB / SCAG / GoS Localization
```

每個 Subphase 必須可獨立實作、驗證、commit；完成時專案必須保持可啟動、可 build、可測試，不得用「等下一個 Subphase 才修」作為已知 regression 的理由。

# M02-A — Locale Foundation & Runtime Switch

## 目標

建立全站唯一 locale runtime state，完成 `zh-TW` / `en` 一鍵切換、即時 rerender 與瀏覽器記憶，且證明 locale 與 Draft / Character domain state 完全分離。

## 完成後必須為真

1. 全站存在一致、容易找到的語言切換控制。
2. 可在 `zh-TW` 與 `en` 間一鍵切換。
3. 切換不做 full page reload。
4. 切換後仍停留在相同 URL、相同功能頁與相同工作位置。
5. locale preference 保存於瀏覽器，reload / reopen 後沿用。
6. 無既存 preference 時預設 `zh-TW`。
7. page language / accessibility metadata 能反映目前 locale。
8. locale runtime state 可供全站 UI 與後續 content presentation 共用，不允許每個 feature 自己維護第二份 locale state。
9. 切換 locale 不修改 Draft payload、Draft revision、Character Build 或 Current State。
10. 在 Builder 中連續切換語言，不得觸發 Draft PATCH / autosave。
11. locale state 本身失效或出現未知值時，系統可回到受支援的安全預設，不會破壞頁面。

## 本 Subphase 不要求

- 此時所有既有 UI / content 已經翻完。
- SRD / PHB / SCAG / GoS localization coverage。
- localized search。

這些由後續 Subphase 完成。

# M02-B — Full UI Copy Localization

## 目標

把目前網站所有 frontend-owned UI copy 正式納入 localization，不再由 React component 到處散落不可切換的英文／中文 literal。

## 翻譯範圍

至少涵蓋目前既有：

- Landing page。
- Character Workshop。
- Character Builder 全步驟。
- Character Sheet。
- Character Version History。
- Review / Confirm flow。
- loading state。
- empty state。
- error banner 中由 frontend 自己產生的文字。
- button / link / heading / label / hint / placeholder。
- badge / status / helper text。
- modal / confirmation copy（若現有 UI 有使用）。
- accessible name / `aria-label` / visually hidden system text。

## 完成後必須為真

1. `zh-TW` 模式中，frontend-owned natural-language UI copy 只顯示繁中。
2. `en` 模式中，frontend-owned natural-language UI copy 只顯示英文。
3. 同一頁即時切換時，所有 frontend-owned UI copy 同步更新。
4. 不以 duplicated page/component 的方式維護兩套 UI。
5. UI 翻譯不影響 navigation、form value、selection、Draft save 或 validation semantics。
6. Button / label 因兩語長度差異不得造成主要操作不可見、文字重疊或基本 responsive regression。
7. Source abbreviations / D&D notation 可依共通規則保留，但其周邊句子必須使用當前 locale。

## 本 Subphase 不包含

Server / Content Registry 產生的 race / class / spell / equipment / feature names 與規則 descriptions；這些由 M02-C～F 接管。

# M02-C — Localized Content Model & Terminology Contract

## 目標

建立正式的 rules-content localization contract，讓 StableKey / mechanics 與 display language 分離，並解決 Builder / Review / Sheet 目前可能直接攜帶單一語言 `name` / `label` / `desc` 的問題。

## 完成後必須為真

### C.1 Stable identity 不受 locale 影響

同一 content entry 在兩語下具有相同：

- StableKey。
- source / pack identity。
- references。
- choices / grants semantics。
- mechanical data。

只有 presentation 改變。

### C.2 Rules presentation 可按 locale resolve

所有正式 Content Registry entry 與可見 nested rules presentation，必須存在一致的方式取得目前 locale 對應的：

- name。
- short label。
- description。
- choice / option presentation。
- source label。
- user-visible structured text。

具體 storage / API 形狀留給 `開發設計方針.md`，但不得要求 feature component 各自靠 display string 猜 StableKey。

### C.3 Server-generated presentation 不再綁死單一語言

Builder / Review / Character Sheet 等 server-derived view 若包含 user-visible：

- `name`
- `label`
- `message`
- `description`

必須能依正式 locale contract 呈現，不能永久把英文 display string 當 domain identity。

Machine-readable code / reference / id 保持語言中立。

### C.4 Terminology glossary

建立 D&D 5e 2014 `en ↔ zh-TW` 核心術語標準。

同一概念不得在不同頁隨意出現互相矛盾的繁中譯名；若存在特定專有名詞決策，以 glossary 為翻譯一致性的 Source of Truth。

### C.5 System suggestion 與 free text boundary

Background / roleplay 等系統 suggestion 必須能依 locale 顯示。

如果系統 suggestion 被保存後仍需要維持 locale-aware presentation，保存結果必須保留 system identity；不得只把某一語言的 display string 當唯一身份。

使用者手動輸入或手動改寫的自由文字保持原文，不自動翻譯、不因 locale switch 被改寫。

### C.6 Backward compatibility

既有 Character、Build Version、Draft、Current State 不得因加入 localization 失效。

M02 不以改 StableKey 或重新建立 Character Version 的方式完成翻譯。

# M02-D — SRD 5.1 Names & Structured Text

## 目標

完成 SRD 5.1 Character Content 所有名稱與短型／結構型 presentation 的 `zh-TW` / `en` localization，讓 selector、summary、Review、Sheet 等不再出現 untranslated rules names。

## 翻譯範圍

包含 SRD 正式 Character Content 中所有可翻譯的：

- entity name。
- full name / short name。
- category / type display text。
- race / subrace / class / subclass / background names。
- ability / skill / proficiency / language names。
- equipment / equipment category / weapon property names。
- spell / magic school names。
- feat / feature / trait names。
- condition / damage type names。
- item names。
- choice labels / option labels。
- structured short hints / one-line text。
- 其他會直接作為 UI label / selector option / grant summary 出現的 presentation text。

## 完成後必須為真

1. `zh-TW` 下所有上述 SRD presentation 使用繁中。
2. `en` 下所有上述 SRD presentation 使用英文。
3. 同一 selection 在切換語言前後 StableKey 完全相同。
4. Builder selected values、Review grants、Character Sheet rules names、Spell choices、Equipment choices 等都能同步切換 display name。
5. 同名或相似名稱仍以 StableKey / source 正確區分，不以翻譯名稱 dedupe。
6. SRD translatable structured fields 的 completeness 可被機器枚舉，不依人工印象判定「應該翻完了」。

## 本 Subphase 不要求

長篇 rule descriptions 的完整繁中內容；由 M02-E 完成。

# M02-E — SRD 5.1 Full Descriptions

## 目標

補齊 SRD 5.1 所有正式 translatable 長篇規則說明，使任何既有或未來 UI 只要呈現該 SRD Character Content 的 description，都可以直接依 locale 正確顯示。

## 翻譯範圍

包含但不限於：

- spell descriptions。
- feature descriptions。
- trait descriptions。
- feat descriptions。
- condition descriptions。
- damage type descriptions。
- skill descriptions。
- magic school descriptions。
- item descriptions。
- weapon property descriptions。
- race / class / subclass / background 中正式保存的 user-visible long-form rules text。
- 其他 SRD runtime content 中屬於 presentation、而非 machine-only metadata 的自然語言說明。

## 完成後必須為真

1. SRD 5.1 所有納入 M02 scope 的 long-form translatable fields 具有 `zh-TW` 與 `en`。
2. 翻譯不得改變 dice formula、數值、DC、range、duration、component、reference identity 或其他 mechanics semantics。
3. 內文中的術語遵守 M02-C glossary。
4. Markdown / rich-text / list 等既有 presentation semantics 在兩語下等價，不因翻譯破壞內容結構。
5. 任何正式 UI 顯示這些 description 時，切換 locale 可立即更新，不需要重新取得或重建 Character。
6. Missing description translation 可被完整性檢查抓到。

# M02-F — PHB / SCAG / GoS Localization

## 目標

把 M01-B / M01-C 導入的所有非 SRD runtime content 完整納入雙語 presentation，讓 M02 closeout 時所有正式 enabled content packs 都符合純語言模式。

## F.1 PHB 2014 additions

需涵蓋 M01-B 正式導入的：

- Backgrounds / Background Variants。
- Variant Human。
- PHB subraces。
- racial / origin features。
- Background Features。
- starting proficiency / language / tool / equipment choice presentation。
- roleplay suggestions。
- 其他正式 runtime UI 可見文字。

## F.2 SCAG

需涵蓋 M01-C 正式導入的：

- SCAG Background names。
- Background Feature names / descriptions。
- choice / branch presentation。
- roleplay suggestions。
- reused PHB roleplay tables 在 SCAG Background context 下的 localized presentation。
- source label 與其他 user-visible text。

Roleplay suggestion inheritance 只能重用 presentation suggestion，不得因 localization 改變既有「roleplay inheritance ≠ mechanical inheritance」規則。

## F.3 GoS

需涵蓋 M01-C 正式導入的：

- GoS Background names。
- Background Feature names / descriptions。
- choice / equipment presentation。
- optional Fisher Tale / Marine Hardship 等 flavor / roleplay presentation（以實際 M01-C runtime content 為準）。
- source label 與其他 user-visible text。

Optional flavor content 在任何 locale 下都仍是 optional，不得因 localization 變成 Confirm blocking choice。

## 完成後必須為真

1. `phb2014` / `scag` / `gos` 的正式 translatable runtime fields 同時具有 `zh-TW` / `en`。
2. 跨 pack reference 在兩語下仍指向同一 StableKey。
3. selector / Review / Sheet 可顯示正確 locale 的 source-aware names。
4. roleplay suggestion reuse 不因翻譯造成 mechanical grant pollution。
5. Background variant / branch 在切換語言後仍保持相同 active identity，不會選到另一來源或另一 variant。
6. `zh-TW` 模式不得因缺 non-SRD translation 偷偷 fallback 成英文。

# M02-G — Localized Search, Errors & Completeness Gates

## 目標

把 localization 從「看起來會切」提升成可長期維護的正式系統：搜尋／排序／錯誤訊息符合目前 locale，並建立 machine-verifiable translation completeness gate。

## G.1 Localized search

所有目前提供 rules-content 搜尋的 selector 必須：

- 顯示目前 locale 的名稱。
- 以目前 locale 的 display text 作為主要搜尋語言。
- 允許以另一正式 locale 的名稱作為 search alias，方便熟悉英文 D&D 術語的繁中使用者或反向查找。
- 搜尋結果仍只顯示目前 locale，不因 alias search 變成雙語顯示。

例如繁中模式搜尋：

```text
fireball
```

可以找到：

```text
火球術
```

但正常結果不需要顯示 `火球術 / Fireball` 雙語並列。

## G.2 Localized sorting

只要 UI 有依名稱排序：

- 排序依目前 locale 的 display name。
- 不以另一語言 name 或 StableKey 造成使用者可見的異常順序。
- locale switch 後可重新呈現符合該語言的排序結果。

## G.3 User-visible errors / validation

所有正式使用流程中的 system-owned user-visible：

- validation issue。
- disabled reason。
- save / load / confirm error。
- not-found / invalid-selection message。
- network fallback message。
- rules warning / non-standard message。

必須能依目前 locale 顯示。

Machine-readable error / validation code 保持穩定且語言中立；不得讓 domain logic 依翻譯後字串判斷錯誤種類。

## G.4 Completeness gate

建立可機器驗證的 translation completeness 定義。

至少能驗證：

```text
supported locale
× enabled content pack
× translatable field
```

沒有缺漏。

M02 closeout scope：

```text
locales: zh-TW, en
packs:   srd5.1, phb2014, scag, gos
```

缺任何 required translation 必須造成 test / CI gate failure；不得以 silent fallback 當成通過。

## G.5 Duplicate / orphan localization detection

Localization maintenance 必須能發現至少下列問題：

- runtime content 有 StableKey 但缺 locale entry。
- locale entry 指向不存在的 StableKey。
- required field 只有一種 locale。
- 同一 locale / StableKey 出現衝突定義。

# M02-H — Full M02 Integration & Closeout

## 目標

以真實使用流程驗證 M02 已達到「兩個純語言模式 + 完整 rules translation + Draft-safe instant switch」，並正式把 localization 變成後續所有內容 Subphase 的完成條件。

## H.1 全站純語言驗收

至少逐頁確認：

- Landing。
- Character Workshop。
- Create Character Builder 全步驟。
- Review / Confirm。
- Character Sheet。
- Version History。
- Existing Character Level Up / Edit flow 中目前可到達的頁面。

`zh-TW` 與 `en` 都不得出現可避免的另一語言 system/rules presentation。

## H.2 Draft-safe switch

在已有實際未完成 Draft 的情況下，至少驗證：

```text
zh-TW
→ en
→ zh-TW
```

過程前後必須保持：

- same Draft ID。
- same Draft revision。
- same name / target level input。
- same race / subrace / background / alignment StableKey。
- same ability scores。
- same class progression。
- same structural choices。
- same spell selections。
- same equipment selections。
- same roleplay user text。

Locale switch 本身不得產生 Draft mutation request。

## H.3 Create / reload / persistence

至少完成：

1. `zh-TW` 建立角色 → Confirm → Character Sheet → reload，保持繁中。
2. `en` 建立角色 → Confirm → Character Sheet → reload，保持 English。
3. 已存在 Character 在兩語間切換只改 presentation，不建立新 Version。
4. 關閉再開網站後沿用上次 locale preference。

## H.4 Cross-source localization flow

至少以會同時引用多個 pack 的角色流程驗證：

- SRD + PHB。
- SRD + SCAG。
- SRD / PHB + GoS（依 M01-C 合法組合）。

Review / Sheet / selector / grants 不得因跨 source 而漏翻、錯翻或 identity 混用。

## H.5 Content completeness closeout

M02 不得關門，直到：

- `srd5.1` required translation coverage = complete。
- `phb2014` required translation coverage = complete。
- `scag` required translation coverage = complete。
- `gos` required translation coverage = complete。
- UI copy required translation coverage = complete。
- user-visible system errors / validation required translation coverage = complete。
- automated completeness gate green。

## H.6 Regression

M02 必須保持 P0 / P1 / M01-A～C 既有核心能力：

- Character Sheet mechanics 不變。
- Builder legality 不變。
- Confirm atomicity / idempotency 不變。
- immutable Build Version 不變。
- Current State 不因 locale 改變。
- content source provenance 不變。
- multi-source StableKey correctness 不變。

## H.7 Human gate

M02 closeout 前需要一次真人 browser smoke，至少確認：

- 語言切換位置直覺且容易使用。
- 兩語在主要 desktop layout 無明顯 overflow / broken layout。
- Builder 中途切換不丟資料、不跳 step。
- Character Sheet 主要規則名稱與說明確實同步切換。
- 搜尋 English alias → 繁中結果與繁中 alias → English result 都可理解使用。
- 沒有肉眼可見的大面積漏翻／混語。

Blocker / Major localization 或 Draft-safety 問題必須在 M02 closeout 前修完。
