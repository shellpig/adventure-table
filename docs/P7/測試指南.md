| A.2 | 多 Session 排序／filter／opaque cursor；bounded page／scan budget、稀疏可見結果可繼續；沒有 raw secret 命中／count／snippet；Human 目前 Seat 範圍及來源 DM Seat、AI 同 Seat 過去歷史、foreign Room／wrong Campaign／無 Seat／pre-session grant／revoke／Take Back／reassignment；每種 visibility 與 hidden Monster／HP／AC／Secret DC 測試 |

PG：從既有 heads＋seed events 升級 P7-A，核對場次 position 分配／indexes／constraints；Session Start 與場外管理紀錄並行分配的 position 唯一且單調；active Session 期間例外管理紀錄的 record_rank 唯一且不消耗 seq；failpoint 令場外寫入與管理紀錄共同 rollback；以兩個 independent connections 證明場內 append 不等待 Campaign guard。不能只用 `metadata.create_all()` 驗 migration。

Browser：在兩場以 DM／Player 留下 public/private 內容，Timeline 查舊場、篩選、分頁、展開；Player 搜尋 secret 詞無洩漏，另一個 DM Seat 不取得舊 DM-only；reload 不重播舊傷害。AI adapter 用真 server HTTP／MCP 測工具 schema 及 scope，不只 mock service。

A.2 必測同一頁包含已結束 Combat A 與目前 active Combat B：A 的 hidden Monster entry／instance id、名稱在 M05 `/events/history`、Timeline、AI history search／snippet 中皆被遮蔽，B 名單不能代替 A；合法 DM 仍可讀。另測同一 Monster 後續 visibility 改變、來源關聯缺失的保守遮蔽、Restore archived 路徑與 package remap 後的歷史讀取。Player 搜尋 hidden 名稱無命中洩漏；Owner 完整匯出保留秘密不算失敗。

## P7-B — Campaign Snapshot Capture

| ID | 驗證要求 |
|---|---|
| B.1 | restore payload 涵蓋 world／override／knowledge／attachments／context／非戰鬥中的 Monster，Stage 獨立保存為 historical presentation；零 Scene／Adventure 合法；沒有 Character／versions／state／Roster／Seat／credentials／Combat board；引用 manifest／digest 完整 |
| B.2 | 沒有自動存檔：Session Start／End、Scene Change、Combat Start／End 前後 Snapshot 數量不變；場內該場 Human DM 與場外 Room DM／Owner 可手動存檔，Player／AI DM／AI Player 拒絕，AI DM 主持中無人可存；Quick／Tactical active Combat、Session End 後延續 Combat 均拒絕；場外入口遇到已開場回 409；存檔 failpoint 不留半份或孤兒事件，同 idempotency key retry 一份 |
| B.3 | 列表分頁／payload 管理 scope／secret DTO；immutable checksum、restart 後讀取；沒有個別刪除或自動淘汰入口；被 Snapshot 引用資料個別刪除遭 FK 拒絕、Room Hard Delete 仍完整清理；兩 locale blocked 與 empty UI |

PG race：場內手動存檔 vs 場內世界寫入／Combat Start；場外手動存檔 vs 場外世界寫入／Session Start；asset delete vs capture；檢查 payload 與 boundary 同一切面，不只檢查「都有 rows」。P7-B 關門附 Snapshot 涵蓋資料 writer 清單，逐項標明走場內事件隊列或 Campaign guard，例外路徑有對應測試。

Browser：active Combat 時手動按鈕與 API 都拒絕；結戰後存檔成功；缺 Scene 仍可玩；列表說明角色不回復。測試按鈕 disabled 只是 UX，另需 forged HTTP 拒絕證據。

B.1／B.2另驗：member Human current DM可依場內Human DM scope手動capture，但沒有Room庫authoring／場外Restore／portable管理權；Instance own rules snapshot／provenance被保存，Room模板／map／配置authoring不進restore payload。Capture引用revision／digest時並發Room庫編輯，來源必須是完整一致版本或拒絕，不能只靠Campaign guard假定庫沒改。Snapshot引用阻擋模板／map個別hard delete，Room整包刪除仍合法。

## P7-C — Campaign Restore & History Archive

| ID | 驗證要求 |
|---|---|
| C.1 | Human 場外 DM／Owner 可 Preview／Confirm；active Session、AI DM Session、無 Session 卻有 active Combat 均拒絕；Player／AI／foreign Room／expired access／forged Preview／過期 TTL／world revision 變更／missing reference／digest 變更零副作用 |
| C.2 | 世界完整回復、後新增 world entry 退出 active；兩 Campaign 共用角色的 Build／所有 Version／HP／slots／items／conditions 逐欄完全不變；Roster／Seat 不回捲；authoring／asset bytes 不回捲；不開 Session／Combat、不重擲／spend／反向調 Character writer |
| C.3 | 同 Session 中途手動存檔精確 cutoff 到該場 seq；連續多次 Restore、Restore 更早／不同 segment、同 Confirm retry；後續 history 只 archive 不 delete、不改 source event seq；archived filter 與 visibility；epoch／revision／position 單調、old mutation retry 不 replay、pre-session grant／OAuth 失效、Resume／AI context 取目前 lineage |

PG race：Preview 後另一 DM 寫世界；Confirm 與 Session Start／場外世界寫入／第二次 Confirm 競爭；在各 restore 階段注入 failure 檢查完整 rollback。取下一場 grant 不得復用被撤銷 OAuth family。由兩個 independent connections 驗 guard，mock lock 不是 race 證據。

Browser：存檔→改世界／角色 HP 與升等→End→Preview 顯示角色保持→Confirm→世界退回但角色新等級／HP 保留→查看 archived→新場繼續。拒絕時保持 Preview 可理解的錯誤，不能顯示成功後才報衝突。archive 事件不進本場 state projection。

C.2逐欄before／after：Capture後改Room模板數值／presentation、map geometry／預配置、封存及revision，再Restore Campaign A；所有Room authoring與Campaign B保持目前值，A的非戰鬥Instance使用自己的captured rules，不改成最新模板。完整Instance快照不能因模板更新被當作缺規則；真正需要但無法解析的舊外部版本仍由Preview拒絕，不silent用最新庫。

Snapshot引用不應阻止上述合法庫編輯：stable模板／map的hard delete受保護，geometry／placement replace不因Snapshot FK掛住當前child rows而失敗。歷史payload提到已被替換的child ID時，export／import從frozen material做typed mapping，不拿目前庫假補舊內容。

## P7-D — Portable Package Export

| ID | 驗證要求 |
|---|---|
| D.1 | Adventure 無 runtime 且 sources 選項；Campaign 完整 reference closure 含歷史／Snapshots／角色 Versions／map；Room 包含共用角色、未掛 Adventure／map／asset 與未完成 Builder／Import Draft；Character JSON v1 及 HTML 不受影響 |
| D.2 | Room／Campaign Owner-only、Adventure Owner／DM；Player／AI／一般 member 拒絕；active Session／Combat 拒絕；完整 ZIP manifest／hash／bytes 離線可讀；所有 nested fields 不含 credentials／hash／salt／token／secret prefix／OAuth／實體 path，audit ref 無授權效力；超限與 missing bytes 不輸出殘缺成功檔 |

對完整 fixture 做 typed reference coverage：每類 entity 及 nested ID 有 adapter；canonical stable keys／文字中的 UUID 不被改。包內同角色只一份，Campaign 包不洩其他 Campaign；source 文件含一般使用者文字時不以猜測 secret 字串去破壞內容，驗證的是系統憑證欄位與 authority 資料。

PG 一致切面／asset pin：匯出讀取時另一 connection 嘗試 mutation／delete，graph 與 bytes 一致或拒絕；下載 stream 不長持 DB transaction。管理匯出包含 DM-only 資料的提示與雙語下載流程需 browser 證據。

D.1 typed closure必測：Room包含未使用／封存模板與maps，兩Campaign共用來源只一份；Campaign／Adventure只收本身閉包，不帶其他Campaign／不相關庫。map帶完整配置及其builtin dependency／custom templates；P6 typed custom refs、Instance／board／historical／Snapshot nested來源均可解析。保留rules／presentation_json、archived_at／revision、anchor／visibility／sort_order與frozen snapshots；版本資訊不能被latest source替換或為湊完整性而清除Restore blocker。並發庫authoring時所有adapters沿同一export read snapshot，不得各開transaction。

## P7-E — Previewed Copy Import

| ID | 驗證要求 |
|---|---|
| E.1 | Preview 不建正式 entities；bad version／ruleset／content pack／schema／dangling ref／missing file／bad checksum／oversize／ZIP bomb／duplicate path／Windows 大小寫碰撞／absolute／drive／UNC／traversal／symlink 皆拒絕；不執行 script、不 fetch URL |
| E.2 | Room→new Room、Campaign→target Room 新 copy、Adventure→new copy；typed remap 含 nested payload／Snapshot／lineage／recipient／participant／geometry；同 Room 包共享角色維持、Campaign copy 不改 target 原角色；StableKey／Character JSON v1 不改；無 active Session／Combat／live queue／AI grant／OAuth／controller binding；相同 label 不自動授權 |
| E.3 | Confirm 重驗 auth／target／digest／TTL／pack 與完整性；retry 一次結果；failure／crash 各階段 DB rollback 或已 commit 可辨識，bytes reconcile 不刪已成功 imports；取消／過期 cleanup 隔離、不刪別 Room；成功連結可用，重新授權後可 Start |

Roundtrip 比較使用 semantic normalized graph，不比較必須改掉的 UUID／secret／created timestamp；明確列出設計排除的憑證／live authority。Room 測試包含兩 Campaign 共享一 Character；Campaign copy 比較原 Room 所有角色 before／after 不變。新 Server 上關閉原 Server URL 仍可讀 assets／Preview／Start，防「portable 只有連結」。

E.2 roundtrip再比對共用Room模板／map identity關係與獨立placement／geometry new IDs；同Room import也不patch原庫，source_key／同名資料不自動merge。builtin stable keys不變，reserved typed `custom:<uuid>`指向新模板，自由文字中的UUID／同字串不改。封存資料不自動解封：封存map不能新選開戰、封存模板只供已保存配置載入；新Instance用新庫、historical Instance維持凍結規則／雙語名稱，不回查最新版。

真 PostgreSQL 匯入原 Human／AI DM 的已結束 Session，驗 `sessions`／`session_participants` binding constraint 仍成立：kind normalize 為 none、舊 access／grant／generation 不落地，原 kind／作者名稱只在無授權 provenance 呈現。Recipient／DM Seat remap 後歷史秘密過濾仍正確。另驗 P3 `room_stage_images` bytes 與 Snapshot historical Stage round trip，不能只有 P6 filesystem asset round trip；Restore 及一般新場 Start 都不接續 Stage。

B.1／C.2 必測：來源 Session 有 Stage 的 Snapshot 可在歷史詳情顯示，場外 manual capture 的 historical Stage 為空；Restore 不改舊 Stage、不寫接續 seed、不發 Stage replay。比較有 Restore 與無 Restore 的新 Session，Stage 都是空白，角色與世界按各自契約保持／回復。

Browser：Owner 上傳→Preview 數量／warning→取消無正式資料→再次 Confirm→新 Room／Campaign→領新 Owner 憑證／重新分配 Seat→查看世界／歷史／角色→Start。Player 不能藉知道 job ID 讀 Preview／download；Room import 依 create-room policy 取得新 authority，不要求包內舊 Owner Key。

## P7-F — Full P7 Integration & Closeout

### F.1 全旅程

真 backend＋隔離 PG 上跑：兩場有 public/private events → 搜尋 → 手動存檔（場內一次、場外一次）→ 修改 world 與角色 → End → Preview／Restore → 世界回復而角色完全保留 → archived 可查且 filtered → 新場 Human／AI 使用當前 world → End／完成 Combat → export → 關原 server → clean DB／asset root import new copy → remap／new authority → 再 Start。

包含 Quick 及 Tactical 使用既有 Combat 服務，至少一條跨 Session 延續 active Combat 的案例，證明 Snapshot／Restore／Export 限制不是只看 Session status；另一 Campaign 共用角色保持不變。所有 optional Scene／Adventure 為空亦可跑。

M07整合旅程再串兩Campaign共庫、不同Size／hidden配置、Snapshot後編輯／封存庫、Restore只回世界與Instance、完整Room及Campaign closure export、clean import到新Room與同Room新copy；驗引用remap／封存使用限制／old frozen rules，以及Player歷史秘密過濾仍正確。

### F.2 正式 AI gate

透過 M04 正式公開 HTTPS connector，使用既有 Join Kit，至少一個 AI DM 與一個 AI Player scope（可分次執行）：

- `get_recent_timeline`／`search_campaign_history` 跨 Session 取得 bounded 相關 history；DM／Player 都以合法有效 Seat 參與。
- Player 以 secret 關鍵字搜尋仍無 secret 結果，其他 Seat private history 無法取得；revoke／Take Back 後工具拒絕。
- Restore 後重新開場並授權，AI 以恢復世界及目前角色為 context；archived history 帶標籤，不能把舊傷害重新扣一次。
- 保存 tool request／response、scope、使用者 UI 觀察與 server evidence；去除 Join Token／OAuth／keys。正式 gate 不得由 mock transport 或 Human 兩瀏覽器替代；管理 Import／Export 不在 AI gate。

### F.3 Regression 與關門

- 全套 backend pytest、前端 unit／build、`docker compose config`、全套 Docker E2E 依 AGENTS 實跑；PG 專用 job 與 migration 證據明列，不 silent skip。
- M03 import boundary／schema parity、Web↔Standalone Character JSON legacy／v1 exchange、HTML 不 Import；若 packaging／Python dependencies 受影響依 release pin 跑 build／frozen smoke。
- P3／M05 歷史 scope、Session Resume／wait、M06 echo、P4／P5 resolution／secrecy／Reaction、P6 world／context／writeback／Importer 共用接線回歸。
- 完整 locale parity 及兩 locale browser journey；unknown system key／overflow／raw rule key 列問題，不僅 snapshot 字串比對。
- 多 Room 隔離、reader 權限變更、restart／兩次 Restore／匯入崩潰恢復、完整包新 Server round trip。

Closeout 列每條 A.1～E.3 與 F.1～F.3 的實際證據、剩餘限制及影響；缺必要 gate 不關門。Subphase 完成逐項更新 PROJECT_BRIEF；Phase 全關門後搬歷史入口至 ROADMAP_HISTORY，不在兩檔維護重複進度表。文件內不得填不存在的測試通過紀錄。
