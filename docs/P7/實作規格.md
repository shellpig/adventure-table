# P7 — 實作規格

> Phase：**P7 — Timeline, Snapshot & Portable Data**
> 本文件定義完成條件；具體契約見 [開發設計方針](開發設計方針.md)，驗收與證據見 [測試指南](測試指南.md)。產品行為的單一事實來源仍是根目錄 `規格企劃.md`。

最後更新：2026-10-05

## 定位與開工前提

P7 提供可回看的 Campaign 歷史、Campaign 存檔與還原，以及可攜式 Adventure／Campaign／Room 資料交換。承接 P3 durable events、M05 跨 Session history、P4／P5 Combat、P6 Adventure／Runtime與M07 Room地圖庫／怪物庫；不重建遊戲引擎。

P7 coding依 `PROJECT_BRIEF.md` 排在M07之後。本次M07-D文件交接不代表M07已關門或P7已開工，目前沒有任何 P7 功能已交付。每個 Subphase 完成後應可獨立執行、測試、commit；P8 的全面 Polish 不得用來延期本 Phase 的 correctness、權限或雙語驗收。

## 固定 Subphase

三份文件使用完全一致的名稱與順序：

```text
P7-A — Campaign Timeline & History Retrieval
P7-B — Campaign Snapshot Capture
P7-C — Campaign Restore & History Archive
P7-D — Portable Package Export
P7-E — Previewed Copy Import
P7-F — Full P7 Integration & Closeout
```

A → B → C；D 承接 A～C 的格式；E 承接 D；F 驗證整體。三份文件不是實作紀錄；開工時才依指揮者手冊建立接手摘要與 step 板。

## 共用邊界

- Server authoritative，Human UI／AI MCP 共用服務與 projection；秘密不送給無權讀者。
- Web Room-first，Standalone Character-first。P7 全部多人能力只住 Web；Character JSON v1 與 HTML sheet 不另造格式。
- Gameplay Undo／Revert Transaction 不做。Human DM Direct Edit 沿既有流程，形成正式歷史；不為 P7 新造通用 `resolve_action` 或擴充戰鬥自動化。
- AI DM 的 active Session 不提供 Restore。結束 AI DM 場後，Human 可依正常 DM authority 在符合還原條件時操作；不是在場中取得代理 DM 權利。
- Timeline／Snapshot／Importer 都 optional；不要求先存檔、填 Scene、建 Adventure 才能跑團。
- 使用者文字不翻譯；新增介面、錯誤、摘要格式與規則呈現同時交付 `zh-TW`／`en`。
- Campaign／Room 管理型 Import／Export 先做 Human Owner UI；Owner-scoped 管理 MCP 延後，Seat grant 不得升格為管理授權。AI 的歷史查詢工具仍在 P7。
- Human current DM可以只有member Room authority；場內操作依current DM binding，場外Restore／portable管理與Room庫authoring仍依各自Room authority，不因坐DM Seat而升權。

## P7-A — Campaign Timeline & History Retrieval

### A.1 可回看的正式歷史

跨 Session 分頁呈現既有正式事件，另納入必要的 Session 外世界改動、存檔／還原／歸檔管理紀錄。Dialogue、Narration、擲骰、Combat／Movement／Attack／Spell、資源及世界變化依實際已存在的 producer 收錄；不因清單而實作尚未交付的 Shop／Quest 等 engine。

hover、zoom／pan、開角色卡、未提交草稿、getter／AI read、debug 不進遊戲 Timeline。正式改動與歷史提交原子；retry 不產生重複歷史。摘要可展開細節，不以 client 拼湊另一份真值。

### A.2 搜尋與可見性

Human 可依文字、Session、事件種類、時間範圍與關聯角色篩選；AI 提供 `get_recent_timeline()`、`search_campaign_history()`，回傳 bounded page 與 continuation cursor。

沿 M05 Seat-scoped 歷史讀取；沒有當前 gameplay actor 的合法 Human 歷史讀者仍可讀。DM 層按每個來源 Session 的 DM Seat 判斷，不因今天當 DM 而自動取得別的 DM Seat 舊秘密。AI 每次依當前有效 Seat grant 重驗，歷史讀取不授予舊場寫入權。

隱藏事件／Monster／Secret DC／精確敵人資源不出現在結果、摘要、搜尋 snippet、計數、補全或可下載資料。控制權改派／revoke／Take Back 後下一次查詢立即套用新 scope。Session 外管理紀錄沒有可套用的舊場 DM 身分時，採明確的 Room DM 管理 scope，不假冒 Session event。

隱藏 Monster 的歷史遮蔽按事件所屬戰鬥判斷；已結束戰鬥、另一場戰鬥開始及 Restore 後都不得因此洩漏舊 identity／名稱。P7-A 修正共用歷史讀取，包含 M05 聊天回捲；完整 Owner 管理匯出可保留秘密，匯入後的 Player 讀取仍須正確過濾。

### A.3 與現有流程相容

舊 Session 的事件只供閱讀，不混入本場 seq-based gameplay projection。M06 own-echo 最佳化只影響 wait，不令 Timeline 缺紀錄。P3 Resume／wait 與 M05 聊天回捲保持原有正確性。

## P7-B — Campaign Snapshot Capture

### B.1 存檔範圍

Snapshot 是 **Human DM 手動建立的 Campaign 世界存檔，不是角色回捲、Room 備份或斷線保護**。保存當時 Campaign Runtime 世界、Adventure attachment／override 的 Campaign 關係、Current Scene／Situation，以及 Campaign 所屬非戰鬥中 Monster Instance 的可恢復狀態與必要引用。來源 Session 的 Stage 只保存作歷史呈現，不是可恢復狀態；場外存檔不自動帶入上一場 Stage。

不保存可回捲的 Character Build／Version／Current State；角色 private knowledge 若住 P6 Campaign world visibility relation，屬世界資料而非 Character Current State。不回捲 Room 共用 Adventure、Monster Template、Battle Map與怪物預配置等authoring或素材bytes；保存相關引用及可驗證的revision／內容識別，避免悄悄把舊引用解釋成另一份素材。

Campaign Monster Instance保留自身建立時的rules snapshot與來源provenance；Restore其可恢復狀態不向最新版Room模板重新生成規則。模板／地圖／配置的編輯與封存不被Campaign Restore回捲，也不影響同Room其他Campaign。

Room／Campaign lifecycle、Roster、Seat assignment／controller、身份與憑證不屬世界還原範圍。完整package仍包含Room／Campaign結構、Roster／Seat及無授權效力的歷史；憑證與live controller binding依D.2／E.2排除或normalize。不能把「Snapshot 排除」誤作所有結構都不備份，也不能以完整備份為由攜帶憑證。

### B.2 時點與權限

**只有手動存檔，沒有自動存檔。** Session Start／End、Scene Change、Combat Start／End 都不建立 Snapshot，也不新增任何 lifecycle 存檔 hook。斷線或 Server 重啟不靠存檔：正式改動成功時已持久化，沿既有 Session Resume 接續。

Manual Save Point 由 Human DM 明確要求：active Session 中只允許該場 Human DM；場外使用 Human Room DM authority（含 Owner 管理 authority），沿用既有權限，不要求虛構 actor。AI DM／AI Player／Player 不能存檔；AI DM 主持的 active Session 中沒有 Human DM，因此該場進行中無人可存檔。

任何 active Combat（Quick／Tactical，即使 Session 已結束）存在時拒絕存檔並說明原因。

Snapshot payload 不完整、非法引用或儲存失敗不得顯示成功，也不留下半份存檔；同一請求 retry 只產生一份。

### B.3 保存與讀取

Snapshot immutable，記建立者、可選 label、來源時點、版本及校驗資訊；列表 bounded，payload／Preview 僅管理 scope 可讀。玩家／AI Player 不收到 DM-only 世界包。手動存檔永久保留：P7 不做自動淘汰、個別刪除或 recycle bin；被 Snapshot／歷史引用的資料不個別 hard delete，Room Hard Delete 仍整包刪除。

## P7-C — Campaign Restore & History Archive

### C.1 還原條件

只允許 Human DM 管理 scope；沒有 active Session，且沒有 active Combat。檢查的是目標 Campaign，不能靠結束 Session 繞過仍延續的 Combat。Owner 的管理 authority 可使用此場外入口，但不取得 active Session 的 DM gameplay role。

先 Preview：來源時間、將回復的世界範圍、保持不變的角色與控制權、將歸檔的歷史，以及缺失／變更引用。Confirm 必須綁定該 Preview 的當前 revision；過期、跨 Room、缺引用或資料格式不支援皆拒絕且零副作用。

### C.2 保留角色與管理狀態

Characters 的 Build、所有 Version、等級、HP、法術位、職業資源、Inventory、Conditions 等 Current State 完整保留。Restore 不呼叫角色寫入流程，不影響同 Room 其他 Campaign 共用角色，也不重建／重新啟動舊戰鬥。

Room 素材與authoring（含怪物模板、地圖、預配置、封存狀態與revision）、Campaign status、Roster、Seat／controller 不回捲。Stage 不還原、不跨場接續，新場維持既有空 Stage 行為。Campaign 世界回到存檔內容；存檔後新增的世界條目退出 active truth，但其歷史／references 不被刪除。Snapshot 不是把資料庫任意 rows 倒回舊 bytes。

### C.3 歷史與接續

Restore commit 原子形成世界更新、history archive boundary、還原管理紀錄與新的接續 generation。原始 Session／事件／seq 不改寫、不刪除；事件 timestamp 不回退。

正常歷史顯示目前延續路徑；可明確切換查閱 archived 歷史，仍受原 visibility 過濾。Restore 後的 AI context 預設不把 archived 世界變化當現況，明確歷史搜尋可取得附 archived 標記的結果。UI 不暴露 Git 式 branch／merge 操作。

Restore 不啟動 Session、不重擲骰、不重新執行舊 mutation；舊 Pending Roll／Reaction／idempotency 結果不復活。舊 pre-session AI grant 與 OAuth family 失效，下一場重新授權；單調 epoch／revision／cursor 不回捲。重複 Confirm 不重複歸檔。

## P7-D — Portable Package Export

### D.1 既有 Character 輸出與三種 Portable Package

Character JSON 與 HTML sheet 沿既有契約；HTML 永不 Import。

| Package | 必須包含 |
|---|---|
| Adventure | Definition、entries、附件及其typed引用閉包（包含實際引用的Room自訂怪物模板）；不含Campaign Runtime；original source files可選 |
| Campaign | Characters及版本、所引用Adventures／Room怪物模板／Battle Maps與預配置、Runtime世界、Roster／Seat結構、Sessions／participants、Timeline（含archived）、Snapshots、Monster／Combat歷史及所需Assets |
| Room | 整個workspace，包括Campaigns、共用Characters／versions／未完成Builder Drafts、整個Room自訂怪物庫／地圖與預配置（含未使用／封存）、未掛Adventure／assets、未完成Adventure Import Drafts與來源；不包含身份憑證 |

同一 Room 共用角色在 Room package 只有一個 identity；Campaign package 只帶自己的完整引用閉包，不捎帶其他 Campaign 歷史。Campaign 中仍被歷史引用的 archived／retired 角色不能漏掉。

Room package內共用怪物模板／地圖亦各只有一份identity。Campaign／Adventure package只帶實際閉包，不把整個Room庫或其他Campaign一起帶走；閉包須追到預配置、Instance、歷史與Snapshot的來源，保留封存狀態、revision、雙語presentation及凍結rules snapshot。內建模板以canonical content stable key及pack dependency表達，不另複製一套內建規則真值。

### D.2 安全與一致性

Campaign／Room 匯出僅 Human Owner；Adventure authoring export 沿 Human Room Owner／DM authority，不開放給 Player 或 AI Seat。完整管理匯出可含秘密，Preview 明確提示，不把這個權限套用到玩家 Timeline。

不 Export 密碼／hash／salt、Owner／DM Key、AI grant secret／token、OAuth token／code／family、access session、API credential、實體 storage path。歷史 actor 使用 package-local audit identity，不能攜帶可重用的 access identity。

Campaign／Room export 取得一致資料點；P7 第一版只在匯出範圍內沒有 active Session／active Combat 時建立完整 package。這不限制既有 Character JSON export。拒絕時不產生冒充完整備份的殘缺檔。

Portable package 帶 schema_version、ruleset、export_type、manifest 與完整性資訊；ZIP／JSON manifest＋asset bytes 可離線保存，不依賴原 Server URL。可在另一個 Web server／新 Room 匯入；多人 package 不送進 Standalone。不承諾舊版本程式可讀未來 schema。

## P7-E — Previewed Copy Import

### E.1 Preview 必須先行

上傳、驗證、Preview、Confirm 明確分離。Preview 不新增正式 Characters／Campaign／Room；列出內容、版本、引用／缺少 content pack、assets、名字衝突及預計建立的新副本。未知版本、錯 ruleset、非法資料／缺檔／checksum mismatch 必須在 Confirm 前拒絕。

不 Merge、不覆蓋既有 identity。Campaign 匯入 target Room 由 Human Owner 執行；Adventure 由 Human Owner／DM 匯入 target Room；Room 完整備份建立新 Room，沿既有 create-room 流程簽發新 Owner authority 與新安全設定，不接受檔案裡的管理身份。

### E.2 Identity 與安全

所有持久 entity identity 依包內引用圖 remap；content stable key、ruleset、既有 Character JSON schema 保持 canonical。Room package 內多 Campaign 對同角色的共用關係維持；Campaign package 匯入既有 Room 也建立新角色副本，不碰原角色。

Room庫與配置同樣copy-as-new：Room package維持包內多Campaign共用同一新模板／地圖；Campaign或Adventure匯入同Room仍建立閉包中的新模板／地圖副本，不因原UUID、名稱或source_key合併既有庫。預配置的自訂模板／map參照、Instance來源／provenance、Combat board來源與Snapshot引用依typed registry remap；revision與凍結規則保留來源語義，不以最新庫覆寫歷史。封存狀態與使用限制沿M07，不因import自動解封。

新 Seat 為待重新指派的結構；歷史 participant／DM Seat／private recipient 對應 remapped Seat，歷史記錄可讀但不提供原 controller binding。不得因 label／display name 自動綁到目前使用者。不匯入、也不啟動任何 active Session／Combat、AI grant、OAuth、Pending Action；已結束事項僅按設計保留無授權效力的歷史證據。

Assets 改用新 Server 管理路徑；visibility 不放寬。封包路徑、壓縮大小、檔案種類與內容皆按 Server 驗證；不執行包內腳本、不抓取包內 URL、不採信匯出者提供的 filesystem path。

### E.3 原子與 retry

Confirm 重新驗 Owner／DM scope、target Room、Preview digest、引用與格式；失效 Preview 要重新 Preview。成功產物完整且立即可由既有 Lobby／Character／世界管理流程使用。失敗不留下半個正式 Room／Campaign 或不完整角色；staging 與素材清理可復原且可追蹤。相同 Confirm retry 回同一次 import 結果，不多建副本。

## P7-F — Full P7 Integration & Closeout

完成「兩個 Session → 秘密過濾與搜尋 → 非戰鬥存檔 → 世界改變／角色變動 → 結束 Session → Restore 世界且保留角色 → archived 歷史查閱 → 下一場 AI context → 匯出 → 新 Room Preview／Import → 接續跑團」整條旅程。

關門必須有 acceptance-to-test matrix、真 PostgreSQL migration／restart／race、Human／AI 權限與拒絕原子性、Web↔Standalone Character exchange regression、雙語 UI、完整 package 冷啟動 round trip、全套工程 gate，以及正式 connector 的 AI DM／Player 歷史查詢證據。後者不要求管理 MCP。

任何未完成要求只可報告缺口，不能以「P8 會補」或「其他 Phase 已關門」宣稱 P7 完成。
